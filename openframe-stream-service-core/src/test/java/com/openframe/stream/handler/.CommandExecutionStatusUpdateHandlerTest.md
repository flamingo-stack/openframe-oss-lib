Unit test suite for `CommandExecutionStatusUpdateHandler`, verifying that Debezium stream events correctly transition `CommandExecution` documents from `RUNNING` to terminal states (`SUCCESS` or `FAILED`) in MongoDB.

## Key Components

| Test Method | Scenario Covered |
|---|---|
| `getDestination_isMongoCommandHistory` | Handler routes to `MONGO_COMMAND_HISTORY` with `COMMON_TYPE` |
| `handle_success_transitionsRowToSuccess` | Exit code 0 + no timeout/error → `SUCCESS`; result fields and timestamps written |
| `handle_nonZeroExit_transitionsRowToFailing` | Non-zero exit code → `FAILED` |
| `handle_timedOut_transitionsRowToFailing` | `timedOut=true` → `FAILED` regardless of exit code |
| `handle_agentError_transitionsRowToFailing` | Agent error string present → `FAILED`; error field persisted |
| `handle_alreadyTerminal_doesNotOverwrite` | Row already in terminal state → `save()` never called (race-condition guard) |
| `handle_rowMissing_skipsSaveQuietly` | No matching row (ad-hoc/legacy) → silently skipped, no exception |
| `handle_truncatesLargeStdoutAndStderr` | stdout/stderr exceeding `MAX_OUTPUT_BYTES` → truncated; `*Truncated` flags set `true` |
| `handle_missingIds_skipsQuietly` | Payload missing `executionId`/`machineId` → repository never touched |

**Helpers:**
- `messageWith(...)` — builds a `DeserializedDebeziumMessage` with a configurable `after` payload
- `runningRow()` — creates a `CommandExecution` fixture in `RUNNING` state

## Usage Example

```java
// Typical handler invocation under test
CommandExecution row = runningRow();
when(commandExecutionRepository.findByMachineIdAndExecutionId(MACHINE_ID, EXECUTION_ID))
        .thenReturn(Optional.of(row));

handler.handle(
    messageWith(0, false, null, 42L, "ok\n", ""),
    new IntegratedToolEnrichedData()
);

ArgumentCaptor<CommandExecution> captor = ArgumentCaptor.forClass(CommandExecution.class);
verify(commandExecutionRepository).save(captor.capture());
assertThat(captor.getValue().getStatus()).isEqualTo(ExecutionStatus.SUCCESS);
```
