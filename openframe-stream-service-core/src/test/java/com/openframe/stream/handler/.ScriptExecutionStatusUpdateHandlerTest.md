Unit test suite for `ScriptExecutionStatusUpdateHandler`, verifying all status transition logic, edge cases, and repository interaction behavior when processing Debezium-sourced script execution completion events.

## Key Components

| Component | Description |
|---|---|
| `ScriptExecutionStatusUpdateHandlerTest` | Main test class using JUnit 5 + Mockito |
| `scriptExecutionRepository` | Mocked repository for `ScriptExecution` document lookup and persistence |
| `handler` | Instance of `ScriptExecutionStatusUpdateHandler` under test |
| `runningRow()` | Helper that builds a `ScriptExecution` fixture in `RUNNING` state |
| `messageWith()` | Helper that constructs a `DeserializedDebeziumMessage` with configurable result fields |

## Test Coverage Summary

| Scenario | Expected Behavior |
|---|---|
| Exit code 0, no error, no timeout | Transitions to `SUCCESS`; result fields copied, timestamps set |
| Non-zero exit code | Transitions to `FAILED` |
| `timedOut=true` | Transitions to `FAILED`, `timedOut` flag preserved |
| Agent error string present | Transitions to `FAILED`, `error` field persisted |
| Row already in terminal status | `save()` never called (watchdog race guard) |
| No row found in repository | `save()` never called, no exception thrown |
| stdout/stderr over `MAX_OUTPUT_BYTES` | Content truncated; `*Truncated` flags set to `true` |
| Missing `executionId` in payload | Repository never touched |
| Missing `machineId` in payload | Repository never touched |
| No `tenantId` (stream enrichment miss) | Still matches by `(machineId, executionId, scriptId)`, transitions correctly |
| `scriptId` present in payload | Correlates lookup on full 3-part key |

## Usage Example

```java
// The handler is dispatched by the Kafka stream processor when Destination = MONGO_HISTORY
// Tests verify routing metadata is correctly declared
assertThat(handler.getDestination()).isEqualTo(Destination.MONGO_HISTORY);
assertThat(handler.getType()).isEqualTo(EventHandlerType.COMMON_TYPE);

// Core transition: exit 0 → SUCCESS
handler.handle(messageWith(EXECUTION_ID, 0, false, null, 42L, "ok\n", ""), new IntegratedToolEnrichedData());
verify(scriptExecutionRepository).save(argThat(e -> e.getStatus() == ExecutionStatus.SUCCESS));

// Truncation guard: oversized output is capped at ScriptExecution.MAX_OUTPUT_BYTES
String huge = "x".repeat(ScriptExecution.MAX_OUTPUT_BYTES + 1024);
handler.handle(messageWith(EXECUTION_ID, 0, false, null, null, huge, huge), enrichedData);
// saved.getStdoutTruncated() == true
```
