Unit test suite for `RmmEnrichmentService`, validating the enrichment logic that resolves machine and organization metadata from a Redis cache and attaches tenant context to deserialized Debezium messages.

## Key Components

| Test | Behavior Verified |
|---|---|
| `getType_returnsRmmResults` | Service routing key is `DataEnrichmentServiceType.RMM_RESULTS` |
| `getExtraParams_resolvesMachineDirectlyAndPopulatesAllFields` | Happy path — all five fields (`machineId`, `hostname`, `organizationId`, `organizationName`, `tenantId`) populated |
| `getExtraParams_unknownMachine_leavesMachineFieldsNullButFillsTenant` | Cache miss on machine — machine/org fields null, `tenantId` still set |
| `getExtraParams_unknownOrganization_keepsMachineFields` | Cache miss on org — machine fields survive, org fields null |
| `getExtraParams_nullAgentId_skipsMachineLookup` | Null `agentId` short-circuits cache interaction entirely |
| `getExtraParams_nullMessage_returnsEmpty` | Null message returns empty enrichment, no collaborator side effects |

**Mocks:** `MachineIdCacheService`, `TenantIdProvider`
**Setup note:** `ClusterTenantIdResolver` is passed as `null` to simulate single-tenant cluster mode.

## Usage Example

```java
// Construct the service under test (mirrors setUp)
RmmEnrichmentService service = new RmmEnrichmentService(
    machineIdCacheService,
    null,               // no ClusterTenantIdResolver in tenant-cluster mode
    tenantIdProvider
);

// Build a minimal inbound Debezium message
DeserializedDebeziumMessage msg = new DeserializedDebeziumMessage();
msg.setAgentId("6d925893-702a-4223-b62f-2f80b927cbaa");

// Enrich — resolves machine → org → tenant from Redis caches
IntegratedToolEnrichedData result = service.getExtraParams(msg);
// result.getMachineId(), .getHostname(), .getOrganizationId(), .getTenantId() now populated
```
