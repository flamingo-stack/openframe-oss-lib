Regression integration test that verifies `SCRIPT_EXECUTED` and `COMMAND_EXECUTED` Kafka messages are fully enriched with device and organization metadata, guarding against a bug where `deviceId`, `hostname`, `organizationId`, and `organizationName` were previously `null` in the dashboard's LogEvent UI.

## Key Components

| Component | Role |
|---|---|
| `scriptExecutedKafkaMessage_yieldsFullyPopulatedEnrichment` | Regression test: parses a `SCRIPT_EXECUTED` Kafka envelope via `ScriptResultDeserializer`, then asserts all four dashboard-visible fields are populated by `RmmEnrichmentService` |
| `commandExecutedKafkaMessage_yieldsFullyPopulatedEnrichment` | Companion regression test for `COMMAND_EXECUTED`, using `CommandResultDeserializer` with the same enrichment path |
| `inboundScriptResult()` | Helper that builds a `CommonDebeziumMessage` envelope mirroring what `RmmResultService` writes to Kafka (payload wraps an `RmmResultEvent` as the `after` field) |
| `RmmEnrichmentService` | Service under test — resolves Machine and Organization directly from `MachineIdCacheService` using the native openframe `machineId`, bypassing the `ToolConnection` lookup that caused the null fields |

## Usage Example

```java
// The test reproduces the exact broken-dashboard scenario:
// 1. Build a Kafka envelope with a known machineId
CommonDebeziumMessage inbound = inboundScriptResult();

// 2. Deserialize — verifies agentId is extracted from machineId (not toolConnection)
ScriptResultDeserializer deserializer = new ScriptResultDeserializer(mapper, ...);
DeserializedDebeziumMessage deserialized = deserializer.deserialize(inbound, MessageType.SCRIPT_EXECUTED);

// 3. Stub cache lookups
when(machineIdCacheService.getMachineByMachineId(MACHINE_ID))
        .thenReturn(new CachedMachineInfo(MACHINE_ID, HOSTNAME, ORG_ID));
when(machineIdCacheService.getOrganization(ORG_ID))
        .thenReturn(new CachedOrganizationInfo(ORG_ID, ORG_NAME));

// 4. Enrich and assert all four fields are non-null
RmmEnrichmentService enrichmentService =
        new RmmEnrichmentService(machineIdCacheService, null, tenantIdProvider);
IntegratedToolEnrichedData enriched = enrichmentService.getExtraParams(deserialized);

assertThat(enriched.getMachineId()).isEqualTo(MACHINE_ID);
assertThat(enriched.getHostname()).isEqualTo(HOSTNAME);
assertThat(enriched.getOrganizationId()).isEqualTo(ORG_ID);
assertThat(enriched.getOrganizationName()).isEqualTo(ORG_NAME);
```

## Root Cause Guarded Against

The original bug: inbound RMM result events carry an `agentId` that is the native openframe `machineId`. The shared enrichment path previously resolved it through `ToolConnection`, which has no entry for native RMM — causing all four fields to return `null`. The fix routes `RMM_RESULTS` messages through `RmmEnrichmentService`, which performs a direct `MachineIdCacheService` lookup instead.
