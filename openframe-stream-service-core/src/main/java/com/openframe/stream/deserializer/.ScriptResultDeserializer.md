Deserializer that binds the shared `RmmResultDeserializer` logic to `MessageType.SCRIPT_EXECUTED` events, resolving a human-readable script name from the result payload to compose the activity stream message.

## Key Components

| Member | Description |
|---|---|
| `getType()` | Returns `MessageType.SCRIPT_EXECUTED` to register this deserializer for that event type |
| `getSourceEventType()` | Returns `SourceEventTypes.Rmm.SCRIPT_RUN_FINISHED` as the canonical source event label |
| `getMessage()` | Builds the display message (e.g. `"Script MyScript executed."`), falling back to `"Script executed"` when the name cannot be resolved |
| `findScriptName()` | Looks up the script name via `ScriptRepository` using the resolved tenant + script ID |
| `resolveScriptId()` | Prefers the `scriptId` field echoed on the result; falls back to an execution-row lookup only when `scriptId` is absent, avoiding ambiguous matches on shared `executionId` values from scheduled runs |

## Usage Example

```java
// Spring auto-detects and registers this component via RmmResultDeserializer dispatch.
// No manual instantiation required. Incoming SCRIPT_EXECUTED stream events are routed here:

JsonNode afterNode = ...; // parsed CDC/event payload

// Framework calls internally:
MessageType type = deserializer.getType();           // SCRIPT_EXECUTED
Optional<String> msg = deserializer.getMessage(afterNode); // "Script Cleanup executed."
```

## Notes

- **Fallback chain for script ID:** direct `scriptId` field → `executionId` → `ScriptExecution` row → `ScriptRepository`. Using the echoed `scriptId` directly avoids the known ambiguity where a single scheduled `executionId` spans multiple scripts.
- All name-resolution failures are caught and logged at `WARN` level; the message gracefully degrades to `"Script executed"` rather than failing the event.
