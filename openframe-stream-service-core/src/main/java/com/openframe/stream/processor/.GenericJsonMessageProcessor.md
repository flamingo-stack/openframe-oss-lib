A Spring `@Service` that orchestrates the full processing pipeline for incoming Debezium CDC messages — deserializing, enriching, and routing them to registered destination handlers.

## Key Components

| Member | Type | Description |
|---|---|---|
| `handlers` | `Map<EventHandlerType, Map<Destination, MessageHandler>>` | Two-level lookup: event handler type → destination → handler instance |
| `dataEnrichmentServices` | `Map<DataEnrichmentServiceType, DataEnrichmentService>` | Enrichment services keyed by their service type |
| `deserializers` | `Map<MessageType, KafkaMessageDeserializer>` | Deserializers keyed by message type |
| `process()` | Method | Entry point — deserializes, enriches, and fans out to all eligible destinations |
| `deserialize()` | Private | Resolves and invokes the correct `KafkaMessageDeserializer`; throws `IllegalArgumentException` for unsupported types |
| `getExtraParams()` | Private | Resolves and invokes the correct `DataEnrichmentService` to produce `IntegratedToolEnrichedData` |

**Constructor injection** auto-wires all `MessageHandler`, `DataEnrichmentService`, and `KafkaMessageDeserializer` beans from the Spring context and indexes them into maps for O(1) lookup.

## Usage Example

```java
// Injected and invoked by a Kafka listener
@KafkaListener(topics = "device-events")
public void onMessage(CommonDebeziumMessage message) {
    genericJsonMessageProcessor.process(message, MessageType.DEVICE_SYNC);
}
```

**Processing flow:**

```text
CommonDebeziumMessage
       │
       ▼
KafkaMessageDeserializer  →  DeserializedDebeziumMessage
       │                            │
       │                            ▼
       │                  DataEnrichmentService  →  IntegratedToolEnrichedData
       │                            │
       └────────────────────────────▼
              For each Destination in MessageType.destinationList
                  (skip if in excludedDestinations or no handler)
                        │
                        ▼
                  MessageHandler.handle(...)
```

> Destinations listed in `deserializedKafkaMessage.getExcludedDestinations()` are silently skipped, allowing per-message routing control without modifying handler logic.
