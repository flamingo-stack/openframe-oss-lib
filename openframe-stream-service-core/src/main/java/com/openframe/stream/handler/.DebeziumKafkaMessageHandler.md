Abstract base handler that processes Debezium CDC events and publishes enriched `IntegratedToolEvent` messages to a Kafka topic (targeting Apache Pinot).

## Key Components

| Member | Description |
|---|---|
| `DebeziumKafkaMessageHandler` | Abstract class extending `DebeziumMessageHandler<IntegratedToolEvent, DeserializedDebeziumMessage>` |
| `kafkaProducer` | `BaseRetryingKafkaProducer` used to publish transformed events to Kafka |
| `validator` | `DebeziumEventValidator` that guards message processing |
| `getTopic()` | Abstract method — subclasses define the target Kafka topic |
| `transform()` | Maps a `DeserializedDebeziumMessage` + `IntegratedToolEnrichedData` into an `IntegratedToolEvent` |
| `handleCreate/Read/Update()` | All route to `kafkaProducer.publish()` with a derived message key |
| `handleDelete()` | No-op — delete events are intentionally ignored |
| `isValidMessage()` | Passes only when `isVisible == true` and `validator.isValid()` returns true |
| `buildMessageBrokerKey()` | Produces a Kafka partition key as `{deviceId|userId}-{toolType}` |
| `getDestination()` | Returns `Destination.KAFKA_PINOT` |
| `getType()` | Returns `EventHandlerType.COMMON_TYPE` |

## Usage Example

```java
@Component
public class AntivirusKafkaHandler extends DebeziumKafkaMessageHandler {

    public AntivirusKafkaHandler(
            BaseRetryingKafkaProducer kafkaProducer,
            ObjectMapper objectMapper,
            DebeziumEventValidator validator) {
        super(kafkaProducer, objectMapper, validator);
    }

    @Override
    protected String getTopic() {
        return "antivirus-events";
    }
}
```

When a Debezium CDC row arrives, the handler validates visibility and business rules, transforms raw CDC data into an `IntegratedToolEvent` (merging device/org/tenant context from `IntegratedToolEnrichedData`), then publishes to the configured topic using a deterministic partition key (`deviceId-toolType`, `userId-toolType`, or `toolType` as fallback).

## Notes

- Subclasses **must** implement `getTopic()` to route events to the correct Kafka topic.
- Delete operations are silently dropped by design — override `handleDelete()` if tombstone records are needed.
- Message broker key priority: `deviceId` → `userId` → `toolType` bare value.
