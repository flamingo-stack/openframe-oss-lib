Handles Debezium CDC (Change Data Capture) messages by transforming them into `UnifiedLogEvent` entities and persisting them to Apache Cassandra. Only active when Cassandra is on the classpath and `spring.data.cassandra.enabled=true`.

## Key Components

| Component | Description |
|---|---|
| `DebeziumCassandraMessageHandler` | Spring `@Component` extending `DebeziumMessageHandler<UnifiedLogEvent, DeserializedDebeziumMessage>` |
| `transform()` | Maps a `DeserializedDebeziumMessage` + `IntegratedToolEnrichedData` into a `UnifiedLogEvent` |
| `createKey()` | Builds the Cassandra composite key (`UnifiedLogEventKey`) from tenant, ingest day, tool type, event type, timestamp, and tool event ID |
| `handleCreate/Read/Update()` | All upsert operations delegate to `repository.save()` |
| `handleDelete()` | No-op — deletes are intentionally ignored |
| `getType()` | Returns `EventHandlerType.COMMON_TYPE` |
| `getDestination()` | Returns `Destination.CASSANDRA_EVENT_LOG` |

## Usage Example

```java
// Bean is auto-configured when Cassandra is available.
// Triggered internally by the Debezium stream processing pipeline.

// The handler resolves enriched context and persists the event:
DeserializedDebeziumMessage msg = ...; // deserialized from Kafka
IntegratedToolEnrichedData enriched = ...; // device/org metadata

UnifiedLogEvent event = handler.transform(msg, enriched);
// Persisted to Cassandra via UnifiedLogEventRepository.save(event)
```

> **Conditional activation:** This bean requires both `CassandraRepository` on the classpath and the property `spring.data.cassandra.enabled=true`. In environments without Cassandra, the bean is skipped entirely.
