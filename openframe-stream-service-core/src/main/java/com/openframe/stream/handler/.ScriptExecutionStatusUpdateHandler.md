Kafka message handler that transitions a `ScriptExecution` document from `RUNNING` to `SUCCESS` or `FAILED` by reading RMM result fields directly from the Debezium `payload.after` envelope, then persisting the updated record to MongoDB.

## Key Components

| Member | Description |
|---|---|
| `getDestination()` | Routes to `Destination.MONGO_HISTORY` — only `MessageType.SCRIPT_EXECUTED` events carry this destination |
| `handle()` | Entry point; validates `executionId`, `machineId`, and `scriptId` from `payload.after`, then delegates to `applyResult()` |
| `applyResult()` | Guards against overwriting a terminal status set by the watchdog, reads result fields, calls `decideStatus()`, truncates outputs, and saves |
| `decideStatus()` | Returns `FAILED` if `timedOut == true`, `exitCode != 0`, or `error` is non-blank; otherwise `SUCCESS` |
| `truncate()` | Caps stdout/stderr at `ScriptExecution.MAX_OUTPUT_BYTES`, respecting UTF-8 codepoint boundaries; sets a `*Truncated` flag on the row |
| `stringOrNull()` / `intOrNull()` / `longOrNull()` / `boolOrNull()` | Null-safe `JsonNode` field extractors used throughout `applyResult()` |

## Usage Example

```java
// The handler is auto-registered as a Spring @Component.
// The stream router selects it by matching Destination.MONGO_HISTORY:

DeserializedDebeziumMessage message = kafkaConsumer.poll();
IntegratedToolEnrichedData extra = enrichmentService.enrich(message);

// Router dispatches to ScriptExecutionStatusUpdateHandler.handle()
messageHandlerRouter.dispatch(message, extra);

// After dispatch, the ScriptExecution row reflects the terminal state:
// status: RUNNING → SUCCESS | FAILED
// exitCode, executionTimeMs, timedOut, stdout, stderr, error — all populated
```

> **Idempotency note:** `applyResult()` refuses to overwrite any status that is not `RUNNING`, making the handler safe against watchdog races and duplicate Kafka deliveries.
