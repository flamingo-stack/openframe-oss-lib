Enrichment service for native OpenFrame RMM execution-result events (`SCRIPT_EXECUTED`, `COMMAND_EXECUTED`). Unlike the external-tool path, it resolves machines directly by `machineId` (carried as `agentId`) rather than going through the `ToolConnection.agentToolId → machineId` indirection.

## Key Components

| Member | Description |
|---|---|
| `getExtraParams(DeserializedDebeziumMessage)` | Main enrichment entry point; populates an `IntegratedToolEnrichedData` with machine, organization, and tenant context |
| `enrichFromMachine(...)` | Resolves `CachedMachineInfo` and `CachedOrganizationInfo` directly from `message.getAgentId()` via `MachineIdCacheService` |
| `enrichFromTenant(...)` | Resolves tenant ID using `TenantIdProvider` (tenant cluster) or `ClusterTenantIdResolver` (shared cluster); mirrors the external-tool path |
| `getType()` | Returns `DataEnrichmentServiceType.RMM_RESULTS` to identify this enricher |
| `ClusterTenantIdResolver` | Optional bean (`required = false`); when absent the service falls back to `TenantIdProvider` |

## Usage Example

```java
// Injected automatically via DataEnrichmentServiceType.RMM_RESULTS dispatch
DeserializedDebeziumMessage message = new DeserializedDebeziumMessage();
message.setAgentId("machine-abc-123");
message.setTenantId("tenant-xyz");

IntegratedToolEnrichedData enriched = rmmEnrichmentService.getExtraParams(message);

// enriched now carries:
// - machineId, hostname        (from CachedMachineInfo)
// - organizationId, name       (from CachedOrganizationInfo)
// - tenantId                   (from TenantIdProvider or ClusterTenantIdResolver)
```

## Notes

- Returns an empty `IntegratedToolEnrichedData` (no exception) when `message` is `null` or `agentId` is missing.
- Logs a `WARN` if the `machineId` from the event has no corresponding cache entry — partial enrichment continues for tenant resolution.
- `ClusterTenantIdResolver` is injected as `@Autowired(required = false)`; omitting it is valid for single-tenant deployments.
