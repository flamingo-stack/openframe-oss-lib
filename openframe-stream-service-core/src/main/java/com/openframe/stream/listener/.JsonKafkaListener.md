Kafka listener for tenant-cluster deployments that consumes Debezium CDC events from multiple integrated-tool topics and delegates processing to `GenericJsonMessageProcessor`.

## Key Components

| Component | Description |
|---|---|
| `@ConditionalOnProperty` | Activates only when `openframe.cluster.mode=tenant` (default); yields to `SharedMeshCentralKafkaListener` in shared SaaS deployments |
| `listenIntegratedToolsEvents` | Consumes from four inbound topics: MeshCentral events, Fleet MDM events, Fleet MDM query results, and Fleet MDM policy membership events |
| `GenericJsonMessageProcessor` | Injected delegate that handles the actual message processing logic |

**Subscribed topics (resolved from properties):**
- `openframe.oss-tenant.kafka.topics.inbound.meshcentral-events.name`
- `openframe.oss-tenant.kafka.topics.inbound.fleet-mdm-events.name`
- `openframe.oss-tenant.kafka.topics.inbound.fleet-mdm-query-result-events.name`
- `openframe.oss-tenant.kafka.topics.inbound.fleet-mdm-policy-membership-events.name`

## Usage Example

```java
// Auto-wired by Spring; no manual instantiation required.
// Activate tenant mode in application properties:

// application.yml
openframe:
  cluster:
    mode: tenant

spring:
  oss-tenant:
    kafka:
      consumer:
        group-id: openframe-tenant-consumer-group

// The listener processes incoming messages automatically:
// Each message is deserialized as CommonDebeziumMessage,
// with MessageType extracted from the Kafka header.
messageProcessor.process(debeziumMessage, messageType);
```

## Notes

- Requires all four topic name properties to be resolvable at startup; missing properties will cause placeholder resolution failure.
- For shared/SaaS multi-tenant deployments, set `openframe.cluster.mode=shared` to disable this listener in favor of `SharedMeshCentralKafkaListener`.
