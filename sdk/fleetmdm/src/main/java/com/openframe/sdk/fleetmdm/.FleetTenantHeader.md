Startup-time guard that validates the `X-Tenant-Id` header value before it is passed into `FleetMdmClient` or `FleetMdmSetupClient`, converting silent 401 failures into a descriptive `IllegalStateException` at construction time.

## Key Components

| Member | Description |
|---|---|
| `validate(boolean, String)` | Static factory-style validator; enforces that a non-blank tenant ID is present when `openframe.fleet.multi-tenancy.enabled=true`, then returns the value for pass-through into a client constructor. |

## Usage Example

```java
// Resolved from Spring Environment or system properties
boolean multiTenancyEnabled = env.getProperty(
    "openframe.fleet.multi-tenancy.enabled", Boolean.class, false);

// Typically sourced from the TENANT_ID environment variable
String tenantId = System.getenv("TENANT_ID");

// Throws IllegalStateException early if multi-tenancy is on but tenantId is blank
String validatedTenantId = FleetTenantHeader.validate(multiTenancyEnabled, tenantId);

FleetMdmClient client = new FleetMdmClient(baseUrl, apiToken, validatedTenantId);
```

## Behavior Notes

- When `multiTenancyEnabled` is `false`, a null or blank `tenantId` passes through silently — the header is simply omitted from outbound requests.
- When `multiTenancyEnabled` is `true` and `tenantId` is blank, throws:
  ```text
  IllegalStateException: openframe.fleet.multi-tenancy.enabled=true but no tenant id is
  configured (TENANT_ID env var missing?)
  ```
- A Fleet server without multi-tenancy ignores the header entirely, so passing a tenant ID to a single-tenant deployment is always safe.
