Default fallback implementation of `EventLogsPublisher` that routes event log messages to the OSS tenant Kafka topic using a retrying producer.

## Key Components

| Component | Description |
|---|---|
| `EventLogsPublisher` | Interface this class implements |
| `OssTenantRetryingKafkaProducer` | Injected producer that handles publish-with-retry logic |
| `openframe.oss-tenant.kafka.topics.outbound.logs-events` | Configuration property binding the target Kafka topic |
| `@ConditionalOnMissingBean` | Ensures this bean is only registered when no other `EventLogsPublisher` is present (e.g. SaaS deployments supply their own) |

## Usage Example

This bean is auto-registered by Spring Boot in OSS deployments. No manual wiring is required — it activates only when a custom `EventLogsPublisher` is absent.

```java
// Triggered automatically; direct usage via the interface:
@RequiredArgsConstructor
public class SomeCommandHandler {

    private final EventLogsPublisher eventLogsPublisher;

    public void handleResult(String commandId, KafkaMessage result) {
        Map<String, Object> headers = Map.of("source", "command-handler");
        eventLogsPublisher.publish(commandId, result, headers);
    }
}
```

Configure the target topic in your `application.yml`:

```yaml
openframe:
  oss-tenant:
    kafka:
      topics:
        outbound:
          logs-events: oss.logs.events
```

## Notes

- In SaaS deployments, provide a custom `EventLogsPublisher` bean to override this default and redirect events to a shared Kafka cluster.
- Failed publishes are retried automatically by `OssTenantRetryingKafkaProducer`; no additional retry logic is needed at the call site.
- Debug-level logging captures `topic` and `key` on each successful publish.
