Configures distributed scheduled job locking for the client-service using ShedLock backed by Redis, ensuring each cron job fires on exactly one pod when multiple replicas are running.

## Key Components

| Element | Description |
|---|---|
| `@EnableScheduling` | Activates Spring's `@Scheduled` task execution |
| `@EnableSchedulerLock` | Enables ShedLock integration with a default max lock duration of 10 minutes |
| `lockProvider` bean | Constructs a `RedisLockProvider` scoped to the current tenant and environment |

## Configuration Properties

| Property | Default | Description |
|---|---|---|
| `openframe.shedlock.environment` | `default` | Environment discriminator injected into the Redis key to isolate locks across environments (e.g., `prod`, `staging`) |

## Redis Key Structure

Lock keys follow the tenant-scoped pattern built by `OpenframeRedisKeyBuilder`:

```text
of:{tenantId}:job-lock:<environment>:<lockName>
```

This prevents lock collisions between tenants and between environments sharing the same Redis instance.

## Usage Example

Annotate any scheduled method in client-service to acquire the distributed lock before execution:

```java
@Scheduled(cron = "${openframe.rmm.sweep.cron}")
@SchedulerLock(name = "rmmScheduleSweep", lockAtMostFor = "5m", lockAtLeastFor = "1m")
public void sweepRmmSchedules() {
    // Executes on exactly one replica
}
```

> The `lockAtMostFor` on each `@SchedulerLock` overrides the 10-minute default from `@EnableSchedulerLock`. Always set `lockAtLeastFor` to prevent a fast-completing job from being re-acquired by another node before the scheduled interval has elapsed.
