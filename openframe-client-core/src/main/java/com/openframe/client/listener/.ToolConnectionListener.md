A Spring component that listens for tool connection events on a NATS JetStream subject, manages a durable push consumer, and delegates processing to `ToolConnectionService`.

## Key Components

| Member | Description |
|---|---|
| `STREAM_NAME` | JetStream stream: `TOOL_CONNECTIONS` |
| `SUBJECT` | Wildcard subject pattern: `machine.*.tool-connection` |
| `CONSUMER_NAME` | Durable consumer identifier: `tool-connection-processor-v2` |
| `DELIVERY_GROUP` | Load-balancing group: `tool-connection` |
| `MAX_DELIVER` | Maximum redelivery attempts before abandoning: `50` |
| `ACK_WAIT` | Acknowledgement timeout: `30s` |
| `subscribeToToolConnections()` | `@EventListener(ApplicationReadyEvent)` — sets up the dispatcher and JetStream push subscription on startup |
| `buildConsumerConfig()` | Creates or updates the durable consumer; handles 404 (consumer not found) by creating a fresh consumer |
| `handleMessage(Message)` | Deserializes `ToolConnectionMessage`, extracts `machineId` from the subject, invokes `ToolConnectionService.addToolConnection`, and explicitly acks on success |
| `isLastAttempt(long)` | Returns `true` when `deliveredCount` equals `MAX_DELIVER` |
| `cleanup()` | `@PreDestroy` — unsubscribes and drains the dispatcher with a 5-second timeout |

## Usage Example

The listener activates automatically on application startup — no manual wiring is required. Messages published to any subject matching `machine.*.tool-connection` are consumed and processed:

```java
// Publish a tool connection event (producer side)
String subject = "machine.abc123.tool-connection";
ToolConnectionMessage msg = new ToolConnectionMessage();
msg.setToolType("ssh");
msg.setAgentToolId("agent-tool-42");

byte[] payload = objectMapper.writeValueAsBytes(msg);
natsConnection.jetStream().publish(subject, payload);

// ToolConnectionListener picks this up automatically and calls:
// toolConnectionService.addToolConnection("abc123", "ssh", "agent-tool-42", false);
```

> **Note:** The `v2` consumer suffix was introduced during a hotfix to attach a delivery group to an existing durable consumer. The original `tool-connection-processor` consumer is deprecated. Messages left unacknowledged on processing errors are automatically redelivered up to `MAX_DELIVER` times.
