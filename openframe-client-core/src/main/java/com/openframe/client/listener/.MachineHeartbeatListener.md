Subscribes to NATS heartbeat messages from machines and delegates processing to `MachineStatusService`. It initializes on application startup and handles graceful shutdown via dispatcher draining.

## Key Components

| Member | Type | Description |
|---|---|---|
| `SUBJECT` | Constant | NATS wildcard subject pattern `machine.*.heartbeat` |
| `subscribeToMachineHeartbeats()` | `@EventListener` | Creates a NATS dispatcher and subscribes on `ApplicationReadyEvent` |
| `handleMessage(Message)` | Private | Extracts machine ID from subject, timestamps the event, and calls `machineStatusService.processHeartbeat()` |
| `cleanup()` | `@PreDestroy` | Drains the dispatcher with a 5-second timeout before shutdown |

## Usage Example

This component is auto-registered as a Spring bean. No manual wiring is required — it activates once the application context is ready.

```java
// Automatic subscription on startup via @EventListener(ApplicationReadyEvent.class)
// Listens on: machine.*.heartbeat
// e.g., machine.abc123.heartbeat → machineId = "abc123"

// Internally delegates to:
machineStatusService.processHeartbeat(machineId, Instant.now());
```

Incoming NATS messages are handled in NATS-managed threads. Each message triggers `NatsTopicMachineIdExtractor` to parse the machine ID from the subject wildcard, then forwards the ID and a server-side timestamp to `MachineStatusService` for processing.

Errors in individual message handling are caught and logged without stopping the dispatcher, ensuring resilience across malformed or unexpected payloads.
