Subscribes to core NATS command-result messages published by the RMM agent and forwards them to `RmmResultService` for relay to Kafka. Operates as a fire-and-forget, non-durable subscriber mirroring the dispatch path.

## Key Components

| Member | Description |
|---|---|
| `SUBJECT` | NATS wildcard subject `machine.*.command-execution.result` — captures results for all machine IDs |
| `subscribeToCommandResults()` | `@EventListener(ApplicationReadyEvent.class)` — creates a NATS `Dispatcher` and subscribes once the Spring context is fully started |
| `handleMessage(Message)` | Extracts `machineId` from the subject, parses the payload into `CommandResultMessage`, and delegates to `RmmResultService.processResult()` |
| `cleanup()` | `@PreDestroy` — drains the dispatcher with a 5-second timeout for graceful shutdown |

## Usage Example

```java
// Bean is auto-registered by Spring; no manual wiring required.
// Subscription lifecycle is tied to ApplicationReadyEvent → @PreDestroy.

// Internally, handleMessage delegates like:
String machineId = machineIdExtractor.extract("machine.abc123.command-execution.result");
// → "abc123"

CommandResultMessage result = resultParser.parse(data, CommandResultMessage.class);
rmmResultService.processResult(machineId, result);
// RmmResultService derives MessageType.COMMAND_EXECUTED from the subtype discriminator.
```

## Error Handling Notes

- Subscription failure at startup rethrows as `RuntimeException` to prevent silent misconfiguration.
- Per-message errors log subject and payload size only — raw command output is intentionally excluded to avoid leaking sensitive data.
