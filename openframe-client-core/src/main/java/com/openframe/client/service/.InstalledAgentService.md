Manages the lifecycle of installed agents on machines, handling registration, version updates, and connection status tracking (CONNECTED/DISCONNECTED).

## Key Components

| Method | Description |
|---|---|
| `addInstalledAgent()` | Registers a new agent or updates an existing one for a given machine, setting status to `CONNECTED` |
| `disconnectAll()` | Marks all agents on a machine as `DISCONNECTED`, typically called on machine disconnection events |
| `markDisconnected()` | Updates a single agent's status to `DISCONNECTED`; skips if already disconnected |
| `updateExistingInstalledAgent()` | Updates version and resets status to `CONNECTED` for an existing agent record |
| `addNewInstalledAgent()` | Creates and persists a new `InstalledAgent` document with timestamps |
| `validateMachineId()` | Guards against null/empty machine IDs, throws `InvalidAgentIdException` |
| `validateAgentType()` | Guards against null/empty agent types, throws `IllegalArgumentException` |
| `validateMachineExists()` | Confirms the machine exists in the repository, throws `MachineNotFoundException` |

## Usage Example

```java
// Register or update an agent on a machine
installedAgentService.addInstalledAgent(
    "machine-abc123",   // machineId
    "MONITORING",       // agentType
    "2.4.1",            // version
    true                // lastAttempt
);

// Disconnect all agents when a machine goes offline
installedAgentService.disconnectAll("machine-abc123");
```

> Both methods are `@Transactional`. `addInstalledAgent` upserts by `(machineId, agentType)` — if a record exists it updates version/status; otherwise it inserts a new document. `disconnectAll` is idempotent and skips agents already in `DISCONNECTED` state.
