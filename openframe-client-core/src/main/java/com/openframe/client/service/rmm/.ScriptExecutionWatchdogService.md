Watchdog service that detects and reaps `ScriptExecution` rows stuck in `RUNNING` status, transitioning them to `FAILED` when no result is received within the expected threshold.

## Key Components

| Member | Description |
|---|---|
| `markStuckExecutionsAsFailing()` | Public entry point; queries for candidates via a coarse DB pre-filter, then applies per-row precision filtering and bulk-saves reaped rows |
| `isStuck(row, now)` | Returns `true` if the row's `dispatchedAt` has exceeded its computed per-execution threshold |
| `thresholdSecondsFor(row)` | Computes the effective timeout: `timeoutSeconds + graceSeconds` per row, or `fallbackThresholdSeconds` when no timeout was recorded |
| `markFailing(row, now)` | Mutates the row to `FAILED`, sets `timedOut = true`, stamps finish timestamps, and writes a descriptive error message |
| `graceSeconds` | Configurable via `openframe.rmm.execution.watchdog.grace-seconds` (default: `120`) — buffer covering dispatch and result-propagation latency |
| `fallbackThresholdSeconds` | Configurable via `openframe.rmm.execution.watchdog.threshold-seconds` (default: `600`) — used when a row has no `timeoutSeconds` |

## Usage Example

This service is intended to be called on a schedule (e.g., via Spring `@Scheduled`):

```java
@Scheduled(fixedDelayString = "${openframe.rmm.execution.watchdog.interval-ms:60000}")
public void runWatchdog() {
    scriptExecutionWatchdogService.markStuckExecutionsAsFailing();
}
```

The two-phase filtering strategy minimises DB load: a single indexed query on `status = RUNNING AND dispatchedAt < now − coarseFloor` fetches candidates, and the precise per-row threshold (`timeoutSeconds + graceSeconds`) is evaluated in-memory before any rows are mutated.

## Configuration

```yaml
openframe:
  rmm:
    execution:
      watchdog:
        grace-seconds: 120      # latency buffer on top of per-execution timeout
        threshold-seconds: 600  # fallback for executions with no timeout set
```
