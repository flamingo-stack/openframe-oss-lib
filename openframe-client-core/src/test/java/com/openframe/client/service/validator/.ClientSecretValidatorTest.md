Unit tests for `ClientSecretValidator`, verifying secret validation logic across matching, blank, and incorrect secret scenarios using Mockito and JUnit 5.

## Key Components

| Component | Description |
|---|---|
| `ClientSecretValidator` | Subject under test — validates raw client secrets against stored encoded values |
| `PasswordEncoder` | Mocked Spring Security component used for secret matching |
| `InvalidClientSecretException` | Expected exception type thrown on validation failure |
| `ErrorCode` | Enum providing specific error codes (`CLIENT_SECRET_EMPTY`, `CLIENT_SECRET_INVALID`) |

## Test Cases

| Test | Scenario | Expected Outcome |
|---|---|---|
| `validate_WithMatchingSecret_Passes` | Raw secret matches encoded secret | No exception thrown |
| `validate_WithBlankSecret_ThrowsEmpty` | Blank/whitespace secret provided | `CLIENT_SECRET_EMPTY` error code; `PasswordEncoder` never invoked |
| `validate_WithWrongSecret_ThrowsInvalid` | Secret does not match stored hash | `CLIENT_SECRET_INVALID` error code |

## Usage Example

```java
// Reproducing the blank secret test scenario
OAuthClient client = new OAuthClient();
client.setClientSecret("encoded-secret");

InvalidClientSecretException ex = assertThrows(
    InvalidClientSecretException.class,
    () -> validator.validate(client, "   ")
);
assertEquals(ErrorCode.CLIENT_SECRET_EMPTY, ex.getErrorCode());

// Verifying PasswordEncoder is short-circuited for blank input
verify(passwordEncoder, never()).matches(any(), any());
```

> **Note:** Blank secret validation short-circuits before invoking `PasswordEncoder`, ensuring no unnecessary crypto operations occur on empty input.
