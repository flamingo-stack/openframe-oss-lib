Unit test suite for `ScriptExecutionWatchdogService`, validating the per-execution stuck-detection logic that marks long-running script executions as `FAILED` based on a per-row timeout plus a configurable grace period.

## Key Components

| Component | Description |
|---|---|
| `GRACE` (120s) | Injected grace buffer added to each execution's own `timeoutSeconds` |
| `FALLBACK` (600s) | Fixed threshold used when an execution has no `timeoutSeconds` set |
| `markStuckExecutionsAsFailing()` | The method under test — identifies and reaps stuck `RUNNING` executions |
| `coarsePreFilter_usesMinThresholdFloorAndRunningStatus` | Asserts the DB pre-filter query uses `min(grace, fallback)` as the earliest cutoff |
| `reapsOnlyStuckSubset_andStampsRow` | Verifies reaped rows receive `FAILED`, `timedOut=true`, `finishedAt`, and a threshold-specific error message |
| `nullTimeout_usesFixedFallback` | Confirms fallback threshold (600s) applies when `timeoutSeconds` is null |
| `running(Integer, long)` | Builder helper creating a `ScriptExecution` in `RUNNING` status with a given timeout and simulated age |

## Usage Example

```java
// Threshold rules exercised by this test suite:
// per-row threshold = timeoutSeconds + graceSeconds  (when timeout is set)
// per-row threshold = fallbackThresholdSeconds       (when timeout is null)

// Reaped: timeout=60s, age=200s → threshold=180s < 200s (stuck)
ScriptExecution stuck = running(60, 200);

// Spared: timeout=3600s, age=700s → threshold=3720s > 700s (healthy, even past fallback)
ScriptExecution healthy = running(3600, 700);

// Spared: no timeout, age=500s → fallback threshold=600s > 500s
ScriptExecution fresh = running(null, 500);
```

## Test Matrix

| Timeout | Age | Threshold | Outcome |
|---|---|---|---|
| 60s | 200s | 180s | ✅ Reaped |
| 60s | 150s | 180s | ⏭ Spared (within grace) |
| 3600s | 700s | 3720s | ⏭ Spared (long-running) |
| `null` | 700s | 600s (fallback) | ✅ Reaped |
| `null` | 500s | 600s (fallback) | ⏭ Spared |
