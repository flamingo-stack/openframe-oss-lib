Unit test suite for `DeviceOnlineScheduleTriggerService`, verifying that the service correctly identifies and fires `DEVICE_ONLINE` script schedules when a device comes online, while handling filtering, edge cases, and dispatch error isolation.

## Key Components

| Component | Role |
|---|---|
| `DeviceOnlineScheduleTriggerService` | Subject under test — processes device-online events and triggers matching schedules |
| `ScriptScheduleMachineAssignedRepository` | Mock — returns schedule assignments for a given tenant/machine |
| `ScriptScheduleRepository` | Mock — fetches full schedule details by ID |
| `ScheduleFireDispatcher` | Mock — dispatches (fires) a schedule to a list of machines |

## Test Cases

| Test | Description |
|---|---|
| `firesActiveDeviceOnlineOnly` | Only schedules with `DEVICE_ONLINE` trigger **and** `ACTIVE` status are dispatched |
| `noAssignment_noOp` | No assignments for the machine → repositories and dispatcher are never called |
| `assignedButNoDeviceOnline_noDispatch` | Assignments exist but no matching `DEVICE_ONLINE` trigger → nothing fired |
| `errorIsolation` | A `RuntimeException` from one dispatch does not prevent remaining schedules from firing |

## Usage Example

```java
// Typical interaction under test
service.onDeviceOnline("tenant-1", "m-1");

// Verifying only the qualifying schedule was dispatched
verify(fireDispatcher).dispatch(eq(deviceOnline), eq(List.of("m-1")), any(Instant.class));
verify(fireDispatcher, never()).dispatch(eq(wrongTrigger), any(), any(Instant.class));
```

## Notes

- Helper methods `assignment()` and `schedule()` keep test setup concise and readable.
- Error isolation (test 4) confirms per-schedule `try/catch` semantics — a NATS failure on one schedule must not block others.
