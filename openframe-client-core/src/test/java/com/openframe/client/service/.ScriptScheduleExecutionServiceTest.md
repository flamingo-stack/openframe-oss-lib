Unit test suite for `ScriptScheduleExecutionService`, verifying schedule orchestration logic including due-schedule sweeps, cadence advancement, one-shot execution, and per-schedule error isolation.

## Key Components

| Component | Role |
|---|---|
| `ScriptScheduleExecutionService` | System under test — runs due schedules and manages state transitions |
| `ScheduleFireDispatcher` | Mocked firing mechanism; dispatches individual schedule executions |
| `ScriptScheduleRepository` | Mocked persistence layer for querying and saving schedule documents |
| `due(Instant, Long)` | Helper factory that builds a minimal `ScriptSchedule` in `ACTIVE` state |

## Test Coverage

| Test | Scenario |
|---|---|
| `noDueSchedules` | Empty result set → no dispatch, no save |
| `dueSchedule_firesThenAdvancesCadence` | Recurring schedule overdue by 3.5 intervals → fires once, `lastRunAt` stamped, `nextRunAt` rolled to the next single future slot |
| `oneShot_clearsNextRun` | `null` interval → fires once, `nextRunAt` set to `null` afterward |
| `dispatchFailure_stillAdvancesButDoesNotStampLastRun` | Dispatch throws → cadence still advances and saves, `lastRunAt` left null, subsequent schedule in the sweep still fires |

## Usage Example

```java
// Run all due ACTIVE schedules (called from a scheduler trigger)
service.runDueSchedules();

// Verify cadence roll-forward in tests
ArgumentCaptor<ScriptSchedule> saved = ArgumentCaptor.forClass(ScriptSchedule.class);
verify(scheduleRepository).save(saved.capture());
assertThat(saved.getValue().getNextRunAt()).isAfter(now);
assertThat(saved.getValue().getLastRunAt()).isNotNull();
```

> **Design note:** Firing logic is intentionally delegated to `ScheduleFireDispatcher` (tested separately). These tests focus exclusively on schedule-state transitions — `lastRunAt`/`nextRunAt` bookkeeping and the missed-interval collapse behaviour — keeping each test suite's concerns isolated.
