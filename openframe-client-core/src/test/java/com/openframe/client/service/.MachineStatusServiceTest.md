Unit tests for `MachineStatusService`, verifying the correct application events are published when a machine's connectivity status transitions between `OFFLINE`, `ONLINE`, and `PENDING` states.

## Key Components

| Component | Description |
|---|---|
| `MachineStatusService` | Subject under test; handles device status updates and event publishing |
| `MachineRepository` | Mocked repository used to simulate persisted machine state |
| `ApplicationEventPublisher` | Mocked Spring publisher; verified for correct event dispatch |
| `DeviceCameOnlineEvent` | Event expected only on `OFFLINE → ONLINE` transitions |
| `DeviceFirstConnectedEvent` | Event expected only on `PENDING → ONLINE` (first-ever connection) |

## Test Cases

| Test | Transition | Expected Behaviour |
|---|---|---|
| `offlineToOnline_publishesCameOnline` | `OFFLINE → ONLINE` | Publishes `DeviceCameOnlineEvent` |
| `onlineToOnline_noCameOnline` | `ONLINE → ONLINE` (heartbeat) | No `DeviceCameOnlineEvent` published |
| `pendingToOnline_firstConnectOnly` | `PENDING → ONLINE` | Publishes `DeviceFirstConnectedEvent`; never publishes `DeviceCameOnlineEvent` |

## Usage Example

```java
// Typical test interaction pattern used in this suite:
when(machineRepository.findByMachineId(MACHINE))
    .thenReturn(Optional.of(machine(DeviceStatus.OFFLINE)));

service.updateToOnline(MACHINE, LATER);

// Assert the reconnection event fires
verify(eventPublisher).publishEvent(any(DeviceCameOnlineEvent.class));

// Assert first-connect event is NOT fired for a known offline device
verify(eventPublisher, never()).publishEvent(any(DeviceFirstConnectedEvent.class));
```

The `machine()` helper method constructs a `Machine` fixture with a given `DeviceStatus`, keeping test setup minimal and readable.
