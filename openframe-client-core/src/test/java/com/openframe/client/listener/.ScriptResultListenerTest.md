Unit tests for `ScriptResultListener`, verifying that incoming NATS messages on the `machine.*.script-execution.result` subject are correctly deserialized into `ScriptResultMessage` and delegated to `RmmResultService`.

## Key Components

| Element | Description |
|---|---|
| `ScriptResultListenerTest` | JUnit 5 test class using Mockito for NATS infrastructure mocks |
| `handleMessage_extractsMachineIdDeserializesAndDelegates` | Verifies full happy-path: subject parsing, snake_case JSON deserialization, and service delegation |
| `handleMessage_ignoresUnknownFields` | Ensures forward-compatible wire contract — unknown JSON fields do not break deserialization |
| `handleMessage_swallowsMalformedPayload` | Confirms malformed JSON is silently swallowed, protecting the NATS dispatcher thread |
| `handleMessage_swallowsInvalidSubject` | Confirms unparseable subjects are silently swallowed without reaching the service |
| `captureSubscribedHandler()` | Test helper that triggers `subscribeToScriptResults()` and captures the registered `MessageHandler` via `ArgumentCaptor` |

## Usage Example

```java
// Typical test flow: capture the handler, fire a synthetic message, assert delegation
MessageHandler handler = captureSubscribedHandler();

String json = "{\"execution_id\":\"exec-1\",\"exit_code\":0,...}";
handler.onMessage(message("machine.machine-42.script-execution.result", json));

ArgumentCaptor<ScriptResultMessage> captor = ArgumentCaptor.forClass(ScriptResultMessage.class);
verify(rmmResultService).processResult(eq("machine-42"), captor.capture());
assertThat(captor.getValue().getExecutionId()).isEqualTo("exec-1");
```

## Notes

- Mirrors `CommandResultListenerTest` — the only differences are the NATS subject (`script-execution.result` vs `command-execution.result`) and the concrete payload subtype (`ScriptResultMessage`), which acts as the discriminator for downstream `MessageType` routing in `RmmResultService`.
