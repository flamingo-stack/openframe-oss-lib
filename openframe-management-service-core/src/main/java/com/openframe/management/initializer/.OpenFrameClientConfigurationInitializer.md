Loads and applies the OpenFrame client configuration from a bundled JSON file at application startup, ensuring the configuration store reflects the latest settings defined in `agent-configurations/client-configuration.json`.

## Key Components

| Element | Description |
|---|---|
| `OpenFrameClientConfigurationInitializer` | Spring `ApplicationRunner` component that executes during startup |
| `CONFIG_FILE` | Classpath resource path: `agent-configurations/client-configuration.json` |
| `objectMapper` | Deserializes the JSON config file into an `OpenFrameClientConfiguration` document |
| `clientConfigurationService` | Persists/merges the loaded config via `updateConfigurationFields()` |
| `@Order(30)` | Controls initialization order relative to other `ApplicationRunner` beans |

## Usage Example

This component runs automatically on startup — no manual invocation required. To customize the client configuration, edit the bundled JSON file:

```java
// Classpath resource resolved at startup:
// src/main/resources/agent-configurations/client-configuration.json

// Internally, the runner performs:
ClassPathResource resource = new ClassPathResource("agent-configurations/client-configuration.json");
OpenFrameClientConfiguration config = objectMapper.readValue(
    resource.getInputStream(),
    OpenFrameClientConfiguration.class
);
clientConfigurationService.updateConfigurationFields(config);
```

To register a custom initializer at a different priority, adjust `@Order`:

```java
@Component
@Order(35) // Runs after OpenFrameClientConfigurationInitializer (@Order(30))
public class MyPostConfigInitializer implements ApplicationRunner { ... }
```

## Notes

- Runs once per application startup; not triggered on live config changes.
- Uses `updateConfigurationFields()` (merge/patch semantics) rather than a full replace, preserving any fields not present in the JSON file.
