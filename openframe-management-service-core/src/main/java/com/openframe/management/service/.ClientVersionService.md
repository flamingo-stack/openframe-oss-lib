Manages the lifecycle of client release versions by persisting version records and propagating updates across OpenFrame client configurations and integrated tool agents.

## Key Components

| Member | Type | Description |
|---|---|---|
| `process(String releaseVersion)` | `@RetryOnOptimisticLockingFailure` method | Entry point — upserts a `ReleaseVersion` record and triggers propagation |
| `updateExistingReleaseVersion(...)` | Private method | Updates an existing version document if changed; re-propagates idempotently even when version is unchanged |
| `createNewReleaseVersion(...)` | Private method | Creates the initial `ReleaseVersion` document when none exists |
| `propagate(String version)` | Private method | Fans out the new version to client configuration and all release-flagged tool agents |
| `updateReleaseAgents(String version)` | Private method | Fetches all `IntegratedToolAgent` records with `releaseVersion=true` and updates each to the new version |

## Usage Example

```java
// Injected by Spring — trigger version promotion on new release
@Autowired
private ClientVersionService clientVersionService;

// Called when a new client build is published (e.g., from a webhook or scheduled job)
clientVersionService.process("1.4.2");
// Logs: "Processing release version: 1.4.2"
// → upserts ReleaseVersion doc
// → calls openFrameClientConfigurationService.updateVersion("1.4.2")
// → updates every IntegratedToolAgent where releaseVersion == true
```

## Notes

- **Optimistic locking**: `@RetryOnOptimisticLockingFailure` on `process()` handles concurrent version updates safely without explicit locking.
- **Idempotency**: propagation always runs even when the stored version already matches, ensuring downstream state stays consistent on retries.
