REST controller managing CRUD operations for integrated tools in a multi-tenant environment, handling tool persistence, Debezium connector lifecycle, and post-save hook execution.

## Key Components

| Component | Description |
|---|---|
| `GET /v1/tools` | Returns all tools for the current tenant |
| `GET /v1/tools/{id}` | Fetches a single tool by its Mongo `_id` |
| `POST /v1/tools/{key}` | Creates or updates a tool addressed by `(tenantId, key)` |
| `SaveToolRequest` | Inner DTO wrapping the `IntegratedTool` payload |
| `IntegratedToolPostSaveHook` | Extension hooks executed after a successful save |

## Usage Example

```java
// GET all tools
GET /v1/tools
// Response: { "status": "success", "tools": [...] }

// Save or update a tool by key
POST /v1/tools/meshcentral-server
Content-Type: application/json

{
  "tool": {
    "name": "MeshCentral",
    "debeziumConnectors": [...]
  }
}
// Response: { "status": "success", "tool": { ... } }
```

## Multi-Tenant ID Safety

The `POST` handler explicitly guards against cross-tenant document collisions. If the incoming payload carries an `_id` equal to the tool key, reusing it in a shared MongoDB collection could overwrite another tenant's document. Instead, the controller resolves the correct `_id` by looking up the existing `(tenantId, key)` record via `getToolByKey`, or clears `_id` to let MongoDB generate a fresh one.

## Post-Save Hooks

Hooks registered as `IntegratedToolPostSaveHook` beans run after each save. Failures are caught and logged as warnings — they do not roll back the save or affect the HTTP response, ensuring resilience against non-critical side effects.
