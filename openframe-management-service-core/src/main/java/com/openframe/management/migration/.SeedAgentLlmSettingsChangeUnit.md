Mongock change unit that backfills missing `agent_llm_settings` records for each agent type (`CLIENT`, `ADMIN`) by reading the tenant's active `ai_model_configs` document, ensuring the AI settings UI and config endpoints return non-null values after initial deployment.

## Key Components

| Element | Description |
|---|---|
| `@ChangeUnit(id = "seed-agent-llm-settings", order = "006")` | Mongock migration identifier; runs in ordered sequence |
| `execution()` | Seeds one `agent_llm_settings` document per missing agent type using the tenant's active model config |
| `rollback()` | No-op rollback — seeded records are benign and retained on failure |
| `AGENT_TYPES` | Fixed list `["CLIENT", "ADMIN"]` defining the agent scopes to backfill |
| `PROVIDER_TYPE_FIELD` | Uses `"type"` (not `"providerConfigType"`) to match how Spring Data actually persists the provider discriminator |

## Behavior

- **Idempotent**: skips any agent type that already has an existing record; duplicate key errors from concurrent inserts are silently swallowed
- **Tenant-scoped**: resolves the current tenant via `TenantIdProvider`; tenants with no active model config are skipped entirely
- **Raw collection access**: bypasses Spring Data typed mapping intentionally, since `AgentLlmSettings` and `AIModelConfig` live in a SaaS lib not available to this OSS module
- **Explicit `createdAt`**: stamped manually because raw `insertOne` does not trigger Spring Data `@CreatedDate` auditing

## Usage Example

```java
// Mongock picks this up automatically via component scanning.
// No manual invocation needed — runs once per tenant on application startup
// when the change unit has not yet been applied.

// To verify seeded records in MongoDB shell:
db.agent_llm_settings.find({ tenantId: "your-tenant-id" })
// Expected output: two documents, one per agentType ("CLIENT", "ADMIN"),
// each containing llmProvider, providerModel, and createdAt fields.
```
