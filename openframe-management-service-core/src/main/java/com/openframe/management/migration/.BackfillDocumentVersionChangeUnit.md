Mongock migration change unit that backfills a `documentVersion` field (set to `0L`) on existing MongoDB documents that are missing it, targeting three collections scoped by tenant ID.

## Key Components

| Element | Description |
|---|---|
| `@ChangeUnit(id = "backfill-document-version", order = "001")` | Registers this class as a Mongock migration, executed first in the sequence |
| `execution()` | Entry point annotated with `@Execution`; resolves the current tenant ID and delegates to `backfill()` for each collection |
| `rollback()` | No-op `@RollbackExecution` handler — the backfill is considered safe to leave in place on failure |
| `backfill()` | Queries documents missing `documentVersion` for the given tenant and sets the field to `0L` via `updateMulti` |

**Target collections:**
- `integrated_tool_agents`
- `openframe_client_configuration`
- `release_versions`

## Usage Example

This class is picked up automatically by Mongock at application startup. No manual invocation is needed. Ensure the Mongock scan path includes `com.openframe.management.migration`.

```java
// application.yml (Mongock scan configuration)
// mongock:
//   migration-scan-package: com.openframe.management.migration

// At runtime, Mongock calls execution() once per tenant context:
// 1. Resolves tenantId via TenantIdProvider
// 2. For each collection, runs:
Query query = new Query(
    Criteria.where("tenantId").is(tenantId)
             .and("documentVersion").exists(false)
);
Update update = new Update().set("documentVersion", 0L);
mongoTemplate.updateMulti(query, update, "integrated_tool_agents");
// Logs: "Backfilled documentVersion on N document(s) in collection integrated_tool_agents"
```

> **Note:** Rollback is intentionally a no-op. Re-running this migration is idempotent — documents already carrying `documentVersion` are excluded by the `exists(false)` predicate.
