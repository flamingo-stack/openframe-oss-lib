A Mongock database migration change unit that backfills the `organizationId` field on `TimeEntry` documents by looking up the associated `Ticket` and copying its `organizationId`.

## Key Components

| Member | Type | Description |
|---|---|---|
| `execution()` | `@Execution` | Main migration logic — finds all `TimeEntry` documents missing `organizationId`, resolves each via its linked `Ticket`, and updates the field |
| `rollback()` | `@RollbackExecution` | No-op rollback (backfill is considered safe to leave in place) |
| `setOrganizationId()` | Private helper | Issues a targeted `updateFirst` on a single `TimeEntry` by `_id` |

**Change unit metadata:** `id = "backfill-timeentry-organization-id"`, `order = "007"`, `author = "openframe"`

## Behavior

The migration queries for `TimeEntry` records where:
- `tenantId` matches the current tenant
- `organizationId` is `null`
- `ticketId` is not `null`

For each result it fetches the parent `Ticket` and copies `organizationId`. Three skip conditions are tracked and logged:

- `skippedMissingTicket` — referenced ticket not found
- `skippedTicketWithoutOrg` — ticket exists but has no `organizationId`
- `backfilled` — successfully updated entries

## Usage Example

```java
// Executed automatically by Mongock on application startup.
// Manual invocation is not required. Mongock resolves dependencies via Spring context.

@ChangeUnit(id = "backfill-timeentry-organization-id", order = "007", author = "openframe")
public class BackfillTimeEntryOrganizationIdChangeUnit {

    @Execution
    public void execution(MongoTemplate mongoTemplate, TenantIdProvider tenantIdProvider) {
        // Mongock injects MongoTemplate and TenantIdProvider automatically
    }

    @RollbackExecution
    public void rollback() {
        // No-op: safe to leave backfilled data in place
    }
}
```
