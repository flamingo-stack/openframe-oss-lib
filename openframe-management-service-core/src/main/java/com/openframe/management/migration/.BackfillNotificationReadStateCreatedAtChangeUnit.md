Mongock migration change unit that backfills the `createdAt` field on existing `notification_read_states` documents by extracting the timestamp embedded in each document's ObjectId `_id`, enabling a 30-day TTL index to expire pre-existing records correctly.

## Key Components

| Element | Description |
|---|---|
| `@ChangeUnit(id = "backfill-notification-read-state-created-at", order = "007")` | Registers this as the 7th migration step in the Mongock changelog |
| `execution()` | Runs an aggregation-pipeline `updateMany` scoped to the current tenant, setting `createdAt` from `$toDate($\_id)` only on documents missing the field with an ObjectId `_id` |
| `rollback()` | No-op — backfilled timestamps are non-destructive and safe to leave in place on rollback |

## Behavior Details

- **Tenant-scoped** — filters by `tenantId` via `TenantIdProvider` so the migration is safe in multi-tenant deployments.
- **Idempotent** — the `$exists: false` filter ensures already-migrated documents are never re-written.
- **ObjectId-only** — the `$type: "objectId"` guard skips any documents with non-ObjectId `_id` values to avoid incorrect timestamps.

## Usage Example

```java
// Mongock discovers and runs this automatically during application startup.
// No manual invocation is needed. The migration targets the collection directly:

// Effective MongoDB operation per tenant:
db.notification_read_states.updateMany(
  {
    tenantId: "<current-tenant>",
    createdAt: { $exists: false },
    _id: { $type: "objectId" }
  },
  [{ $set: { createdAt: { $toDate: "$_id" } } }]
);
```
