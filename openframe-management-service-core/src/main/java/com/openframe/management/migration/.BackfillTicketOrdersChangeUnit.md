A Mongock migration change unit that backfills LexoRank-based ordering values onto existing tickets that lack an `order` field, organized by ticket status.

## Key Components

| Component | Description |
|---|---|
| `@ChangeUnit(id = "backfill-ticket-orders", order = "002")` | Mongock annotation registering this as the second migration in sequence |
| `execution()` | Entry point iterating over all `TicketStatus` values and triggering per-status backfill |
| `backfillColumn()` | Queries tickets with a null `order` for a given tenant and status, then assigns sequential LexoRank values sorted by `createdAt` descending |
| `assignOrder()` | Performs the individual MongoDB `updateFirst` to set the `order` field on a single ticket |
| `rollback()` | No-op rollback — order assignment is considered safe to leave in place on failure |

## Usage Example

This class is auto-discovered and executed by Mongock on application startup. No manual invocation is required.

```java
// Mongock wires dependencies automatically via Spring context.
// The migration targets tickets matching this query shape:
Query query = new Query(
    Criteria.where("tenantId").is(tenantId)
            .and("status").is(status)
            .and("order").is(null)
);
query.with(Sort.by(Sort.Direction.DESC, "createdAt"));

// LexoRank sequence is seeded from middle and walks forward:
LexoRank rank = LexoRank.middle();
rank = rank.genNext(); // advances for each ticket
```

Tickets without an `order` value are ranked starting from `LexoRank.middle()`, walking forward (`genNext()`), so newly ordered tickets interleave cleanly with any future manual reordering.

## Notes

- Only tickets where `order IS NULL` are affected — already-ordered tickets are left untouched.
- The rollback is intentionally empty; re-running the migration is idempotent since ordered tickets are skipped by the null check.
