Mongock change unit that repairs ticket ordering on the lifecycle (custom-status) board by re-ranking all tickets within each `statusId` column using LexoRank, sorted by `createdAt` descending.

## Key Components

| Member | Type | Description |
|---|---|---|
| `execution()` | `@Execution` | Entry point: fetches distinct `statusId` values for the tenant and normalizes each column |
| `rollback()` | `@RollbackExecution` | No-op rollback (rank reassignment is not reversible) |
| `distinctStatusIds()` | Private helper | Queries all non-null `statusId` values for the current tenant |
| `normalizeColumn()` | Private helper | Re-ranks tickets in a single `statusId` column newest-first using `LexoRank.middle()` → `genNext()` |
| `assignOrder()` | Private helper | Writes the computed LexoRank string to the `order` field on a single ticket document |

**Migration metadata:** `id = "normalize-ticket-order-by-status-id"`, `order = "004"`, `author = "openframe"`

## Usage Example

This class is executed automatically by Mongock during application startup. No manual invocation is needed.

```java
// Mongock picks this up via @ChangeUnit and calls execution() once per tenant
@ChangeUnit(id = "normalize-ticket-order-by-status-id", order = "004", author = "openframe")
public class NormalizeTicketOrderByStatusIdChangeUnit {

    @Execution
    public void execution(MongoTemplate mongoTemplate, TenantIdProvider tenantIdProvider) {
        // 1. Resolve tenant
        // 2. Find all distinct statusId values
        // 3. For each column: sort tickets by createdAt DESC, assign ascending LexoRank
    }
}
```

> **Side effect:** Manual drag-drop ordering within a column is reset to `createdAt` descending. This migration specifically targets tickets whose `order` was incorrectly computed against the legacy `status` field instead of `statusId`.
