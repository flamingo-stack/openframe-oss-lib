Defines the MongoDB document model for tenant-scoped ticket status definitions, mapping to the `ticket_statuses` collection with a unique compound index enforcing one status per `tenantId`/`kind` pair for built-in status types.

## Key Components

| Member | Type | Description |
|---|---|---|
| `id` | `String` | MongoDB document identifier (`@Id`) |
| `tenantId` | `String` | Tenant scoping field (via `TenantScoped`) |
| `kind` | `TicketStatusKind` | Enum classifying the status (e.g., `AI_ASSISTANCE`, `TECH_REQUIRED`, `RESOLVED`, `ARCHIVED`) |
| `name` | `String` | Display name for the status |
| `color` | `String` | UI color representation |
| `position` | `String` | Ordering/display position |
| `createdAt` / `updatedAt` | `Instant` | Auto-managed audit timestamps |

**Index:** `tenant_kind_unique` — compound unique index on `tenantId` + `kind`, scoped to the four built-in `TicketStatusKind` values via a partial filter.

## Usage Example

```java
TicketStatusDefinition status = TicketStatusDefinition.builder()
    .tenantId("tenant-abc")
    .kind(TicketStatusKind.RESOLVED)
    .name("Resolved")
    .color("#4CAF50")
    .position("4")
    .build();

mongoTemplate.save(status);
```

> **Note:** The partial filter on the compound index only enforces uniqueness for the four built-in kinds (`AI_ASSISTANCE`, `TECH_REQUIRED`, `RESOLVED`, `ARCHIVED`), allowing multiple custom statuses per tenant without constraint conflicts.
