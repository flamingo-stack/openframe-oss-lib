MongoDB document entity representing a connection between a machine and a specific tool within a tenant's scope, stored in the `tool_connections` collection.

## Key Components

| Member | Type | Description |
|--------|------|-------------|
| `id` | `String` | MongoDB document identifier (`@Id`) |
| `tenantId` | `String` | Tenant scope identifier (implements `TenantScoped`) |
| `machineId` | `String` | Reference to the associated machine |
| `toolType` | `ToolType` | Enum identifying the type of tool connected |
| `agentToolId` | `String` | External reference ID within the agent/tool system |
| `status` | `ConnectionStatus` | Current connection state |
| `metadata` | `String` | JSON string for tool-specific arbitrary data |
| `connectedAt` | `Instant` | Timestamp when the connection was established |
| `lastSyncAt` | `Instant` | Timestamp of the most recent sync |
| `disconnectedAt` | `Instant` | Timestamp when the connection was terminated |

A **compound unique index** (`tenant_machine_tool_idx`) enforces that a given machine can only have one active connection per tool type within a tenant.

## Usage Example

```java
ToolConnection connection = new ToolConnection();
connection.setTenantId("tenant-abc");
connection.setMachineId("machine-xyz");
connection.setToolType(ToolType.MONITORING);
connection.setAgentToolId("agent-tool-001");
connection.setStatus(ConnectionStatus.CONNECTED);
connection.setMetadata("{\"endpoint\": \"https://tool.example.com\"}");
connection.setConnectedAt(Instant.now());

toolConnectionRepository.save(connection);
```

## Notes

- Implements `TenantScoped` to ensure all queries are automatically filtered by `tenantId`
- `metadata` is stored as a raw JSON string to accommodate varying tool-specific configuration schemas without requiring schema migrations
