MongoDB document entity representing a single notification record within the OpenFrame platform, supporting tenant-scoped storage with automatic 30-day TTL expiration.

## Key Components

| Field | Type | Description |
|---|---|---|
| `id` | `String` | MongoDB document identifier (`@Id`) |
| `severity` | `NotificationSeverity` | Alert level; defaults to `INFO` |
| `category` | `NotificationCategory` | Logical grouping of the notification |
| `title` | `String` | Short display title |
| `description` | `String` | Full notification body |
| `createdAt` | `Instant` | Auto-set on insert (`@CreatedDate`); drives 30-day TTL index |
| `context` | `NotificationContext` | Arbitrary contextual metadata |
| `correlationId` | `String` | Optional key linking to a source event (e.g. an approval request); allows in-place updates of an existing notification |
| `tenantId` | `String` | Tenant isolation via `TenantScoped` contract |

## Usage Example

```java
Notification notification = Notification.builder()
    .severity(NotificationSeverity.WARNING)
    .category(NotificationCategory.APPROVAL)
    .title("Approval Required")
    .description("A new change request requires your approval.")
    .correlationId("approval-request-789")
    .tenantId("tenant-abc")
    .build();

notificationRepository.save(notification);
```

> **TTL:** The `createdAt` field carries a MongoDB TTL index (`expireAfterSeconds = NotificationRetention.HISTORY_TTL_SECONDS`), automatically purging documents after 30 days.

> **Upsert pattern:** When `correlationId` is non-null, callers can query by this indexed field to update an existing notification in place rather than inserting a duplicate.
