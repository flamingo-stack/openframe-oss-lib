Persisted MongoDB document representing a single script-execution attempt, mapping to the Script Details → Execution History UI view.

## Key Components

| Member | Type | Description |
|---|---|---|
| `MAX_OUTPUT_BYTES` | `int` | 64 KiB cap on persisted stdout/stderr; larger output is truncated |
| `executionId` | `String` | Server-minted correlation ID shared between dispatch message and agent result |
| `scriptId` / `machineId` | `String` | Indexed foreign keys for query filtering |
| `status` | `ExecutionStatus` | Current execution state (e.g. `RUNNING`, `COMPLETED`) |
| `stdoutTruncated` / `stderrTruncated` | `Boolean` | Flags set when output exceeds `MAX_OUTPUT_BYTES` |
| Compound indexes | — | Uniqueness constraint on `(tenantId, executionId, machineId, scriptId)`; history queries on `(tenantId, scriptId, dispatchedAt)`; watchdog sweep on `(status, dispatchedAt)` |

## Usage Example

```java
ScriptExecution execution = ScriptExecution.builder()
    .tenantId("tenant-abc")
    .executionId("exec-001")
    .scriptId("script-xyz")
    .machineId("machine-123")
    .privilegeLevel(PrivilegeLevel.ADMIN)
    .timeoutSeconds(60)
    .initiatedBy("user@example.com")
    .status(ExecutionStatus.RUNNING)
    .dispatchedAt(Instant.now())
    .build();

// After agent responds:
execution.setStatus(ExecutionStatus.COMPLETED);
execution.setExitCode(0);
execution.setStdout(rawOutput.length() > ScriptExecution.MAX_OUTPUT_BYTES
    ? rawOutput.substring(0, ScriptExecution.MAX_OUTPUT_BYTES)
    : rawOutput);
execution.setStdoutTruncated(rawOutput.length() > ScriptExecution.MAX_OUTPUT_BYTES);
execution.setFinishedAt(Instant.now());
```

## Notes

- Implements `TenantScoped` — all queries must include `tenantId` for row-level isolation.
- Full stdout/stderr beyond the 64 KiB limit remains on the agent side; only the truncated slice is persisted in MongoDB.
- The `status_dispatchedAt` index powers the watchdog sweep that detects stalled `RUNNING` executions.
