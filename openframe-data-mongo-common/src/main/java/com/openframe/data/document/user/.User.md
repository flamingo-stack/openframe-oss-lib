MongoDB document entity representing a user within a tenant-scoped system, mapping to the `users` collection with built-in audit timestamps and CRM sync tracking.

## Key Components

| Member | Type | Description |
|---|---|---|
| `id` | `String` | MongoDB document identifier (`@Id`) |
| `tenantId` | `String` | Tenant association for multi-tenancy isolation (indexed) |
| `email` | `String` | Unique user email, normalized on write (indexed) |
| `firstName` / `lastName` | `String` | User display name fields |
| `roles` | `List<UserRole>` | Assigned roles, defaults to empty list |
| `emailVerified` | `boolean` | Email verification flag; auto-set to `true` for SSO logins |
| `status` | `UserStatus` | Account status, defaults to `UserStatus.ACTIVE` (indexed) |
| `crmSynced` | `Boolean` | HubSpot sync state; `null`/`false` = pending sync, `true` = synced |
| `createdAt` / `updatedAt` | `LocalDateTime` | Audit timestamps managed by Spring Data |

**`setEmail(String)`** — Custom setter that trims whitespace and lowercases the email using `Locale.ROOT` before persisting, ensuring consistent storage and lookup.

## Usage Example

```java
// Build a new user for a tenant
User user = User.builder()
    .tenantId("tenant-abc")
    .firstName("Jane")
    .lastName("Doe")
    .roles(List.of(UserRole.TECHNICIAN))
    .status(UserStatus.ACTIVE)
    .build();

// Email is normalized automatically
user.setEmail("  Jane.Doe@Example.com  ");
// Stored as: "jane.doe@example.com"

// Check CRM sync state (null = needs initial sync)
if (Boolean.TRUE.equals(user.getCrmSynced())) {
    // already synced to HubSpot
}
```

## Notes

- Implements `TenantScoped` to enforce multi-tenant data isolation patterns used across the OpenFrame document model.
- `crmSynced` uses `Boolean` (boxed) intentionally — `null` distinguishes "never synced" from `false` ("sync failed/reset"), enabling targeted HubSpot sync queries.
