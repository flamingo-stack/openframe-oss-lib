Persisted MongoDB document representing a single ad-hoc command execution attempt for one target machine, forming one row in the Command Execution History within the RMM (Remote Monitoring & Management) module.

## Key Components

| Member | Type | Description |
|---|---|---|
| `MAX_OUTPUT_BYTES` | `static final int` | 64 KB cap on persisted stdout/stderr; excess is truncated and flagged |
| `id` | `String` | MongoDB document `_id` |
| `tenantId` | `String` | Tenant isolation field; implements `TenantScoped` |
| `executionId` | `String` | Groups all per-machine rows belonging to the same batch dispatch |
| `machineId` | `String` | Target agent machine for this execution slice |
| `command` | `String` | Raw shell command sent to the agent |
| `shell` | `ScriptShell` | Shell interpreter used (e.g., bash, PowerShell) |
| `privilegeLevel` | `PrivilegeLevel` | Elevation context for the command |
| `status` | `ExecutionStatus` | Lifecycle state: `RUNNING` → `SUCCESS` / `FAILED` |
| `stdout` / `stderr` | `String` | Captured output, truncated at `MAX_OUTPUT_BYTES` |
| `stdoutTruncated` / `stderrTruncated` | `Boolean` | Flags set when output exceeds the cap |
| `exitCode` / `executionTimeMs` / `timedOut` | various | Agent result metadata written back on completion |

**MongoDB Indexes:**
- `tenant_executionId_machineId_unique` — unique constraint preventing duplicate dispatch rows
- `tenant_dispatchedAt` — supports tenant-scoped history queries (descending time order)
- `status_dispatchedAt` — serves the watchdog sweep for stale `RUNNING` executions

## Usage Example

```java
CommandExecution execution = CommandExecution.builder()
    .tenantId("tenant-abc")
    .executionId("exec-001")
    .machineId("machine-xyz")
    .command("Get-Service | Where-Object { $_.Status -eq 'Running' }")
    .shell(ScriptShell.POWERSHELL)
    .privilegeLevel(PrivilegeLevel.STANDARD)
    .timeoutSeconds(30)
    .initiatedBy("admin@example.com")
    .status(ExecutionStatus.RUNNING)
    .dispatchedAt(Instant.now())
    .build();

// Agent result frame writes back:
execution.setStatus(ExecutionStatus.SUCCESS);
execution.setExitCode(0);
execution.setStdout("WinRM   Running ...");
execution.setExecutionTimeMs(1_240L);
execution.setFinishedAt(Instant.now());
```
