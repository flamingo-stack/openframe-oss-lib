MongoDB document entity representing an SSO (Single Sign-On) configuration scoped to a specific tenant, stored in the `sso_configs` collection.

## Key Components

| Member | Type | Description |
|---|---|---|
| `id` | `String` | MongoDB document ID (`@Id`) |
| `tenantId` | `String` | Indexed reference to the owning tenant (`TenantScoped`) |
| `provider` | `String` | SSO provider identifier (e.g., Microsoft, Google) |
| `clientId` | `String` | OAuth/OIDC client ID |
| `clientSecret` | `String` | OAuth/OIDC client secret |
| `enabled` | `boolean` | Whether this SSO config is active |
| `autoProvisionUsers` | `boolean` | Auto-create users on first SSO login if `true`; only pre-existing users allowed if `false` |
| `msTenantId` | `String` | Microsoft Entra (Azure AD) tenant ID for Office 365 OIDC (optional) |
| `allowedDomains` | `List<String>` | Email domain whitelist for auto-provisioning; unrestricted if empty/null |

## Usage Example

```java
SSOConfig config = new SSOConfig();
config.setTenantId("tenant-abc");
config.setProvider("microsoft");
config.setClientId("app-client-id");
config.setClientSecret("app-client-secret");
config.setEnabled(true);
config.setAutoProvisionUsers(true);
config.setMsTenantId("ms-entra-tenant-id");
config.setAllowedDomains(List.of("acme.com", "acme.io"));
```

> **Note:** When `autoProvisionUsers` is `false`, users must be pre-created in the system before they can authenticate via the configured SSO provider. Set `allowedDomains` to restrict auto-provisioning to specific email domains.
