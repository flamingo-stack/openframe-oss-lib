An enum representing the possible status categories for a ticket, distinguishing between system-managed statuses and custom user-defined ones.

## Key Components

| Member | Description |
|---|---|
| `AI_ASSISTANCE` | Ticket is being handled by AI automation |
| `TECH_REQUIRED` | Ticket requires human technician intervention |
| `RESOLVED` | Ticket has been resolved |
| `ARCHIVED` | Ticket has been archived |
| `CUSTOM` | User-defined custom status |
| `isSystem()` | Returns `true` for all statuses except `CUSTOM` |

## Usage Example

```java
TicketStatusKind status = TicketStatusKind.AI_ASSISTANCE;

if (status.isSystem()) {
    // Handle system-managed status (AI_ASSISTANCE, TECH_REQUIRED, RESOLVED, ARCHIVED)
    applySystemWorkflow(status);
} else {
    // Handle user-defined custom status
    applyCustomWorkflow(status);
}

// Branching on specific status
switch (status) {
    case AI_ASSISTANCE -> routeToAI();
    case TECH_REQUIRED -> assignToTechnician();
    case RESOLVED      -> notifyClient();
    case ARCHIVED      -> moveToArchive();
    case CUSTOM        -> handleCustomStatus();
}
```

## Notes

- All statuses except `CUSTOM` are considered system statuses via `isSystem()`, making it easy to guard logic that should only apply to platform-managed states.
