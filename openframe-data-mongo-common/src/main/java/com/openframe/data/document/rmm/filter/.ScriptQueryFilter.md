Data-layer filter criteria for querying `Script` documents in the RMM module. Decouples repository filtering from the API layer, following the `OrganizationQueryFilter` pattern; the service layer handles mapping between this class and the API-layer `ScriptFilterInput`.

## Key Components

| Field | Type | Description |
|---|---|---|
| `shells` | `List<ScriptShell>` | Filter by one or more script shell types |
| `statuses` | `List<ScriptStatus>` | Filter by one or more script lifecycle statuses |
| `supportedPlatforms` | `List<ScriptPlatform>` | Filter by one or more target platforms |
| `tagIds` | `List<String>` | Match scripts assigned any of these tag IDs (resolved via `tag_assignments`); `null` = no constraint |
| `createdByIds` | `List<String>` | Match scripts authored by any of these user IDs; `null` = no constraint |

Built with Lombok (`@Data`, `@Builder`, `@NoArgsConstructor`, `@AllArgsConstructor`) for zero-boilerplate construction and mutation.

## Usage Example

```java
// Fetch all active PowerShell scripts on Windows, tagged with a specific tag,
// authored by a known user
ScriptQueryFilter filter = ScriptQueryFilter.builder()
    .shells(List.of(ScriptShell.POWERSHELL))
    .statuses(List.of(ScriptStatus.ACTIVE))
    .supportedPlatforms(List.of(ScriptPlatform.WINDOWS))
    .tagIds(List.of("tag-abc123"))
    .createdByIds(List.of("user-xyz789"))
    .build();

List<Script> scripts = scriptRepository.findAll(filter);
```

## Notes

- All fields are optional — a `null` list field applies no constraint for that dimension, allowing partial or fully unfiltered queries.
- Tag filtering is resolved at the repository level via the `tag_assignments` collection, not inline on the script document.
