MongoDB document entity representing the assignment relationship between a script schedule and a machine within a tenant's scope.

## Key Components

| Member | Type | Description |
|---|---|---|
| `id` | `String` | MongoDB document identifier (`@Id`) |
| `tenantId` | `String` | Tenant scope identifier (`TenantScoped`) |
| `scriptScheduleId` | `String` | Reference to the parent script schedule |
| `machineId` | `String` | Reference to the assigned machine |
| `createdBy` | `String` | Audit field tracking the creator |
| `createdAt` | `Instant` | Auto-populated creation timestamp (`@CreatedDate`) |
| `updatedAt` | `Instant` | Auto-populated last modified timestamp (`@LastModifiedDate`) |

**Indexes:**
- Unique compound index on `(tenantId, scriptScheduleId, machineId)` — prevents duplicate assignments
- Compound index on `(tenantId, machineId)` — optimizes lookups by machine within a tenant

## Usage Example

```java
ScriptScheduleMachineAssigned assignment = ScriptScheduleMachineAssigned.builder()
        .tenantId("tenant-abc")
        .scriptScheduleId("schedule-123")
        .machineId("machine-456")
        .createdBy("user-789")
        .build();

// Persist via Spring Data MongoDB repository
scriptScheduleMachineAssignedRepository.save(assignment);

// Query all assignments for a specific machine within a tenant
List<ScriptScheduleMachineAssigned> assignments =
        repository.findByTenantIdAndMachineId("tenant-abc", "machine-456");
```

> The unique compound index enforces that a machine can only be assigned to a given script schedule once per tenant, making `save()` idempotent when used with upsert patterns.
