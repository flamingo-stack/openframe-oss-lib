MongoDB document entity representing a user invitation within a tenant-scoped system, tracking invitation lifecycle state, role assignments, and expiry.

## Key Components

| Member | Type | Description |
|---|---|---|
| `id` | `String` | MongoDB document identifier (`@Id`) |
| `tenantId` | `String` | Indexed tenant reference (`TenantScoped`) |
| `email` | `String` | Indexed, normalized invitee email address |
| `roles` | `List<UserRole>` | Roles to assign on acceptance; defaults to empty list |
| `expiresAt` | `Instant` | Invitation expiry timestamp |
| `status` | `InvitationStatus` | Lifecycle state; defaults to `PENDING` |
| `createdAt` | `Instant` | Auto-set by Spring Data (`@CreatedDate`) |
| `updatedAt` | `Instant` | Auto-set by Spring Data (`@LastModifiedDate`) |

**`setEmail(String email)`** — Custom setter that trims whitespace and lowercases the address using `Locale.ROOT` before persisting, preventing duplicate invitations caused by case or whitespace variations.

## Usage Example

```java
Invitation invitation = Invitation.builder()
    .tenantId("tenant-abc")
    .email("  Alice@Example.com  ") // normalized to "alice@example.com"
    .roles(List.of(UserRole.TECHNICIAN))
    .expiresAt(Instant.now().plus(Duration.ofDays(7)))
    .build();

// Default status is PENDING
assert invitation.getStatus() == InvitationStatus.PENDING;

// Persisted to the "invitations" collection via a repository
invitationRepository.save(invitation);
```

## Notes

- Implements `TenantScoped` — all queries should filter by `tenantId` to enforce data isolation.
- Both `email` and `tenantId` are indexed for efficient lookup and uniqueness enforcement at the query layer.
- Uses Lombok `@SuperBuilder` to support inheritance-friendly builder patterns alongside `@Data` for boilerplate reduction.
