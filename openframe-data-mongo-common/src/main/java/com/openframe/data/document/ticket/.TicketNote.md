Represents a technician's internal note on a support ticket, stored as a MongoDB document in the `ticket_notes` collection. Notes are tenant-scoped, support plain text or markdown content, and track authorship and timestamps.

## Key Components

| Field | Type | Description |
|---|---|---|
| `id` | `String` | MongoDB document identifier (`@Id`) |
| `tenantId` | `String` | Tenant isolation field (implements `TenantScoped`) |
| `ticketId` | `String` | Reference to the parent ticket |
| `content` | `String` | Note body — plain text or markdown |
| `authorId` | `String` | User ID of the authoring technician; resolved via DataLoader |
| `createdAt` | `Instant` | Auto-populated on insert (`@CreatedDate`) |
| `updatedAt` | `Instant` | Auto-updated on save (`@LastModifiedDate`) |

**Indexes:**
- Compound index on `{ticketId: 1, createdAt: -1}` for efficient per-ticket note retrieval in reverse-chronological order
- Single-field indexes on `tenantId` and `ticketId`

## Usage Example

```java
TicketNote note = TicketNote.builder()
    .tenantId("tenant-abc")
    .ticketId("ticket-123")
    .content("Checked device logs — no hardware faults detected.")
    .authorId("user-456")
    .build();

ticketNoteRepository.save(note);

// Fetch notes for a ticket (uses compound index)
List<TicketNote> notes = ticketNoteRepository
    .findByTicketIdOrderByCreatedAtDesc("ticket-123");
```

> **Note:** `authorId` is a reference only — display name and avatar are resolved at the API layer via a DataLoader to avoid redundant data duplication across documents.
