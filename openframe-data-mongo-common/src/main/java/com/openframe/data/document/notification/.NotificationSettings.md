MongoDB document entity for storing per-user notification preferences within a tenant, enforcing a unique compound index on `tenantId` + `userId`. Absence of a document is treated as the default "all enabled" state, eliminating the need for backfill migrations.

## Key Components

| Member | Type | Description |
|---|---|---|
| `id` | `String` | MongoDB document identifier (`@Id`) |
| `tenantId` | `String` | Tenant identifier (from `TenantScoped`) |
| `userId` | `String` | User the settings belong to |
| `pushEnabled` | `boolean` | Push notification toggle; defaults to `true` |
| `createdAt` / `updatedAt` | `Instant` | Audit timestamps |

**Collection:** `notification_settings`
**Index:** Unique compound index on `(tenantId, userId)`

## Usage Example

```java
// Create settings explicitly disabling push for a user
NotificationSettings settings = NotificationSettings.builder()
    .tenantId("tenant-abc")
    .userId("user-123")
    .pushEnabled(false)
    .createdAt(Instant.now())
    .updatedAt(Instant.now())
    .build();

// Default (no document) = all notifications enabled.
// Only persist when overriding defaults.
notificationSettingsRepository.save(settings);
```

## Notes

- Implements `TenantScoped` to ensure consistent multi-tenant data isolation patterns across the platform.
- The `@Builder.Default` on `pushEnabled` ensures the builder path also initialises the field to `true` (Lombok builders otherwise ignore field-level defaults).
- Reader logic should resolve a missing document as fully-enabled rather than fully-disabled, keeping the collection lean.
