Data-layer filter criteria DTO for querying `ScriptSchedule` documents, designed to keep the repository layer decoupled from the API module.

## Key Components

| Field | Type | Description |
|---|---|---|
| `statuses` | `List<ScriptStatus>` | Filter by one or more script schedule statuses |
| `supportedPlatforms` | `List<ScriptPlatform>` | Filter by target platform(s) |
| `createdByIds` | `List<String>` | Filter by author user ID(s); `null` applies no author constraint |

## Usage Example

```java
// Filter for active schedules on Windows, created by specific users
ScriptScheduleQueryFilter filter = ScriptScheduleQueryFilter.builder()
    .statuses(List.of(ScriptStatus.ACTIVE))
    .supportedPlatforms(List.of(ScriptPlatform.WINDOWS))
    .createdByIds(List.of("user-123", "user-456"))
    .build();

// Unconstrained filter (match all schedules)
ScriptScheduleQueryFilter noConstraints = new ScriptScheduleQueryFilter();
```

## Notes

- Intentionally omits shell and tag facets present in `ScriptQueryFilter`, as schedules do not carry those attributes.
- The service layer is responsible for mapping between this filter and the API-layer `ScriptScheduleFilterInput`.
- All fields are `null`-safe — a `null` list field means no constraint is applied for that dimension.
