Defines the lifecycle states for a `Script` document in the RMM (Remote Monitoring and Management) data model, implementing a soft-delete pattern.

## Key Components

| Value | Description |
|---|---|
| `ACTIVE` | Script is available for use and visible in API responses |
| `ARCHIVED` | Script is retained but hidden from default workflows |
| `DELETED` | Soft-deleted; hidden from API surfaces but preserved in MongoDB for historic execution record resolution |

## Usage Example

```java
// Filter scripts visible to end-users (excludes soft-deleted)
List<Script> visibleScripts = scriptRepository
    .findByTenantIdAndStatusIn(tenantId, List.of(ScriptStatus.ACTIVE, ScriptStatus.ARCHIVED));

// Soft-delete a script (retains document for execution history)
script.setStatus(ScriptStatus.DELETED);
scriptRepository.save(script);

// Check if a script name can be reused
boolean nameIsAvailable = !scriptRepository.existsByTenantIdAndNameAndStatusIn(
    tenantId, name, List.of(ScriptStatus.ACTIVE, ScriptStatus.ARCHIVED)
);
```

## Notes

- **Partial unique index** on `(tenantId, name)` is scoped to `ACTIVE` and `ARCHIVED` statuses only — `DELETED` scripts free their name for reuse. See `MongoIndexConfig` for index definition.
- Mirrors the `OrganizationStatus` pattern used elsewhere in the data model.
- Historic execution records continue to resolve a script's display name even after deletion because the underlying document is never purged from MongoDB.
