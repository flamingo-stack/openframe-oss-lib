MongoDB document model tracking per-recipient read/unread state for notifications, with compound indexes for efficient recipient-based queries and a 30-day TTL mirroring the parent `Notification` document retention policy.

## Key Components

| Member | Type | Description |
|---|---|---|
| `id` | `String` | MongoDB document identifier (`@Id`) |
| `recipientId` | `String` | ID of the notification recipient |
| `recipientType` | `RecipientType` | Enum classifying the recipient (e.g. user, group) |
| `notificationId` | `String` | Reference to the parent `Notification` document |
| `status` | `ReadStatus` | Current read state (e.g. `READ`, `UNREAD`) |
| `category` | `NotificationCategory` | Notification category for filtered queries |
| `title` | `String` | Denormalized notification title for quick access |
| `createdAt` | `Instant` | Auto-populated creation timestamp; drives 30-day TTL expiry |
| `readAt` | `Instant` | Timestamp when the recipient marked the notification as read |
| `tenantId` | `String` | Tenant scope identifier (implements `TenantScoped`) |

**Compound Indexes:**

- `recipient_notification_unique` — enforces one read-state document per recipient/notification pair
- `recipient_status` — supports unread-count and inbox queries
- `recipient_category_status` — supports category-filtered inbox views

## Usage Example

```java
NotificationReadState readState = NotificationReadState.builder()
    .recipientId("user-123")
    .recipientType(RecipientType.USER)
    .notificationId("notif-456")
    .status(ReadStatus.UNREAD)
    .category(NotificationCategory.ALERT)
    .title("Disk usage critical on SERVER-01")
    .tenantId("tenant-abc")
    .build();

// Mark as read
readState.setStatus(ReadStatus.READ);
readState.setReadAt(Instant.now());
```
