MongoDB document entity representing a named, tenant-scoped task that executes one or more `Script`s against assigned machines, either ad-hoc or on a recurring schedule.

## Key Components

| Field | Type | Description |
|---|---|---|
| `id` | `String` | MongoDB document identifier |
| `tenantId` | `String` | Tenant isolation key (from `TenantScoped`) |
| `name` | `String` | Human-readable schedule name |
| `scriptIds` | `List<String>` | References to associated `Script` documents |
| `supportedPlatforms` | `List<ScriptPlatform>` | Target OS/platform filter |
| `trigger` | `ScriptScheduleTrigger` | Trigger type; defaults to `DATE_TIME` |
| `startAt` | `Instant` | Initial execution timestamp |
| `repeat` | `Long` | Recurrence interval (e.g., in seconds) |
| `nextRunAt` / `lastRunAt` | `Instant` | Scheduling bookkeeping fields |
| `status` | `ScriptStatus` | Lifecycle state; defaults to `ACTIVE`, indexed |
| `createdAt` / `updatedAt` | `Instant` | Auditing timestamps (Spring Data auto-managed) |

**Indexes:**
- Compound index on `{tenantId, name}` — enforces name uniqueness per tenant
- Compound index on `{status, nextRunAt}` (`status_nextRunAt`) — optimizes scheduler polling queries

## Usage Example

```java
ScriptSchedule schedule = ScriptSchedule.builder()
    .tenantId("tenant-abc")
    .name("Nightly Patch Check")
    .description("Runs patch audit scripts on all Windows endpoints")
    .supportedPlatforms(List.of(ScriptPlatform.WINDOWS))
    .scriptIds(List.of("script-001", "script-002"))
    .trigger(ScriptScheduleTrigger.DATE_TIME)
    .startAt(Instant.parse("2025-01-01T02:00:00Z"))
    .repeat(86400L) // every 24 hours
    .status(ScriptStatus.ACTIVE)
    .build();
```

## Notes

- Implements `TenantScoped` to enforce multi-tenant data isolation
- Uses Lombok (`@Data`, `@Builder`, `@NoArgsConstructor`, `@AllArgsConstructor`) to reduce boilerplate
- Stored in the `script_schedules` MongoDB collection
