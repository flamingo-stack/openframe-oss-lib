A Spring `@Component` registry that maps notification type strings to their corresponding `NotificationContextDescriptor` implementations, enabling category resolution by type key or full notification context.

## Key Components

| Member | Description |
|---|---|
| `byType` | Immutable map of notification type string → `NotificationContextDescriptor`, built at construction time |
| `NotificationContextDescriptorRegistry(List<NotificationContextDescriptor>)` | Constructor that auto-collects all `NotificationContextDescriptor` beans via Spring dependency injection |
| `categoryOf(String type)` | Resolves a `NotificationCategory` from a bare type string; returns `GENERIC` if unregistered |
| `categoryOf(NotificationContext context)` | Resolves a `NotificationCategory` from a full `NotificationContext` instance, allowing payload-aware category logic (e.g. ticket-linked approvals); returns `GENERIC` for null or unregistered contexts |

## Usage Example

```java
// Inject the registry wherever category resolution is needed
@Service
public class NotificationRouter {

    private final NotificationContextDescriptorRegistry registry;

    public NotificationRouter(NotificationContextDescriptorRegistry registry) {
        this.registry = registry;
    }

    public void route(NotificationContext context) {
        // Resolve category from a full context (supports payload-aware descriptors)
        NotificationCategory category = registry.categoryOf(context);

        // Or resolve from a bare type string
        NotificationCategory categoryByType = registry.categoryOf("ticket.approval");

        // Use category to determine routing logic
        if (category == NotificationCategory.GENERIC) {
            // handle generic notification
        }
    }
}
```

> **Note:** All `NotificationContextDescriptor` beans are registered automatically at startup. To add a new notification type, implement `NotificationContextDescriptor` and annotate it with `@Component` — no manual registry wiring required.
