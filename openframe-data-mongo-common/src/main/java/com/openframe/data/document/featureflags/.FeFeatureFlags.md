MongoDB document entity for storing per-tenant frontend feature flag overrides. Values stored in this document take precedence over YAML configuration defaults (`openframe.fe-feature-flag.*`), with any missing flags falling back to the configured defaults.

## Key Components

| Member | Type | Description |
|--------|------|-------------|
| `id` | `String` | MongoDB document identifier (`@Id`) |
| `flags` | `Map<String, Boolean>` | Key-value map of feature flag name → enabled state; defaults to an empty `LinkedHashMap` |
| `createdAt` | `LocalDateTime` | Auto-populated on insert via `@CreatedDate` |
| `updatedAt` | `LocalDateTime` | Auto-updated on every save via `@LastModifiedDate` |
| `tenantId` | `String` | Indexed tenant discriminator; one document per tenant in the `fe_feature_flags` collection |

Implements `TenantScoped` to participate in the platform-wide multi-tenant data isolation pattern.

## Usage Example

```java
// Create a per-tenant override document enabling a specific flag
FeFeatureFlags featureFlags = FeFeatureFlags.builder()
    .tenantId("tenant-abc")
    .flags(new LinkedHashMap<>(Map.of(
        "newDashboardEnabled", true,
        "betaReportsEnabled",  false
    )))
    .build();

featureFlagsRepository.save(featureFlags);

// Check a specific override at runtime
boolean isDashboardEnabled = featureFlags.getFlags()
    .getOrDefault("newDashboardEnabled", false);
```

## Notes

- The `fe_feature_flags` collection holds **one document per tenant**; query by `tenantId` to retrieve overrides.
- Flags absent from `flags` map are **not evaluated** here — the calling service is responsible for falling back to YAML defaults.
- `LinkedHashMap` preserves insertion order, which aids predictable serialization and debugging.
