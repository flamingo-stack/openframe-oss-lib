Base interface defining common repository operations for integrated tool persistence, supporting both reactive (`Mono`) and blocking (`Optional`) implementations through generic type parameters.

## Key Components

| Element | Description |
|---|---|
| `BaseIntegratedToolRepository<T, B, ID>` | Generic base interface parameterized for return type wrapper, boolean return type, and ID type |
| `findByType(String type)` | Looks up an integrated tool by its type identifier |
| `findByKey(String key)` | Looks up an integrated tool by its human-readable key (e.g. `"fleetmdm-server"`); tenant-aware when used with `TenantAwareMongoTemplate` |

## Usage Example

```java
// Blocking implementation (e.g. Spring Data)
public interface IntegratedToolRepository
        extends BaseIntegratedToolRepository<Optional<IntegratedTool>, Boolean, String> {
    // findByType and findByKey return Optional<IntegratedTool>
}

// Reactive implementation (e.g. Spring Data Reactive)
public interface ReactiveIntegratedToolRepository
        extends BaseIntegratedToolRepository<Mono<IntegratedTool>, Mono<Boolean>, String> {
    // findByType and findByKey return Mono<IntegratedTool>
}

// Querying a tool by key
Optional<IntegratedTool> tool = repository.findByKey("fleetmdm-server");
tool.ifPresent(t -> System.out.println("Found: " + t.getType()));
```

## Notes

- `T` — return wrapper (`Optional<IntegratedTool>` for blocking, `Mono<IntegratedTool>` for reactive)
- `B` — boolean return wrapper (`boolean` vs `Mono<Boolean>`)
- `ID` — identifier type, conventionally `String`
- `findByKey` relies on `TenantAwareMongoTemplate` to automatically inject `tenantId` in tenant-scoped services
