Defines the contract for resolving the current pod's tenant identity, with a default OSS implementation backed by an environment variable and an override point for SaaS multi-tenant deployments.

## Key Components

| Member | Type | Description |
|---|---|---|
| `getTenantId()` | `String` | Returns the tenant ID for the running pod. OSS default reads from the `TENANT_ID` env var. |
| `isTenantRegistered()` | `default boolean` | Returns `true` if the tenant is registered and ready. Always `true` in OSS; SaaS implementations may return `false` during cluster provisioning. |

## Usage Example

```java
// OSS default — resolved via TENANT_ID environment variable
@Component
public class EnvTenantIdProvider implements TenantIdProvider {
    @Override
    public String getTenantId() {
        return System.getenv("TENANT_ID");
    }
    // isTenantRegistered() inherited default returns true
}

// SaaS override — annotated @Primary to replace the OSS default
@Primary
@Component
public class ClusterTenantIdProvider implements TenantIdProvider {
    @Override
    public String getTenantId() {
        // resolves clusterName -> tenantId via tenant_cluster_registrations
        return tenantClusterRegistry.resolveByClusterName(clusterName);
    }

    @Override
    public boolean isTenantRegistered() {
        return tenantClusterRegistry.isProvisioned(clusterName);
    }
}
```

## Notes

- The OSS default requires no registration or database lookup — only the `TENANT_ID` environment variable must be set.
- SaaS deployments inject a `@Primary` bean to override both methods without modifying shared code.
- Consumers should check `isTenantRegistered()` before performing tenant-scoped operations in environments where provisioning may be in progress.
