Configures a dedicated virtual-thread executor for NATS notification channel processing, preventing `@Async` tasks from falling back to unbounded platform threads in consumer applications that have no default executor defined.

## Key Components

| Name | Type | Description |
|---|---|---|
| `CHANNEL_EXECUTOR` | `String` constant | Bean name (`"notificationChannelExecutor"`) used to reference the executor via `@Async` or `@Qualifier` |
| `notificationChannelExecutor()` | `@Bean` | Returns a `VirtualThreadPerTaskExecutor` — a lightweight, one-virtual-thread-per-task executor backed by JDK 21+ virtual threads |

## Usage Example

Reference the executor by its constant name in `@Async` or when injecting an `Executor` directly:

```java
// Trigger async work on the library-owned virtual-thread executor
@Async(NotificationChannelExecutorConfig.CHANNEL_EXECUTOR)
public void handleNotification(NotificationEvent event) {
    // Runs on a virtual thread; no platform thread pool contention
    process(event);
}
```

```java
// Or inject it directly
@Qualifier(NotificationChannelExecutorConfig.CHANNEL_EXECUTOR)
private final Executor channelExecutor;

public void dispatch(Runnable task) {
    channelExecutor.execute(task);
}
```

> **Note:** Requires JDK 21+. The virtual-thread executor spawns a new virtual thread per submitted task — ideal for high-concurrency, I/O-bound NATS message handling without the overhead of a fixed thread pool.
