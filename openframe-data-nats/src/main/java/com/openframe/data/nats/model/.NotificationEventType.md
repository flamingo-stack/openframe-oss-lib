Defines the lifecycle event types for notifications published to the NATS stream, indicating whether a notification is newly created or an update to an existing one.

## Key Components

| Constant | Description |
|---|---|
| `CREATED` | Initial push of a new notification to the stream |
| `UPDATED` | Supersedes a prior notification with the same ID; clients should upsert rather than append |

## Usage Example

```java
NotificationEvent event = NotificationEvent.builder()
    .id("notif-123")
    .eventType(NotificationEventType.CREATED)
    .message("Backup completed successfully")
    .build();

// On a subsequent state change, signal clients to upsert the existing card
NotificationEvent update = NotificationEvent.builder()
    .id("notif-123")
    .eventType(NotificationEventType.UPDATED)
    .message("Backup verified and archived")
    .build();
```

## Notes

- Clients consuming the NATS stream should **upsert by notification ID** when they receive `UPDATED`, not append a new card.
- The enum is intentionally minimal — extend it (e.g. `DELETED`) if tombstone/removal semantics are needed in the future.
