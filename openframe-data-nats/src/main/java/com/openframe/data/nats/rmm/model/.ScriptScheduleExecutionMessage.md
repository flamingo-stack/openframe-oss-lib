Represents the wire payload dispatched to an OpenFrame agent over NATS when a scheduled script run fires — one message per target machine, bundling all scripts for that schedule into a single envelope.

## Key Components

| Field | Type | Description |
|---|---|---|
| `executionId` | `String` | Shared correlation ID across all messages and leaf `ScriptExecution` rows in the run |
| `scheduleId` | `String` | Identifies the originating schedule |
| `machineId` | `String` | Target machine for this message |
| `initiatedBy` | `String` | User or system that triggered the schedule |
| `scripts` | `List<ScriptScheduleExecutionItem>` | Full set of scripts the schedule executes on this machine |

## Usage Example

```java
ScriptScheduleExecutionMessage message = ScriptScheduleExecutionMessage.builder()
    .executionId(UUID.randomUUID().toString())
    .scheduleId("sched-abc123")
    .machineId("machine-xyz789")
    .initiatedBy("admin@example.com")
    .scripts(List.of(
        ScriptScheduleExecutionItem.builder()
            .scriptId("script-001")
            .build()
    ))
    .build();

// Published on subject: machine.{machineId}.script-schedule-execution
natsConnection.publish(
    "machine." + message.getMachineId() + ".script-schedule-execution",
    objectMapper.writeValueAsBytes(message)
);
```

## Notes

- Replaces the per-script fan-out pattern from [`ScriptMessage`](https://github.com/flamingo-stack/openframe-oss-lib/blob/main/src/main/java/com/openframe/data/nats/rmm/model/ScriptMessage.java) for schedule-triggered dispatches — for M machines and N scripts, emits M messages instead of N×M
- `@JsonInclude(NON_NULL)` ensures null fields are omitted from the wire payload
- The agent correlates individual `(scriptId, machineId)` results back via the shared `executionId`
