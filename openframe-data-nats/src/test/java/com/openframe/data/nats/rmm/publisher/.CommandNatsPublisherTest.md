Unit test suite for `CommandNatsPublisher`, verifying subject routing, transport selection, input validation, and error propagation for RMM command and cancel NATS messages.

## Key Components

| Test Method | What It Verifies |
|---|---|
| `publishCommand_routesToMachineSubjectWithUnchangedPayload` | Routes to `machine.<machineId>.command-execution` and forwards `CommandMessage` unmodified |
| `publishCommand_usesCoreNatsNotJetStream` | Confirms core NATS `publish` is used, never `publishPersistent` (no JetStream durability) |
| `publishCommand_rejectsNullMessage` | Null `CommandMessage` throws `IllegalArgumentException` before any broker call |
| `publishCommand_rejectsBlankExecutionId` | Blank/whitespace `executionId` is rejected early with a meaningful error |
| `publishCommand_propagatesTransportFailure` | `NatsException` from the transport layer propagates to the caller |
| `publishCancel_routesToCancelSubject` | Routes to `machine.<machineId>.command-cancel` (distinct from command-execution) |
| `publishCancel_usesCoreNatsNotJetStream` | Cancel messages also use core NATS to avoid re-delivery risk on broker restart |
| `publishCancel_rejectsMissingExecutionId` | Both null and blank `executionId` rejected before broker interaction |

## Usage Example

```java
// Production wiring
NatsMessagePublisher transport = ...; // injected
CommandNatsPublisher publisher = new CommandNatsPublisher(transport);

// Dispatch a command to a specific machine
CommandMessage cmd = CommandMessage.builder()
        .executionId("exec-1")
        .code("df -h")
        .build();
publisher.publishCommand("machine-42", cmd);
// → publishes to: machine.machine-42.command-execution

// Cancel an in-flight execution
CancelMessage cancel = CancelMessage.builder()
        .executionId("exec-1")
        .build();
publisher.publishCancel("machine-42", cancel);
// → publishes to: machine.machine-42.command-cancel
```

## Design Notes

- **Core NATS over JetStream**: Both `publishCommand` and `publishCancel` intentionally use non-persistent delivery. Commands are ad-hoc and must not replay; cancels re-delivered after a broker restart could target an unrelated execution.
- **Eager validation**: `executionId` is checked before any broker call, ensuring correlation IDs are always present on the wire.
- **Subject pattern**: `machine.<machineId>.command-execution` vs `machine.<machineId>.command-cancel` gives the receiving agent a distinct subject to prioritize cancel processing.
