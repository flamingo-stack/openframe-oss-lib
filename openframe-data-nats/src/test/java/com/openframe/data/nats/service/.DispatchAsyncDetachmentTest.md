## Key Components

- **`DispatchAsyncDetachmentTest`** — Spring Boot integration test validating `@Async` proxy detachment behavior
- **`RecordingChannel`** — Test stub implementing `NotificationChannel` that captures the delivering thread via `AtomicReference` and signals completion via `CountDownLatch`
- **`AsyncApp`** — Inner `@SpringBootConfiguration` that wires `NotificationChannelExecutorConfig`, `NotificationChannelDispatcher`, `RecordingChannel`, and a mocked `NotificationReadStateService`
- **`dispatch_is_detached_onto_a_virtual_thread()`** — Asserts three guarantees: the caller returns in under 500ms, delivery eventually completes within 5s, and delivery occurs on a virtual thread distinct from the caller

## Usage Example

```java
// The test guards against this regression: constructing the dispatcher
// with `new` bypasses the @Async proxy, causing broadcast() to block
// the dispatch() call and inspecting the delivery thread.

@Test
void dispatch_is_detached_onto_a_virtual_thread() throws Exception {
    long startNanos = System.nanoTime();
    dispatcher.dispatch(Set.of("alice"),
            Notification.builder().id("n1").build(), NotificationCategory.TICKETS);
    long elapsedMs = (System.nanoTime() - startNanos) / 1_000_000;

    assertThat(elapsedMs).isLessThan(500);
    // Delivery must complete asynchronously
    assertThat(channel.latch.await(5, TimeUnit.SECONDS)).isTrue();
    // Delivery must run on a virtual thread, not the caller's thread
    assertThat(channel.deliveredThread.get().isVirtual()).isTrue();
    assertThat(channel.deliveredThread.get()).isNotEqualTo(Thread.currentThread());
}
```

## Notes

- The mocked `NotificationReadStateService` returns a single `UNREAD` recipient (`alice`) to satisfy the dispatcher's recipient-resolution path without requiring a real data store
