Unit tests for `ScriptNatsPublisher`, verifying NATS subject routing, transport selection, input validation, and error propagation for script execution dispatch.

## Key Components

| Element | Description |
|---|---|
| `publishScript_routesToMachineSubjectWithUnchangedPayload` | Asserts the subject resolves to `machine.<machineId>.script-execution` and the `ScriptMessage` payload is forwarded without modification |
| `publishScript_usesCoreNatsNotJetStream` | Locks in the transport contract — confirms core `publish` is used and `publishPersistent` (JetStream) is never called |
| `publishScript_rejectsNullMessage` | Validates that a `null` message throws `IllegalArgumentException` containing `"ScriptMessage"` before any broker interaction |
| `publishScript_propagatesTransportFailure` | Confirms `NatsException` from the underlying transport propagates up so GraphQL mutations can surface dispatch failures |

## Usage Example

```java
// Exercising the publisher under test with a full ScriptMessage
ScriptMessage message = ScriptMessage.builder()
        .machineId("machine-42")
        .code("df -h")
        .shell(ScriptShell.BASH)
        .privilegeLevel(PrivilegeLevel.ADMIN)
        .build();

publisher.publishScript("machine-42", message);

// Verify subject routing
ArgumentCaptor<String> subject = ArgumentCaptor.forClass(String.class);
verify(messagePublisher).publish(subject.capture(), any(ScriptMessage.class));
assertThat(subject.getValue()).isEqualTo("machine.machine-42.script-execution");
```

## Key Assertions

- **Subject pattern:** `machine.<machineId>.script-execution`
- **Transport:** Core NATS `publish` only — JetStream (`publishPersistent`) must never be used for script dispatch
- **Null guard:** Broker is never reached when message is `null`
- **Error surfacing:** Transport failures propagate as `NatsException` to allow GraphQL mutation error handling
