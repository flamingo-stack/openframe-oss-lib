Defines the contract for resolving the post-authentication redirect URL after a successful OAuth2 code exchange.

## Key Components

- **`RedirectTargetResolver`** — Reactive interface with a single method for determining where to send the browser once OAuth2 authentication completes.

| Method | Returns | Description |
|--------|---------|-------------|
| `resolve(tenantId, userId, requestedRedirectTo, request)` | `Mono<String>` | Resolves the final redirect URL for the authenticated user |

### Parameters

| Parameter | Type | Notes |
|-----------|------|-------|
| `tenantId` | `String` | Tenant the user authenticated into |
| `userId` | `String` | Authenticated user's `sub` claim; may be `null` if unreadable from the issued token |
| `requestedRedirectTo` | `String` | Client-supplied redirect hint; may be `null` |
| `request` | `ServerHttpRequest` | The incoming reactive HTTP request |

## Usage Example

```java
@Component
public class DefaultRedirectTargetResolver implements RedirectTargetResolver {

    @Override
    public Mono<String> resolve(
            String tenantId,
            String userId,
            String requestedRedirectTo,
            ServerHttpRequest request) {

        if (requestedRedirectTo != null) {
            return Mono.just(requestedRedirectTo);
        }
        return Mono.just("/dashboard");
    }
}
```

## Notes

- Returns a `Mono<String>` making it composable within a Spring WebFlux reactive pipeline.
- Implementations should validate `requestedRedirectTo` against an allowlist to prevent open redirect vulnerabilities.
