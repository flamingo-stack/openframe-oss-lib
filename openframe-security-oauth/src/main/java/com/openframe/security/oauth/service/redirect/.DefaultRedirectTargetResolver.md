Default fallback implementation of `RedirectTargetResolver` that determines the post-OAuth redirect target using a priority-based resolution strategy.

## Key Components

- **`DefaultRedirectTargetResolver`** — Spring `@Component` implementing `RedirectTargetResolver`, auto-registered only when no other `RedirectTargetResolver` bean is present (`@ConditionalOnMissingBean`).
- **`resolve()`** — Reactive method returning a `Mono<String>` with the resolved redirect URL, evaluated in priority order:
  1. Explicit `requestedRedirectTo` parameter (if non-blank)
  2. `Referer` request header (if present and non-blank)
  3. Root path `"/"` as the final fallback

## Usage Example

```java
// Custom override — suppresses DefaultRedirectTargetResolver via @ConditionalOnMissingBean
@Component
public class TenantAwareRedirectResolver implements RedirectTargetResolver {
    @Override
    public Mono<String> resolve(String tenantId, String userId,
                                String requestedRedirectTo,
                                ServerHttpRequest request) {
        // Custom tenant-specific logic
        return Mono.just("/tenant/" + tenantId + "/dashboard");
    }
}

// Default behavior when no custom bean is defined:
// resolve(tenantId, userId, "/dashboard", request) → Mono("/dashboard")
// resolve(tenantId, userId, null, requestWithReferer) → Mono("<referer url>")
// resolve(tenantId, userId, null, requestNoReferer)  → Mono("/")
```

## Extension Point

To override the default strategy, define any bean implementing `RedirectTargetResolver`. The `@ConditionalOnMissingBean` annotation ensures `DefaultRedirectTargetResolver` is skipped automatically — no exclusion configuration required.
