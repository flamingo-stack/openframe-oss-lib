Core service for managing Debezium/Kafka Connect connectors via the Kafka Connect REST API. Handles the full connector lifecycle including creation, updates, versioned recreation on config drift, and deletion.

## Key Components

| Method | Description |
|---|---|
| `createOrUpdateDebeziumConnector` | Entry point — processes an array of connector specs, routing each to create or update logic |
| `applyConnectorSpec` | Dispatches to identity-update or versioned-recreation strategy based on `ConnectorNameStrategy` |
| `createInitialVersion` | Creates a new connector when no version exists yet |
| `tryUpdateExistingIdentityConnector` | Updates config in-place for identity (non-versioned) connectors via `PUT /connectors/{name}/config` |
| `recreateOnConfigDrift` | Detects config changes for versioned connectors and recreates with a new version name, gated by `RecreationTracker` |
| `createConnector` | `POST /connectors` — registers a new connector with Kafka Connect |
| `deleteConnector` | `DELETE /connectors/{name}` — tolerates 404 (already gone) |
| `listConnectors` | `GET /connectors` — returns empty list on transient failure |
| `getConnectorStatus` | `GET /connectors/{name}/status` — returns `null` on 404 |
| `getConnectorConfig` | `GET /connectors/{name}/config` — returns `null` if connector is gone or unreachable |
| `configsEquivalent` | Normalizes both configs to `Map<String, String>` (excluding `name`) for semantic comparison |

## Usage Example

```java
@Autowired
private DebeziumService debeziumService;

// Create or update connectors from a spec array (e.g. loaded from MongoDB)
Object[] specs = mongoTemplate.findAll(IntegratedTool.class).toArray();
debeziumService.createOrUpdateDebeziumConnector(specs);

// Directly create a connector with an explicit config map
Map<String, Object> config = new HashMap<>();
config.put("connector.class", "io.debezium.connector.mongodb.MongoDbConnector");
config.put("mongodb.connection.string", "mongodb://localhost:27017");
debeziumService.createConnector("my-mongo-connector-v1", config);

// Delete a stale versioned connector
debeziumService.deleteConnector("my-mongo-connector-v0");

// Check connector health
ConnectorStatus status = debeziumService.getConnectorStatus("my-mongo-connector-v1");
```

## Configuration Properties

| Property | Default | Description |
|---|---|---|
| `openframe.debezium.base-url` | *(required)* | Kafka Connect REST API base URL |
| `openframe.debezium.connect.connect-timeout` | `5s` | HTTP connection timeout |
| `openframe.debezium.connect.read-timeout` | `30s` | HTTP read timeout |

## Notes

- **Identity strategy**: updates connector config in-place using `PUT`; no versioning.
- **Versioned strategy**: detects drift by stringifying config values for comparison, then recreates under a new name and deletes stale versions. Recreation is rate-limited by the optional `RecreationTracker` bean to prevent job-replay storms.
- `listConnectors()` returns an empty list (not an exception) on Kafka Connect unavailability — callers must handle the ambiguity.
