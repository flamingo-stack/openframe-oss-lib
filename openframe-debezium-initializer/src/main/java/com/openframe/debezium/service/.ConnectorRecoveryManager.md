Manages health checking and auto-recovery for Debezium connectors by monitoring connector/task states, applying exponential backoff for restarts, and triggering KIP-745 restarts or connector recreation when failure thresholds are exceeded.

## Key Components

| Member | Type | Description |
|---|---|---|
| `checkAndRecoverAll()` | Method | Iterates all registered connectors, invokes per-connector health checks, and prunes stale in-memory backoff entries |
| `checkAndRecover(String)` | Method | Evaluates a single connector's status; routes to non-recoverable handling, backoff-gated restart, or healthy-path cleanup |
| `attemptRecovery(String)` | Method | Applies exponential backoff and calls `restartConnectorWithFailedTasks`; caps retries at `MAX_RECOVERY_ATTEMPTS` (5) |
| `tryRecreate(String, String, String)` | Method | Recreates a connector under a new versioned name when `RecreationTracker` and a non-default `ConnectorNameStrategy` are present |
| `handleMissingStatus(String)` | Method | Distinguishes a deleted connector (no config) from a stuck one (config present, no status) and triggers recreation for the latter |
| `clearFailureState(String)` | Method | Removes in-memory backoff entry and resolves any open MongoDB alert on healthy ticks |
| `backoffStates` | `ConcurrentHashMap` | Thread-safe map of per-connector `ConnectorBackoffState` tracking failure counts and next-eligible-restart timestamps |
| `NON_RECOVERABLE_ERROR_PATTERNS` | `Set<String>` | Static set of exception class names/prefixes that short-circuit retries immediately |
| `BACKOFF_INCREMENT_MS` | Constant | 2-minute linear backoff increment applied per failure |

## Usage Example

```java
// Injected by Spring; typically called from a scheduled health-check task
@Scheduled(fixedDelay = 60_000)
public void runHealthCheck() {
    connectorRecoveryManager.checkAndRecoverAll();
}

// Or recover a single connector on-demand (e.g. after a deploy event)
connectorRecoveryManager.checkAndRecover("inventory-connector-v3");
```

> **Recreation mode** activates automatically when both a non-default [`ConnectorNameStrategy`](https://github.com/flamingo-stack/openframe-oss-lib/blob/main/src/main/java/com/openframe/debezium/naming/ConnectorNameStrategy.java) and a [`RecreationTracker`](https://github.com/flamingo-stack/openframe-oss-lib/blob/main/src/main/java/com/openframe/debezium/recovery/RecreationTracker.java) bean are present (SaaS shared-cluster profile). In that mode, exhausted retries and non-recoverable errors recreate the connector under a new versioned name and clean up stale versions instead of raising a plain alert.
