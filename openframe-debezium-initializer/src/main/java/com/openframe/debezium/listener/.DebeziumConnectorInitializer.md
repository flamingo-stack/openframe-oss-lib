Bootstraps Debezium connector lifecycle on application startup — reconciling orphaned connectors in Kafka Connect and seeding new connectors from MongoDB-backed tool configurations when none exist.

## Key Components

| Member | Description |
|---|---|
| `onApplicationReady()` | `@EventListener` triggered on `ApplicationReadyEvent`; orchestrates reconciliation then initialization |
| `reconcileOrphanedConnectors()` | Prunes connectors with no matching tool spec and removes stale `_vN` versioned duplicates; opt-in via `openframe.debezium.reconcile.delete-orphans=true` |
| `initializeConnectorsIfEmpty()` | Seeds Kafka Connect from all `IntegratedTool` records in MongoDB when zero connectors exist |
| `deleteOrphans` | `@Value`-injected flag; gates the reconciliation path (defaults to `false`) |
| `@ConditionalOnProperty` | Entire bean is inactive unless `openframe.debezium.health-check.enabled=true` |

**Safety guards built in:**
- Skips all operations if no tenant is registered (`TenantIdProvider`)
- Skips orphan deletion when `knownBaseNames` is empty (prevents wiping an entire cluster on misconfiguration)
- Skips initialization when connectors already exist (idempotent)
- Treats an empty `listConnectors()` response as a transient API failure, not an empty cluster

## Usage Example

```java
# application.yml — enable the initializer and opt into orphan cleanup
openframe:
  debezium:
    health-check:
      enabled: true
    reconcile:
      delete-orphans: true   # default: false
```

```java
// Injected automatically by Spring; no manual wiring required.
// Execution order on startup:
// 1. reconcileOrphanedConnectors() — remove stale/orphaned connectors
// 2. initializeConnectorsIfEmpty()  — seed connectors from MongoDB tools
```
