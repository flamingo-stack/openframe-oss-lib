Provides a MongoDB-backed, rolling-window rate limiter for Debezium connector recreations, shared across all management replicas in a multi-tenant MSP cluster.

## Key Components

| Member | Description |
|---|---|
| `WINDOW` | Fixed 1-hour rolling window for rate evaluation |
| `canRecreate(String baseName)` | Queries MongoDB for recent recreation events; denies if the count meets or exceeds `maxPerHour`. Fails closed if Mongo is unreachable |
| `record(String baseName)` | Inserts a new `ConnectorRecreationEvent` document and purges stale events older than the rolling window (avoids needing a TTL index) |
| `cutoff()` | Returns `Instant.now() - 1 hour`; the reusable window boundary |
| `maxPerHour` | Configurable via `openframe.debezium.recovery.max-recreations-per-hour` (default: `1`) |

**Activation conditions:**
- `@ConditionalOnProperty`: `openframe.debezium.recovery.recreation.enabled=true`
- `@ConditionalOnMissingBean`: defers to `InMemoryRecreationTracker` when present (per-tenant cluster with `recreation.in-memory=true`)

## Usage Example

```java
// application.yml
// openframe.debezium.recovery.recreation.enabled: true
// openframe.debezium.recovery.max-recreations-per-hour: 3

@Autowired
RecreationTracker tracker;

String connectorBase = "tenant-orders-db";

if (tracker.canRecreate(connectorBase)) {
    // Proceed with connector recreation
    recreateConnector(connectorBase);
    tracker.record(connectorBase); // Persist event + purge stale docs
} else {
    log.warn("Skipping recreation — hourly limit reached for '{}'", connectorBase);
}
```

> **Fail-closed behavior:** if MongoDB is unavailable during `canRecreate`, the tracker returns `false` rather than allowing potentially runaway recreations under unknown state.
