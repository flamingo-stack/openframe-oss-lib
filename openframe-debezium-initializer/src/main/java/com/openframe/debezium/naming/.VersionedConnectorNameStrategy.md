A versioned implementation of `ConnectorNameStrategy` that assigns Debezium connectors names in the form `<baseName>_vN`, enabling safe recreate-based recovery by isolating each connector generation in its own Kafka Connect offset namespace.

## Key Components

| Member | Description |
|---|---|
| `VERSION_SEPARATOR` | Constant `"_v"` used to join base name and version number |
| `VERSION_SUFFIX` | Regex pattern matching `<base>_v<digits>` connector names |
| `LEGACY_VERSION` / `INITIAL_VERSION` | Version constants: `0` for unversioned legacy connectors, `1` for the first versioned name |
| `supportsRecreation()` | Returns `true`; signals to the recovery manager that this strategy is safe for connector recreation |
| `matchesBase(baseName, connectorName)` | Returns `true` if a connector name belongs to the given base (including unversioned legacy names) |
| `currentVersion(baseName, existing)` | Finds the highest-versioned active connector for a base name from a list of existing connectors |
| `extractBaseName(connectorName)` | Strips the `_vN` suffix to recover the original base name |
| `resolveNextName(baseName, existing)` | Computes the next connector name by incrementing the highest existing version, defaulting to `_v1` |

**Activation:** Enabled via `openframe.debezium.recovery.recreation.enabled=true`. Declared `@Primary` so it takes precedence over any non-versioned `ConnectorNameStrategy` bean.

## Usage Example

```java
// Injected automatically when recreation is enabled
@Autowired
ConnectorNameStrategy nameStrategy;

List<String> existing = List.of("orders-cdc_v1", "orders-cdc_v2");

// Resolve the next safe connector name before recreating
String nextName = nameStrategy.resolveNextName("orders-cdc", existing);
// → "orders-cdc_v3"

// Find the currently active connector
Optional<String> current = nameStrategy.currentVersion("orders-cdc", existing);
// → Optional["orders-cdc_v2"]

// Extract base name from a versioned connector name
String base = nameStrategy.extractBaseName("orders-cdc_v3");
// → "orders-cdc"
```

After a successful recreation, the caller is responsible for deleting older versions (e.g., `_v1`, `_v2`), leaving exactly one active connector per base name.
