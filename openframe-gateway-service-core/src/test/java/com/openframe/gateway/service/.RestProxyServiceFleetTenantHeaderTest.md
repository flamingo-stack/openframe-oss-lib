Unit tests for `RestProxyService.addFleetTenantHeader`, verifying that the `X-Tenant-Id` header is correctly forwarded to FleetMDM upstream requests and never injected for other tools or blank values.

## Key Components

| Element | Purpose |
|---|---|
| `addsTenantHeaderForFleet` | Confirms the tenant header is propagated when multi-tenancy is enabled and the tool is `fleetmdm-server` |
| `addsTenantHeaderForFleetEvenWhenMultiTenancyDisabled` | Asserts the header is still forwarded when the multi-tenancy flag is off — Fleet is expected to silently ignore it |
| `neverAddsTenantHeaderForOtherTools` | Guards against header leakage to non-Fleet tools (e.g. `tactical-rmm`) |
| `doesNotAddBlankHeaderWhenRequestCarriesNoTenantId` | Ensures no empty `X-Tenant-Id` entry is injected when the incoming request omits the header |
| `service(boolean)` | Helper that builds a `RestProxyService` with mocked dependencies and a configurable `FleetMultiTenancyProperties` |
| `request(String)` | Helper that constructs a `MockServerHttpRequest` targeting a Fleet hosts endpoint, optionally with a tenant header |

## Usage Example

```java
// Reproducing the core assertion pattern used across all test cases
Map<String, String> headers = new HashMap<>();

// multi-tenancy flag ON, correct tool, header present → forwarded
service(true).addFleetTenantHeader(headers, "fleetmdm-server", request("3f2c9a1e-tenant"));
assertThat(headers).containsEntry("X-Tenant-Id", "3f2c9a1e-tenant");

// wrong tool → header must NOT be injected
headers.clear();
service(true).addFleetTenantHeader(headers, "tactical-rmm", request("3f2c9a1e-tenant"));
assertThat(headers).doesNotContainKey("X-Tenant-Id");
```

## Notes

- The flag-off behaviour is intentional by design — see the Javadoc on `addsTenantHeaderForFleetEvenWhenMultiTenancyDisabled`.
- All repository and resolver dependencies are Mockito mocks; only `FleetEndpointAllowlist` is constructed with real properties to keep the Fleet-routing logic exercised.
