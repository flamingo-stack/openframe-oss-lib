Unit tests for `WsAwareAuthenticationEntryPoint`, verifying the observability contract that silently-rejected WebSocket upgrade attempts produce the correct metrics and always return HTTP 401.

## Key Components

| Component | Description |
|---|---|
| `expiredTokenOnWsPath_countsExpiredToken_andStill401s` | Verifies an expired JWT on a WS path records `expired_token` metric and returns 401 |
| `noTokenOnWsPath_countsMissingToken` | Verifies a missing Authorization header records `missing_token` metric |
| `badTokenOnWsPath_countsInvalidToken` | Verifies a malformed/garbage JWT records `invalid_token` metric |
| `plainHttpRequest_isNotCounted` | Verifies non-WebSocket requests never trigger metrics, but still return 401 |
| `oauthError(String)` | Helper that constructs an `OAuth2AuthenticationException` with a given description |
| `unsignedJwt(String)` | Helper that builds an unsigned `alg=none` JWT; the entry point reads `sub` without verifying the signature |

## Usage Example

```java
// The entry point under test is wired with a mocked metrics sink:
GatewayTrafficMetrics metrics = mock(GatewayTrafficMetrics.class);
WsAwareAuthenticationEntryPoint entryPoint = new WsAwareAuthenticationEntryPoint(metrics);

// Simulate a WebSocket upgrade request with an expired token
MockServerWebExchange exchange = MockServerWebExchange.from(
    MockServerHttpRequest.get("/ws/tools/agent/meshcentral-server/agent.ashx")
        .header(HttpHeaders.UPGRADE, "websocket")
        .header(HttpHeaders.AUTHORIZATION, "Bearer " + unsignedJwt("agent_x")));

entryPoint.commence(exchange, oauthError("Jwt expired at ...")).block();

// Assert metric was recorded with the correct tool name and reason
verify(metrics).recordUpgradeRejected("meshcentral-server", "expired_token");

// Assert the HTTP response is always 401
assertThat(exchange.getResponse().getStatusCode()).isEqualTo(HttpStatus.UNAUTHORIZED);
```

## Notes

- Plain HTTP requests (`/api/v1/...`) must **never** interact with `GatewayTrafficMetrics`, enforced via `verifyNoInteractions`.
- The tool name is extracted from the WS path segment (e.g., `meshcentral-server`, `nats`).
- Reason codes are derived from the OAuth2 error description: `expired_token`, `missing_token`, or `invalid_token`.
