Fallback implementation of `ToolUpstreamResolver` that resolves upstream proxy URLs for integrated tools by reading configuration from MongoDB via `ToolUrlService`. Used for any tool that does not register a dedicated resolver.

## Key Components

| Member | Type | Description |
|---|---|---|
| `toolUrlService` | Dependency | Fetches `ToolUrl` documents from MongoDB for a given tool and URL type |
| `proxyUrlResolver` | Dependency | Constructs the final proxy `URI` from the resolved tool URL, port, and incoming request |
| `supportsToolId()` | Method | Returns `Optional.empty()`, marking this as the catch-all fallback resolver |
| `resolveRest()` | Method | Resolves a REST upstream URI using `ToolUrlType.API` |
| `resolveWs()` | Method | Resolves a WebSocket upstream URI using `ToolUrlType.WS` |
| `resolveByType()` | Method | Shared logic — fetches the `ToolUrl` by type and delegates to `ProxyUrlResolver`, throwing `IllegalStateException` if no URL is configured |

## Usage Example

This bean is auto-discovered by the gateway's resolver chain. It activates for any tool without a dedicated `ToolUpstreamResolver` registered.

```java
// Resolved automatically by the upstream resolver chain — no manual wiring needed.
// For a tool with only a generic API URL in MongoDB:

IntegratedTool tool = toolRepository.findByKey("some-tool");
ServerHttpRequest request = ...; // incoming reactive HTTP request

// REST proxy resolution (ToolUrlType.API)
URI restUpstream = defaultToolUpstreamResolver.resolveRest(tool, request, "/some-tool");

// WebSocket proxy resolution (ToolUrlType.WS)
URI wsUpstream = defaultToolUpstreamResolver.resolveWs(tool, request, "/some-tool/ws");
```

> **Note:** If a tool has no URL of the requested type configured in MongoDB, `resolveByType` throws an `IllegalStateException` with the tool key and missing URL type. Ensure all tools have both `API` and `WS` entries in `ToolUrl` before routing traffic through the gateway.
