Implements the Fleet MDM upstream routing strategy for shared-database multi-tenancy, directing all tenant traffic for `fleetmdm-server` to a single shared Fleet server per cluster rather than per-tenant deployments.

## Key Components

| Member | Description |
|---|---|
| `TOOL_ID` | Constant identifier `"fleetmdm-server"` used to bind this resolver to Fleet MDM requests |
| `supportsToolId()` | Declares this resolver handles only Fleet MDM traffic |
| `resolveRest()` | Routes REST/browser proxy requests; uses shared Fleet URL when multi-tenancy is enabled, otherwise delegates to `DefaultToolUpstreamResolver` |
| `resolveWs()` | Routes WebSocket requests independently; follows the same enable/fallback pattern as `resolveRest()` |
| `sharedRoutingEnabled()` | Guard predicate — returns `true` only when `openframe.fleet.multi-tenancy.enabled=true` AND the given plane's URL is non-blank |

## Usage Example

```java
// Typical Spring-managed injection — no manual wiring needed.
// The gateway resolves the correct upstream at request time.

// application.yml — shared Fleet topology
openframe:
  fleet:
    multi-tenancy:
      enabled: true
      upstream:
        api:
          url: http://fleet.internal
          port: 8080
        websocket:
          url: ws://fleet.internal
          port: 8080
```

When `enabled: true` and a URL is present, all tenants' REST traffic routes to `http://fleet.internal:8080`; WebSocket traffic routes to `ws://fleet.internal:8080`. If either URL is omitted, that plane falls back to the per-tenant URL stored in the tenant's `IntegratedTool` document — ensuring a blank URL is never forwarded to the proxy resolver.

## Plane Independence

REST (`api`) and WebSocket (`websocket`) planes are gated separately. A partial configuration (e.g., only `api.url` set) enables shared routing for REST while keeping per-tenant WebSocket routing, preventing misconfigured deployments from silently passing empty URLs downstream.
