Defines the routing strategy interface for resolving proxied requests to integrated tools, mapping incoming REST or WebSocket requests to their upstream target URIs.

## Key Components

| Member | Type | Description |
|---|---|---|
| `supportsToolId()` | `Optional<String>` | Identifies which `toolId` this resolver handles; return `Optional.empty()` to act as the default fallback |
| `resolveRest()` | `URI` | Computes the upstream target URI for REST or REST-style agent requests |
| `resolveWs()` | `URI` | Computes the upstream target URI for WebSocket requests |

## Usage Example

```java
// Custom resolver for a specially-routed tool
@Component
public class MyToolUpstreamResolver implements ToolUpstreamResolver {

    @Override
    public Optional<String> supportsToolId() {
        return Optional.of("my-tool-id"); // handle only this tool
    }

    @Override
    public URI resolveRest(IntegratedTool tool, ServerHttpRequest request, String stripPrefix) {
        String upstreamPath = request.getPath().value().replaceFirst(stripPrefix, "");
        return URI.create("https://my-tool-host.internal" + upstreamPath);
    }

    @Override
    public URI resolveWs(IntegratedTool tool, ServerHttpRequest request, String stripPrefix) {
        String upstreamPath = request.getPath().value().replaceFirst(stripPrefix, "");
        return URI.create("wss://my-tool-host.internal" + upstreamPath);
    }
}
```

## Extension Pattern

Add support for a new tool by creating a `@Component` that implements this interface. Spring auto-discovers it via component scanning — no registration or factory changes required. The `DefaultToolUpstreamResolver` (returns `Optional.empty()`) serves as the catch-all fallback for any tool without a dedicated resolver.
