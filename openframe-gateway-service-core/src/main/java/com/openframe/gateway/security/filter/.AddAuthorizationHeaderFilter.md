A reactive Spring `WebFilter` that normalizes bearer token delivery by injecting an `Authorization` header from alternative token sources before the request reaches the OAuth2 resource server.

## Key Components

| Member | Description |
|---|---|
| `filter()` | Core filter logic — skips public paths, short-circuits if `Authorization` already present, otherwise resolves and injects a bearer token |
| `isPrivatePath()` | Determines whether a path requires authentication, covering API, tools, WebSocket, chat, content, and client-private routes (with explicit public carve-outs) |
| `resolveBearerToken()` | Attempts token resolution in priority order: cookie → `Access-Token` header → `authorization` query param |
| `CookieService` | Injected dependency for extracting the access token from an HTTP-only cookie |

**Token resolution priority:**
1. `access_token` cookie (via `CookieService`)
2. `Access-Token` custom request header
3. `authorization` query parameter

## Usage Example

The filter is auto-registered as a Spring `@Component` and applies to all requests. No manual wiring is required. Token sources are resolved transparently:

```java
// Browser client — token delivered via HttpOnly cookie
// GET /api/resource  (no Authorization header in request)
// → filter extracts cookie, mutates request with: Authorization: Bearer <token>

// WebSocket client — token passed in query string
// GET /ws/tools/connect?authorization=eyJhb...
// → filter extracts query param, mutates request with: Authorization: Bearer eyJhb...

// Programmatic client — token in custom header
// GET /api/resource
// Access-Token: eyJhb...
// → filter extracts header, mutates request with: Authorization: Bearer eyJhb...
```

> Paths explicitly excluded from auth (e.g., `/clients/metrics/`, `/clients/oauth/token`) pass through the filter chain unchanged.
