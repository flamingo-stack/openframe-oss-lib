Utility class that defines trusted multi-tenant routing headers (`X-Tenant-Id` / `X-Tenant-Ns`) and provides helpers to extract them from incoming requests and rewrite Kubernetes cluster-local upstream hosts/URIs with the per-request tenant namespace.

## Key Components

| Member | Type | Description |
|---|---|---|
| `TENANT_ID_HEADER` | `String` constant | Header name `X-Tenant-Id` carrying the tenant UUID |
| `TENANT_NS_HEADER` | `String` constant | Header name `X-Tenant-Ns` carrying the Kubernetes namespace |
| `TENANT_UUID_PLACEHOLDER` | `String` constant | Literal token (`tenant-uuid`) used in shared-pod route config for path splicing |
| `tenantNamespace(request)` | Static method | Reads `X-Tenant-Ns` from a reactive `ServerHttpRequest`, returns `null` if absent |
| `tenantId(request)` | Static method | Reads `X-Tenant-Id` from a reactive `ServerHttpRequest`, returns `null` if absent |
| `applyToHost(host, ns)` | Static method | Replaces the namespace label in a `*.svc.cluster.local` hostname; no-ops on invalid input |
| `applyToUri(uri, ns)` | Static method | Rewrites the namespace in a full URI's host, preserving all raw components verbatim |

## Usage Example

```java
// In a gateway filter — extract tenant context from trusted headers
String tenantNs = TenantRoutingHeaders.tenantNamespace(request);
String tenantId = TenantRoutingHeaders.tenantId(request);

// Rewrite a configured upstream host for the resolved tenant namespace
String upstreamHost = "meshcentral-backend.placeholder.svc.cluster.local";
String resolved = TenantRoutingHeaders.applyToHost(upstreamHost, tenantNs);
// → "meshcentral-backend.acme-prod.svc.cluster.local"

// Rewrite a full URI (preserves raw query strings with base64 '=' characters)
URI upstream = URI.create("https://meshcentral-backend.placeholder.svc.cluster.local/api?token=abc=");
URI routed = TenantRoutingHeaders.applyToUri(upstream, tenantNs);
// → https://meshcentral-backend.acme-prod.svc.cluster.local/api?token=abc=
```

**Additive by design:** when `X-Tenant-Ns` is absent (single-tenant / OSS deployments), all methods return their inputs unchanged, so existing single-tenant pods require no changes.
