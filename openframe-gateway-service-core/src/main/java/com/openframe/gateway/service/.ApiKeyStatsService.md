Reactive Spring service that tracks API key usage statistics by atomically incrementing success and failure counters in Redis, with configurable TTL-based expiry.

## Key Components

| Member | Type | Description |
|---|---|---|
| `statsRepository` | `ReactiveApiKeyStatsRepository` | Reactive Redis repository for atomic counter operations |
| `redisTtl` | `Long` | TTL in seconds for stats keys, injected from `openframe.api-key-stats.redis-ttl` |
| `incrementSuccessful()` | Method | Atomically increments the success counter for a given API key and tenant |
| `incrementFailed()` | Method | Atomically increments the failure counter for a given API key and tenant |

Both methods follow a fire-and-forget pattern — errors are logged but swallowed via `onErrorResume`, preventing stats failures from affecting the request pipeline.

## Usage Example

```java
@Service
@RequiredArgsConstructor
public class GatewayFilterService {

    private final ApiKeyStatsService apiKeyStatsService;

    public void handleRequestResult(String keyId, String tenantId, boolean success) {
        if (success) {
            apiKeyStatsService.incrementSuccessful(keyId, tenantId);
        } else {
            apiKeyStatsService.incrementFailed(keyId, tenantId);
        }
    }
}
```

## Configuration

```yaml
openframe:
  api-key-stats:
    redis-ttl: 86400  # TTL in seconds (e.g. 24 hours)
```

## Notes

- Operations are **non-blocking** and use Project Reactor's `Mono` pipeline
- Errors are **silently absorbed** after logging — stats tracking never blocks or fails a gateway request
- The `keyId` + `tenantId` combination scopes counters per tenant, supporting multi-tenant isolation
