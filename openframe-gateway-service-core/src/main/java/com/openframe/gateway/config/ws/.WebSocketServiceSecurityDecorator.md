Decorates the default Spring `WebSocketService` to enforce JWT-based session lifecycle management on secured WebSocket endpoints in the OpenFrame gateway.

## Key Components

| Member | Description |
|---|---|
| `handleRequest(...)` | Intercepts WebSocket upgrade requests; validates JWT expiration, registers sessions, and routes to the appropriate handler |
| `scheduleSessionRemoveJob(...)` | Creates a reactive delayed job that closes the WebSocket session when the JWT expires (plus `CLOCK_SKEW_SECONDS`) |
| `processSessionClosedEvent(...)` | Subscribes to the session's close status, records metrics, logs lifetime, and disposes the expiry job if the client closes first |
| `isSecuredEndpoint(String path)` | Checks if a path matches any of the four secured WS prefixes (`TOOLS_API`, `TOOLS_AGENT`, `NATS`, `NATS_API`) |
| `toolFromPath(String path)` | Extracts a low-cardinality tool label from the path for Prometheus metrics tagging |
| `sessionRegistry` | In-memory `ConcurrentHashMap` tracking active sessions by ID with their creation time, path, and subject |
| `CLOCK_SKEW_SECONDS` | 60-second buffer added to JWT expiry delay, aligned with Spring Security's default clock skew |

## Usage Example

```java
@Bean
public WebSocketService webSocketService(
        WebSocketService defaultService,
        RequestJwtClaimsReader jwtReader,
        GatewayTrafficMetrics metrics,
        WebSocketLoggingProperties loggingProps) {

    return new WebSocketServiceSecurityDecorator(
            defaultService,
            jwtReader,
            metrics,
            loggingProps
    );
}
```

On an incoming WebSocket upgrade to `/ws/tools/agent/meshcentral-server/...`, the decorator:
1. Reads the JWT expiration from the request
2. Registers the session in `sessionRegistry`
3. Schedules auto-close at `expiry + 60s`
4. Wraps the session in `LoggingWebSocketSessionDecorator` if frame-level logging is enabled
5. Cancels the expiry job and records metrics when the client closes first

> **Note:** Path-based security detection is acknowledged as a temporary approach. A TODO exists to delegate to Spring Security for token presence checks rather than relying on hardcoded path prefixes.
