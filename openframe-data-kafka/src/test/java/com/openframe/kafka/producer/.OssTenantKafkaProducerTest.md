Unit tests for `OssTenantKafkaProducer` that verify the Kafka message header contract used by the RMM command-result flow, ensuring that custom headers (`message-type`, topic, key) are correctly propagated onto outgoing Spring `Message` objects.

## Key Components

| Test | Description |
|---|---|
| `headersAreSetOnOutgoingMessage` | Asserts that `MESSAGE_TYPE_HEADER`, `KafkaHeaders.TOPIC`, and `KafkaHeaders.KEY` are all present on the outgoing `Message` when a headers map is supplied |
| `nullHeadersAreTolerated` | Confirms that passing `null` as the headers map does not throw, and that topic/key headers are still set while `MESSAGE_TYPE_HEADER` remains absent |
| `noHeadersVariantUsesTopicKeyOverload` | Verifies that the no-headers overload of `sendAndAwaitMessage` delegates to the plain `KafkaTemplate.send(topic, key, payload)` method rather than the `Message`-based path |

## Usage Example

```java
// Construct the producer (wired via Spring in production)
OssTenantKafkaProducer producer = new OssTenantKafkaProducer(kafkaTemplate);

// Send with custom headers (e.g. RMM command-result flow)
KafkaMessage payload = new CommonDebeziumMessage();
producer.sendAndAwaitMessage(
    "logs.events",
    payload,
    "machine-42",
    Map.of(KafkaHeader.MESSAGE_TYPE_HEADER, "RMM")
);

// Send without headers — uses the lightweight topic/key overload
producer.sendAndAwaitMessage("logs.events", payload, "machine-42");
```

> **Contract guarded:** Any regression that silently drops headers (e.g. a self-recursive default-method delegation bug) is caught by `headersAreSetOnOutgoingMessage`. The `nullHeadersAreTolerated` test prevents `NullPointerException` from callers that omit optional headers.
