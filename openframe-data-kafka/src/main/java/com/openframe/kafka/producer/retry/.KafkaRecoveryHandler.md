Defines the contract for handling unrecoverable Kafka message delivery failures by enqueuing failed messages for later retry or dead-letter processing.

## Key Components

| Member | Description |
|--------|-------------|
| `enqueue(Throwable, String, String, Object)` | Enqueues a failed message with its exception, topic, key, and payload |
| `enqueue(Throwable, String, String, Object, Map<String, Object>)` | Overload that additionally accepts custom Kafka headers alongside the failed message context |

## Usage Example

```java
@Component
public class DeadLetterRecoveryHandler implements KafkaRecoveryHandler {

    @Override
    public void enqueue(Throwable ex, String topic, String key, Object payload) {
        enqueue(ex, topic, key, payload, Map.of());
    }

    @Override
    public void enqueue(Throwable ex, String topic, String key, Object payload,
                        Map<String, Object> headers) {
        // Persist or forward to a dead-letter queue
        log.error("Message delivery failed on topic [{}] key [{}]: {}",
                topic, key, ex.getMessage());
        deadLetterStore.save(topic, key, payload, headers);
    }
}
```

Implement this interface to define custom recovery strategies — such as dead-letter queuing, persistent retry stores, or alerting — when Kafka message production fails after all retry attempts are exhausted.

## Notes

- Both overloads receive the originating `Throwable` for root-cause inspection and logging.
- The `headers` map allows propagating trace IDs, correlation IDs, or other metadata into the recovery pipeline.
- Implementations are typically registered as Spring beans and injected into the producer retry configuration.
