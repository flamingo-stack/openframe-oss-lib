Kafka event model representing the result of a dispatched RMM (Remote Monitoring & Management) execution — either an ad-hoc command or a saved script — produced by the client-service after consuming the agent's execution-result NATS message.

## Key Components

| Member | Type | Description |
|---|---|---|
| `tenantId` | `String` | Tenant scoping for multi-tenant isolation |
| `machineId` | `String` | Target machine that ran the execution |
| `executionId` | `String` | Unique identifier for this execution run |
| `scriptId` | `String` | References a saved script (nullable for ad-hoc) |
| `scheduleId` | `String` | References a schedule trigger (nullable for manual) |
| `stdout` / `stderr` | `String` | Standard output/error captured from the execution |
| `exitCode` | `Integer` | Process exit code returned by the agent |
| `executionTimeMs` | `Long` | Total wall-clock execution duration in milliseconds |
| `timedOut` | `Boolean` | Whether the execution was terminated due to timeout |
| `error` | `String` | Transport or agent-level error message (non-stderr) |
| `eventTimestamp` | `Long` | Unix epoch timestamp when the event was emitted |

**Extends:** `DebeziumMessage<RmmResultEvent>` — enables Debezium-style envelope wrapping for downstream CDC consumers.

**Implements:** `KafkaMessage` — satisfies the shared Kafka message contract used across the OpenFrame event bus.

**`@JsonInclude(NON_NULL)`** — omits null fields from serialization, keeping Kafka payloads lean across optional fields like `scriptId` and `scheduleId`.

## Usage Example

```java
RmmResultEvent event = new RmmResultEvent();
event.setTenantId("tenant-abc");
event.setMachineId("machine-xyz");
event.setExecutionId("exec-001");
event.setStdout("Patch applied successfully");
event.setExitCode(0);
event.setExecutionTimeMs(3200L);
event.setTimedOut(false);
event.setEventTimestamp(System.currentTimeMillis());

kafkaTemplate.send("rmm.execution.results", event.getTenantId(), event);
```
