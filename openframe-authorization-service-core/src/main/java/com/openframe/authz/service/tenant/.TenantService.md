Manages tenant lifecycle operations in OpenFrame's multi-tenant architecture, providing CRUD and lookup operations backed by `TenantRepository` with domain-uniqueness validation on creation.

## Key Components

| Method | Description |
|---|---|
| `createTenant(String tenantId, String tenantName, String domain)` | Creates and persists a new `ACTIVE` tenant using a caller-supplied ID (pre-generated UUID or SaaS cluster ID), after validating domain availability |
| `existByDomain(String domain)` | Returns `true` if a tenant with the given domain already exists |
| `findById(String tenantId)` | Looks up a tenant by its unique ID, returning an `Optional<Tenant>` |
| `findFirst()` | Returns the first tenant found — typically used in OSS single-tenant scenarios |
| `save(Tenant tenant)` | Persists an existing tenant entity (e.g., after status updates) |

## Usage Example

```java
// Registration flow: reserve a tenant ID first, then create the tenant
String reservedId = registrationProcessor.reserveTenantIdForRegistration();

Tenant tenant = tenantService.createTenant(
    reservedId,
    "Acme Corp",
    "acme.openframe.ai"
);

// Look up tenant later
Optional<Tenant> found = tenantService.findById(reservedId);
found.ifPresent(t -> log.info("Tenant status: {}", t.getStatus()));

// Check domain availability before registration
boolean taken = tenantService.existByDomain("acme.openframe.ai");

// OSS single-tenant: retrieve the only tenant
Optional<Tenant> only = tenantService.findFirst();
```

> **Note:** `createTenant` validates domain uniqueness via `RegistrationValidationService` before persisting. All methods run within a Spring `@Transactional` context.
