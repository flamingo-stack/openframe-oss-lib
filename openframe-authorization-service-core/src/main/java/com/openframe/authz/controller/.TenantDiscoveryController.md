REST controller handling tenant discovery and email validation endpoints used during multi-tenant login and registration flows.

## Key Components

| Method | Endpoint | Description |
|---|---|---|
| `discoverTenants` | `GET /tenant/discover` | Returns tenants and auth providers for a given email (returning user flow) |
| `emailAvailable` | `GET /tenant/email-available` | Checks if an email is free to register — validates uniqueness then domain policy |
| `emailDomainAllowed` | `GET /tenant/email-domain-allowed` | Checks domain policy only, independent of registration status |

**Dependencies:**
- `TenantDiscoveryService` — resolves tenant/provider mappings by email
- `UserService` — active user lookup for uniqueness check
- `EmailDomainPolicy` — blocks disposable/blocked domains

## Usage Example

```java
// Discover tenants for a returning user
GET /tenant/discover?email=user@acme.com
// → TenantDiscoveryResponse { tenants: [...], providers: [...] }

// Check email availability before registration
GET /tenant/email-available?email=newuser@acme.com
// → { available: true }
// → { available: false, reason: "TAKEN" }
// → { available: false, reason: "BLOCKED_DOMAIN" }

// UI live-validation: check domain only while user types
GET /tenant/email-domain-allowed?email=user@mailinator.com
// → { allowed: false }
```

> **Note:** `emailAvailable` applies a short-circuit optimization — it checks user existence first (cheap local DB call) before invoking the domain policy, avoiding unnecessary external disposable-domain lookups for already-registered addresses.
