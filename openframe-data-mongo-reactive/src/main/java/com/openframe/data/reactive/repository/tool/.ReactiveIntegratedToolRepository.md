Reactive MongoDB repository for `IntegratedTool` documents, providing non-blocking lookup operations including tenant-scoped queries for multi-tenant isolation.

## Key Components

| Member | Return Type | Description |
|---|---|---|
| `findByType(String type)` | `Mono<IntegratedTool>` | Looks up a tool by its integration type |
| `findByKey(String key)` | `Mono<IntegratedTool>` | Looks up a tool by its unique key |
| `findByTenantIdAndKey(String tenantId, String key)` | `Mono<IntegratedTool>` | Tenant-scoped lookup enforcing `{tenantId, key}` uniqueness |

**Extends:**
- `ReactiveMongoRepository<IntegratedTool, String>` — Spring Data reactive MongoDB base
- `BaseIntegratedToolRepository<Mono<IntegratedTool>, Mono<Boolean>, String>` — shared contract across reactive and blocking implementations

## Usage Example

```java
// Resolve a tool for the current tenant (safe in a shared multi-tenant store)
reactiveIntegratedToolRepository
    .findByTenantIdAndKey(tenantId, "jira")
    .switchIfEmpty(Mono.error(new ToolNotFoundException("jira")))
    .flatMap(tool -> integrationService.execute(tool, payload))
    .subscribe();

// Type-based lookup (single-tenant or internally trusted context)
reactiveIntegratedToolRepository
    .findByType("ticketing")
    .doOnNext(tool -> log.info("Found tool: {}", tool.getKey()))
    .subscribe();
```

## Notes

- **Multi-tenancy:** Always prefer `findByTenantIdAndKey` when a resolved tenant context is available. Using `findByKey` alone on a shared store risks returning another tenant's credentials.
- The `{tenantId, key}` combination is enforced as unique on the `IntegratedTool` document.
- All operations return `Mono`, making this safe to compose in fully non-blocking reactive pipelines.
