Reactive Spring Data MongoDB repository for the `user_onboarding_progress` collection, designed for use in the WebFlux gateway. It mirrors the blocking `UserOnboardingProgressRepository` from `openframe-data-mongo-sync` with a fully non-blocking API.

## Key Components

| Element | Description |
|---|---|
| `ReactiveUserOnboardingProgressRepository` | Extends `ReactiveMongoRepository<UserOnboardingProgress, String>` to provide reactive CRUD operations |
| `findByUserIdAndTenantId` | Looks up a single onboarding progress document by `userId` and `tenantId`, returning a `Mono` |

## Usage Example

```java
@Service
public class OnboardingService {

    private final ReactiveUserOnboardingProgressRepository progressRepository;

    public OnboardingService(ReactiveUserOnboardingProgressRepository progressRepository) {
        this.progressRepository = progressRepository;
    }

    public Mono<UserOnboardingProgress> getProgress(String userId, String tenantId) {
        return progressRepository.findByUserIdAndTenantId(userId, tenantId);
    }
}
```

## Notes

- **Not tenant-aware via aspect** — unlike multi-tenant repositories that resolve `tenantId` automatically, this repository requires `tenantId` to be passed explicitly on every query. This is intentional for the shared/SaaS runtime used by the WebFlux gateway.
- **Reactive only** — all operations return Project Reactor types (`Mono`/`Flux`); do not use in blocking Spring MVC contexts.
