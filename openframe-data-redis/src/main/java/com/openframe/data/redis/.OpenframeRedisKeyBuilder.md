Builds structured Redis keys with consistent global prefix, optional tenant namespace, and Redis Cluster hash-tag support, using configuration from `OpenframeRedisProperties`.

## Key Components

| Method | Description |
|---|---|
| `tenantKey(String relativeKey)` | Builds a namespaced key using the pod-wide `openframe.redis.tenant-id` property; throws `IllegalStateException` if absent |
| `tenantKey(String relativeKey, String tenantId)` | Builds a namespaced key under an explicitly provided tenant ID; useful for multi-tenant gateways |
| `requireTenantId()` | Validates and returns the configured tenant ID, failing fast if not set |
| `cacheKeyPrefix(String domainPrefix, String cacheName)` | Produces a full Spring `RedisCache` key prefix including the required `::` suffix |
| `build(...)` *(private)* | Assembles colon-separated key segments: `keyPrefix:tenantId:relativeKey`, wrapping tenant in `{...}` hash tags when configured |

## Usage Example

```java
// Single-tenant service (tenant resolved from config)
String sessionKey = keyBuilder.tenantKey("session:abc123");
// → "openframe:acme:session:abc123"

// Multi-tenant gateway (tenant resolved per request)
String tokenKey = keyBuilder.tenantKey("auth:token:xyz", requestTenantId);
// → "openframe:tenant-b:auth:token:xyz"

// Spring RedisCache prefix
String cachePrefix = keyBuilder.cacheKeyPrefix("iam", "users");
// → "openframe:acme:iam:users::"

// With hash-tag enabled (Redis Cluster slot affinity)
// → "openframe:{acme}:session:abc123"
```

## Notes

- For token-based flows where `tenantId` is unknown at read time, use an index key (`globalKey → tenantId`) paired with a tenant-scoped key.
- Colons are automatically trimmed from prefix and relative key boundaries to prevent double-colon segments.
- Hash-tag wrapping (`{tenantId}`) is controlled by `openframe.redis.tenant-hash-tag` and ensures Redis Cluster co-locates all keys for a tenant on the same slot.
