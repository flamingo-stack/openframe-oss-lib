Spring Data Cassandra repository for reading `CommandResult` rows, conditionally activated when Cassandra is enabled. Provides the read side of command result persistence; TTL-aware writes are handled separately via `CassandraOperations`.

## Key Components

| Element | Description |
|---|---|
| `CommandResultRepository` | Spring Data repository interface extending `CassandraRepository` |
| `CommandResult.CommandResultKey` | Composite primary key type used as the repository's ID |
| `@ConditionalOnProperty` | Activates only when `spring.data.cassandra.enabled=true` |

## Usage Example

```java
// Injecting the repository
@Service
public class CommandResultService {

    private final CommandResultRepository commandResultRepository;

    public CommandResultService(CommandResultRepository commandResultRepository) {
        this.commandResultRepository = commandResultRepository;
    }

    // Read a single result by its composite key
    public Optional<CommandResult> findResult(CommandResult.CommandResultKey key) {
        return commandResultRepository.findById(key);
    }

    // TTL writes bypass this repository — use CassandraOperations instead
    public void saveWithTtl(CommandResult result, int ttlSeconds) {
        InsertOptions options = InsertOptions.builder().ttl(ttlSeconds).build();
        cassandraOperations.insert(result, options);
    }
}
```

## Notes

- **Read-only intent** — the interface exposes standard CRUD methods inherited from `CassandraRepository`, but only the read path (e.g., `findById`) is the intended use case in production.
- **Conditional activation** — the bean is not created unless `spring.data.cassandra.enabled=true` is explicitly set, preventing startup failures in environments without Cassandra.
