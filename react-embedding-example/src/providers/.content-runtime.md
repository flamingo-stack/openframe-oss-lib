Singleton factory module that constructs the two runtime configuration objects (`ChatRuntime` and `EndpointsRuntime`) required by the OpenFrame frontend core library, wiring all endpoint URLs, navigation mode, and content URL composition for the embedder's SPA context.

## Key Components

### `HOSTED_TYPES`
A `Set` of content type strings (`'onboarding_guide'`, `'product_release'`) identifying content types for which this embedder owns slugged detail routes (e.g. `/onboarding-guides/:slug`). Used by `makeComposeContentUrl` to emit relative in-app hrefs instead of canonical hub URLs.

### `buildChatRuntime()`
Returns `Omit<ChatRuntime, 'source'>` — the full chat runtime config including:

- **`endpoints`** — All proxied API URLs (chat stream, approval, commands, docs search/resolve, list builder, attachment upload/view, identity, image proxy, etc.), routed through `CONTENT_PREFIX` so the proxy rewrites `/content` → hub.
- **`navigation`** — Set to `mode: 'host'`, delegating routing to the embedded react-router instance via the lib's `embed-router-bridge`.
- **`composeContentUrl`** — Built via `makeComposeContentUrl` with explicit overrides for `roadmap_item`, `delivery_item`, and `faq` types that deep-link into in-app list routes using `?search=<id>` or hash anchors rather than canonical hub URLs.
- **`docPlatformTargets`** — Maps `data_room_doc` to the `company-hub` platform; `markdown` is intentionally omitted so doc chips soft-navigate in-app via `/knowledge-base`.

### `buildEndpointsRuntime()`
Returns `EndpointsRuntime` with announcements, access code (validate/consume), and contact endpoint URLs.

## Usage Example

```typescript
// app-providers.tsx — memoized at app root, passed into lib providers
import { buildChatRuntime, buildEndpointsRuntime } from './runtimes/content-runtime'

const chatRuntime = buildChatRuntime()
const endpointsRuntime = buildEndpointsRuntime()

// <OpenFrameProvider chatRuntime={chatRuntime} endpointsRuntime={endpointsRuntime} />
```

> Both functions are pure (no side effects) and are intended to be called once and memoized at the provider level.
