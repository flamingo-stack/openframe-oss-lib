Renders the embeddable AI chat interface for the OpenFrame OSS lib demo, supporting both default Guide mode and OpenFrame agent mode (Fae / Mingo) via a demo agent switcher.

## Key Components

### `AGENT_CHOICES`
A read-only array defining the three switchable chat personalities:
- `undefined` → Guide mode (default)
- `'fae'` → Fae agent (client-facing)
- `'mingo'` → Mingo agent (technician-facing)

### `AskAi` (React component)
The top-level exported component. Composes two elements:
- **Agent switcher** — a fixed bottom-left pill UI that sets `activeAgentSlug` via `useState`.
- **`EmbeddableChat`** — imported from `@flamingo-stack/openframe-frontend-core`; receives the active agent slug and `baseRoute` for in-app doc chip routing.

## Usage Example

```typescript
import { AskAi } from './ask-ai'

// Drop into any page — the component is self-contained.
export default function DocsPage() {
  return (
    <main>
      <DocsContent />
      <AskAi />
    </main>
  )
}
```

To hardcode a specific agent without the demo chooser, pass `activeAgentSlug` directly to `EmbeddableChat`:

```typescript
<EmbeddableChat
  modes={{ guide: {} }}
  defaultActiveMode="guide"
  baseRoute={DOCS_BASE_ROUTE}
  activeAgentSlug="fae"
/>
```

## Notes

- **No auth gate** — identity is resolved server-side via the proxy's `act-as` headers.
- **Agent config** is fetched from `runtime.endpoints.aiAgentConfigUrl(slug)` (→ `/content/api/ai-agents/:slug`), so greeting and suggested prompts are fully server-driven.
- `baseRoute` is sourced from [`../config/content`](https://github.com/flamingo-stack/openframe-oss-lib/blob/main/config/content.ts) via `DOCS_BASE_ROUTE`, controlling where markdown doc chips resolve inside the app.
