Vite alias stub that replaces `next/font/google` with harmless no-ops, preventing build crashes when a Next.js font compiler macro is transitively imported in a non-Next.js bundler context.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `FontResult` | `type` | Shape returned by all font stubs: `className`, `variable`, and `style.fontFamily` (all empty strings) |
| `Azeret_Mono` | `() => FontResult` | No-op stub for the `Azeret_Mono` Google font macro |
| `DM_Sans` | `() => FontResult` | No-op stub for the `DM_Sans` Google font macro |
| `default` | `Proxy` | Catch-all proxy — any other Google font name resolves to the same no-op |

## Usage Example

This file is not imported directly. It is wired up as a Vite resolve alias in `vite.config.ts`:

```typescript
// vite.config.ts
export default defineConfig({
  resolve: {
    alias: {
      'next/font/google': '/path/to/stubs/next-font-google.ts',
    },
  },
})
```

Once aliased, any transitive import of a Google font resolves safely:

```typescript
// Somewhere in a dependency (handled transparently by the stub)
import { DM_Sans } from 'next/font/google'

const font = DM_Sans({ subsets: ['latin'] })
// → { className: '', variable: '', style: { fontFamily: '' } }
// No build error; no-op at runtime.
```

## Notes

- Fonts reach the consuming app via the `./styles` CSS import, **not** through this module — making this stub purely defensive.
- The `default` `Proxy` ensures forward-compatibility: any Google font added in the future also resolves to a no-op without updating this file.
- See [`vite.config.ts`](https://github.com/flamingo-stack/openframe-oss-lib/blob/main/vite.config.ts) for the alias registration.
