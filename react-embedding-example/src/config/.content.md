Single source of truth for hub-related URL constants used across client-side routing and API calls.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `CONTENT` | `string` | Base URL for all hub API endpoints; constructed from the shared `CONTENT_PREFIX` so the proxy mapping stays in sync with a single edit |
| `DOCS_BASE_ROUTE` | `string` | In-app route where `<DocsHubPage>` mounts (`/knowledge-base`); consumed by both `app-routes.tsx` (route path) and `ask-ai.tsx` (chat chip navigation) |

## Usage Example

```typescript
import { CONTENT, DOCS_BASE_ROUTE } from './content'

// Fetch from a hub API endpoint
const response = await fetch(`${CONTENT}/documents`)

// Soft-navigate to the docs hub page
router.push(DOCS_BASE_ROUTE)

// Use as a base route in the router config
<Route path={DOCS_BASE_ROUTE} element={<DocsHubPage />} />
```

## Notes

- `CONTENT_PREFIX` is imported from `proxy/content-prefix.mjs` — the single shared source for the namespace prefix. Changing it there automatically updates all hub API calls.
- `DOCS_BASE_ROUTE` is intentionally centralised here so that both the route declaration and chat chip navigation always agree on the destination path — no cross-domain redirects.
