Thin config-only page component that wires the Releases section chrome to its data endpoint, delegating all layout, filtering, fetching, and pagination to imported library components.

## Key Components

| Export | Type | Description |
|---|---|---|
| `ReleasesPage` | React component | Page-level entry point for the Releases list view |

### Dependencies

- **`DevSectionPage`** — Provides section chrome: hero, search bar, and release-status filter, all URL-param-wired. Section title is sourced from the registry (no manual `<h1>` needed). Keyed with `"releases"`.
- **`ProductReleasesView`** — Reads URL params, fetches paginated release data from the supplied endpoint, and renders the releases list.
- **`EP.productReleases`** — The API route constant sourced from the local endpoint config (`../config/endpoints`).

## Usage Example

```typescript
// Route definition (e.g. react-router or Next.js page file)
import { ReleasesPage } from './pages/releases'

// Mount at your releases route — no props required
<Route path="/releases" element={<ReleasesPage />} />
```

The component accepts no props. All runtime behaviour (search query, status filter, pagination) is driven by URL search params managed internally by `DevSectionPage` and consumed by `ProductReleasesView`.

## Notes

- To point the view at a different API route, update `EP.productReleases` in [`../config/endpoints`](https://github.com/flamingo-stack/openframe-oss-lib/blob/main/config/endpoints.ts).
- Section metadata (title, hero copy) is controlled by the section registry inside `@flamingo-stack/openframe-frontend-core`, not this file.
