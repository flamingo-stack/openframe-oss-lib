Renders the Knowledge Base page by embedding `<DocsHubPage>` with sidebar navigation, content area, scroll-spy, and an in-source RAG search bar, proxied through the app's `/content` reverse proxy.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `KnowledgeBasePage` | React component | Page-level wrapper that extracts the wildcard route segment and passes it to `DocsHubPage` |

**Key dependencies:**

- **`DocsHubPage`** — full docs shell (sidebar tree, content panel, scroll-spy, RAG search bar)
- **`RichMarkdownRenderer`** — XSS-safe Markdown renderer with built-in rehype HAST sanitizer; configured via `RichMarkdownRuntimeProvider` in `app-providers.tsx`
- **`EP`** — endpoint helpers that apply the `/content` proxy prefix to `docsStructure`, `docsContent`, and `resolveLink`

## Usage Example

```typescript
// Registered in your router as a wildcard route:
// <Route path="/knowledge-base/*" element={<KnowledgeBasePage />} />

import { KnowledgeBasePage } from './pages/knowledge-base'

// React Router's `*` wildcard segment is extracted internally:
// /knowledge-base/getting-started/quickstart → docPath = "getting-started/quickstart"
```

## Notes

- **`chatSource`** is hardcoded to `"react-embedding-example"` — never derive this from `window.location` or any user-controlled input (see `EMBEDDING_DOCS_HUB.md §6`).
- The `resolveLinkEndpointUrl` prop overrides the renderer's default `/api/docs/resolve-link`, which would 404 in this embedded SPA (no Next.js route handler present).
- Embedders do **not** need to install `react-markdown` independently; it resolves transitively from the lib.
- RAG search endpoint is wired once via `ChatRuntime.endpoints.docsSearchUrl` in `content-runtime.ts` — no additional prop is required here.
