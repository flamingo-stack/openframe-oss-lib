Thin page composition component that wires the onboarding guides catalog UI to application-specific API endpoints, delegating all rendering and data-fetching logic to the shared library component.

## Key Components

| Export | Type | Description |
|---|---|---|
| `OnboardingCatalogPage` | React component | Page-level component composing `DevSectionPage` chrome with the `OnboardingGuidesCatalogView` catalog UI |

**Dependencies:**

- `DevSectionPage` — supplies page chrome (hero, back button) scoped to the `"onboarding"` section key
- `OnboardingGuidesCatalogView` — renders RAG search, section pills, guide grid, and handles internal data-fetching (reads `?section=` from the URL)
- `EP` — centralized endpoint config providing `EP.onboarding` and `EP.onboardingSections` route values

## Usage Example

```typescript
// Route definition (e.g. React Router / TanStack Router)
import { OnboardingCatalogPage } from './pages/onboarding-catalog'

const routes = [
  {
    path: '/onboarding-guides',
    element: <OnboardingCatalogPage />,
  },
]
```

```typescript
// The component itself requires no props — all configuration is
// sourced from the EP config and the URL's ?section= query param.
<OnboardingCatalogPage />
```

## Notes

- **Config-only** — follows the same zero-props pattern as roadmap, releases, and delivery pages in this app
- API routes (`guidesEndpoint`, `sectionsEndpoint`) are the only application-specific values; swap `EP.*` entries to point at a different backend
- Navigation base path is fixed to `"/onboarding-guides"` — update `basePath` if the route changes
