Demonstrates two embeddable author UI surfaces — `AuthorDetailView` (full author page) and `ArticleAuthorByline` (end-of-article card) — fed by authors discovered from the hub's release payload.

## Key Components

| Export / Symbol | Description |
|---|---|
| `AuthorsPage` | Page component rendering an author picker, the full `AuthorDetailView` with an author-scoped `RelatedContentSection` rail, and the standalone `ArticleAuthorByline` card |
| `useDiscoveredAuthors` | Internal hook that fetches up to 50 release rows and deduplicates hydrated `EntityAuthor` payloads by ID; always-fresh posture (`staleTime: 0`, `gcTime: 0`) |

**Key behaviours:**
- **Author discovery** — no dedicated public authors API; authors are extracted from `/content/api/releases` rows via `extractItems` + `hydrateAuthor` shape
- **Unified content-URL seam** — `runtime.composeContentUrl({ type: 'author' })` resolves to the hub's `/authors/<slug>` because `'author'` is not in the app's `hostedTypes`; absent slug → name rendered as plain text
- **Image proxying** — avatar URLs route through `ChatRuntime.endpoints.imageProxyUrlPrefix` (`/content/api/image-proxy`)
- **Author-scoped rail** — `RelatedContentSection` in `authorId` mode self-fetches all content by that profile, grouped per type with per-group pagination

## Usage Example

```typescript
// Render the full Authors demo page (router entry point)
import { AuthorsPage } from './pages/authors'

export default function App() {
  return <AuthorsPage />
}
```

```typescript
// Standalone byline — embed at the end of any article
import { ArticleAuthorByline } from '@flamingo-stack/openframe-frontend-core/components'

<ArticleAuthorByline
  author="Jane Smith"
  avatar="https://cdn.example.com/jane.jpg"
  jobTitle="Senior Engineer"
  bio="Jane writes about cloud infrastructure."
  href="https://hub.example.com/authors/jane-smith"
  fallbackBio="Contributing author."
/>
```
