Thin config-only page component that wires API endpoints into the shared `RoadmapView` UI shell — all layout, filtering, and voting logic is delegated to `@flamingo-stack/openframe-frontend-core`.

## Key Components

- **`RoadmapPage`** — The sole export. A stateless wrapper that composes `DevSectionPage` and `RoadmapView`, supplying only the API route bindings via `EP`.
- **`DevSectionPage`** — Provides canonical chrome: hero, search input, and status filter pills, all wired to URL params. Receives `sectionKey="roadmap"` to scope its configuration.
- **`RoadmapView`** — Reads URL params, fetches the filtered roadmap list, renders the item grid, and handles user voting.
- **`EP`** — Endpoint constants imported from local config (`../config/endpoints`).

## Usage Example

```typescript
// Render the full roadmap page — no props required.
// Routing, filtering, and voting are handled internally.
import { RoadmapPage } from './roadmap'

// In your router config:
{ path: '/roadmap', element: <RoadmapPage /> }
```

**Endpoint bindings passed to `RoadmapView`:**

```typescript
<RoadmapView
  endpoint={EP.roadmap}              // list fetch
  buildRefreshUrl={EP.roadmapById}   // single-item refresh after vote
  votingOptions={{
    voteApiEndpoint: EP.roadmapVote  // POST target for upvotes
  }}
/>
```

To add new roadmap API routes, update `EP` in [`../config/endpoints`](https://github.com/flamingo-stack/openframe-oss-lib/blob/main/config/endpoints.ts) — no changes to this file are needed.
