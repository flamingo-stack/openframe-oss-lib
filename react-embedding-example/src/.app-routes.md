Defines the top-level React Router v6 route tree for the application, mapping URL paths to page components within a shared `AppShell` layout.

## Key Components

| Export | Type | Description |
|---|---|---|
| `AppRoutes` | Component | Root route registry; renders all `<Route>` definitions inside a single `<Routes>` tree |
| `DOCS_ROUTE_PATH` | `string` | Derived from `DOCS_BASE_ROUTE` config with the leading slash stripped for React Router compatibility |

### Registered Routes

| Path | Component |
|---|---|
| `/` | `HomePage` |
| `/onboarding-guides` | `OnboardingCatalogPage` |
| `/onboarding-guides/:slug` | `OnboardingDetailPage` |
| `/roadmap` | `RoadmapPage` |
| `/delivery` | `DeliveryPage` |
| `/releases` | `ReleasesPage` |
| `/releases/:slug` | `ReleaseDetailRoute` |
| `/authors` | `AuthorsPage` |
| `/faqs` | `FaqsPage` |
| `/legal/:docType` | `LegalPage` |
| `/contact` | `ContactPage` |
| `/case-studies` | `CaseStudiesPage` |
| `/tickets` | `TicketsPage` |
| `/{DOCS_BASE_ROUTE}` + `/*` | `KnowledgeBasePage` |
| `*` | `PageError` (404) |

All routes are nested under `AppShell`, which provides the shared chrome (nav, footer, etc.).

## Usage Example

```typescript
// Mount AppRoutes at the application entry point
import { BrowserRouter } from 'react-router-dom'
import { AppRoutes } from './app-routes'

export function App() {
  return (
    <BrowserRouter>
      <AppRoutes />
    </BrowserRouter>
  )
}
```

> **Adding a new surface:** declare a single `<Route>` inside `AppRoutes` — no other wiring needed. The `KnowledgeBasePage` mount path is intentionally driven by `DOCS_BASE_ROUTE` so the chat `baseRoute` in `ask-ai.tsx` and the actual mount point stay in sync.
