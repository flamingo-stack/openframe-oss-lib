Vite configuration for the OpenFrame OSS dev/preview server, wiring up React plugins, proxy rules that forward hub-bound requests with injected auth headers, and pre-bundling settings for the yalc-linked `openframe-frontend-core` library.

## Key Components

### Proxy Setup
Three proxy routes are configured for both `server` and `preview`:

| Route | Behavior |
|---|---|
| `CONTENT_PREFIX` (`/content/*`) | Rewrites path, injects auth headers, forwards to hub |
| `/api/docs/search` | Passthrough with auth headers (bare `/api` fallback) |
| `/api/chat/agent` | Passthrough with auth headers (bare `/api` fallback) |

Auth headers are injected server-side via `injectHeaders(proxyReq, env)` on the `proxyReq` event. Secrets are loaded with `loadEnv(mode, cwd, '')` (all env vars, no prefix filter) and never reach the browser bundle.

### `resolve.dedupe`
Forces a single copy of React, React DOM, React Router, and TanStack Query across the app and linked library — prevents "invalid hook call" and split-context errors when `optimizeDeps` would otherwise bundle the lib's own peer copies.

### `resolve.alias`
Stubs `next/font/google` to `src/stubs/next-font-google.ts`, guarding against accidental imports of the Next.js compiler macro in a Vite build.

### `optimizeDeps.include`
Pre-bundles all `@flamingo-stack/openframe-frontend-core` entry points via esbuild into `.vite/deps`. This resolves two yalc dev issues: missing files during `tsup` rebuild windows, and Babel deoptimisation warnings on large chunks. The `dev` script runs `vite --force` on every restart to re-bundle, since yalc does not bump the package version (which is what Vite keys its cache on).

## Usage Example

```typescript
// .env.local (not committed)
HUB_ORIGIN=https://your-hub.example.com
CHAT_SECRET=supersecret

// Start dev server — --force re-bundles the yalc lib on every restart
// "dev": "vite --force"
```

> **Note:** The bare `/api/docs/search` and `/api/chat/agent` fallback routes are temporary. They exist because some lib hooks still hardcode bare `/api` paths. Remove them once the optional lib seam (`catalog searchEndpoint` + `tickets agentBaseUrl`) lands.
