Provides thread-safe MongoDB connectivity for test infrastructure, supporting both in-service (connection string URI) and standalone (discrete environment variable) authentication modes.

## Key Components

| Member | Description |
|---|---|
| `getDatabase()` | Returns a thread-local `MongoDatabase` instance with automatic POJO codec support |
| `getCollection(name, docClass)` | Convenience method to retrieve a typed `MongoCollection<T>` from the active database |
| `openConnection()` | Lazily initializes a thread-local `MongoClient` with a 10-second timeout; branches on connection string vs. discrete credentials |
| `closeConnection()` | Closes and removes the thread-local client and database references |
| `resolveDatabaseName()` | Extracts the database name from the connection string URI when available, falling back to the `MONGODB_DATABASE` env var |

## Usage Example

```java
// Retrieve a typed collection and query documents
MongoCollection<Device> devices = MongoDB.getCollection("devices", Device.class);
devices.find().forEach(device -> System.out.println(device.getId()));

// Always close the connection after use (e.g., in an @AfterEach hook)
MongoDB.closeConnection();
```

## Notes

- **Thread isolation:** Both `MongoClient` and `MongoDatabase` are stored in `ThreadLocal` fields, making this safe for parallel test execution.
- **Dual auth modes:** When `MongoConfig.hasConnectionString()` returns `true` (injected by the host service), credentials and database name are parsed directly from the URI. Otherwise, `MONGODB_USER`, `MONGODB_PASSWORD`, `MONGODB_AUTH_DATABASE`, and `MONGODB_URI` env vars are used for standalone runs.
- **POJO codec:** `PojoCodecProvider` with `automatic(true)` is registered on the database, enabling direct mapping of BSON documents to Java POJOs without manual codec configuration.
