Utility class providing factory methods for generating test data related to tickets, including creation inputs, filter inputs, reorder operations, and ticket extraction helpers.

## Key Components

| Method | Description |
|---|---|
| `assigneeId(List<AuthUser>)` | Returns a random user ID from the provided list |
| `firstTicket(TicketConnection)` | Extracts the first ticket node from a connection |
| `firstTicketId(TicketConnection)` | Returns the ID of the first ticket in a connection |
| `firstTicketWithStatusKindNotIn(TicketConnection, String...)` | Finds the first ticket whose lifecycle status kind is not in the excluded set |
| `lastTicket(TicketConnection)` | Extracts the last ticket node from a connection |
| `moveLastBeforeFirst(TicketConnection)` | Builds a `ReorderTicketInput` to promote the last ticket to the top of a column |
| `createTicketRequest(...)` | Builds a `CreateTicketInput` with device, assignee, and label associations |
| `activeTickets()` | Returns a `TicketFilterInput` pre-filtered for `ACTIVE` status |
| `ticketsWithStatusId(String)` | Returns a `TicketFilterInput` scoped to a specific status ID |
| `createStatusRequest()` | Builds a `CreateTicketStatusInput` with a unique name and valid hex color |

## Usage Example

```java
// Create a ticket request with device, assignee, and labels
String assigneeId = TicketGenerator.assigneeId(users);
CreateTicketInput input = TicketGenerator.createTicketRequest(
    organizationId, device, assigneeId, labels
);

// Filter for active tickets
TicketFilterInput filter = TicketGenerator.activeTickets();

// Extract from a connection
Ticket first = TicketGenerator.firstTicket(connection);
Ticket notClosed = TicketGenerator.firstTicketWithStatusKindNotIn(connection, "CLOSED", "RESOLVED");

// Reorder: move last ticket before first
ReorderTicketInput reorder = TicketGenerator.moveLastBeforeFirst(connection);

// Create a custom status
CreateTicketStatusInput status = TicketGenerator.createStatusRequest();
```

## Notes

- Uses [DataFaker](https://www.datafaker.net/) for random data generation (unique status names, random assignee selection).
- `firstTicketWithStatusKindNotIn` guards against lifecycle tenant edge cases where the legacy `status` field may be out of sync after a `transitionTicket` mutation.
- `createStatusRequest` generates names capped at 11 characters (`qa-` + 8 hex chars) to stay within the backend's 32-character limit.
