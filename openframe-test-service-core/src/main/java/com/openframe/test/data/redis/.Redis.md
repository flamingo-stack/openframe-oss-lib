Utility class for querying Redis cluster data during tests, specifically for retrieving password-reset tokens stored by the auth-server.

## Key Components

### `getResetToken(String email)`
Scans Redis cluster nodes for a password-reset token associated with the given email. Searches for keys matching the tenant-scoped pattern `of:{<tenant>}:pwdreset:*`, then returns the token portion of the matching key.

**Behavior:**
- Connects standalone to each seed node from `RedisConfig.getClusterNodes()` to avoid topology discovery issues over dev tunnels
- Uses cursor-based `SCAN` with `count(100)` per node iteration
- Matches the email as the key's value to identify the correct token
- Silently skips unreachable nodes or nodes that don't own the relevant slot
- Returns `null` if no matching token is found

## Usage Example

```java
// Retrieve the password-reset token for a user during an e2e test
String token = Redis.getResetToken("user@example.com");

if (token != null) {
    // Use token to construct reset URL or assert its existence
    String resetUrl = "https://app.example.com/reset?token=" + token;
} else {
    throw new AssertionError("No reset token found for user");
}
```

## Notes

- Relies on `RedisConfig.getTenant()` and `RedisConfig.getClusterNodes()` for cluster configuration
- The hash tag `{<tenant>}` in the key pattern ensures all `pwdreset` keys are pinned to a single Redis slot/node, so only one seed will return results
- Uses [Jedis](https://github.com/redis/jedis) standalone client per node rather than a cluster-aware client
