Generates test data fixtures for script-related API operations, providing factory methods that produce pre-configured request and input DTOs using the Datafaker library for random values.

## Key Components

| Method | Return Type | Description |
|---|---|---|
| `createScriptRequest()` | `CreateScriptInput` | Builds a PowerShell `dir` script creation payload with randomized name, env vars, and Windows platform targeting |
| `updateScriptRequest(Script, String)` | `UpdateScriptInput` | Mirrors a full PUT update from an existing `Script`, overriding only the description field |
| `runSpeedTestScriptRequest(String...)` | `RunScriptRequest` | Constructs a run-script request targeting specific agents using script ID `14` with a 10-second timeout |
| `createOnlineCheckSchedule()` | `CreateScriptScheduleRequest` | Schedules a one-time online connectivity check (script ID `129`) to run 5 minutes from now |

## Usage Example

```java
// Create a new script
CreateScriptInput input = ScriptGenerator.createScriptRequest();
graphqlClient.createScript(input);

// Update only the description of an existing script (full PUT semantics)
UpdateScriptInput update = ScriptGenerator.updateScriptRequest(existingScript, "Updated description");
graphqlClient.updateScript(update);

// Run a speed test script against specific agents
RunScriptRequest run = ScriptGenerator.runSpeedTestScriptRequest("agent-001", "agent-002");
graphqlClient.runScript(run);

// Schedule a one-time online check 5 minutes from now
CreateScriptScheduleRequest schedule = ScriptGenerator.createOnlineCheckSchedule();
graphqlClient.createScriptSchedule(schedule);
```

## Notes

- `Faker` is a shared static instance — not thread-safe; avoid parallel test execution without synchronization.
- `updateScriptRequest` echoes all writable fields back to prevent accidental field clearing under PUT semantics.
- Script IDs `14` and `129` are hardcoded environment constants; ensure the target environment has matching scripts seeded.
