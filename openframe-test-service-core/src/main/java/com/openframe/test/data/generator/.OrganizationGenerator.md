Provides static factory methods for generating test data related to organizations, including create/update requests, sort inputs, filter inputs, and supporting DTOs for addresses and contacts.

## Key Components

| Method | Description |
|---|---|
| `createOrganizationRequest(boolean)` | Builds a `CreateOrganizationRequest` with fixed organization data and a parameterized mailing address flag |
| `updateOrganizationRequest(boolean)` | Builds a modified `CreateOrganizationRequest` simulating an organization update scenario |
| `lastActivitySort(String)` | Produces an `OrganizationSortInput` sorted by `LAST_ACTIVITY` in the given direction |
| `lastActivityRangeFilter(String, String)` | Produces an `OrganizationFilterInput` with a date range on `lastActivityFrom`/`lastActivityTo` |
| `contactInformation(boolean)` | Private helper that assembles `ContactInformationDto`, conditionally adding a separate mailing address |
| `address()` | Private helper using `Faker` to generate a randomized `AddressDto` |
| `contactPerson()` | Private helper using `Faker` to generate a randomized `ContactPersonDto` |

## Usage Example

```java
// Generate a request where mailing address differs from physical
CreateOrganizationRequest createReq = OrganizationGenerator.createOrganizationRequest(false);

// Generate an update payload sharing the same mailing and physical address
CreateOrganizationRequest updateReq = OrganizationGenerator.updateOrganizationRequest(true);

// Sort organizations by last activity descending
OrganizationSortInput sort = OrganizationGenerator.lastActivitySort("DESC");

// Filter organizations by last activity date range
OrganizationFilterInput filter = OrganizationGenerator.lastActivityRangeFilter(
    "2024-01-01",
    "2024-12-31"
);
```

> **Note:** Address and contact person fields are randomized via [Datafaker](https://github.com/datafaker-net/datafaker) on each invocation. Organization-level fields (`name`, `category`, `monthlyRevenue`, etc.) use fixed values to ensure predictable assertions in tests.
