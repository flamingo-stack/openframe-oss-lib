Programmatic JUnit 5 test runner that discovers, filters, and executes tests by tag using the JUnit Platform Launcher API, with support for both JAR-based and package-based classpath scanning.

## Key Components

| Component | Description |
|---|---|
| `TestRunner(TestRunnerConfig)` | Constructor — initializes the JUnit `Launcher` and registers test execution listeners from config |
| `run(String... tags)` | Discovers and executes tests matching the given include tags |
| `run(LauncherDiscoveryRequest)` | Executes tests from a pre-built discovery request |
| `run(TestPlan)` | Executes a pre-discovered `TestPlan` directly |
| `discover(String... tags)` | Returns a `TestPlan` for tests matching the given tags without executing |
| `discover(String[], String[])` | Returns a `TestPlan` with explicit include and exclude tag filters; sequential |
| `discover(String[], String[], int)` | As above, running up to `int` test **classes** concurrently — methods within a class stay on one thread |
| `applyParallelism(builder, int)` | Sets the JUnit parallel config parameters; a no-op at `SEQUENTIAL` |
| `discoverTestClasses()` | Scans the configured package path via classpath resources; handles JAR-based scanning with fallback to `selectPackage` |
| `list(TestPlan)` | Flattens a `TestPlan` into a `List<Test>` with display name and tags |

## Usage Example

```java
// Configure the runner
TestRunnerConfig config = TestRunnerConfig.builder()
    .testPackage("com.openframe.tests")
    .testListeners(List.of(myListener))
    .build();

TestRunner runner = new TestRunner(config);

// Run only tests tagged "smoke"
runner.run("smoke");

// Discover tests tagged "integration", excluding "slow"
TestPlan plan = runner.discover(
    new String[]{"integration"},
    new String[]{"slow"}
);

// Inspect discovered tests before executing
List<Test> tests = runner.list(plan);
tests.forEach(t -> System.out.println(t.getDisplayName()));

// Execute the plan
runner.run(plan);
```

## Notes

- Parallelism is opt-in per discovery, not global: only suites whose cases are isolated from one another qualify. The AI assistant suite does (artifacts namespaced by `RunId`, a per-thread `AgentSession`); a suite sharing fixtures or driving one browser does not.
- The parallel parameters are set on the *discovery* request and are honoured when the resulting plan is executed later via `run(TestPlan)` — discovery and execution need not share a call.
- Speedup is bounded by the slowest single class, not the thread count, since a class is never split across threads.
- Test code runs on `ForkJoinPool` workers rather than the caller's thread. `AuthHelper`/`RequestSpecHelper` keep their session in a `ThreadLocal` and fall back to the static `UserConfig`/`EnvironmentConfig`, so each worker logs itself in on first use — configure those before executing, as `AsyncTestRunner` already does.
- When running from a JAR (e.g., fat/uber JARs), `discoverTestClasses()` iterates `JarEntry` records directly to locate `.class` files, avoiding reliance on filesystem directory listing.
- Inner classes (containing `$`) are excluded from discovery.
- If no classes are found via JAR scanning, the runner falls back to `selectPackage()` for standard filesystem classpaths.
