A process-wide static holder that shares test fixtures (org ID, tenant credentials, device keys, users) across phases of an ordered integration pipeline run, using `volatile` fields for safe cross-thread visibility.

## Key Components

| Member | Description |
|---|---|
| `orgId` | Organization ID created in the first pipeline phase, consumed by all subsequent phases |
| `registeredEmail` / `registeredDomain` | Tenant credentials registered by `OwnerRegistrationTest`, used for E2E lifecycle tests |
| `initialKey` | Active agent registration secret used as the device install `--initialKey` flag |
| `invitedUserId` / `invitedUserEmail` | User created during the invitation flow; deleted at teardown to avoid polluting shared state |
| `fixtureAdminId` / `fixtureAdminEmail` | Pipeline-scoped `ADMIN` user created at setup and torn down at the end; required for tests like ticket-assignment that need an `ADMIN` role |
| `setFixtureAdmin()` / `setInvitedUser()` / `setRegisteredTenant()` | Composite setters that atomically store related fields together |
| `has*()` methods | Guard helpers that return `false` when a fixture is unset, allowing consumers to fall back to default behavior in standalone or single-tag runs |
| `clear()` | Resets all fields to `null`; call at the end of a full pipeline run for isolation |

## Usage Example

```java
// Publishing phase — store the newly registered tenant
PipelineContext.setRegisteredTenant(email, subdomain);
PipelineContext.setOrgId(createdOrg.getId());

// Consuming phase — fall back gracefully when running standalone
String orgId = PipelineContext.hasOrgId()
        ? PipelineContext.getOrgId()
        : defaultOrgId;

// Teardown — remove only the fixture user created by this run
if (PipelineContext.hasInvitedUser()) {
    userService.delete(PipelineContext.getInvitedUserId());
}

// Final cleanup after full pipeline completes
PipelineContext.clear();
```

> **Thread safety note:** All fields are `volatile`. The pipeline orchestrator reads them after blocking on a phase `Future` (establishing happens-before), but `volatile` also makes isolated reads from other threads safe without additional synchronization.
