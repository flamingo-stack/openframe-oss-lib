Builds a RestAssured `HttpClientConfig` with a retry handler that transparently retries connection-establishment failures caused by transient network blips (e.g., dropped SYNs from a cluster's external load balancer hairpin path).

## Key Components

| Member | Description |
|---|---|
| `config()` | Static factory — returns an `HttpClientConfig` wired with the retrying client factory and both timeout parameters |
| `createRetryingHttpClient()` | Instantiates `SystemDefaultHttpClient` with a custom `HttpRequestRetryHandler` that retries only `ConnectException` / `ConnectTimeoutException` |
| `backoffFor(int)` | Computes capped exponential backoff: `base × 2^(attempt−1)`, max 5 s |
| `sleep(Duration)` | Sleeps the current thread; aborts retry chain (returns `false`) on `InterruptedException` |

**Timeout constants**

| Constant | Value | Rationale |
|---|---|---|
| `CONNECT_TIMEOUT` | 10 s | Fast-fail on dropped SYNs |
| `SOCKET_TIMEOUT` | 32 s | Generous allowance for slow server responses |
| `CONNECT_RETRIES` | 4 | 5 total attempts span ~50 s+ of wall-clock time |
| `RETRY_BACKOFF_BASE` | 500 ms | Initial backoff window |
| `RETRY_BACKOFF_MAX` | 5 s | Backoff ceiling |

## Usage Example

```java
import io.restassured.RestAssured;
import io.restassured.config.RestAssuredConfig;

// Wire the retrying client into a RestAssured config
RestAssuredConfig config = RestAssuredConfig.config()
        .httpClient(RetryingHttpClientFactory.config());

RestAssured.given()
        .config(config)
        .get("https://api.example.com/health")
        .then()
        .statusCode(200);
```

> **Why only connection failures?** A connect failure guarantees the request never reached the server, making retries side-effect-free even for non-idempotent mutations. Read timeouts (where the request *was* sent) are deliberately excluded.
