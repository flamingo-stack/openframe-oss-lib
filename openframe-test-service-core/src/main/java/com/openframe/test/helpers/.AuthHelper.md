Thread-safe authentication state manager for test suites, providing lazy-initialized, per-thread cookie storage to isolate auth sessions across parallel test executions.

## Key Components

| Member | Type | Description |
|---|---|---|
| `cookies` | `ThreadLocal<Map<String, String>>` | Per-thread cookie storage ensuring test isolation |
| `getCookies()` | `static` method | Returns current thread's cookies, triggering `AuthFlow.login()` on first access |
| `setCookies(Map)` | `static` method | Manually overrides the current thread's cookie map |
| `refresh()` | `static` method | Calls `AuthApi.refresh()` and updates the stored cookies in-place |
| `clearCookies()` | `static` method | Removes the current thread's cookies, enabling clean teardown |

## Usage Example

```java
// Automatically logs in on first access (lazy init)
Map<String, String> cookies = AuthHelper.getCookies();

// Refresh an expiring session mid-test
Map<String, String> refreshed = AuthHelper.refresh();

// Inject pre-built cookies (e.g., from a fixture or setup step)
AuthHelper.setCookies(Map.of("session", "abc123", "token", "xyz789"));

// Clean up after test to prevent state leakage between runs
@AfterEach
void tearDown() {
    AuthHelper.clearCookies();
}
```

## Notes

- Relies on `UserConfig.getUser()` to resolve credentials — ensure the user config is initialized before the first `getCookies()` call.
- The `ThreadLocal` pattern makes this safe for parallel test runners (e.g., JUnit 5 parallel execution, TestNG).
- Always call `clearCookies()` in teardown to prevent memory leaks in thread pool environments.
