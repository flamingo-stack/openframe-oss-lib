Provides a thin REST-Assured wrapper around the SAS OAuth user registration endpoint, exposing both successful and failure-path registration calls for use in API tests.

## Key Components

| Member | Type | Description |
|---|---|---|
| `REGISTER` | `static final String` | Fully-qualified registration endpoint (`{registrationUrl}/sas/oauth/register`) resolved at class load time via `EnvironmentConfig` |
| `registerUser(UserRegistrationRequest)` | `static` method | Posts a registration payload, asserts HTTP 200, and deserializes the response into `UserRegistrationResponse` |
| `attemptRegistration(UserRegistrationRequest)` | `static` method | Posts a registration payload **without** asserting a status code; returns the raw HTTP status for negative-path assertions |

## Usage Example

```java
// Successful registration
UserRegistrationRequest newUser = new UserRegistrationRequest("alice@example.com", "SecurePass1!");
UserRegistrationResponse created = RegistrationApi.registerUser(newUser);
System.out.println("Registered tenant ID: " + created.getTenantId());

// Negative-path: duplicate/conflicting registration
UserRegistrationRequest duplicate = new UserRegistrationRequest("alice@example.com", "SecurePass1!");
int status = RegistrationApi.attemptRegistration(duplicate);
// Tenant still provisioning → 409; established tenant → 400; both are >= 400
assertThat(status).isGreaterThanOrEqualTo(400);
```

## Notes

- `relaxedHTTPSValidation()` disables SSL certificate checks — appropriate for test environments only.
- The registration URL is resolved once at class initialization via `EnvironmentConfig.getRegistrationUrl()`, so environment variables must be set before the class is loaded.
- `attemptRegistration` intentionally avoids a fixed status-code assertion because tenant provisioning state can yield either `409 Conflict` or `400 Bad Request`; callers should assert `>= 400` rather than a specific code.
