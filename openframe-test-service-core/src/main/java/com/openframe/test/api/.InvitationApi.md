REST-Assured API client for managing user invitations, covering invite creation, acceptance, conflict detection, and revocation operations.

## Key Components

| Method | Endpoint | Auth | Description |
|---|---|---|---|
| `inviteUser` | `POST /api/invitations` | Authorized | Sends a user invitation; expects `201 Created` |
| `attemptInviteUser` | `POST /api/invitations` | Authorized | Attempts an invitation expected to conflict; expects `409` |
| `acceptInvitation` | `POST /sas/invitations/accept` | Unauthorized Auth | Accepts an invitation; expects `200 OK` |
| `attemptAcceptInvitation` | `POST /sas/invitations/accept` | Unauthorized Auth | Attempts acceptance expected to conflict; expects `409` |
| `revokeInvitation` | `DELETE /api/invitations/{id}` | Authorized | Revokes an existing invitation; expects `204 No Content` |

## Usage Example

```java
// Invite a new user
InvitationRequest request = new InvitationRequest("user@example.com", "admin");
Invitation invitation = InvitationApi.inviteUser(request);

// Test duplicate invite conflict
InvitationConflictResponse conflict = InvitationApi.attemptInviteUser(request);

// Accept the invitation
AcceptInvitationRequest acceptRequest = new AcceptInvitationRequest(invitation.getToken());
AcceptInvitationResponse accepted = InvitationApi.acceptInvitation(acceptRequest);

// Revoke an invitation by ID
InvitationApi.revokeInvitation(invitation.getId());
```

## Notes

- `attemptInviteUser` and `attemptAcceptInvitation` are negative-path helpers designed for conflict-scenario tests, asserting `409 Conflict` responses.
- `acceptInvitation` uses `getUnAuthorizedAuthSpec`, indicating the accept endpoint uses a token-based flow rather than session authentication.
- All methods are `static`, making this a stateless utility class suitable for direct use in test steps without instantiation.
