Defines reusable GraphQL query string constants for fetching organization data in the OpenFrame API test suite.

## Key Components

| Constant | Description |
|---|---|
| `ORGANIZATIONS` | Paginated query for a list of organizations with optional filtering, sorting, and cursor-based pagination |
| `ORGANIZATION_BY_ORGANIZATION_ID` | Query to fetch a single organization by its unique `organizationId` |

Both queries return a comprehensive organization payload including contact information, addresses, contract details, and audit timestamps.

## Usage Example

```java
// Paginated list query with variables
Map<String, Object> variables = new HashMap<>();
variables.put("first", 10);
variables.put("after", null);
variables.put("filter", Map.of("status", "ACTIVE"));
variables.put("orderBy", Map.of("field", "NAME", "direction", "ASC"));

graphQLClient.query(OrganizationQueries.ORGANIZATIONS, variables);

// Single organization lookup by organizationId
Map<String, Object> variables = new HashMap<>();
variables.put("organizationId", "ORG-12345");

graphQLClient.query(OrganizationQueries.ORGANIZATION_BY_ORGANIZATION_ID, variables);
```

## Query Variables

**`ORGANIZATIONS`**
- `$first` — page size (`Int`)
- `$after` — pagination cursor (`String`)
- `$filter` — `OrganizationFilterInput` for narrowing results
- `$orderBy` — `OrganizationSortInput` for sort field and direction

**`ORGANIZATION_BY_ORGANIZATION_ID`**
- `$organizationId` — required unique identifier (`String!`)

## Notes

- `ORGANIZATIONS` returns a `Connection` type with `edges/node` and `pageInfo` for cursor-based pagination.
- Both queries fetch identical field sets, including nested `contactInformation` with `contacts`, `physicalAddress`, and `mailingAddress`.
