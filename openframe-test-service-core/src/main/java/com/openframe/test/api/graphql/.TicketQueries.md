Defines static GraphQL query and mutation string constants used for ticket-related API testing in the OpenFrame test suite.

## Key Components

| Constant | Type | Description |
|---|---|---|
| `TICKET_LABELS` | Query | Fetches all ticket labels (id, key, description, color, timestamps) |
| `GET_TICKETS` | Query | Paginated ticket list with filtering, search, and cursor-based pagination |
| `GET_TICKET` | Query | Full ticket detail by ID, including dialog, attachments, and notes |
| `REORDER_TICKET` | Mutation | Updates ticket order within a status column |
| `TICKET_STATUSES` | Query | Retrieves all ticket status definitions |
| `CREATE_TICKET_STATUS` | Mutation | Creates a new ticket status |
| `DELETE_TICKET_STATUS` | Mutation | Deletes an existing ticket status |
| `TRANSITION_TICKET` | Mutation | Moves a ticket to a new status |
| `CREATE_TICKET` | Mutation | Creates a new ticket with owner, device, labels, and attachments |

## Usage Example

```java
// Execute a paginated ticket list query in a test
Map<String, Object> variables = Map.of(
    "filter", Map.of("organizationId", "org-123"),
    "pagination", Map.of("first", 10),
    "search", "network issue"
);

graphQLClient.execute(TicketQueries.GET_TICKETS, variables);

// Create a ticket via mutation
Map<String, Object> input = Map.of(
    "title", "VPN not connecting",
    "organizationId", "org-123",
    "deviceId", "device-456"
);

graphQLClient.execute(TicketQueries.CREATE_TICKET, Map.of("input", input));
```

## Notes

- `GET_TICKETS` supports polymorphic `owner` resolution via inline fragments (`ClientTicketOwner` / `AdminTicketOwner`)
- `GET_TICKET` includes AI dialog token usage metadata, useful for asserting Mingo AI interactions in tests
