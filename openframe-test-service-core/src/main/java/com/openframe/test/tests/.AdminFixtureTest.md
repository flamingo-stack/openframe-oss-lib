Manages the lifecycle of a shared ADMIN user fixture for the e2e test pipeline, ensuring exactly one admin member exists across all functional tests without per-test setup overhead.

## Key Components

| Member | Type | Description |
|---|---|---|
| `setupAdminUser()` | `@Test` (`admin-setup`) | Invites and accepts an admin user invitation, stores the resulting ID and email in `PipelineContext` |
| `teardownAdminUser()` | `@Test` (`admin-teardown`) | Deletes the fixture admin user via `UserApi`; no-ops safely if none was created |

**Dependencies:**

- `InvitationApi` — sends and accepts user invitations
- `UserApi` — deletes the fixture user during teardown
- `InvitationGenerator` — builds `InvitationRequest` and `AcceptInvitationRequest` payloads
- `PipelineContext` — pipeline-scoped store for the admin user's ID and email

## Usage Example

```java
// Phase ordering in the pipeline runner (conceptual)
// 1. admin-setup runs before functional tests
@Tag("admin-setup")
void setupAdminUser() { ... }

// 2. Functional tests access the fixture admin via PipelineContext
String adminId = PipelineContext.getFixtureAdminId();

// 3. admin-teardown runs after all functional tests complete
@Tag("admin-teardown")
void teardownAdminUser() { ... }
```

## Notes

- A freshly registered tenant has only an **OWNER** role, which differs from **ADMIN**. This fixture bridges that gap for tests relying on `getUsers(ADMIN)`.
- `teardownAdminUser` guards against missing context with `PipelineContext.hasFixtureAdmin()`, making it safe to run even if setup failed.
- Tagged `oss` for suite-level filtering alongside `admin-setup` / `admin-teardown` for phase-level ordering.
