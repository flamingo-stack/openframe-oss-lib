Integration test suite for the user invitation lifecycle in OpenFrame, covering invitation creation, acceptance, revocation, conflict handling, and user deletion.

## Key Components

| Method | Order | Description |
|---|---|---|
| `testInviteUser()` | 1 | Creates a new invitation and validates API response matches DB record |
| `testAcceptInvitation()` | 2 | Accepts a pending invitation and publishes the new user to `PipelineContext` for cleanup |
| `testAcceptAcceptedInvitation()` | 3 | Asserts that re-accepting an already-accepted invitation returns a conflict error |
| `testRevokeInvitation()` | 4 | Revokes an invitation and verifies `REVOKED` status in DB |
| `testAcceptRevokedInvitation()` | 5 | Asserts that accepting a revoked invitation returns a conflict error |
| `testInviteActiveUser()` | 6 | Asserts that inviting an existing tenant member returns a conflict error |
| `testDeleteUser()` | 8 | Deletes the pipeline-created user (or falls back to any non-owner admin); verifies `DELETED` status |
| `testInviteDeletedUser()` | 9 | Verifies that a previously deleted user can be re-invited with `PENDING` status |

## Usage Example

```java
// Run all invitation tests
@Tag("oss")
@Tag("invitations")
public class UserInvitationsTest extends BaseTest { ... }

// Run only the delete phase in isolation
// Tests tagged "delete" can be filtered separately:
// mvn test -Dgroups="oss & invitations & delete"
```

## Notes

- Tests are **strictly ordered** via `@TestMethodOrder(OrderAnnotation.class)` — they depend on shared DB state across steps.
- `PipelineContext.setInvitedUser()` / `PipelineContext.getInvitedUserId()` enable self-cleaning pipeline runs without affecting pre-existing shared admin fixtures.
- `testInviteActiveUser()` intentionally targets the **authenticated user's own email** (from `UserConfig`) rather than a random active user, avoiding cross-tenant false positives.
- Timestamp assertions use `within(1, ChronoUnit.SECONDS)` to tolerate minor serialization drift between API and DB values.
