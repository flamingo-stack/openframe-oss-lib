JUnit5 integration test suite for the OpenFrame ticket management API, validating CRUD operations, lifecycle transitions, search, reordering, and error handling for the ticket domain.

## Key Components

| Method | Order | Tags | Description |
|---|---|---|---|
| `testListTickets()` | — | `saas`, `read` | Fetches paginated active tickets and asserts mandatory fields |
| `testListTicketLabels()` | — | `saas`, `read` | Retrieves all ticket labels and validates `id`/`key` presence |
| `testCreateTicket()` | 1 | — | Creates a ticket with device, assignee, and label; asserts all returned fields |
| `testSearchTicket()` | 2 | `saas`, `read` | Searches by title and verifies the target ticket appears in results |
| `testReorderTicket()` | 3 | — | Moves the last ticket in a column before the first and confirms the order key changes |
| `testResolveTicket()` | 4 | — | Transitions an ACTIVE ticket to RESOLVED and validates `statusDefinition` and `resolvedAt` |
| `testArchiveActiveTicketRejected()` | — | — | Asserts that skipping RESOLVED → ARCHIVED returns a `TICKET_INVALID_TRANSITION` error |
| `testArchiveTicket()` | 5 | — | Full resolve-then-archive lifecycle transition |

## Usage Example

```java
// Run the full suite via Maven with the "saas" tag
mvn test -Dgroups="saas"

// Run only read-safe tests (no mutations)
mvn test -Dgroups="saas & read"

// Run a single test by display name
mvn test -Dtest="TicketsTest#testCreateTicket"
```

## Notes

- Extends `BaseTest` for shared authentication and client setup.
- `@TestMethodOrder(MethodOrderer.OrderAnnotation.class)` ensures stateful tests (`create → search → reorder → resolve → archive`) execute in dependency order.
- Device selection prefers ONLINE devices via `onlineDevicesFilter()`, falling back to `offlineDevicesFilter()`.
- Lifecycle transitions follow a strict state machine: `ACTIVE → RESOLVED → ARCHIVED`; skipping RESOLVED is explicitly rejected and tested.
