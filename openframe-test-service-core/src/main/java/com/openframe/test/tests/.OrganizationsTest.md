Integration test suite for the Organizations API, covering full CRUD lifecycle operations plus sorting and filtering behaviors for organization records.

## Key Components

| Method | Order | Tags | Description |
|--------|-------|------|-------------|
| `testCreateOrganization()` | 1 | `create` | Creates a new org, validates all fields, and publishes the org ID and agent registration secret to `PipelineContext` |
| `testListOrganizations()` | 2 | `read` | Asserts the list endpoint returns non-empty results with required fields populated |
| `testRetrieveOrganization()` | 3 | `read` | Fetches a single org by ID and validates it matches the list response |
| `testUpdateOrganization()` | 4 | `update` | Updates the first non-default org and validates the response reflects the new data |
| `testArchiveOrganization()` | 5 | `delete`, `org-archive` | Archives the pipeline-created org (or first available) and confirms it is removed from the active list |
| `testSortOrganizationsByLastActivityAscending()` | 6 | `read` | Verifies ascending sort on `lastActivityAt` returns results in oldest-first order |
| `testFilterOrganizationsByLastActivityRange()` | 7 | `read` | Filters by the full `[min, max]` `lastActivityAt` range and asserts all results fall within bounds |

## Usage Example

```java
// Run only create + read tests against the OSS environment
mvn test -Dgroups="oss & (create | read)" -Dtest=OrganizationsTest

// Run the full suite including archive in a pipeline context
mvn test -Dgroups="oss" -Dtest=OrganizationsTest
```

> **Pipeline integration:** `testCreateOrganization` publishes the created org ID via `PipelineContext.setOrgId()` and attempts to capture the active agent registration secret via `AgentApi.getActiveRegistrationSecret()`. Downstream tests (especially `testArchiveOrganization`) use `PipelineContext.hasOrgId()` to target the exact org created by the pipeline rather than defaulting to the first available record.

## Notes

- Tests run in strict `@Order` sequence via `MethodOrderer.OrderAnnotation`.
- Tagged `oss` and `saas` for environment-level filtering.
- Recursive comparison via AssertJ's `usingRecursiveComparison()` ignores system-managed fields (`id`, `createdAt`, `updatedAt`, etc.) when validating request/response parity.
