Page Object for the post-login Dashboard page (`https://test-qa.openframe.build/dashboard/`), used in Playwright-based UI tests to assert successful login and verify the app shell has fully rendered.

## Key Components

| Member | Type | Description |
|---|---|---|
| `URL_FRAGMENT` | `String` constant | Path fragment (`/dashboard`) used for URL-based navigation checks, tolerates presence or absence of trailing slash |
| `userBadge()` | `Locator` | Top-right header avatar button showing user initials (e.g. `TQ`) |
| `pageHeading()` | `Locator` | First `h1` or `h2` within `<main>` |
| `sidebar()` | `Locator` | `<aside>` main navigation sidebar — reliable indicator the app shell loaded |
| `dashboardNavActive()` | `Locator` | Dashboard nav item with `aria-current="page"` — confirms the dashboard route actually rendered, not just the URL |
| `isLoaded()` | `boolean` | Composite check: URL contains fragment, sidebar visible, user badge visible, and dashboard nav item is active |
| `getCurrentUrl()` | `String` | Returns the browser's current URL |
| `getUserBadgeText()` | `String` | Returns trimmed inner text of the user avatar badge |

## Usage Example

```java
// Instantiate after successful login redirect
DashboardPage dashboard = new DashboardPage(page);

// Wait for the page to be fully rendered
page.waitForURL("**" + DashboardPage.URL_FRAGMENT + "**");

// Assert the app shell loaded correctly
assertTrue(dashboard.isLoaded(), "Dashboard did not load after login");

// Assert the correct user is logged in
assertEquals("TQ", dashboard.getUserBadgeText());
```

## Notes

- All selectors use ARIA attributes (`aria-label`, `aria-current`) — tests remain resilient to CSS class changes.
- `dashboardNavActive()` waits on a rendered route indicator rather than the URL alone, avoiding false-positives during client-side navigation.
