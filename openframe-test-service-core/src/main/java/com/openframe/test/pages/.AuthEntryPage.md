Page Object Model class for the OpenFrame authentication entry page (`/auth`), handling navigation, tab switching, email input, and transition to the auth-method picker.

## Key Components

| Member | Type | Description |
|---|---|---|
| `URL` | `static final String` | Resolved auth entry URL from `EnvironmentConfig.getAuthUrl()` |
| `navigate()` | Method | Navigates to `/auth`, waits for DOM + network idle |
| `switchToLogin()` | Method | Clicks the Login tab, waits for `/auth/login` URL and SSO button visibility |
| `enterEmail(String)` | Method | Fills the email field with hydration-safe retry loop |
| `submitEmail(String)` | Method | Calls `enterEmail`, then returns an `AuthMethodPage` instance |
| `signUpTab()` / `loginTab()` | Locators | Segmented toggle buttons matched via `:has-text()` |
| `emailInput()` | Locator | `input[type='email']` on the login form |
| `forgotPasswordLink()` | Locator | "Forgot Password?" button |

## Usage Example

```java
// Navigate to auth, switch to Login, and proceed to the auth-method picker
AuthMethodPage methodPage = new AuthEntryPage(page)
        .navigate()
        .switchToLogin()
        .submitEmail("user@example.com");

// Or step-by-step with intermediate assertions
AuthEntryPage authEntry = new AuthEntryPage(page).navigate();
authEntry.loginTab().click();
authEntry.enterEmail("user@example.com");
```

## Notes

- Selectors use `:has-text()` because the buttons expose no accessible name for `getByRole()`, and `:text-is()` binds to inner `<span>` elements rather than the `<button>`.
- `enterEmail` retries `fill()` in a polling loop to guard against controlled-input hydration drops after tab switching.
- `submitEmail` returns [`AuthMethodPage`](https://github.com/flamingo-stack/openframe-oss-lib/blob/main/src/main/java/com/openframe/test/pages/AuthMethodPage.java), continuing the Page Object chain without a URL change.
