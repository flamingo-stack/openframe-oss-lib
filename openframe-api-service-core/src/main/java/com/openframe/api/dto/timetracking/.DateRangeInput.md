A simple DTO used to capture a validated date range for time tracking queries, requiring both a start and end date.

## Key Components

| Field | Type | Constraint | Description |
|---|---|---|---|
| `startDate` | `LocalDate` | `@NotNull` | Beginning of the date range |
| `endDate` | `LocalDate` | `@NotNull` | End of the date range |

**Lombok annotations:** `@Data`, `@Builder`, `@NoArgsConstructor`, `@AllArgsConstructor` — generate getters/setters, builder pattern, and constructors automatically.

## Usage Example

```java
// Builder pattern
DateRangeInput range = DateRangeInput.builder()
    .startDate(LocalDate.of(2024, 1, 1))
    .endDate(LocalDate.of(2024, 1, 31))
    .build();

// Constructor
DateRangeInput range = new DateRangeInput(
    LocalDate.of(2024, 1, 1),
    LocalDate.of(2024, 1, 31)
);

// Typical use in a REST controller
@GetMapping("/time-entries")
public List<TimeEntry> getEntries(@Valid @RequestBody DateRangeInput input) {
    return timeTrackingService.findByDateRange(
        input.getStartDate(),
        input.getEndDate()
    );
}
```

> **Note:** Both fields are required. Passing `null` for either will trigger a `ConstraintViolationException` when validated via `@Valid`. No cross-field validation (e.g., `startDate` before `endDate`) is enforced at the DTO level — add that logic in the service layer if needed.
