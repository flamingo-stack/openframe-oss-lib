Maps a `User` document entity to a `UserResponse` DTO, resolving effective roles and formatting enum fields as strings.

## Key Components

- **`UserMapper`** — Spring `@Component` responsible for converting `User` domain objects into `UserResponse` DTOs for API responses.
- **`toResponse(User entity)`** — Single mapping method that transforms a `User` document into a `UserResponse`, including:
  - Core identity fields (`id`, `email`, `firstName`, `lastName`)
  - Email verification status
  - Effective roles via `UserRole.effective(...)`, mapped to their string names
  - Account status as a string
  - Audit timestamps (`createdAt`, `updatedAt`)

## Usage Example

```java
@RestController
@RequestMapping("/users")
public class UserController {

    private final UserMapper userMapper;
    private final UserService userService;

    public UserController(UserMapper userMapper, UserService userService) {
        this.userMapper = userMapper;
        this.userService = userService;
    }

    @GetMapping("/{id}")
    public ResponseEntity<UserResponse> getUser(@PathVariable String id) {
        User user = userService.findById(id);
        return ResponseEntity.ok(userMapper.toResponse(user));
    }
}
```

## Notes

- `UserRole.effective(entity.getRoles())` resolves inherited or computed roles before mapping, ensuring the response reflects actual permissions rather than raw stored values.
- Enum fields (`roles`, `status`) are serialized as strings using `Enum::name`, keeping the API response decoupled from internal enum types.
