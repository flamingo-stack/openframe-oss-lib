Maps `Notification` domain objects to GraphQL-compatible DTOs, handling cursor pagination and notification category resolution for the OpenFrame API.

## Key Components

| Member | Description |
|---|---|
| `toCursorPaginationCriteria(ConnectionArgs)` | Converts GraphQL `ConnectionArgs` into a `CursorPaginationCriteria` for repository queries |
| `toView(Notification, boolean)` | Transforms a `Notification` document into a `NotificationView` DTO, including read state |
| `categoryOf(Notification)` | Resolves the notification category — returns the stored value or falls back to `NotificationContextDescriptorRegistry` lookup by context |
| `toConnection(GenericQueryResult<NotificationView>)` | Wraps a paginated result into a `GenericConnection` with cursor-encoded edges and `pageInfo` |

## Usage Example

```java
// Injected via Spring DI
@Autowired
private GraphQLNotificationMapper mapper;

// Convert raw domain + read-status into a view
NotificationView view = mapper.toView(notification, isRead);

// Build a Relay-style connection from a paginated query result
GenericConnection<GenericEdge<NotificationView>> connection =
    mapper.toConnection(queryResult);

// Convert GraphQL pagination args for a repository call
CursorPaginationCriteria criteria =
    mapper.toCursorPaginationCriteria(connectionArgs);
```

## Notes

- Category resolution is **lazy**: if the `Notification` document already carries a `category`, the registry is not consulted, avoiding unnecessary lookups.
- Cursors are encoded via `CursorCodec.encode(view.id())`, keeping pagination opaque to GraphQL clients.
- The mapper is a stateless Spring `@Component` — `NotificationContextDescriptorRegistry` is the only injected dependency.
