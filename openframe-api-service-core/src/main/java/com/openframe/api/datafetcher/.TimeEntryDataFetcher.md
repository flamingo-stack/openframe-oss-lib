GraphQL DGS data fetcher that handles all time tracking operations — queries, mutations, and field resolvers — for `TimeEntry` entities in the OpenFrame API.

## Key Components

### Queries
| Method | Description |
|---|---|
| `currentTimer()` | Returns the authenticated user's active timer |
| `timeEntry(id)` | Fetches a single entry by Relay global ID |
| `myTimeEntries(...)` | Paginated list of the current user's entries filtered by date range |
| `employeeTimeEntries(...)` | Paginated entries filtered by employee/ticket/org |
| `employeeTimeStats(...)` | Aggregated time statistics for filtered employees |

### Mutations
| Method | Description |
|---|---|
| `startTimer(input)` | Starts a new timer for the current user |
| `pauseTimer()` / `resumeTimer()` | Pause or resume the active timer |
| `stopTimer(input)` | Stops and finalizes the active timer |
| `cancelTimer()` | Discards the active timer |
| `createTimeEntry(input)` | Manually creates a time entry (admin use) |
| `updateTimeEntry(input)` | Updates an existing entry |
| `unlinkTicketFromTimeEntry(id)` | Detaches a ticket association |
| `deleteTimeEntry(id)` | Deletes an entry by ID |

### Field Resolvers (`@DgsData`)
- **`id`** — converts internal ID to Relay global ID
- **`state`** — derives `RUNNING`, `PAUSED`, or `COMPLETED` from timestamps
- **`user`** — batch-loads `UserResponse` via `userDataLoader`
- **`ticket`** — batch-loads `Ticket` via `ticketDataLoader`
- **`organization`** — batch-loads `Organization` via `organizationDataLoader`

## Usage Example

```java
// GraphQL query — fetch current user's time entries for a date range
query {
  myTimeEntries(
    period: { startDate: "2024-01-01", endDate: "2024-01-31" }
    first: 20
  ) {
    filteredCount
    edges {
      cursor
      node {
        id
        state
        startedAt
        durationSeconds
        ticket { id title }
        user { id name }
      }
    }
  }
}

// GraphQL mutation — start a timer linked to a ticket
mutation {
  startTimer(input: {
    ticketId: "VGlja2V0OjEyMw=="
    notes: "Investigating network issue"
  }) {
    id
    state
  }
}
```

> **Note:** All IDs use [Relay Global Object Identification](https://relay.dev/graphql/objectidentification.htm). The fetcher automatically decodes incoming Relay global IDs (via `RELAY.fromGlobalId`) and encodes outgoing IDs before returning them to clients. Authentication is resolved from the JWT in the Spring Security context on every operation.
