GraphQL data fetcher for device-related queries in the OpenFrame API, handling device listing, filtering, pagination, and resolving nested fields on the `Machine` type via DataLoader-based batching.

## Key Components

| Method | Type | Description |
|---|---|---|
| `deviceFilters` | `@DgsQuery` | Returns available filter options based on a `DeviceFilterInput` |
| `devices` | `@DgsQuery` | Paginated, filterable, sortable list of `Machine` records using Relay cursor pagination |
| `deviceById` | `@DgsQuery` | Fetches a single device by its Relay global ID (decodes internally) |
| `device` | `@DgsQuery` | Fetches a single device by its raw `machineId` |
| `updateDeviceNickname` | `@DgsMutation` | Sets or clears a device's user-defined `nickname` (delegates to `DeviceService.updateNickname`) |
| `machineNodeId` | `@DgsData` | Encodes `Machine.machineId` as a Relay global ID |
| `toolConnectionNodeId` | `@DgsData` | Encodes `ToolConnection.id` as a Relay global ID |
| `installedAgentNodeId` | `@DgsData` | Encodes `InstalledAgent.id` as a Relay global ID |
| `tags` | `@DgsData` | Batch-loads tags for a `Machine` via `tagDataLoader` |
| `toolConnections` | `@DgsData` | Batch-loads tool connections via `toolConnectionDataLoader` |
| `installedAgents` | `@DgsData` | Batch-loads installed agents via `installedAgentDataLoader` |
| `organization` | `@DgsData` | Batch-loads the parent organization, returning `null` if inactive or missing |

## Usage Example

```java
// Querying devices with pagination and filtering (GraphQL)
query {
  devices(
    filter: { organizationId: "org_123", osType: WINDOWS },
    first: 20,
    after: "cursor==",
    sort: { field: "hostname", direction: ASC },
    search: "web-server"
  ) {
    totalCount
    edges {
      node {
        id
        machineId
        hostname
        organization { id name }
        tags { id name }
        toolConnections { id toolType }
        installedAgents { id version }
      }
    }
    pageInfo {
      hasNextPage
      endCursor
    }
  }
}
```

> **Note:** `deviceById` expects a Relay-encoded global ID (e.g. `"Machine:abc123"` base64-encoded), while `device` accepts the raw `machineId` directly. The `organization` resolver silently returns `null` for organizations with a non-`ACTIVE` status.
