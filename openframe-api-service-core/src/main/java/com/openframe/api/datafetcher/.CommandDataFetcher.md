GraphQL mutation resolver for RMM (Remote Monitoring and Management) ad-hoc command dispatch. Bridges incoming GraphQL mutations to the `CommandDispatchService`, handling single commands, batch execution, and cancellation.

## Key Components

| Member | Type | Description |
|---|---|---|
| `runCommand` | `@DgsMutation` | Dispatches a single command to a target device |
| `batchRunCommand` | `@DgsMutation` | Dispatches a command to multiple devices; injects the authenticated user's ID |
| `cancelExecution` | `@DgsMutation` | Cancels an in-progress command execution |
| `getCurrentUserId` | private helper | Extracts the user ID from the JWT principal via `AuthPrincipal` |

All mutation inputs are validated via `@Valid` + `@Validated` before reaching the service layer.

## Usage Example

```java
// GraphQL mutation — single command
mutation {
  runCommand(input: { deviceId: "dev-123", command: "ipconfig /all" }) {
    dispatchId
    status
  }
}

// GraphQL mutation — batch command (userId injected server-side from JWT)
mutation {
  batchRunCommand(input: { deviceIds: ["dev-123", "dev-456"], command: "hostname" }) {
    dispatchId
    status
  }
}

// GraphQL mutation — cancel execution
mutation {
  cancelExecution(input: { dispatchId: "exec-789" }) {
    dispatchId
    status
  }
}
```

## Notes

- `batchRunCommand` is the only mutation that requires the caller's identity — the user ID is resolved automatically from the Spring Security context rather than accepted as a client-supplied input, preventing privilege escalation.
- All three mutations return a `DispatchResponse`, making client-side response handling uniform across operations.
