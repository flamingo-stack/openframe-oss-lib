Thin adapter that exposes the GraphQL Relay `node` and `nodes` queries. It decodes nothing itself: the lookup is delegated to `RelayNodeFinder` from the `openframe-graphql-node` library, which parses the global ID, finds the `NodeLoader` registered for its `NodeType` and returns the node.

## Key Components

| Member | Description |
|---|---|
| `node(id)` | `@DgsQuery` — passes the caller (`AuthPrincipal`), the global ID and the schema to `RelayNodeFinder.findNode()`; answers `null` when nothing is found |
| `nodes(ids)` | `@DgsQuery` — resolves each ID the same way; an ID that fails to resolve is logged and answers `null` in its slot instead of failing the whole list |

## Where the loaders live

- `ApiNodeLoaderConfiguration` declares one `NodeLoader` bean per supported type (service-backed, e.g. `DeviceService` for `MACHINE`, `TicketService` for `TICKET`). Adding a node type means adding a loader bean there.
- The same loaders answer the Federation `_entities` query (`NodeEntityFinder`) and map runtime objects to GraphQL type names for the `Node` interface (`NodeTypeResolver`).
- A type declared in the schema as a bare reference stub (for example `Dialog`, owned by another subgraph) has no loader; `node(id)` answers a reference to it without a lookup.
- An ID of a type that has no loader and is not a reference stub fails with `Unsupported node type`.

## Usage Example

```graphql
query {
  node(id: "TWFjaGluZToxMjM") {
    ... on Machine {
      id
      hostname
    }
  }
}

query {
  nodes(ids: ["TWFjaGluZToxMjM", "T3JnYW5pemF0aW9uOjQ1Ng"]) {
    ... on Machine { hostname }
    ... on Organization { name }
  }
}
```
