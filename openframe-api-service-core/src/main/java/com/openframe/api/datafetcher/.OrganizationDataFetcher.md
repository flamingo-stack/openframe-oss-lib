GraphQL DataFetcher for Organization-related queries, exposing Relay-compatible node IDs, paginated/filtered organization lists, and single-organization lookups via the DGS framework.

## Key Components

| Member | Description |
|---|---|
| `organizationNodeId` | Resolves the Relay global ID for an `Organization` node by encoding the internal `organizationId`. |
| `organizationLastActivityAt` | Computes the canonical last-activity timestamp — returns `updatedAt` if present, falls back to `createdAt`. Aligns with `lastActivityFrom/To` filter and `LAST_ACTIVITY` sort. |
| `organizations` | Paginated query supporting cursor-based pagination (`first`/`after`/`last`/`before`), free-text `search`, structured `filter`, and `orderBy` sorting. Returns a `CountedGenericConnection`. |
| `organization` | Fetches a single organization by Relay global ID, decoding it before lookup. |
| `organizationByOrganizationId` | Fetches a single organization directly by its internal `organizationId`. |

## Usage Example

```java
// Paginated organizations query (GraphQL)
// query {
//   organizations(
//     first: 10,
//     after: "cursor==",
//     search: "Acme",
//     orderBy: { field: LAST_ACTIVITY, direction: DESC }
//   ) {
//     totalCount
//     edges { node { id name lastActivityAt } }
//   }
// }

// Single lookup by Relay global ID
// query {
//   organization(id: "T3JnYW5pemF0aW9uOjEyMw==") {
//     id
//     name
//   }
// }

// Single lookup by internal ID
// query {
//   organizationByOrganizationId(organizationId: "org-123") {
//     id
//     name
//   }
// }
```

## Notes

- Relay global IDs are encoded/decoded using `graphql.relay.Relay` with the type name `"Organization"`.
- Input validation is enforced via Jakarta `@Valid` and `@NotBlank` — invalid inputs are rejected before service calls.
- Pagination and sort inputs are mapped through `GraphQLOrganizationMapper` before being passed to `OrganizationQueryService`.
