DGS GraphQL data fetcher for audit log queries, exposing log events, filters, and details via cursor-based pagination. Only active when Cassandra is enabled (`spring.data.cassandra.enabled=true`).

## Key Components

| Member | Type | Description |
|---|---|---|
| `logEventId` | `@DgsData` | Resolves Relay global ID for `LogEvent.id` |
| `logDetailsId` | `@DgsData` | Resolves Relay global ID for `LogDetails.id` |
| `logFilters` | `@DgsQuery` | Returns available filter options for the log UI |
| `logs` | `@DgsQuery` | Paginated log event list using Relay cursor-based pagination |
| `logDetails` | `@DgsQuery` | Fetches a single log detail record by composite key |

## Usage Example

```java
// Query: fetch paginated logs
GenericConnection<GenericEdge<LogEvent>> result = logDataFetcher.logs(
    filter,       // LogFilterInput (validated)
    10,           // first
    null,         // after cursor
    null,         // last
    null,         // before cursor
    "search term",
    sort          // LogSortInput
);

// Query: fetch detail for a specific event
LogDetails details = logDataFetcher.logDetails(
    "2024-01-15",         // ingestDay
    "psa",                // toolType
    "ticket.created",     // eventType
    Instant.now(),        // timestamp
    "EVT-001"             // toolEventId
);
```

## Notes

- Relay global IDs are generated for both `LogEvent` and `LogDetails` using the `Relay` utility, ensuring spec-compliant cursor pagination.
- `logDetails` returns `null` (resolves to GraphQL `null`) when no matching record is found, rather than throwing.
- All inputs are validated via Jakarta Bean Validation (`@Valid`, `@NotBlank`).
