GraphQL DGS data fetcher that exposes notification queries and mutations for authenticated `ADMIN` and `AGENT` users, translating between Relay-compliant global IDs and internal notification identifiers.

## Key Components

| Member | Type | Description |
|---|---|---|
| `notifications` | `@DgsQuery` | Returns a paginated, filterable `Connection<NotificationView>` for the current recipient |
| `hasUnreadNotifications` | `@DgsQuery` | Returns `true` if the current recipient has any unread notifications |
| `unreadCountsByCategory` | `@DgsQuery` | Returns per-category unread counts as `List<UnreadCategoryCount>` |
| `markNotificationAsRead` | `@DgsMutation` | Marks a single notification read by Relay global ID |
| `markAllNotificationsAsRead` | `@DgsMutation` | Marks all notifications read; returns affected count |
| `deleteNotification` | `@DgsMutation` | Deletes a single notification by Relay global ID |
| `deleteAllReadNotifications` | `@DgsMutation` | Deletes all read notifications; returns affected count |
| `notificationNodeId` | `@DgsData` | Resolves the Relay global `id` field on `Notification` objects |
| `currentRecipient()` | private | Derives `RecipientType.USER` or `RecipientType.MACHINE` from the JWT principal |
| `decodeNotificationId()` | private | Validates and decodes a Relay global ID, asserting the `Notification` type |

## Usage Example

```java
// GraphQL query — paginated notifications with filter
query {
  notifications(first: 20, filter: { read: false }, sort: { field: "createdAt", direction: DESC }) {
    edges {
      node {
        id
        title
        category
      }
    }
    pageInfo {
      hasNextPage
      endCursor
    }
  }
}

// GraphQL mutation — mark a single notification read
mutation {
  markNotificationAsRead(notificationId: "Tm90aWZpY2F0aW9uOjEyMzQ=")
}

// GraphQL query — unread badge counts per category
query {
  hasUnreadNotifications
  unreadCountsByCategory {
    category
    count
  }
}
```

> **Auth:** All operations require a valid JWT and either the `ADMIN` or `AGENT` authority. `AGENT` principals must carry a `machine_id` claim; all others are resolved as `USER` recipients.
