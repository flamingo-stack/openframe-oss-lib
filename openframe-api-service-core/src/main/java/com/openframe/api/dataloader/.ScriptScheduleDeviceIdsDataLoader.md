Batch DataLoader that resolves `machineId` lists for multiple script schedules in a single query, preventing N+1 database calls when fetching `assignedDevices` or `deviceCount` across a list of schedules.

## Key Components

| Component | Description |
|---|---|
| `@DgsDataLoader(name = "scriptScheduleDeviceIdsDataLoader")` | Registers this loader with the DGS framework under a named key used by GraphQL field resolvers |
| `BatchLoader<String, List<String>>` | Accepts a batch of `scheduleId` strings and returns an ordered list of `machineId` lists |
| `load(List<String> scheduleIds)` | Delegates to `ScriptScheduleDeviceService.getMachineIdsByScheduleIds`, maps results back in input order, and returns a completed future |
| `ScriptScheduleDeviceService` | Service responsible for the bulk DB query; injected via `@RequiredArgsConstructor` |

**Design note:** The future is resolved synchronously (`CompletableFuture.completedFuture`) rather than via `supplyAsync` to ensure the tenant context (`TenantIdProvider`) is read on the original request thread instead of a pool thread.

## Usage Example

```java
// In a DGS data fetcher, reference the loader by its registered name
@DgsData(parentType = "ScriptSchedule", field = "assignedDevices")
public CompletableFuture<List<String>> assignedDevices(
        DgsDataFetchingEnvironment env) {

    ScriptSchedule schedule = env.getSource();
    DataLoader<String, List<String>> loader =
            env.getDataLoader("scriptScheduleDeviceIdsDataLoader");

    return loader.load(schedule.getId());
}
```

Calling `loader.load(id)` from each sibling field resolver batches all `scheduleId` keys into a single `load()` invocation, replacing per-row queries with one bulk lookup.
