Implements a DGS `BatchLoader` that resolves `ScriptResponse` objects by ID in a single batched call, used by the `Execution.scriptName` GraphQL field resolver to avoid snapshotting script names onto every History row.

## Key Components

| Member | Description |
|---|---|
| `ScriptDataLoader` | `BatchLoader<String, ScriptResponse>` registered as `"scriptDataLoader"` via `@DgsDataLoader` |
| `scriptService` | Injected `ScriptService` dependency used for tenant-scoped script lookups |
| `load(List<String> scriptIds)` | Core batch method; deduplicates IDs, fetches in bulk, and maps results back to the original key order |

## Usage Example

```java
// Injected automatically by DGS into a field resolver via DataFetchingEnvironment
@DgsData(parentType = "Execution", field = "scriptName")
public CompletableFuture<String> scriptName(DgsDataFetchingEnvironment dfe) {
    DataLoader<String, ScriptResponse> loader =
        dfe.getDataLoader("scriptDataLoader");

    String scriptId = ((Execution) dfe.getSource()).getScriptId();
    return loader.load(scriptId)
                 .thenApply(script -> script != null ? script.getName() : null);
}
```

## Behavior Notes

- **Null safety** — `null` keys in the input list are passed through as `null` results, preserving positional alignment required by the `DataLoader` contract.
- **Soft-deleted scripts** — `ScriptService#getScriptsByIds` intentionally includes soft-deleted records so History entries can still resolve a script name after the script is removed.
- **Async execution** — the bulk fetch runs inside `CompletableFuture.supplyAsync`, keeping the GraphQL event loop unblocked.
