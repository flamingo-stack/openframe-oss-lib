Service layer managing SSO (Single Sign-On) provider configurations, handling CRUD operations, encryption of client secrets, domain validation, and post-processing hooks for config lifecycle events.

## Key Components

| Member | Description |
|---|---|
| `getEnabledProviders()` | Returns a list of enabled SSO providers (used by login UI components) |
| `getAvailableProviders()` | Returns all SSO providers defined in `SSOProperties` config |
| `getConfig(provider)` | Fetches full config for a provider, decrypting the client secret; returns an empty response if not found |
| `upsertConfig(provider, request)` | Creates or updates an SSO config with validation and post-processing |
| `deleteConfig(provider)` | Deletes an SSO config by provider and triggers post-delete processing |
| `toggleEnabled(provider, enabled)` | Enables or disables an SSO provider without modifying other fields |
| `validateAutoProvision(...)` | Enforces domain and tenant rules when auto-provisioning users; requires `msTenantId` for Microsoft single-tenant apps |
| `normalizeDomains(domains)` | Trims, lowercases, deduplicates, and filters blank domain entries |

## Usage Example

```java
// Retrieve enabled providers for login page rendering
List<SSOConfigStatusResponse> enabled = ssoConfigService.getEnabledProviders();

// Upsert a Microsoft SSO configuration
SSOConfigRequest request = SSOConfigRequest.builder()
        .clientId("your-client-id")
        .clientSecret("your-client-secret")
        .msTenantId("your-tenant-id")
        .autoProvisionUsers(true)
        .allowedDomains(List.of("contoso.com"))
        .build();

SSOConfigResponse response = ssoConfigService.upsertConfig("microsoft", request);

// Toggle a provider off
ssoConfigService.toggleEnabled("google", false);

// Delete a provider's config entirely
ssoConfigService.deleteConfig("github");
```

## Notes

- Client secrets are encrypted at rest via `EncryptionService` and decrypted only when returned to admin forms.
- Auto-provisioning requires at least one `allowedDomain`; Microsoft additionally requires a non-blank `msTenantId`.
- All domain inputs are normalized (trimmed, lowercased, deduplicated) before persistence or validation.
- Post-processing hooks (`SSOConfigProcessor`) are triggered on save, delete, and toggle events for extensibility.
