Unit test suite for `ScriptExecutionFilterService`, verifying filter facet construction, label resolution, and query mapping for script execution filtering in the RMM module.

## Key Components

- **`getExecutionFilters_buildsInitiatorOptions`** — Verifies the initiator facet maps user IDs to display names (full name when available, email fallback) and passes `filteredCount` correctly.
- **`getExecutionFilters_buildsStatusAndMachineOptions`** — Validates that status options are self-labeled and machine options resolve to hostnames via `MachineRepository`.
- **`getExecutionFilters_noInitiators_skipsUserLookup`** — Confirms that when the initiator facet is empty, `UserRepository` is never called.
- **`getExecutionFilters_mapsInputAndForwardsScriptIdSearch`** — Asserts that `ScriptExecutionFilterInput` fields (notably `initiatorIds` → `initiatedByIds`) are correctly mapped to `ScriptExecutionQueryFilter` and forwarded to all repository calls alongside the search term.

The service under test is wired with a real `ScriptFilterOptionMapper` (backed by mocked repositories) to exercise label resolution end-to-end.

## Usage Example

```java
// Constructing the service (mirrors setUp in the test)
ScriptExecutionFilterService service = new ScriptExecutionFilterService(
    scriptExecutionRepository,
    new ScriptFilterOptionMapper(userRepository, machineRepository),
    tenantIdProvider
);

// Fetching filters with active status and initiator constraints
ScriptExecutionFilterInput input = ScriptExecutionFilterInput.builder()
    .statuses(List.of(ExecutionStatus.SUCCESS))
    .initiatorIds(List.of("u-9"))
    .machineIds(List.of("m-1"))
    .build();

ScriptExecutionFilters filters = service.getExecutionFilters("s-1", input, "alice");

// Resolved options
filters.getInitiators(); // [{value: "u-9", label: "Alice Smith", count: N}]
filters.getStatuses();   // [{value: "SUCCESS", label: "SUCCESS", count: N}]
filters.getMachines();   // [{value: "m-1",     label: "web-01",  count: N}]
filters.getFilteredCount(); // total matching executions
```
