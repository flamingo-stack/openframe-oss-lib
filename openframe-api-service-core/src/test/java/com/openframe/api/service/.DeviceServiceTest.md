Unit tests for `DeviceService.queryAssignedDevices`, verifying that MongoDB query constraints on `machineId` are correctly applied when querying devices assigned to a `ScriptSchedule`.

## Key Components

| Component | Description |
|---|---|
| `DeviceServiceTest` | JUnit 5 test class using Mockito for dependency isolation |
| `service()` | Factory method that wires a `DeviceService` with lenient mocks |
| `capturedQueryObject()` | Helper that captures the `Query` passed to `countMachines` via `ArgumentCaptor` |
| `scopesToMachineIds()` | Asserts a non-empty ID list produces a `machineId: { $in: [...] }` clause |
| `emptySetYieldsNoResults()` | Asserts an empty list produces a `machineId: { $exists: false }` no-match clause |
| `nullSetTreatedAsEmpty()` | Asserts `null` is treated identically to an empty list |

## Usage Example

```java
// Reproducing the core assertion pattern used in this test suite:
DeviceService service = new DeviceService(
    machineRepository, tagRepository,
    tagAssignmentRepository, deviceStatusProcessor
);

// Query with specific machine IDs
service.queryAssignedDevices(
    List.of("m1", "m2"),
    null,
    CursorPaginationCriteria.builder().limit(10).build(),
    null,
    null
);

// Verify MongoDB query contains: { machineId: { $in: ["m1", "m2"] } }
ArgumentCaptor<Query> captor = ArgumentCaptor.forClass(Query.class);
verify(machineRepository).countMachines(captor.capture());
Document q = captor.getValue().getQueryObject();
List<String> in = (List<String>) ((Document) q.get("machineId")).get("$in");
assertThat(in).containsExactlyInAnyOrder("m1", "m2");
```

## Notes

- An empty or `null` `machineIds` argument intentionally short-circuits to a `$exists: false` predicate, guaranteeing zero results rather than an unbounded scan.
- Tests use `lenient()` stubs so unused mock interactions do not cause unnecessary strictness failures.
