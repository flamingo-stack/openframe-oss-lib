Unit test suite for `CommandExecutionService`, verifying batch command execution persistence and result retrieval with tenant-scoped isolation.

## Key Components

| Test Method | Coverage |
|---|---|
| `createBatch_persistsOneRunningRowPerMachine` | Validates that `createBatch` writes one `RUNNING` `CommandExecution` document per target machine under a shared `executionId`, with correct tenant, command, shell, privilege, timeout, initiator, and timestamp fields |
| `getBatchResults_readsExistingRowsOnly` | Validates that `getBatchResults` performs a per-machine tenant-scoped lookup and silently omits machines with no existing record |

**Mocked dependencies:**
- `CommandExecutionRepository` — MongoDB/data layer for `CommandExecution` documents
- `TenantIdProvider` — supplies the active tenant context (`t-1`)

## Usage Example

```java
// Simulates creating a batch execution across two machines
service.createBatch(
    EXECUTION_ID,       // shared batch ID
    "uptime",           // command string
    ScriptShell.BASH,   // shell interpreter
    List.of("m-1", "m-2"), // target machine IDs
    PrivilegeLevel.ADMIN,
    30,                 // timeout in seconds
    "alice"             // initiator
);

// Simulates polling results — only machines with a stored row are returned
List<CommandExecution> results = service.getBatchResults(
    EXECUTION_ID,
    List.of("m-1", "m-2")
);
// results contains only "m-1" if "m-2" has no record yet
```

## Notes

- All assertions use **AssertJ** fluent API; Mockito's `ArgumentCaptor` captures the full `saveAll` payload for deep field-level inspection.
- `statusChangedAt` is asserted equal to `dispatchedAt` on creation, confirming no premature status drift.
- See source: [`CommandExecutionServiceTest.java`](https://github.com/flamingo-stack/openframe-oss-lib/blob/main/src/test/java/com/openframe/api/service/rmm/CommandExecutionServiceTest.java)
