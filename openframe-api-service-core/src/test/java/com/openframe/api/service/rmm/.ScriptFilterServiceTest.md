Unit test suite for `ScriptFilterService`, verifying filter facet construction, author label resolution, and API-to-data-layer query mapping.

## Key Components

| Component | Role |
|---|---|
| `getScriptFilters_buildsAllFacets` | Asserts shells/platforms are self-labeled, authors resolve to full name or email fallback, and `filteredCount` passes through |
| `getScriptFilters_noAuthors_skipsUserLookup` | Confirms empty author facets short-circuit `UserRepository` calls |
| `getScriptFilters_mapsInputToQueryFilter` | Captures the `ScriptQueryFilter` passed to every repository method and validates field mapping, notably `authorIds → createdByIds` |
| `ScriptFilterOptionMapper` | Instantiated with real implementation over mocked repos to exercise label resolution end-to-end |
| `user()` helper | Builds `User` stubs with configurable first/last name and email for author label scenarios |

## Usage Example

```java
// Typical pattern exercised by the tests:
// 1. Build an API-layer input with optional filter fields
ScriptFilterInput input = ScriptFilterInput.builder()
        .shells(List.of(ScriptShell.BASH))
        .statuses(List.of(ScriptStatus.ACTIVE))
        .supportedPlatforms(List.of(ScriptPlatform.LINUX))
        .tagIds(List.of("tag-1"))
        .authorIds(List.of("user-7"))   // mapped → createdByIds in ScriptQueryFilter
        .build();

// 2. Service builds all three facets + filteredCount
ScriptFilters result = service.getScriptFilters(input);

// 3. Author labels: full name when available, email as fallback
result.getAuthors(); // [{ value="u-1", label="Neo Anderson" }, { value="u-2", label="trinity@example.com" }]
```

## Key Behaviors Verified

- **Self-labeling** — shell and platform filter options use their enum value as both `value` and `label`
- **Author resolution** — `UserRepository.findAllById` is called only when the author facet is non-empty
- **Field mapping** — `ScriptFilterInput.authorIds` is translated to `ScriptQueryFilter.createdByIds` before reaching the data layer; the same mapped filter object is reused across all four repository calls
