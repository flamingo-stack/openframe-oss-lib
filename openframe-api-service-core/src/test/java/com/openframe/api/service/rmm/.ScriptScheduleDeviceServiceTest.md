Unit tests for `ScriptScheduleDeviceService`, covering device assignment lifecycle operations including set, diff, clear, idempotency, and lookup behaviors.

## Key Components

| Test Method | What It Verifies |
|---|---|
| `setDevices_whenNoAssignment_insertsAllPairs` | Inserts deduplicated machine IDs with `createdBy` stamped when no prior assignments exist |
| `setDevices_diffOnly` | Only writes added/removed pairs; unchanged rows are untouched (audit-preserving) |
| `setDevices_emptyList_clears` | Deletes all current assignments; no inserts when requested list is empty |
| `setDevices_noOpWhenUnchanged` | No repository writes when requested set matches current set (fully idempotent) |
| `setDevices_whenScheduleMissing_throws` | Raises `NotFoundException` and skips all writes when schedule does not exist |
| `setDevices_whenScheduleDeleted_throws` | Raises `NotFoundException` and skips all writes for soft-deleted schedules |
| `getMachineIdsByScheduleIds_groupsRows` | Correctly groups flat assignment rows into a per-schedule `Map<String, List<String>>` |
| `setDevices_doesNotWriteScheduleDoc` | Schedule document is never written back; device count is derived at read time |
| `getMachineIdsByScheduleIds_empty_noLookup` | Short-circuits on empty input without hitting the repository |

## Usage Example

```java
// Verifying diff-only behavior in integration context:
// Given: schedule "sch-1" currently has m-1 and m-2 assigned
// When:  setDevices called with [m-1, m-3]
// Then:  m-2 is deleted, m-3 is inserted, m-1 is untouched

service.setDevices("sch-1", List.of("m-1", "m-3"), "user-2");

// Expected repository interactions:
verify(assignedRepository).deleteByTenantIdAndScriptScheduleIdAndMachineIdIn(
    eq("tenant-1"), eq("sch-1"), containsExactly("m-2"));
verify(assignedRepository).saveAll(containsNewMachine("m-3"));
```
