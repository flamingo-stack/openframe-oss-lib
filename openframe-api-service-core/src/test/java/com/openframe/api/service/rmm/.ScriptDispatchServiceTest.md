Unit test suite for `ScriptDispatchService`, verifying script dispatch lifecycle including execution history persistence, NATS message publishing, argument/timeout/env-var resolution, and device validation for both single and batch dispatch operations.

## Key Components

| Test Method | What It Verifies |
|---|---|
| `runScript_persistsExecutionRowBeforeNatsPublish` | Execution history row is created **before** NATS publish (watchdog safety ordering) |
| `runScript_resolvesScriptPublishesAndReturnsExecutionId` | `executionId` is consistent across `DispatchResponse` and the wire `ScriptMessage` |
| `runScript_usesScriptDefaultsWhenNoOverride` | Falls back to stored `args` and `timeoutSeconds` when no input overrides |
| `runScript_tokenizesCombinedArgs` | Tokenizes `"-Name value"` combined args into separate `argv` tokens |
| `runScript_overridesArgsAndTimeout` | Input `args` and `timeoutSeconds` win over script defaults |
| `runScript_persistsEffectiveTimeoutOnRow` | Effective timeout (override or default) is identical on the history row and wire payload |
| `runScript_mergesAndOverridesEnvVars` | Input env vars override same-named stored vars; new vars are appended |
| `runScript_forwardsPrivilegeLevelVerbatim` | `USER` vs `ADMIN` privilege level is passed through from input |
| `runScript_generatesDistinctExecutionIds` | Each invocation mints a unique `executionId` |
| `runScript_rejectsUnknownMachine` | `DeviceNotFoundException` thrown before any persistence or publish side-effects |
| `batchRunScript_fansOutWithSharedExecutionId` | Single `executionId` is minted, N history rows persisted, N NATS messages fanned out |

## Usage Example

```java
// Typical test interaction pattern (mirrors setUp() happy path)
RunScriptInput input = new RunScriptInput();
input.setMachineId("machine-abc");
input.setScriptId("script-1");
input.setPrivilegeLevel(PrivilegeLevel.ADMIN);
input.setTimeoutSeconds(90);          // overrides stored default
input.setArgs(List.of("-x"));         // overrides stored default args

DispatchResponse response = scriptDispatchService.runScript(input, "user-mr-anderson");

// executionId ties the DispatchResponse, History row, and NATS wire payload together
assertThat(response.getExecutionId()).isNotBlank();
```

## Notes

- **Ordering guarantee**: `scriptExecutionService.create(...)` is verified via `InOrder` to run strictly before `scriptNatsPublisher.publishScript(...)`. If the publish fails, the history row survives for watchdog resolution.
- **Batch dispatch** uses a shared `executionId` across all target machines, with per-machine `machineId` in each `ScriptMessage`.
