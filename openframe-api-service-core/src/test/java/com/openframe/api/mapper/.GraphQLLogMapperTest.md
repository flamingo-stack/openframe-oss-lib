Unit tests for `GraphQLLogMapper`, covering `LogSortInput` conversion, timestamp-range filter mapping, and compound edge-cursor encoding.

## Key Components

| Test | Description |
|---|---|
| `toSortInputMapsTimestamp` | Verifies `TIMESTAMP` enum maps to the `eventTimestamp` column and preserves sort direction |
| `toSortInputNull` | Confirms `null` orderBy returns `null`, deferring to the service's default `TIMESTAMP DESC` |
| `toSortInputNullField` | Confirms a `LogSortInput` with no field also returns `null` |
| `toLogFilterCriteriaMapsTimestampRange` | Asserts `timestampFrom`/`timestampTo` values are carried through to `LogFilterCriteria` |
| `toLogConnectionCompoundCursor` | Validates cursors are encoded as `<millis>_<toolEventId>` via `CursorCodec` |

## Usage Example

```java
GraphQLLogMapper mapper = new GraphQLLogMapper();

// Sort input mapping
SortInput sort = mapper.toSortInput(
    LogSortInput.builder()
        .field(LogSortField.TIMESTAMP)
        .direction(SortDirection.DESC)
        .build()
);
// sort.getField() == "eventTimestamp"

// Filter criteria mapping
LogFilterCriteria criteria = mapper.toLogFilterCriteria(
    LogFilterInput.builder()
        .timestampFrom(Instant.ofEpochMilli(1000))
        .timestampTo(Instant.ofEpochMilli(2000))
        .build()
);

// Cursor-encoded connection
GenericConnection<GenericEdge<LogEvent>> connection =
    mapper.toLogConnection(queryResult);
// cursor decodes to: "4321_evt-7"
```

## Notes

- Tests use **AssertJ** fluent assertions via `Assertions.assertThat`.
- Cursor format `<millis>_<toolEventId>` supports stable pagination when multiple events share the same timestamp.
- `null` sort inputs are treated as a no-op — default ordering is enforced at the service layer, not the mapper.
