Unit tests for `ScriptDataLoader`, verifying that GraphQL DataLoader batch-loading behavior correctly maps script IDs to `ScriptResponse` objects while preserving positional order and handling edge cases.

## Key Components

| Component | Description |
|---|---|
| `load_mapsByIdInOrder` | Verifies that batch results are aligned to the input key order |
| `load_unknownId_resolvesToNull` | Ensures unrecognized IDs resolve to `null` at their position |
| `load_nullKey_resolvesToNull` | Confirms null keys are tolerated without being forwarded to the service |
| `load_allNullKeys_noServiceCall` | Validates short-circuit behavior — no service call when all keys are null |

## Usage Example

```java
// Typical batch load: two IDs, results returned in the same order
when(scriptService.getScriptsByIds(anyCollection())).thenReturn(List.of(
        ScriptResponse.builder().id("s-1").name("alpha").build(),
        ScriptResponse.builder().id("s-2").name("beta").build()));

List<ScriptResponse> result = loader.load(List.of("s-1", "s-2"))
        .toCompletableFuture()
        .get();

assertThat(result)
        .extracting(ScriptResponse::getName)
        .containsExactly("alpha", "beta");
```

## Covered Contracts

- **Positional alignment** — result index `i` always corresponds to key index `i`
- **Deduplication** — a single `getScriptsByIds` call is made per batch regardless of duplicates
- **Unknown key handling** — missing IDs yield `null` rather than throwing
- **Null key short-circuit** — all-null batches skip the service entirely, protecting against unnecessary downstream calls
