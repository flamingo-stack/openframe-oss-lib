Unit tests for `CommandDataFetcher`, verifying that each GraphQL mutation resolver correctly delegates to `CommandDispatchService` and returns its response unchanged.

## Key Components

| Component | Role |
|---|---|
| `CommandDataFetcher` | GraphQL mutation resolver under test |
| `CommandDispatchService` | Mocked dependency; handles actual command dispatch logic |
| `RunCommandInput` / `BatchRunCommandInput` / `CancelExecutionInput` | Mutation input DTOs |
| `DispatchResponse` | Shared return type carrying an `executionId` |

## Test Cases

- **`runCommand`** — Confirms the resolver forwards the input directly to `CommandDispatchService.runCommand()` and returns the same `DispatchResponse` instance without modification.

- **`batchRunCommand`** — Verifies that the resolver extracts the authenticated user's `sub` claim from the JWT in `SecurityContextHolder` and passes it as `initiatedBy` to `CommandDispatchService.batchRunCommand()`. The security context is always cleared in a `finally` block to avoid test pollution.

- **`cancelExecution`** — Confirms the resolver forwards the input to `CommandDispatchService.cancelExecution()` and returns the service response as-is.

## Usage Example

```java
// Illustrates the JWT extraction pattern tested in batchRunCommand
Jwt jwt = Jwt.withTokenValue("t")
        .header("alg", "none")
        .subject("user-42")
        .build();
SecurityContextHolder.getContext().setAuthentication(
        new UsernamePasswordAuthenticationToken(jwt, null));

// The resolver reads jwt.getSubject() → "user-42" and stamps it as initiatedBy
dataFetcher.batchRunCommand(new BatchRunCommandInput());
```

## Notes

- The resolver is intentionally a **thin pass-through**; no business logic is tested here — that belongs in `CommandDispatchService` tests.
- Uses `isSameAs` (reference equality) rather than `isEqualTo` to assert that no new object is created in the pass-through.
- `MockitoExtension` drives injection; no Spring context is loaded, keeping tests fast.
