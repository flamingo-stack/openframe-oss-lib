Canonical type definitions for the doc-source system, providing a unified tree structure, content payload, and data-access contract for all doc-viewer consumers (knowledge base, data room, and future sources).

## Key Components

| Export | Kind | Description |
|---|---|---|
| `DocNode` | `interface` | Single node in a doc-source tree; discriminates folders vs. files and supports rich content types via `documentType` |
| `DocumentType` | `type` | Non-nullable alias for `DocNode['documentType']`; use as renderer-map key |
| `DocContent` | `interface` | Content payload from a DAL's `getContent` call; covers both markdown and rich-content (PDF, Google Sheet, Figma) fields |
| `DocSourceDal<Client>` | `interface` | Generic DAL contract each doc source must satisfy; `Client` defaults to `unknown` to avoid pulling in `@supabase/supabase-js` |
| `DocSourceId` | `type` | Registry discriminator union (`'openframe-docs' \| 'data-room-docs'`); type-narrowing handle only — no runtime registry |
| `ResolveLinkResult` | `interface` | Discriminator-style result from the resolve-link endpoint; drives navigate / expand-folder / broken-link behaviour |
| `DocRenderHandlers` | `interface` | Callbacks and context passed into a consumer's `renderContent`; includes optional async link resolver |

## Usage Example

```typescript
import type {
  DocNode,
  DocContent,
  DocSourceDal,
  DocSourceId,
  DocRenderHandlers,
  DocumentType,
} from '@openframe-oss-lib/doc-source'

// Implement a DAL for a new doc source
class MyDocsDal implements DocSourceDal<SupabaseClient> {
  async getStructure(client: SupabaseClient): Promise<DocNode[]> {
    // Return the full nav tree
    return [
      {
        id: 'intro',
        name: 'Introduction',
        slug: 'introduction',
        path: 'docs/introduction',
        type: 'file',
        documentType: 'markdown',
      },
    ]
  }

  async getContent(
    client: SupabaseClient,
    path: string,
  ): Promise<DocContent | null> {
    return {
      content: '# Hello world',
      sections: [{ id: 'hello-world', title: 'Hello world', level: 1 }],
      path,
      documentType: 'markdown',
    }
  }
}

// Build a renderer map keyed by DocumentType
const renderers: Record<DocumentType, React.FC<{ content: DocContent }>> = {
  markdown: MarkdownRenderer,
  pdf: PdfRenderer,
  google_sheet: SheetRenderer,
  figma: FigmaRenderer,
  file: FileRenderer,
}

// Wire render handlers from DocViewer into a page shell
const handlers: DocRenderHandlers = {
  currentPath: 'docs/introduction',
  sourceId: 'openframe-docs' satisfies DocSourceId,
  onInternalLinkClick: (path, opts) => router.push(path),
  onResolveLink: async (href, currentPath) => {
    const res = await fetch('/api/docs/resolve-link', {
      method: 'POST',
      body: JSON.stringify({ href, currentPath, sourceId: 'openframe-docs' }),
    })
    return res.json()
  },
}
```

## Notes

- `documentType` is optional on both `DocNode` and `DocContent`; `undefined` is treated as `'markdown'` by all consumers.
- `DocSourceDal<Client>` is intentionally generic — hub callers tighten `Client` to `SupabaseClient`; the lib itself never imports Supabase.
- Adding a new source requires both adding its id to `DocSourceId` **and** registering it in the hub's `DOC_SOURCES` registry.
