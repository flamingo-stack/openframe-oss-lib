Centralized barrel export file for the `@flamingo/ui-kit` package, re-exporting all platform, application, and domain types from a single entry point.

## Key Components

| Export Group | Source Modules |
|---|---|
| **Core Platform** | `announcement`, `doc-source`, `categories`, `category`, `media`, `platform` |
| **Database & API** | `supabase` |
| **Authentication** | `auth` |
| **Content** | `blog`, `entity-author`, `case-study`, `customer-interview`, `luma`, `product-release`, `delivery`, `vendor`, `video-processing` |
| **User & Profile** | `employee`, `profile`, `team`, `user` |
| **Communication** | `slack`, `waitlist` |
| **Business Logic** | `faq`, `content-ref`, `report`, `stack` |
| **Navigation** | `navigation` |
| **Shell / OS / Tools** | `shell.types`, `os.types`, `tool.types` |
| **Marketing & Access** | `marketing`, `access-code-cohorts`, `icons`, `permissions`, `tmcg` |

> **Note:** `categories` and `platform` use named-only exports (`export type { ... }`) to avoid conflicts with overlapping identifiers from sibling modules.

## Usage Example

```typescript
// Import any type directly from the package root — no deep imports needed
import type {
  PlatformSettings,
  PlatformName,
  Category,
  DocNode,
  DocContent,
} from '@flamingo/ui-kit'

const config: PlatformSettings = {
  name: 'openframe' as PlatformName,
  // ...
}
```

## Notes

- **Single import surface:** consumers never need to reach into sub-paths like `@flamingo/ui-kit/platform`.
- **`doc-source` types** (`DocNode`, `DocContent`, `DocSourceDal`, `DocRenderHandlers`) are shared across knowledge-base, data-room, and future doc-source viewers.
- **Selective re-exports** on `categories` and `platform` prevent name collisions while still exposing the most-used public types.
