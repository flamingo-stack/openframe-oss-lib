Shared TypeScript interfaces defining the author data shapes used across content surfaces — detail pages, bylines, metadata grids, and author profile pages.

## Key Components

### `EntityAuthor`
The universal author shape attached to content entities (product releases, onboarding guides, etc.) by the hub's `hydrateAuthor`. Powers metadata-grid author cells, bylines, and `/authors/[slug]` links.

| Field | Notes |
|---|---|
| `full_name` | Display name, nullable |
| `avatar_url` | Profile image, nullable |
| `about` | Bio paragraph fed to `<ArticleAuthorByline bio>` |
| `slug` | Present only when `is_real` profile gate passes |
| `email` | Server/admin payloads only — stripped by public DALs |

### `AuthorSocialLink`
A single curated social link from the `profile_social_links` junction, ordered by `display_order`. The `platform` key (e.g. `'linkedin'`, `'x'`) feeds directly into `SocialIconRow`.

### `AuthorProfile`
Public author-page view model rendered by `<AuthorDetailView>`. Uses camelCase fields (contrast with `EntityAuthor`'s snake_case). The hub's `PublicAuthor` extends this with server-side extras like `updatedAt`.

## Usage Example

```typescript
import type { EntityAuthor, AuthorProfile, AuthorSocialLink } from './entity-author'

// Attach to a content entity (hub hydrateAuthor output)
const author: EntityAuthor = {
  id: 'usr_123',
  full_name: 'Jane Smith',
  avatar_url: 'https://cdn.example.com/avatars/jane.webp',
  about: 'Infrastructure engineer focused on MSP automation.',
  slug: 'jane-smith',
}

// Construct a public author-page view model
const profile: AuthorProfile = {
  id: 'usr_123',
  slug: 'jane-smith',
  fullName: 'Jane Smith',
  avatarUrl: author.avatar_url,
  about: author.about ?? null,
  jobTitle: 'Infrastructure Engineer',
  company: 'Flamingo',
  knowsAbout: ['MSP', 'AI Automation'],
  socialLinks: [
    { platform: 'linkedin', url: 'https://linkedin.com/in/janesmith', username: 'janesmith' },
  ],
}
```

> **Note:** `EntityAuthor` uses snake_case (database-aligned); `AuthorProfile` uses camelCase (view-model aligned). Keep this distinction in mind when mapping between DAL output and UI components.
