Defines the canonical `ContentRef` interface — the unified shape for link/embed metadata stored in JSONB columns across investor updates, performance baselines, and other entities that surface "related content" rails. This is the single package-wide definition; all other paths (including chat components) re-export from here.

## Key Components

- **`ContentRef`** — Core interface describing a linked or embedded content item, including identity fields (`type`, `id`, `slug`, `url`), display metadata (`title`, `summary`, `image_url`, `image_bg_color`), visibility scope (`'public' | 'internal'`), and optional `targetPlatform`.
- **`ContentRefWithReason`** — Extension of `ContentRef` that appends a `reason: string` field, representing the placement rationale returned by the suggestion service (`/api/related-content`). Used for data transport only; never rendered by the rail.

## Usage Example

```typescript
import type { ContentRef, ContentRefWithReason } from '@openframe-oss-lib/content-ref';

// Persisting a content reference in a JSONB column
const ref: ContentRef = {
  type: 'article',
  id: 'abc-123',
  slug: 'q1-performance-review',
  url: 'https://example.com/q1-performance-review',
  title: 'Q1 Performance Review',
  summary: 'A breakdown of Q1 metrics.',
  visibility: 'internal',
  display_order: 1,
};

// Consuming a suggestion-service response
const suggested: ContentRefWithReason = {
  ...ref,
  reason: 'top_performer',
};
```

## Notes

- `ContentRef` is safe for server-side use; it carries no rendering dependencies.
- `reason` on `ContentRefWithReason` is typed as `string` (not a narrow union) intentionally — the narrow vocabulary is hub-server only.
