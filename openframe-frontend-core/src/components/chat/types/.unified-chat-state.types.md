Unified contract type definitions for the `useChat` hook's transport-agnostic return shape, shared by both the SSE (Guide mode) and NATS (Mingo mode) transport adapters.

### Dialog-list host contract (shared by both adapters)

| Export | Kind | Description |
|---|---|---|
| `FetchDialogsParams` | interface | `{ cursor?, limit?, search? }` — page-fetch params passed to a host `fetchDialogs`. `search` is present ONLY when the adapter runs a server-side list search |
| `FetchDialogsResult` | interface | `{ dialogs: DialogItem[], nextCursor: string \| null }` — `null` terminates infinite scroll |
| `ChatDialogCapabilities` | interface | What a transport (or an injecting host) can honour: `canRename`, `canArchive`, `fetchArchivedDialogs`, `unarchiveDialog`, `searchQuery`, `onSearchChange`, `onCopyLink`. ONE shape for both the adapter-owned (`UnifiedChatState.dialogCapabilities`) and host-injected (`EmbeddableChatProps.mingoDialogCapabilities`) paths |

`UnifiedChatState` additions: **`dialogsManaged?: boolean`** — true when the active adapter owns a server-side dialog list (NATS managed mode, or the SSE/Guide adapter with `ChatRuntime.endpoints.chatConversationsUrl`); `EmbeddableChat` gates its history UI on this rather than on the mode, so Guide mode gets the same "Current Chats" rail as Mingo. **`dialogCapabilities?: ChatDialogCapabilities`** — read in preference to the legacy per-mode derivations, so the ⋯ menu never advertises an unwired action.

## Key Components

| Export | Kind | Description |
|---|---|---|
| `DialogTokenUsage` | Interface | Per-dialog token usage snapshot from the Mingo backend's GraphQL `dialogs` endpoint |
| `ChatConnectionState` | Type | Transport-level connection status: `'connected' \| 'connecting' \| 'disconnected'` |
| `StreamingPhase` | Type | Granular streaming indicator: `'idle' \| 'thinking' \| 'streaming'` |
| `UnifiedUsageBreakdown` | Interface | SSE-only sub-call token costs for the Haiku rewriter/classifier/summarizer pipeline |
| `UnifiedChatMessage` | Interface | Transport-agnostic message shape; the Guide-only `sources` field is optional. `streamSeq` is not render input — it is the per-message coverage signal `mergeHistoryWithRealtime` decides with, and omitting it makes a mid-stream history refetch drop live bubbles |
| `UnifiedSendMessageOptions` | Interface | Options accepted by `sendMessage` honoured by both transports |
| `UnifiedChatState` | Interface | **Primary contract** — the full return shape both transport hooks must satisfy |

## Usage Example

```typescript
import type {
  UnifiedChatState,
  UnifiedChatMessage,
  UnifiedSendMessageOptions,
  StreamingPhase,
} from './unified-chat-state.types'

// Consuming the contract without branching on transport mode
function MyChatShell({ chat }: { chat: UnifiedChatState }) {
  const { messages, isLoading, streamingPhase, sendMessage, stopMessage } = chat

  const handleSend = async (text: string, opts?: UnifiedSendMessageOptions) => {
    await sendMessage(text, {
      hidden: false,
      attachments: opts?.attachments,
      contextItems: opts?.contextItems,
    })
  }

  // SSE-only fields are null in Mingo mode — guard before rendering
  const modelLabel = chat.currentModelLabel ?? 'AI'
  const phase: StreamingPhase = streamingPhase

  return { messages, isLoading, phase, modelLabel, handleSend, stopMessage }
}
```

## Transport Compatibility

| Field | SSE (Guide) | NATS (Mingo) |
|---|---|---|
| `sources` | ✅ Populated | `undefined` |
| `currentProvider` / `currentModelLabel` | ✅ Populated | `null` |
| `currentUsageBreakdown` | ✅ After trailing frame | `null` |
| `DialogTokenUsage` (separate) | `null` | ✅ From GraphQL |
| `discussRef` | ✅ Active | ✅ Active (prompt carries the reference as text) |
| `displayRef` | ✅ Active | **omitted** (optional — consumers fall back to "Ask Mingo") |
