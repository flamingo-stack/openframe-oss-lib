Shared building blocks for the **items level** of the entity-context picker (Figma 31:29102). Provides row chrome, a scrollable list (drawing its own loading rows) with scroll-driven pagination, and an error boundary — consumed by `ChatContextPickerConfig.renderItems` in the host application.

## Key Components

| Export | Type | Description |
|---|---|---|
| `CONTEXT_ROW_CLASS` | `string` | Tailwind classes for a standard menu row |
| `CONTEXT_ICON_CLASS` | `string` | Responsive 16px→24px icon wrapper |
| `CONTEXT_LABEL_CLASS` | `string` | Truncating h4 label slot |
| `CONTEXT_BACK_CLASS` | `string` | Back-navigation row classes |
| `CONTEXT_STATE_CLASS` | `string` | Empty/error state prose classes |
| `ContextMenuRow` | Component | Icon + label + optional trailing slot button primitive; forwards `data-*` markers (`data-loading-item` on item rows); `loading` (or a loading scope, for a row with no label yet) draws the same row inert with its label as a bar |
| `ContextItemsList` | Component | Scrollable `role="listbox"` with selection state, limit enforcement, and scroll-driven pagination |
| `ContextErrorBoundary` | Class Component | Catches failed host fetches; auto-resets on `resetKey` change |

## Usage Example

```typescript
import {
  ContextItemsList,
  ContextErrorBoundary,
} from './context-items-list'
import { LoadingSuspense } from '../loading/loading-fallback'

function MyPickerItems({ query }: { query: string }) {
  const { items, hasMore, fetchNextPage, isFetchingNextPage } = useMyItems(query)

  return (
    <ContextErrorBoundary
      resetKey={`device:${query}`}
      fallback={(retry) => (
        <button onClick={retry}>Failed to load — retry</button>
      )}
    >
      {/* The fallback is the list itself in a loading scope: one page of its own item rows. */}
      <LoadingSuspense label="Loading items">
        <ContextItemsList
          items={items}
          selectedKeys={selectedKeys}
          onToggle={handleToggle}
          atLimit={selectedKeys.size >= 5}
          hasMore={hasMore}
          onLoadMore={fetchNextPage}
          loadingMore={isFetchingNextPage}
          emptyLabel="No devices found"
        />
      </LoadingSuspense>
    </ContextErrorBoundary>
  )
}
```

**Notes:**
- `ContextErrorBoundary.resetKey` should encode both the entity type and current search query so errors clear automatically on navigation or new searches. Pair the `retry` callback with your data library's cache-reset (e.g. react-query's `queryClient.resetQueries`) to ensure the fetch actually re-runs.
- Every item row carries `data-loading-item`, loaded and loading alike; a loading list (a loading scope) draws one page (`pageSize`, default 10) of rows, and `loadingMore` the next page's.
- The list caps height at `min(340px, 45vh)` to stay inside bottom-anchored popovers on short viewports.
