Wire client for the SSE/Guide conversation list — the ONE place the `ChatRuntime.endpoints.chatConversationsUrl` contract is spelled out.

## Key Components

### `createChatConversationsApi(baseUrl)` → `ChatConversationsApi`
- `fetchDialogs({ status, cursor, limit, search })` — `GET <base>?status=active|archived&limit=&cursor=&search=` (empty params omitted); unwraps the route-base `{ data }` envelope; maps rows to `DialogItem` (ISO `timestamp` → `Date`, empty title → `'Untitled chat'`)
- `renameDialog(id, title)` — `PATCH <base>/<id>` body `{ title }`
- `archiveDialog(id)` — `PATCH <base>/<id>` body `{ archived: true }`
- `unarchiveDialog(id)` — `PATCH <base>/<id>` body `{ archived: false }`

All calls go through `embedAuthedFetch` with its DEFAULT credentials mode: the hub identifies anonymous visitors with an httpOnly cookie and `same-origin` is what carries it — never override `credentials`. Failures throw the server's own error copy (`readServerErrorMessage`) or a status fallback.
