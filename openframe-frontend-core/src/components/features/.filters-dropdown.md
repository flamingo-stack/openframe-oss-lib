Accessible, animated filter dropdown component with support for checkbox, radio, and multi-section filter configurations.

## Key Components

### Interfaces
- **`FilterOption`** — Defines individual filter items with `id`, `label`, `value`, optional `count`, and `type` (`'option' | 'separator'`)
- **`FilterSection`** — Groups related filter options with a `type` (`"checkbox" | "radio" | "select"`), optional `allowSelectAll`, and `defaultSelected`
- **`FiltersDropdownProps`** — Full component props including custom trigger, section definitions, callbacks, placement, and `currentFilters` for controlled state

### Internal Components
- **`FilterCheckbox`** — Custom styled checkbox with accent fill and checkmark icon when selected

### Main Component: `FiltersDropdown`
Manages open/close animation (mount/unmount split via `shouldRender`/`isVisible`), viewport-aware placement, mobile responsiveness, outside-click and Escape-key dismissal, per-section selection state, and filter application/reset.

## Usage Example

```typescript
const sections: FilterSection[] = [
  {
    id: "status",
    title: "Status",
    type: "checkbox",
    allowSelectAll: true,
    options: [
      { id: "open", label: "Open", value: "open", count: 12 },
      { id: "closed", label: "Closed", value: "closed", count: 5 },
    ],
  },
]

const [appliedFilters, setAppliedFilters] = useState<Record<string, string[]>>({})

<FiltersDropdown
  sections={sections}
  triggerLabel="STATUS"
  placement="bottom-start"
  currentFilters={appliedFilters}
  onApply={(filters) => setAppliedFilters(filters)}
  onReset={() => setAppliedFilters({})}
/>
```

## Notes

- **Animation**: Uses a double `requestAnimationFrame` pattern to ensure CSS transitions fire correctly on mount; `shouldRender`/`isVisible` are intentionally separate to allow smooth enter/exit without `@keyframes`.
- **Placement auto-correction**: Dynamically overrides the `placement` prop if the dropdown would overflow the viewport.
- **`currentFilters` sync**: Serialized to a JSON string for stable `useEffect` dependency comparison, avoiding infinite re-render loops.
