The catalog's class constants and its sections' loading skeleton, read by `<OnboardingGuidesCatalogView>` so the loading state is the view's size.

## Key Components

- **`CATALOG_*` classes** — the catalog's layout, shared by the view and its skeleton.
- **`ONBOARDING_CATALOG_CARD_FOLD`** — the catalog cards one screen shows under the search and the section pills.
- **`OnboardingCatalogSectionsSkeleton`** — the sections while the guides are read: ONE section of `ONBOARDING_CATALOG_CARD_FOLD` `<OnboardingGuideCardSkeleton size="catalog" />` cards (the section count is the data's, so loaded sections are `data-loading-item`).

## Usage

There is no whole-view skeleton. The view is its own loading state: on its first read (or inside a host's `LoadingScope`) it renders itself in a loading scope, where the search bar is real, the section pills draw their own skeleton (`FilterPillRow`'s `loading`) and the sections switch to `OnboardingCatalogSectionsSkeleton` themselves (`useLoadingScope() || loading`).
