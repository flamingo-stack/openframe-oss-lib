Configures the dual tsup build pipeline for `openframe-oss-lib`, splitting outputs into server-safe and client-side bundles to correctly handle Next.js `"use client"` directive requirements.

## Key Components

### Server/Universal Build
Compiles pure types, configs, utilities, and server-safe modules with `treeshake: true` and **no banner**. Key entries include:

| Entry | Purpose |
|---|---|
| `types/*` | Shared TypeScript interfaces |
| `utils/humanity-signals` | Server-side human verification signals |
| `utils/video-bite-id` | Isomorphic bite ID utilities |
| `schemas/contact-schema` | Zod validation (used server + client) |
| `components/features/mux-origins` | Mux CDN string constants |
| `components/features/video-bites-shared` | Server-safe video-bite adapters |
| `components/faq/json-ld` | FAQ JSON-LD builder for Server Components |
| `platform-domains` | Edge-safe domain/host utilities |

### Client Build
Compiles all React components, hooks, and browser-API-dependent modules. Injects `"use client";` as a banner on every output file. Treeshaking is intentionally **disabled** (banner incompatible with rollup treeshake). Key entries include component barrels (`ui`, `chat`, `tickets`, `docs`, `embeds`) and Next.js embed shims built as individual entries for selective deep-importing.

### Shared Options (Both Builds)
- `format: ['esm', 'cjs']` — dual module output
- `dts: false` — declarations generated separately by `tsc` via `tsconfig.declarations.json`
- `sourcemap: true`
- `external: ['react', 'react-dom', 'next', '@tanstack/react-query']`

## Usage Example

```bash
# Build is invoked from package.json scripts
# dist/ is cleaned before tsup runs (no clean: true needed)
tsup --config tsup.config.ts
```

```typescript
// Server Component — safe deep import, no "use client" boundary crossed
import { hostOf } from 'openframe-oss-lib/platform-domains'
import { buildFaqJsonLd } from 'openframe-oss-lib/components/faq/json-ld'

// Client Component — full barrel, receives injected "use client" banner
import { ContactForm } from 'openframe-oss-lib/components/contact'

// Selective shim import without pulling the full barrel
import { NextImage } from 'openframe-oss-lib/embed-shims/next-image'
```

> **Why two builds?** Bundling client components (which call `createContext()`) into a single barrel and importing it from server code causes `"createContext is not a function"` errors in Next.js. The split ensures server-safe modules never carry the `"use client"` marker.
