A multi-tenant-aware extension of Spring Data's `MongoTemplate` that automatically injects a `tenantId` filter into every MongoDB query for documents implementing the `TenantScoped` marker interface, preventing cross-tenant data leakage without requiring callers to manually apply tenant criteria.

## Key Components

| Member | Description |
|---|---|
| `TenantAwareMongoTemplate(...)` | Constructor accepting `MongoDatabaseFactory`, `MongoConverter`, and a `TenantIdProvider` |
| `tenantId()` | Returns the current pod's tenant ID from the `TenantIdProvider`; useful in composite keys and aggregation stages |
| `tenantCriteria()` | Returns a `Criteria` object pre-scoped to the current tenant for use in aggregation pipelines |
| `scope(Query, Class<?>)` | Core guard method — appends `tenantId` criteria to any query against a `TenantScoped` entity if not already present |
| `query(Class<T>)` | Overrides the fluent query entry point, wrapping the returned `ExecutableFind` in a JDK dynamic proxy (`TenantScopedFindHandler`) to intercept Spring Data 4.x derived queries |
| `TenantScopedFindHandler<T>` | `InvocationHandler` that intercepts `matching(Query)` calls on the fluent API to inject `tenantId` before execution |
| Overridden CRUD methods | `find`, `findOne`, `count`, `exists`, `stream`, `updateFirst`, `updateMulti`, `upsert`, `remove`, `findAndModify`, `findAndRemove` — all delegate to `scope()` before calling `super` |

> **Note:** `aggregate()` is intentionally **not** overridden. Callers must manually add a `tenantId` `$match` stage in aggregation pipelines.

## Usage Example

```java
// Spring Bean configuration
@Bean
public TenantAwareMongoTemplate mongoTemplate(
        MongoDatabaseFactory factory,
        MongoConverter converter,
        TenantIdProvider tenantIdProvider) {
    return new TenantAwareMongoTemplate(factory, converter, tenantIdProvider);
}

// Domain document — must implement TenantScoped to receive auto-filtering
@Document("devices")
public class Device implements TenantScoped {
    private String tenantId;
    private String name;
    // ...
}

// Queries are automatically scoped — no manual tenantId filter needed
List<Device> devices = mongoTemplate.find(new Query(), Device.class);

// For aggregation pipelines, inject tenantId manually
Aggregation agg = Aggregation.newAggregation(
    Aggregation.match(mongoTemplate.tenantCriteria()),
    Aggregation.group("status").count().as("total")
);
```
