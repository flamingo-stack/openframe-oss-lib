Spring Data MongoDB repository for tenant-scoped feature flag overrides. Provides a single-query method to retrieve the current tenant's `FeFeatureFlags` document, leveraging automatic tenant context injection via the `TenantScoped` aspect.

## Key Components

| Component | Description |
|---|---|
| `FeFeatureFlagsRepository` | `@Repository` interface extending `MongoRepository<FeFeatureFlags, String>` |
| `findFirstBy()` | Returns `Optional<FeFeatureFlags>` for the active tenant's overrides document |

## How Tenant Scoping Works

Because `FeFeatureFlags` is marked as `TenantScoped`, the tenant aspect automatically appends a `tenantId` filter to every query. This means `findFirstBy()` — despite having no explicit predicate — resolves to exactly the one document belonging to the currently running pod's tenant, with no manual tenant filtering required at the call site.

## Usage Example

```java
@Service
public class FeatureFlagService {

    private final FeFeatureFlagsRepository featureFlagsRepository;

    public FeatureFlagService(FeFeatureFlagsRepository featureFlagsRepository) {
        this.featureFlagsRepository = featureFlagsRepository;
    }

    public FeFeatureFlags getCurrentTenantFlags() {
        // Tenant context injected automatically — no tenantId param needed
        return featureFlagsRepository.findFirstBy()
                .orElseGet(FeFeatureFlags::defaults);
    }
}
```

## Notes

- Returns `Optional.empty()` when no overrides document exists for the tenant, allowing callers to fall back to platform defaults.
- Relies entirely on the tenant aspect for data isolation; do **not** pass a `tenantId` argument manually.
