Tenant-aware MongoDB repository implementation that performs bulk unordered inserts of `NotificationReadState` documents, silently swallowing duplicate-key errors while propagating any other bulk operation failures.

## Key Components

| Member | Description |
|---|---|
| `MONGO_DUPLICATE_KEY` | MongoDB error code `11000` used to identify duplicate key violations |
| `CustomNotificationReadStateRepositoryImpl(TenantAwareMongoTemplate)` | Constructor wiring in the tenant-scoped Mongo template via `TenantAwareRepositorySupport` |
| `bulkInsertUnordered(List<NotificationReadState>)` | Executes an unordered bulk insert; no-ops on null/empty input; suppresses bulk errors only when every write failure is a duplicate key |
| `allDuplicateKeyErrors(BulkOperationException)` | Private helper that returns `true` only when all errors in the exception carry code `11000` |

**Activation:** This bean is conditional on `openframe.tenant-isolation.enabled=true`.

## Usage Example

```java
// Injected via Spring context when tenant isolation is active
@Autowired
CustomNotificationReadStateRepository readStateRepo;

List<NotificationReadState> states = buildReadStates(userId, notificationIds);

// Safe to call repeatedly — duplicate records are silently ignored;
// any non-duplicate failure will still propagate.
readStateRepo.bulkInsertUnordered(states);
```

> **Note:** Using `BulkMode.UNORDERED` means MongoDB continues processing remaining documents even after individual write failures, maximising throughput when idempotent inserts are expected (e.g. marking the same notification read more than once).
