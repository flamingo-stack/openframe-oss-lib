Spring Data MongoDB repository interface for managing `ScriptExecution` documents, providing tenant-scoped lookups, machine/execution-based queries, and status-based filtering for the RMM script execution history.

## Key Components

| Method | Description |
|---|---|
| `findByTenantIdAndId` | Retrieves a single execution record by tenant and document ID |
| `findByTenantIdAndExecutionIdAndMachineId` | Scoped lookup by tenant, execution batch ID, and target machine |
| `findByMachineIdAndExecutionId` | Machine-level execution lookup without tenant scope |
| `findByMachineIdAndExecutionIdAndScriptId` | Fully qualified lookup by machine, execution, and script |
| `findFirstByTenantIdAndExecutionId` | Returns the first matching record for a given tenant/execution pair |
| `findByStatusAndDispatchedAtBefore` | Fetches stale or timed-out executions by status and dispatch timestamp |

Extends both `MongoRepository<ScriptExecution, String>` and `CustomScriptExecutionRepository` — the latter handles cursor-paged listing via `MongoTemplate`, keeping `Criteria`/sort assembly in the data layer.

## Usage Example

```java
// Fetch a specific execution record scoped to a tenant
Optional<ScriptExecution> execution =
    scriptExecutionRepository.findByTenantIdAndId(tenantId, executionId);

// Find a record by machine and execution correlation
Optional<ScriptExecution> byMachine =
    scriptExecutionRepository.findByMachineIdAndExecutionId(machineId, executionId);

// Query for dispatched-but-unresolved executions older than a threshold
Instant cutoff = Instant.now().minus(Duration.ofMinutes(30));
List<ScriptExecution> stale =
    scriptExecutionRepository.findByStatusAndDispatchedAtBefore(
        ExecutionStatus.DISPATCHED, cutoff
    );
```

## Notes

- Cursor-paged listing is intentionally delegated to `CustomScriptExecutionRepository` to avoid mixing `Criteria`/sort logic into derived query methods — consistent with the `ScriptRepository` pattern.
