Spring Data MongoDB repository interface for managing `TicketStatusDefinition` documents, providing CRUD operations and domain-specific queries for ticket status configurations.

## Key Components

| Method | Description |
|---|---|
| `findAllByOrderByPositionAsc()` | Retrieves all status definitions sorted by position |
| `findByKind(TicketStatusKind kind)` | Looks up a single status definition by its kind enum |
| `findByName(String name)` | Looks up a single status definition by name |
| `findByKindOrderByPositionAsc(TicketStatusKind kind)` | Retrieves all statuses of a given kind, ordered by position |
| `countByKind(TicketStatusKind kind)` | Counts how many statuses exist for a given kind |
| `existsByName(String name)` | Checks if a status with the given name already exists |

## Usage Example

```java
@Service
public class TicketStatusService {

    private final TicketStatusDefinitionRepository repository;

    public TicketStatusService(TicketStatusDefinitionRepository repository) {
        this.repository = repository;
    }

    public List<TicketStatusDefinition> getOrderedStatuses() {
        return repository.findAllByOrderByPositionAsc();
    }

    public Optional<TicketStatusDefinition> resolveByKind(TicketStatusKind kind) {
        return repository.findByKind(kind);
    }

    public boolean isNameTaken(String name) {
        return repository.existsByName(name);
    }

    public List<TicketStatusDefinition> getStatusesByKind(TicketStatusKind kind) {
        return repository.findByKindOrderByPositionAsc(kind);
    }
}
```

## Notes

- Extends `MongoRepository<TicketStatusDefinition, String>`, inheriting standard CRUD via Spring Data MongoDB.
- All ordered queries sort by `position`, enabling consistent UI rendering of status workflows.
- `existsByName` is useful for validation before creating new status definitions to avoid duplicates.
