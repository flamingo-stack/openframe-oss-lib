Spring Data MongoDB repository interface for managing `CommandExecution` documents, providing tenant-scoped and execution-scoped query methods for batch command history tracking in the RMM (Remote Monitoring and Management) module.

## Key Components

| Method | Description |
|---|---|
| `findByTenantIdAndId` | Tenant-scoped lookup by document `_id`; backs GraphQL Relay `node(id)` refetch |
| `findByTenantIdAndExecutionIdAndMachineId` | Per-machine row lookup within a batch; used by result write-back handler and `getBatchResults` |
| `findFirstByTenantIdAndExecutionId` | Retrieves the first row of an execution for execution-level metadata access |
| `findByStatusAndDispatchedAtBefore` | Watchdog coarse pre-filter returning `RUNNING` rows dispatched before a given timestamp |
| `findByMachineIdAndExecutionId` | Routing lookup used by `CommandResultDeserializer` before tenant enrichment is available |
| `findByExecutionId` | Returns all per-machine rows for a single batch execution |

## Usage Example

```java
// Tenant-scoped node refetch (GraphQL Relay)
Optional<CommandExecution> execution = commandExecutionRepository
    .findByTenantIdAndId(tenantId, nodeId);

// Write-back result for a specific machine in a batch
Optional<CommandExecution> machineRow = commandExecutionRepository
    .findByTenantIdAndExecutionIdAndMachineId(tenantId, executionId, machineId);

// Watchdog: find stale RUNNING executions older than 10 minutes
Instant threshold = Instant.now().minus(10, ChronoUnit.MINUTES);
List<CommandExecution> stale = commandExecutionRepository
    .findByStatusAndDispatchedAtBefore(ExecutionStatus.RUNNING, threshold);

// Pre-tenant routing in CommandResultDeserializer
Optional<CommandExecution> row = commandExecutionRepository
    .findByMachineIdAndExecutionId(machineId, executionId);
```

## Notes

- Mirrors the pattern established by `ScriptExecutionRepository`
- `findByMachineIdAndExecutionId` intentionally omits `tenantId` — used only during early deserialization before tenant context is resolved; `(machineId, executionId)` is effectively unique within the underlying compound index
