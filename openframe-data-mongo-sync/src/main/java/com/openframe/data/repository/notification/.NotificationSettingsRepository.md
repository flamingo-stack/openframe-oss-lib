Tenant-scoped Spring Data repository for managing per-user `NotificationSettings` documents, deliberately extending bare `Repository` (not `MongoRepository`) to prevent unscoped `deleteAll()` and `count()` operations across tenants.

## Key Components

| Member | Description |
|---|---|
| `findByUserId(String userId)` | Retrieves a single user's notification settings document, if present. |
| `findByUserIdInAndPushEnabledFalse(Collection<String> userIds)` | Bulk lookup returning only users who have **explicitly disabled** push notifications. |
| `findPushDisabledUserIds(Collection<String> userIds)` | Default method wrapping the bulk lookup; returns a `Set<String>` of opted-out user IDs. Returns an empty set on null or empty input. |
| `@TenantAwareRepository` | Marker annotation ensuring all queries are scoped to the current tenant. |
| `CustomNotificationSettingsRepository` | Extended custom interface for any additional query logic not covered by derived methods. |

## Usage Example

```java
// Resolve which users in a batch have push notifications disabled
Set<String> userIds = Set.of("user-1", "user-2", "user-3");
Set<String> disabledUsers = notificationSettingsRepository.findPushDisabledUserIds(userIds);

// Look up settings for a single user
Optional<NotificationSettings> settings = notificationSettingsRepository.findByUserId("user-1");
settings.ifPresent(s -> System.out.println("Push enabled: " + s.isPushEnabled()));
```

> **Opt-in by default:** A user with no `NotificationSettings` document is treated as push-enabled. Only an explicit `pushEnabled: false` record causes a user to appear in `findPushDisabledUserIds`.
