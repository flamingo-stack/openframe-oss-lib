Custom repository interface for notification settings operations that fall outside standard Spring Data JPA query generation.

## Key Components

- **`setPushEnabled(String userId, boolean enabled)`** — Custom method to update the push notification enabled state for a specific user.

## Usage Example

```java
@Repository
public class CustomNotificationSettingsRepositoryImpl implements CustomNotificationSettingsRepository {

    @PersistenceContext
    private EntityManager entityManager;

    @Override
    @Transactional
    public void setPushEnabled(String userId, boolean enabled) {
        entityManager.createQuery(
            "UPDATE NotificationSettings n SET n.pushEnabled = :enabled WHERE n.userId = :userId"
        )
        .setParameter("enabled", enabled)
        .setParameter("userId", userId)
        .executeUpdate();
    }
}
```

## Notes

- Follows the Spring Data JPA [custom repository fragment pattern](https://docs.spring.io/spring-data/jpa/docs/current/reference/html/#repositories.custom-implementations) — the implementation class must be named `CustomNotificationSettingsRepositoryImpl` and is automatically picked up when the main repository extends this interface.
