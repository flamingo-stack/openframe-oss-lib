Custom repository interface for cursor-based notification pagination, enabling filtered and sorted retrieval of notifications for a specific recipient.

## Key Components

- **`findPageForRecipient` (primary)** — Fetches a paginated `NotificationPage` for a recipient, supporting read-status filtering, text search, cursor-based navigation (forward/backward), configurable sort direction, and a result limit.
- **`findPageForRecipient` (default overload)** — Convenience method that delegates to the primary with a default sort direction of `Sort.Direction.DESC`.

## Usage Example

```java
// Inject the repository (typically via a composed repository interface)
@Autowired
private CustomNotificationRepository notificationRepository;

// Fetch the first page of unread notifications for a user (descending order)
NotificationPage page = notificationRepository.findPageForRecipient(
    "user-123",
    RecipientType.USER,
    false,       // readFilter: only unread
    "alert",     // search keyword
    null,        // cursor: null for first page
    false,       // backward: false = forward pagination
    20           // limit: page size
);

// Fetch the next page using a cursor, with explicit sort direction
NotificationPage nextPage = notificationRepository.findPageForRecipient(
    "user-123",
    RecipientType.USER,
    false,
    "alert",
    page.getNextCursor(),
    false,
    Sort.Direction.ASC,
    20
);
```

## Notes

- Cursor-based pagination avoids offset drift on live data, making it suitable for real-time notification feeds.
- The `backward` flag enables reverse traversal through the result set.
- Implementations are typically provided via a custom MongoDB or JPA repository class. See the full repository at [flamingo-stack/openframe-oss-lib](https://github.com/flamingo-stack/openframe-oss-lib).
