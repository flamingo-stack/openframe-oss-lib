MongoDB repository interface for managing `TimeEntry` documents, providing standard CRUD operations alongside specialized queries for active timer detection and ticket-based lookups.

## Key Components

| Component | Description |
|---|---|
| `TimeEntryRepository` | Main repository interface extending `MongoRepository<TimeEntry, String>` and `CustomTimeEntryRepository` |
| `@TenantAwareRepository` | Ensures all queries are automatically scoped to the current tenant context |
| `findByUserIdAndEndedAtIsNull` | Finds an active (in-progress) time entry for a given user — returns empty if no timer is running |
| `findByTicketId` | Retrieves all time entries associated with a specific ticket |

## Usage Example

```java
// Detect if a user has an active running timer
Optional<TimeEntry> activeEntry = timeEntryRepository.findByUserIdAndEndedAtIsNull(userId);

activeEntry.ifPresent(entry -> {
    System.out.println("Timer started at: " + entry.getStartedAt());
});

// Fetch all time entries logged against a ticket
List<TimeEntry> ticketEntries = timeEntryRepository.findByTicketId("TICKET-001");
ticketEntries.forEach(entry -> {
    System.out.println("Logged by: " + entry.getUserId() + " | Duration: " + entry.getDuration());
});
```

## Notes

- The `findByUserIdAndEndedAtIsNull` query relies on `endedAt` being `null` to represent an open/active timer. Only one active entry per user is expected at a time.
- Additional custom query methods are defined in `CustomTimeEntryRepository`.
