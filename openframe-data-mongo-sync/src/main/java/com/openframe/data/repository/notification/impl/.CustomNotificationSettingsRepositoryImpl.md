Tenant-isolated MongoDB repository implementation for managing user notification settings. It provides atomic upsert operations on the `{tenantId, userId}` unique index, with graceful handling of concurrent insert races.

## Key Components

| Element | Description |
|---|---|
| `CustomNotificationSettingsRepositoryImpl` | Concrete repository extending `TenantAwareRepositorySupport`, activated only when `openframe.tenant-isolation.enabled=true` |
| `setPushEnabled(String userId, boolean enabled)` | Atomically upserts push notification preference for a user; falls back to `updateFirst` on duplicate key race conditions |
| `TenantAwareMongoTemplate` | Injected via constructor; automatically scopes queries to the current tenant |
| `@ConditionalOnProperty` | Guards bean registration — only active in tenant-isolated deployments |

## Usage Example

```java
// Injected where needed (tenant context must be active on the calling thread)
@Service
public class NotificationService {

    private final CustomNotificationSettingsRepository notificationSettingsRepository;

    public NotificationService(CustomNotificationSettingsRepository repo) {
        this.notificationSettingsRepository = repo;
    }

    public void enablePushForUser(String userId) {
        // Atomically inserts or updates the push preference for the current tenant
        notificationSettingsRepository.setPushEnabled(userId, true);
    }

    public void disablePushForUser(String userId) {
        notificationSettingsRepository.setPushEnabled(userId, false);
    }
}
```

## Notes

- **Upsert strategy:** Uses MongoDB `upsert` for atomic insert-or-update. `createdAt` is set only on first insert via `setOnInsert`; `updatedAt` is always refreshed.
- **Race condition handling:** A `DuplicateKeyException` caught after an upsert indicates a concurrent insert won the race — a follow-up `updateFirst` safely resolves it.
- **Tenant stamping:** `tenantId` is applied via the scoped query filter from `TenantAwareRepositorySupport`, since `TenantStampingCallback` does not cover `Update`-based operations.
