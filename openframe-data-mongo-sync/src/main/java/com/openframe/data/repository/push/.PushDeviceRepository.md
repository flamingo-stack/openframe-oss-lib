Manages persistence operations for push notification device tokens, providing tenant-scoped CRUD access to `PushDevice` documents while deliberately avoiding inherited bulk operations that could affect multiple tenants.

## Key Components

| Member | Type | Description |
|---|---|---|
| `PushDeviceRepository` | Interface | Extends bare `Repository` (not `MongoRepository`) to prevent unscoped `count()` and `deleteAll()` exposure |
| `findByUserId` | Query method | Returns all registered push devices for a given user |
| `deleteByUserIdAndToken` | Delete method | Removes a specific device token scoped to the owning user; returns `0` or `1` |
| `deleteByTokenIn` | Delete method | Bulk-removes devices matching a collection of tokens |
| `@TenantAwareRepository` | Annotation | Ensures all queries are automatically scoped to the current tenant |

## Usage Example

```java
@Service
public class PushDeviceService {

    private final PushDeviceRepository pushDeviceRepository;

    // Retrieve all devices for a user
    public List<PushDevice> getDevices(String userId) {
        return pushDeviceRepository.findByUserId(userId);
    }

    // Deregister a specific token, scoped to the owning user
    public boolean deregisterToken(String userId, String token) {
        long deleted = pushDeviceRepository.deleteByUserIdAndToken(userId, token);
        return deleted > 0;
    }

    // Clean up a batch of expired or invalid tokens
    public void purgeStaleTokens(Collection<String> expiredTokens) {
        pushDeviceRepository.deleteByTokenIn(expiredTokens);
    }
}
```

## Design Notes

- Intentionally extends bare `Repository<PushDevice, String>` rather than `MongoRepository` — this prevents accidental exposure of `deleteAll()` and `count()`, which are not tenant-scoped and could corrupt or expose cross-tenant data.
- `deleteByUserIdAndToken` enforces ownership validation at the query level, preventing a token rebound to another user from being deregistered by the original owner.
