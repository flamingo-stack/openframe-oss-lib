MongoDB repository interface for managing per-recipient notification read states, supporting CRUD operations, bulk status transitions, and aggregated unread counts by category.

## Key Components

| Method | Description |
|---|---|
| `existsByRecipientIdAndRecipientTypeAndStatus` | Checks whether any read-state record exists for a recipient with a given `ReadStatus` |
| `findByNotificationId` | Retrieves all recipient read-state records for a specific notification |
| `markAsRead` | Atomically flips a single UNREAD record to READ for one recipient/notification pair |
| `markAllAsRead` | Bulk-marks all UNREAD notifications as READ for a given recipient |
| `markAllRecipientsRead` | Bulk-marks all recipients' UNREAD rows for a notification as READ (used on lifecycle-resolve events) |
| `softDelete` | Soft-deletes a single non-DELETED notification for a recipient by setting status to DELETED |
| `softDeleteAllRead` | Soft-deletes all READ notifications for a recipient |
| `unreadCountsByCategory` | Aggregation pipeline returning unread notification counts grouped by category for a tenant-scoped recipient |

## Usage Example

```java
// Check for any unread notifications
boolean hasUnread = repository.existsByRecipientIdAndRecipientTypeAndStatus(
    "user-123", RecipientType.USER, ReadStatus.UNREAD
);

// Mark a single notification as read
long updated = repository.markAsRead("user-123", RecipientType.USER, "notif-456");

// Mark all as read for a recipient
long totalMarked = repository.markAllAsRead("user-123", RecipientType.USER);

// Dismiss notification for all recipients on resolve
long dismissed = repository.markAllRecipientsRead("notif-456");

// Soft delete all read notifications
long deleted = repository.softDeleteAllRead("user-123", RecipientType.USER);

// Get unread counts grouped by category
List<CategoryCount> counts = repository.unreadCountsByCategory(
    "user-123", RecipientType.USER, "tenant-001"
);
```

## Notes

- Annotated with `@TenantAwareRepository` — all queries are automatically scoped to the current tenant context.
- Status transitions use MongoDB's `$$NOW` server-side timestamp for consistent `readAt` values without clock skew.
- Extends `CustomNotificationReadStateRepository` for any additional query logic not expressible via Spring Data conventions.
