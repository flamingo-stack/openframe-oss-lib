Spring Data MongoDB repository interface for `User` documents, providing standard CRUD operations alongside custom query methods for email-based lookups, role/status filtering, and tenant membership checks.

## Key Components

| Method | Description |
|---|---|
| `findByEmail(String email)` | Looks up a user by email address, returning an `Optional<User>` |
| `existsByEmail(String email)` | Checks if any user exists with the given email |
| `existsByEmailAndStatus(String email, UserStatus status)` | Checks existence scoped to a specific `UserStatus` |
| `findByRolesInAndStatus(Collection<UserRole> roles, UserStatus status)` | Retrieves all users matching any of the given roles and a specific status |
| `existsByTenantIdAndId(String tenantId, String id)` | Verifies a user belongs to a specific tenant — useful for distinguishing real tenant members from cross-tenant super users |

## Usage Example

```java
// Resolve a user by email
Optional<User> user = userRepository.findByEmail("tech@example.com");

// Check active status before proceeding
boolean isActive = userRepository.existsByEmailAndStatus(
    "tech@example.com",
    UserStatus.ACTIVE
);

// Fetch all active admins and technicians
List<User> staff = userRepository.findByRolesInAndStatus(
    List.of(UserRole.ADMIN, UserRole.TECHNICIAN),
    UserStatus.ACTIVE
);

// Confirm tenant membership (e.g. distinguish tenant user vs. super user)
boolean isMember = userRepository.existsByTenantIdAndId("tenant-abc", "user-123");
```

## Notes

- Extends `MongoRepository<User, String>` for full CRUD support.
- Also extends `BaseUserRepository` and `CustomUserRepository`, allowing shared contract definitions and custom query logic to be composed cleanly.
- The `existsByTenantIdAndId` method is intentionally **tenant-first** to support explicit tenant scoping on the SaaS/shared layer.
