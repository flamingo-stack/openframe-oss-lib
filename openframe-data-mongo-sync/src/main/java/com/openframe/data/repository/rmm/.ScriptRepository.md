Tenant-scoped Spring Data MongoDB repository for `Script` documents, providing CRUD and name-collision query methods used by the RMM scripting subsystem.

## Key Components

| Method | Description |
|---|---|
| `findByTenantIdAndId` | Fetches a single script by tenant + document ID |
| `findByTenantIdAndIdIn` | Batch-resolves scripts by ID, including soft-deleted records (for History display) |
| `findByTenantIdAndName` | Looks up a script by name; may return soft-deleted documents |
| `existsByTenantIdAndNameAndStatusIn` | Duplicate-name guard for **create** — ignores `DELETED` rows |
| `existsByTenantIdAndNameAndIdNotAndStatusIn` | Duplicate-name guard for **update** — excludes the document being edited |
| `deleteByTenantIdAndId` | Hard-deletes a script by tenant + ID, returns count of removed documents (0 or 1) |

Pagination and cursor-style listing are delegated to `CustomScriptRepository`, which uses `MongoTemplate` directly.

## Usage Example

```java
// Resolve display names for history rows (includes soft-deleted scripts)
List<Script> scripts = scriptRepository.findByTenantIdAndIdIn(tenantId, executedScriptIds);

// Name collision check before creating a new script
boolean taken = scriptRepository.existsByTenantIdAndNameAndStatusIn(
    tenantId,
    "Disk Cleanup",
    List.of(ScriptStatus.ACTIVE, ScriptStatus.ARCHIVED)
);
if (taken) {
    throw new DuplicateScriptNameException("Disk Cleanup");
}

// Hard-delete a script
long removed = scriptRepository.deleteByTenantIdAndId(tenantId, scriptId);
```

## Notes

- All methods are **tenant-scoped** — no cross-tenant data leakage is possible at the query level.
- Soft-deleted (`DELETED` status) scripts are intentionally **not** filtered in `findByTenantIdAndIdIn` to preserve History row resolution.
- Name uniqueness is enforced only across `ACTIVE` and `ARCHIVED` rows; `DELETED` records free their name for reuse.
