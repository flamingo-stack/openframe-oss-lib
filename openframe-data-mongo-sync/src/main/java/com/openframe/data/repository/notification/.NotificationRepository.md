MongoDB repository interface for `Notification` documents, combining standard CRUD operations with custom query capabilities and tenant-aware data isolation.

## Key Components

| Component | Description |
|---|---|
| `NotificationRepository` | Main repository interface extending `MongoRepository<Notification, String>` |
| `@TenantAwareRepository` | Ensures all queries are automatically scoped to the current tenant context |
| `CustomNotificationRepository` | Extended interface providing additional custom query methods |
| `findByCorrelationId(String)` | Derived query returning an `Optional<Notification>` matched by correlation ID |

## Usage Example

```java
@Service
public class NotificationService {

    private final NotificationRepository notificationRepository;

    public NotificationService(NotificationRepository notificationRepository) {
        this.notificationRepository = notificationRepository;
    }

    public Optional<Notification> getByCorrelationId(String correlationId) {
        // Automatically scoped to current tenant
        return notificationRepository.findByCorrelationId(correlationId);
    }

    public Notification save(Notification notification) {
        return notificationRepository.save(notification);
    }
}
```

## Notes

- The `correlationId` lookup is useful for tracing notifications back to originating events or workflows.
- Tenant scoping is handled transparently via `@TenantAwareRepository` — no manual filtering required.
- Inherits the full `MongoRepository` API (`save`, `findById`, `deleteById`, etc.) alongside any methods declared in `CustomNotificationRepository`.
