Defines a custom Spring Data repository extension for atomic push device token registration operations that cannot be auto-derived by Spring Data's query derivation mechanism.

## Key Components

- **`CustomPushDeviceRepository`** — Interface declaring a single upsert operation for push device tokens, intended to be implemented alongside a standard Spring Data repository.
- **`registerToken(String userId, String token, PushPlatform platform)`** — Performs an atomic insert-or-rebind on the `{tenantId, token}` unique index. Returns `true` if a new record was created, `false` if an existing token was rebound.

## Usage Example

```java
// Typically extended by a Spring Data repository interface
public interface PushDeviceRepository
        extends MongoRepository<PushDevice, String>, CustomPushDeviceRepository {
    // Spring Data-derived queries here
}

// Calling the upsert in a service
boolean isNew = pushDeviceRepository.registerToken(
    "user-123",
    "fcm-device-token-abc",
    PushPlatform.FCM
);

if (isNew) {
    log.info("New device registered for push notifications");
} else {
    log.info("Existing device token rebound to user");
}
```

## Notes

- The implementation class (e.g., `CustomPushDeviceRepositoryImpl`) is responsible for executing the actual atomic upsert against the underlying store (typically MongoDB).
- The atomic nature of `registerToken` prevents race conditions when the same token is concurrently registered by multiple requests.
- See [`PushPlatform`](https://github.com/flamingo-stack/openframe-oss-lib/blob/main/src/main/java/com/openframe/data/document/push/PushPlatform.java) for supported platform enum values.
