MongoDB repository interface for persisting and retrieving `TenantOnboardingProgress` documents, scoped one-per-tenant with explicit tenant ID lookups.

## Key Components

| Element | Description |
|---|---|
| `TenantOnboardingProgressRepository` | Spring Data MongoDB repository extending `MongoRepository<TenantOnboardingProgress, String>` |
| `findByTenantId(String tenantId)` | Derived query method returning an `Optional<TenantOnboardingProgress>` for the given tenant |

> **Design note:** This interface is annotated with plain `@Repository` rather than `@TenantAwareRepository`. The SaaS-side runtime disables tenant isolation at this layer, so callers are responsible for passing `tenantId` explicitly — the tenant aspect is intentionally bypassed.

## Usage Example

```java
@Service
public class OnboardingService {

    private final TenantOnboardingProgressRepository progressRepository;

    public OnboardingService(TenantOnboardingProgressRepository progressRepository) {
        this.progressRepository = progressRepository;
    }

    public TenantOnboardingProgress getProgress(String tenantId) {
        return progressRepository.findByTenantId(tenantId)
                .orElseThrow(() -> new OnboardingNotFoundException(tenantId));
    }

    public void saveProgress(TenantOnboardingProgress progress) {
        progressRepository.save(progress);
    }
}
```

## Notes

- Inherits standard CRUD operations (`save`, `findById`, `delete`, etc.) from `MongoRepository`.
- Always use `findByTenantId` rather than `findById` when looking up onboarding state — the document ID is not the tenant identifier.
