The single entry point for changing a handful of fields on a `Machine` without rewriting the whole document. Writes a field-scoped `findAndModify`, returns the before/after pair from one round trip, and republishes the device to Pinot — which the `save()`-based aspect cannot do for this path.

## Key Components

| Type | Description |
|---|---|
| `MachineWriter` | Executes the write: `findAndModify` with `$set`, guard criteria ANDed in, Pinot event published on success |
| `MachineUpdate` | Records field changes twice over — as a MongoDB `$set` and as the equivalent in-memory mutation |
| `MachineFields` | The registry of writable fields; each constant binds a Mongo path to the matching `Machine` setter |
| `MachineField<T>` | One field: `(path, setter)`. Declaring both is what makes the post-image derivable without a second read |
| `MachineWriteResult` | `before` (as stored when the update matched) and `after` (that document with the update applied) |

## Usage Example

```java
// Set or clear one field
machineWriter.update(machineId, machineUpdate().set(NICKNAME, "Reception iMac"));

// Several fields in one atomic write
machineWriter.update(machineId, machineUpdate()
        .set(STATUS, DeviceStatus.ONLINE)
        .set(LAST_SEEN, eventTimestamp));

// Guarded: apply only while the stored document still satisfies the condition
machineWriter.update(machineId,
        Criteria.where("lastSeen").lt(eventTimestamp),
        machineUpdate().set(STATUS, DeviceStatus.ONLINE).set(LAST_SEEN, eventTimestamp))
    .ifPresent(result -> publishTransition(result.before().getStatus(), result.after()));
```

## Adding a new writable field

1. Add one constant to `MachineFields`: `public static final MachineField<String> LOCATION = field("location", Machine::setLocation);`
2. Call `machineUpdate().set(LOCATION, value)`.

That is the whole change. No repository method, no interface addition, no new test double — and because the field carries its own setter, the returned `after` document and the Pinot event pick it up automatically. Reserve the registry for fields edited in isolation; a full inventory refresh from an agent payload is a different shape of write and stays whole-document.

## Notes

- **Why not optimistic locking.** `Machine` takes a heartbeat write per device per interval, so a `@Version` field would turn routine overlap into retry storms on the hottest collection in the system. Field-scoped updates make it unnecessary: writers touching disjoint fields never conflict. Contrast `Subscription`, which is written only by webhooks and a reconciliation scheduler — there `@Version` plus a retry loop is the cheaper trade.
- **Guards beat check-then-write.** A staleness test evaluated in Java can go stale between the decision and the write. Passing it as `Criteria` makes MongoDB evaluate it inside the same atomic operation.
- **Pinot sync happens in the aspect, not here.** This write never reaches `MachineRepository.save()`, so `MachineTagEventAspect` advises `update(..)` directly and publishes the post-update document. Keeping it there means `MachineWriter` has no Kafka or event dependency, exactly as the `save()` path has none. It matters for any field the Pinot `devices` table carries — `status`, `deviceType`, `organizationId`, `osType`, tags — where a missed event leaves the facet counts wrong; fields the table does not carry (`nickname` among them) are unaffected either way, but the advice fires unconditionally so that adding a column later needs no new wiring. Publication failures are swallowed and logged: a broken Kafka path degrades to a stale index, not a failed write.
- **An ad-hoc `findAndModify` gets none of this.** The aspect matches `MachineWriter.update(..)` and the repository's `save`/`saveAll`, nothing else. That is the practical reason to route new write paths through here rather than hand-rolling one.
- **`updatedAt` is maintained here.** `@LastModifiedDate` auditing only runs on `save()`.
- **Tenant scoping is inherited**, not reimplemented: `TenantAwareMongoTemplate` is the `@Primary` `MongoTemplate` wherever `openframe.tenant-isolation.enabled` is set and injects `tenantId` into `findAndModify`. Do not substitute a raw template.
- **An empty `Optional` means "no document matched"** — either the device does not exist or the guard rejected it. Callers needing to distinguish must look it up separately; the common case (skip quietly) does not.
- `MachineWriteResult`'s two documents are distinct instances but the copy is shallow: collection-valued properties are shared. Treat both as read-only.
