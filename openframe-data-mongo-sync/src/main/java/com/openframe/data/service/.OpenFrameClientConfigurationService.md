Service layer for managing `OpenFrameClientConfiguration` documents in a multi-tenant MongoDB environment, handling CRUD operations, publish state transitions, and version/configuration field updates with optimistic locking retry support.

## Key Components

| Method | Description |
|---|---|
| `get()` | Retrieves the configuration for the current tenant; throws `IllegalStateException` if not found |
| `findById(String id)` | Looks up a configuration by document ID, returning an `Optional` |
| `save(config)` | Persists a configuration document to MongoDB |
| `markAsNonPublished(config)` | Transitions publish state to non-published using the current state |
| `markAsPublished(config)` | Sets publish state to published |
| `updateVersion(newVersion)` | Updates the client version and sets state to `pending` if the version changed; retries on optimistic locking failure |
| `updateConfigurationFields(fromConfig)` | Upserts tenant configuration — merges into an existing document or creates a new one; retries on optimistic locking failure |
| `mergeAndSave(existing, fromConfig)` | Merges `DownloadConfiguration` fields and marks state as `pending` if changes are detected |
| `createForTenant(fromConfig)` | Clears the hardcoded default `_id` before insert to avoid MongoDB `E11000` duplicate key errors in a shared multi-tenant collection |

## Usage Example

```java
// Retrieve the current tenant's configuration
OpenFrameClientConfiguration config = configService.get();

// Update the agent version (retries automatically on concurrent modification)
configService.updateVersion("2.5.1");

// Apply new configuration fields from a bundled default
configService.updateConfigurationFields(incomingConfig);

// Transition publish states
configService.markAsPublished(config);
configService.markAsNonPublished(config);
```

## Notes

- Relies on `TenantIdProvider` to scope all queries to the current tenant.
- `@RetryOnOptimisticLockingFailure` on `updateVersion` and `updateConfigurationFields` prevents lost-update races in concurrent environments.
- `createForTenant` intentionally nullifies the document `_id` before saving; MongoDB then generates a unique `_id` per tenant, and `TenantStampingCallback` stamps the `tenantId` automatically on save.
