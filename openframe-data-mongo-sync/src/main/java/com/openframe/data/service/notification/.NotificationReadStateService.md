Manages the read/delete state of notifications per recipient, acting as the service layer between notification lifecycle events and the `NotificationReadStateRepository`. After every persisted transition it emits a `NotificationReadEvent` to the injected `List<NotificationReadEventListener>` (SPI — empty in the OSS edition; downstream editions plug in push retraction, live web updates, …).

## Key Components

| Method | Description |
|---|---|
| `createForAudience` | Bulk-inserts `UNREAD` read-state rows for a collection of recipient IDs |
| `hasUnread` | Returns `true` if a recipient has any unread notifications |
| `findRecipients` | Retrieves all recipient read-state rows for a given notification ID |
| `markRead` | Marks a single notification as read for one recipient |
| `markAllAsRead` | Marks all notifications as read for a recipient |
| `dismissForAllRecipients` | Flips every `UNREAD` row to `READ` across all recipients (e.g. after an approval resolves) |
| `deleteNotification` | Soft-deletes a single notification for one recipient |
| `deleteAllRead` | Soft-deletes all `READ` notifications for a recipient |
| `unreadCountsByCategory` | Returns a `Map<NotificationCategory, Long>` of unread counts grouped by category for the current tenant |

## Usage Example

```java
// Broadcast a new notification to a set of technicians
notificationReadStateService.createForAudience(
    "notif-001",
    NotificationCategory.APPROVAL,
    "New approval request",
    RecipientType.TECHNICIAN,
    List.of("tech-1", "tech-2", "tech-3")
);

// Check for unread notifications for a recipient
boolean hasUnread = notificationReadStateService.hasUnread("tech-1", RecipientType.TECHNICIAN);

// Dismiss for all recipients once resolved
long dismissed = notificationReadStateService.dismissForAllRecipients("notif-001");

// Get unread counts per category
Map<NotificationCategory, Long> counts = notificationReadStateService
    .unreadCountsByCategory("tech-1", RecipientType.TECHNICIAN);
```

## Notes

- All mutating operations use soft-delete and status-flip patterns; no rows are physically removed.
- `dismissForAllRecipients` is intended for lifecycle-resolve events where a single action (e.g. one admin approving a request) should stop the notification from being actionable for all other recipients.
- Bean validation (`@NotBlank`, `@NotNull`, `@NotEmpty`) is enforced at the service boundary via `@Validated`.
- Read events fire only on ACTUAL transitions (a repeated markRead matches nothing and stays silent). Bulk operations emit one event with all affected ids, snapshotted before the flip; `dismissForAllRecipients` emits per previously-UNREAD recipient. Listeners are called synchronously, fail-open: a throwing listener is logged and skipped, never affecting the mutation or its neighbours.
