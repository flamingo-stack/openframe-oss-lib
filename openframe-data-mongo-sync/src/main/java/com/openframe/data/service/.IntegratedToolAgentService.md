Service layer for managing `IntegratedToolAgent` MongoDB documents, providing CRUD operations, key/UUID-based lookups, configuration sync, and publish-state lifecycle management for tool agents in the OpenFrame platform.

## Key Components

| Method | Description |
|---|---|
| `getAll()` / `getAllEnabled()` | Retrieve all agents or only `ENABLED` agents |
| `findByKey(key)` / `getByKey(key)` | Look up agent by human-readable key (e.g. `"fleetmdm-agent"`); `get*` variant throws if absent |
| `findByUuid(uuid)` / `getByUuid(uuid)` | Look up agent by MongoDB document UUID; `get*` variant throws if absent |
| `findById` / `getById` | **Deprecated** — use the key or UUID variants instead |
| `updateConfigurationFields(config)` | Upserts an agent from a configuration object; creates new or merges into existing, marking publish state `pending` when version or assets change |
| `updateReleaseAgentVersion(id, version)` | Updates the version on a release-channel agent and marks it `pending` for publish |
| `markAsPublished(agent)` / `markAsNonPublished(agent)` | Transitions publish state via `PublishState` factory methods |
| `hasAssetChanges(existing, config)` | (private) Compares asset versions by ID to detect drift requiring republish |

`@RetryOnOptimisticLockingFailure` is applied to write operations that may race under concurrent updates.

## Usage Example

```java
// Upsert agent config arriving from a deployment pipeline
IntegratedToolAgentConfiguration config = loadConfig("fleetmdm-agent");
integratedToolAgentService.updateConfigurationFields(config);

// Fetch by key and check status
IntegratedToolAgent agent = integratedToolAgentService.getByKey("fleetmdm-agent");
if (agent.getStatus() == ToolAgentStatus.ENABLED) {
    // promote to published after validation
    integratedToolAgentService.markAsPublished(agent);
}

// Bump version on a release-channel agent
integratedToolAgentService.updateReleaseAgentVersion(agent.getId(), "2.1.0");
```

> **Note:** Always prefer `findByKey` / `getByKey` over the deprecated `findById` / `getById` to ensure cross-tenant safety via the compound `(tenantId, key)` index.
