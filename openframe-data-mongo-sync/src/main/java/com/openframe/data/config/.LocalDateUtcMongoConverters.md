Provides UTC-pinned `LocalDate` ↔ MongoDB `Date` converters to ensure consistent date serialization across pods in different timezones.

## Key Components

| Component | Type | Description |
|---|---|---|
| `converters()` | Static factory method | Returns the converter list for registration with `MongoCustomConversions` |
| `LocalDateToUtcDateConverter` | `@WritingConverter` enum | Converts `LocalDate` → `Date` using `ZoneOffset.UTC` (midnight UTC) |
| `UtcDateToLocalDateConverter` | `@ReadingConverter` enum | Converts `Date` → `LocalDate` interpreting the instant in UTC |

## Problem Solved

Spring's default JSR-310 converters use `ZoneId.systemDefault()`, meaning the same `LocalDate` is stored at different instants depending on the pod's timezone. For example, UTC stores midnight as `00:00Z` while CEST stores it as the previous day's `22:00Z`. This caused duplicate/overlapping documents in date-deduplication logic (e.g., `product_usage_periods`). Pinning to UTC ensures every pod encodes the same logical date identically.

## Usage Example

Register the converters when configuring MongoDB in any Spring `@Configuration` class:

```java
import org.springframework.data.mongodb.core.convert.MongoCustomConversions;

@Configuration
public class MongoConfig {

    @Bean
    public MongoCustomConversions customConversions() {
        return new MongoCustomConversions(LocalDateUtcMongoConverters.converters());
    }
}
```

> **Note:** Only register these converters once per `MongoCustomConversions` bean. Adding them to multiple configurations that share the same bean will result in duplicate converter registrations.
