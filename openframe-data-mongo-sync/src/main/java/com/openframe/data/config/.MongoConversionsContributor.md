Defines a functional interface for contributing custom MongoDB type converters to the centralized `MongoCustomConversions` bean, avoiding Spring Data's single-bean constraint.

## Key Components

- **`MongoConversionsContributor`** – A `@FunctionalInterface` extending `Consumer<MongoConverterConfigurationAdapter>`. Each implementation receives the shared `MongoConverterConfigurationAdapter` and registers its converters into it.

## Usage Example

```java
@Configuration
public class MyModuleConfig {

    @Bean
    public MongoConversionsContributor myConverters() {
        return adapter -> adapter.registerConverter(new MyTypeReadConverter())
                                 .registerConverter(new MyTypeWriteConverter());
    }
}
```

## Why This Exists

Spring Data MongoDB allows exactly **one** `MongoCustomConversions` bean. Defining a second one causes an ambiguity error at startup. This interface lets multiple modules each register a `@Bean` contributor, which are all collected and applied by [`MongoCustomConversionsConfig`](https://github.com/flamingo-stack/openframe-oss-lib/blob/main/src/main/java/com/openframe/data/config/MongoCustomConversionsConfig.java) into a single `MongoCustomConversions` instance.

> **Note:** Using `@ConditionalOnMissingBean` is not a viable workaround here. Service apps declare an explicit `@ComponentScan` over `com.openframe.data`, which causes auto-configurations in this package to be registered twice as plain scanned configs — where the condition is evaluated too early to detect its sibling bean.
