Registers MongoDB read/write converters for `NotificationContext` objects, wiring Jackson-based serialization into the Spring Data MongoDB conversion pipeline.

## Key Components

| Bean | Type | Description |
|------|------|-------------|
| `notificationContextReadConverter` | `NotificationContextReadConverter` | Deserializes MongoDB documents into `NotificationContext` using Jackson |
| `notificationContextWriteConverter` | `NotificationContextWriteConverter` | Serializes `NotificationContext` objects into MongoDB documents using Jackson |
| `notificationContextConversionsContributor` | `MongoConversionsContributor` | Registers both converters with the shared MongoDB custom conversions adapter |

**Imports:**
- `NotificationContextJacksonConfig` — provides the configured `ObjectMapper`
- `MongoCustomConversionsConfig` — provides the `MongoConversionsContributor` aggregation mechanism

## Usage Example

This is a Spring `@Configuration` class and is auto-discovered or explicitly imported. No manual instantiation is required.

```java
// Import in a composite config or rely on component scanning
@Import(NotificationContextMongoConfig.class)
@Configuration
public class AppMongoConfig {
    // NotificationContext converters are now active
}
```

Once registered, Spring Data MongoDB will automatically invoke the converters during read/write operations:

```java
// Write: NotificationContext → MongoDB Document (via NotificationContextWriteConverter)
notificationContextRepository.save(context);

// Read: MongoDB Document → NotificationContext (via NotificationContextReadConverter)
NotificationContext ctx = notificationContextRepository.findById(id).orElseThrow();
```

## Notes

- Follows the contributor pattern via `MongoConversionsContributor`, allowing multiple modules to register converters without overriding a single `MongoCustomConversions` bean.
- Both converters share the same `ObjectMapper` instance sourced from `NotificationContextJacksonConfig`.
