Defines the seed catalog for default ticket statuses used during system initialization, providing pre-configured `TicketStatusDefinition` instances with names, colors, and LexoRank-based ordering positions.

## Key Components

### Constants

| Constant | Value | Description |
|---|---|---|
| `NAME_AI_ASSISTANCE` | `"AI Assistance"` | Status for tickets handled by Mingo AI |
| `NAME_TECH_REQUIRED` | `"Tech Required"` | Status for tickets needing a human technician |
| `NAME_RESOLVED` | `"Resolved"` | Status for completed tickets |
| `NAME_ARCHIVED` | `"Archived"` | Status for archived tickets |
| `NAME_ON_HOLD` | `"On Hold"` | Label for the default custom on-hold status |
| `COLOR_*` | Hex strings | Display colors for each status in the UI |

### Methods

- **`systemStatuses()`** — Returns an ordered `List<TicketStatusDefinition>` of the four core system statuses (`AI_ASSISTANCE`, `TECH_REQUIRED`, `RESOLVED`, `ARCHIVED`), ranked using LexoRank to establish initial sort order.
- **`onHoldCustom()`** — Returns a single `CUSTOM`-kind `TicketStatusDefinition` for an "On Hold" status, positioned at the LexoRank middle. Intended as a default custom status for tenant seeding.

## Usage Example

```java
// Seed all system-level statuses during tenant provisioning
List<TicketStatusDefinition> defaults = TicketStatusSeedCatalog.systemStatuses();
ticketStatusRepository.saveAll(defaults);

// Optionally add the default custom "On Hold" status
TicketStatusDefinition onHold = TicketStatusSeedCatalog.onHoldCustom();
ticketStatusRepository.save(onHold);
```

## Notes

- The class is `final` with a private constructor — it is a non-instantiable utility.
- LexoRank positions are computed relative to `LexoRank.middle()`, establishing a sensible default ordering: `AI_ASSISTANCE → TECH_REQUIRED → [middle] → RESOLVED → ARCHIVED`.
- The `CUSTOM` kind used in `onHoldCustom()` allows tenants to modify or extend this status without affecting system-managed ones.
