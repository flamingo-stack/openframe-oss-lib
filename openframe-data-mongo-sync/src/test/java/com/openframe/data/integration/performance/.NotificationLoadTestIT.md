Integration test that benchmarks MongoDB query performance for the notification system under high-volume data conditions (up to 1 million documents), measuring latency for inbox listing, search, bulk updates, and unread count aggregations.

## Key Components

| Component | Description |
|---|---|
| `TOTAL` | Configurable target document count (default: 1,000,000 via `-Dnotification.loadtest.total`) |
| `HOT_SLICES` | Inbox sizes tested: 100, 1K, 10K, 100K notifications per user |
| `SPARSE_SLICE` | 30K-notification user with ~1% search hit rate (configurable via `-Dnotification.loadtest.sparse`) |
| `seed()` | `@BeforeAll` setup: drops collections, ensures indexes, bulk-inserts test data across hot, sparse, and noise recipient buckets |
| `captureEnvironment()` | Records JVM, OS, CPU, heap, and MongoDB version metadata into the perf report |
| `installSectionDescriptions()` | Attaches human-readable scenario descriptions to the `PerfResultRecorder` |
| `PerfResultRecorder` | Collects timing samples and writes structured performance reports to `target/perf-results/` |
| `BatchInserter` | Internal helper that buffers documents and flushes in 5,000-document batches |

### Performance Budgets

| Scenario | Budget |
|---|---|
| List (inbox page) | 500 ms |
| Search | 1,500 ms |
| Bulk mark-as-read | 5,000 ms |

## Usage Example

```bash
# Run load tests (disabled by default, requires explicit opt-in)
./mvnw verify -Dloadtest.tests=true -Dnotification.loadtest.total=500000

# Override sparse slice size
./mvnw verify -Dloadtest.tests=true -Dnotification.loadtest.sparse=10000
```

```java
// The test class is activated only when the system property is set
@EnabledIfSystemProperty(named = "loadtest.tests", matches = "true")
@Tag("loadtest")
class NotificationLoadTestIT extends BaseMongoIntegrationTest { ... }
```

> **Note:** Load tests are gated behind `-Dloadtest.tests=true` and tagged `loadtest` to prevent accidental execution in standard CI pipelines. Results are written to `target/perf-results/`.
