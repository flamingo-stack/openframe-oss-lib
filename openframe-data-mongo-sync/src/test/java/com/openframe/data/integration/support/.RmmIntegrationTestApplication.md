Minimal Spring Boot test application context for RMM repository integration tests. It restricts MongoDB repository scanning to the RMM package and explicitly imports custom repository fragment implementations that Spring Data cannot auto-detect.

## Key Components

| Element | Description |
|---|---|
| `@SpringBootConfiguration` | Marks this as a lightweight Spring Boot configuration (not a full `@SpringBootApplication`) |
| `@EnableAutoConfiguration` | Enables Spring Boot's auto-configuration for MongoDB and related infrastructure |
| `@EnableMongoAuditing` | Activates `@CreatedDate` / `@LastModifiedDate` population, matching production behaviour |
| `@EnableMongoRepositories` | Scopes repository scanning to the RMM package via `ScriptRepository.class` as the base anchor |
| `@Import` | Manually registers `CustomScriptRepositoryImpl` and `CustomScriptScheduleRepositoryImpl`, which are not picked up by `@EnableMongoRepositories` fragment resolution in test contexts |

## Usage Example

```java
// Reference this configuration in an RMM repository integration test
@DataMongoTest
@Import(RmmIntegrationTestApplication.class)
class ScriptRepositoryIT {

    @Autowired
    private ScriptRepository scriptRepository;

    @Test
    void shouldPersistAndAuditScript() {
        Script script = new Script("backup-job", "echo hello");
        Script saved = scriptRepository.save(script);

        assertThat(saved.getCreatedDate()).isNotNull();
        assertThat(saved.getLastModifiedDate()).isNotNull();
    }
}
```

> **Why not use the shared `IntegrationTestApplication`?**
> Restricting to the RMM package prevents unrelated repositories (notifications, organizations, etc.) from being wired into the test context, keeping test startup fast and dependencies minimal.
