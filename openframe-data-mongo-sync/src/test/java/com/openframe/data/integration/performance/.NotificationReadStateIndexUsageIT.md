Integration test that validates MongoDB index usage and query performance for the `NotificationReadState` collection, ensuring that key read/write operations against notification data use appropriate indexes rather than collection scans.

## Key Components

| Component | Description |
|---|---|
| `NotificationReadStateIndexUsageIT` | Main test class extending `BaseMongoIntegrationTest`; runs only when `performance.tests=true` system property is set |
| `seed()` / `@BeforeAll` | Drops and re-seeds `notifications` and `notification_read_states` collections with configurable volumes (default: 30k notifications, 3k hot-admin read states, 1k hot-machine read states, 20k noise records) |
| `PerfResultRecorder` | Captures execution metrics and writes a Markdown performance report to `target/perf-results` |
| `MongoExplain` | Utility wrapping MongoDB's `explain()` to assert index usage and execution stats |

### Test Coverage

| Test | Index Asserted |
|---|---|
| `list_for_recipient_step_one_uses_indexed_plan` | `recipient_notification_unique` or `recipient_status` |
| `list_for_recipient_machine_uses_indexed_plan` | `recipient_notification_unique` or `recipient_status` |
| `has_unread_uses_recipient_status_index` | `recipient_status`, max 2 keys examined |
| `mark_read_uses_unique_compound_index` | `recipient_notification_unique`, max 1 key examined |
| `mark_all_as_read_uses_recipient_status_index` | `recipient_status` |
| `unread_counts_by_category_uses_recipient_category_status_index` | `recipient_category_status` or `recipient_status` |

## Usage Example

```bash
# Run performance tests with custom dataset sizes
mvn verify -Dperformance.tests=true \
  -Dperf.notifications.count=50000 \
  -Dperf.readStates.hotAdmin=5000 \
  -Dperf.readStates.hotMachine=2000 \
  -Dperf.readStates.noise=30000
```

```java
// All index assertions follow this pattern via MongoExplain.Stats
Stats stats = MongoExplain.explainFind(mongoTemplate, READS_COLL, query);

stats.assertNoCollectionScan()
     .assertUsesIndex(IDX_RECIPIENT_STATUS)
     .assertExecutionTimeBelow(FIND_BUDGET_MS)
     .assertExaminedAtMost(2);
```

Performance budgets: **200 ms** for reads, **100 ms** for writes. Reports are written to `target/perf-results/` after all tests complete.
