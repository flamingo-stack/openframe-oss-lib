Integration test suite for `CommandExecutionRepository`, validating MongoDB persistence, query methods, and compound unique index enforcement for the `CommandExecution` document.

## Key Components

| Component | Description |
|---|---|
| `CommandExecutionRepositoryIT` | Main test class extending `BaseMongoIntegrationTest`, gated by `integration.tests=true` system property |
| `resetCollection()` | `@BeforeEach` hook that clears documents while preserving indexes to avoid index recreation overhead |
| `save_assignsIdAndRoundTrips` | Verifies MongoDB ID assignment and field round-trip on save |
| `findByMachineIdAndExecutionId_returnsTheUniqueRow` | Validates exact-pair lookup and negative case for mismatched execution ID |
| `findByExecutionId_returnsAllRowsOfBatch` | Confirms batch scoping — rows from other executions do not leak into results |
| `uniqueIndex_rejectsDuplicateMachineAndExecution` | Asserts `DuplicateKeyException` on duplicate `(machineId, executionId)` pairs |
| `uniqueIndex_allowsDifferentPairs` | Confirms index uniqueness is on the composite pair, not individual fields |
| `newRow(machineId, executionId)` | Builder helper producing a `RUNNING` `CommandExecution` fixture under `tenant-a` |

## Usage Example

```java
// Run integration tests with the required system property
// mvn verify -Dintegration.tests=true

// Typical assertion pattern used in this suite
CommandExecution saved = repository.save(newRow("machine-1", "exec-1"));
assertThat(saved.getId()).isNotBlank();
assertThat(saved.getStatus()).isEqualTo(ExecutionStatus.RUNNING);

// Compound unique index enforcement
repository.save(newRow("machine-1", "exec-1"));
assertThatThrownBy(() -> repository.save(newRow("machine-1", "exec-1")))
    .isInstanceOf(DuplicateKeyException.class);
```

> **Note:** `resetCollection()` uses `MongoTemplate.remove()` rather than `dropCollection()` to preserve the compound unique index between test runs. Dropping the collection would require a full application restart to recreate indexes.
