Integration test suite for `CustomScriptExecutionRepositoryImpl`, verifying MongoDB-backed cursor pagination, tenant isolation, status/initiator filtering, and sort field validation using Testcontainers via a real `MongoTemplate`.

## Key Components

- **`ScriptExecutionRepositoryIT`** — Main test class extending `BaseMongoIntegrationTest`, activated only when system property `integration.tests=true`.
- **`resetCollection()`** — `@BeforeEach` cleanup that removes all documents while preserving indexes.
- **`countForScript` tests** — Verify row counts scoped by tenant, script ID, status filters, and initiator filters.
- **`findPageForScript` tests** — Cover forward/backward cursor pagination, DESC/ASC ordering, row limits, tenant isolation, invalid cursor fallback, and combined filter+cursor predicates.
- **`sortAllowlistAndDefault`** — Validates that only `dispatchedAt`, `finishedAt`, `statusChangedAt`, and `_id` are accepted as sort fields; arbitrary fields and `null` are rejected.

## Usage Example

```java
// Forward pagination: first page, newest-first (no cursor)
List<ScriptExecution> page = repository.findPageForScript(
    "tenant-a", "script-1",
    null,               // no filter
    "_id",              // sort field
    Sort.Direction.DESC,
    null,               // no cursor → first page
    false,              // forward direction
    10,                 // limit
    null
);

// Next page using last row's ID as cursor
List<ScriptExecution> nextPage = repository.findPageForScript(
    "tenant-a", "script-1", null,
    "_id", Sort.Direction.DESC,
    page.get(page.size() - 1).getId(),  // cursor
    false, 10, null
);

// Count with status filter
long count = repository.countForScript(
    "tenant-a", "script-1",
    ScriptExecutionQueryFilter.builder()
        .statuses(List.of(ExecutionStatus.SUCCESS, ExecutionStatus.FAILED))
        .build(),
    null
);
```
