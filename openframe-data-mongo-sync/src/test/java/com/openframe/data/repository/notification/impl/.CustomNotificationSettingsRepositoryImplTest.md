Unit tests for `CustomNotificationSettingsRepositoryImpl`, verifying upsert behavior and duplicate-key race condition handling when toggling push notification settings per user.

## Key Components

| Component | Description |
|---|---|
| `disabling_push_upserts_by_user_id` | Asserts that `setPushEnabled` issues a MongoDB upsert filtered by `userId`, sets `pushEnabled` via `$set`, and seeds `createdAt` only on insert via `$setOnInsert` |
| `lost_insert_race_settles_with_a_plain_update` | Asserts that when a concurrent insert loses to a unique index constraint (`E11000 DuplicateKeyException`), the repository falls back to `updateFirst` rather than surfacing the exception |

## Usage Example

```java
// Arrange
TenantAwareMongoTemplate mongoTemplate = mock(TenantAwareMongoTemplate.class);
CustomNotificationSettingsRepositoryImpl repository =
    new CustomNotificationSettingsRepositoryImpl(mongoTemplate);

when(mongoTemplate.upsert(any(Query.class), any(Update.class), eq(NotificationSettings.class)))
    .thenReturn(mock(UpdateResult.class));

// Act
repository.setPushEnabled("alice", false);

// Assert — upsert query contains the userId
ArgumentCaptor<Query> query = ArgumentCaptor.forClass(Query.class);
ArgumentCaptor<Update> update = ArgumentCaptor.forClass(Update.class);
verify(mongoTemplate).upsert(query.capture(), update.capture(), eq(NotificationSettings.class));

assertThat(query.getValue().getQueryObject().toJson()).contains("alice");
assertThat(update.getValue().getUpdateObject().get("$set").toString())
    .contains("pushEnabled=false");
assertThat(update.getValue().getUpdateObject().get("$setOnInsert").toString())
    .contains("createdAt");
```

## Notes

- The tenant filter is injected by `TenantAwareMongoTemplate`, not by the repository itself — tests only assert on `userId` presence in the query.
- The duplicate-key fallback path ensures at-least-once settlement semantics in concurrent environments without exposing the exception to callers.
