Unit tests for the `NotificationSettingsRepository.findPushDisabledUserIds` default method, verifying short-circuit behavior on empty audiences and correct filtering of explicitly disabled users.

## Key Components

| Method | Description |
|---|---|
| `empty_audience_issues_no_query()` | Asserts that passing an empty collection returns an empty set without delegating to the underlying `findByUserIdInAndPushEnabledFalse` query |
| `only_explicitly_disabled_users_are_returned()` | Asserts that only users with a `pushEnabled=false` settings document are returned — users with no document are treated as enabled by default |

## Usage Example

```java
// Simulates the default method logic under test:
// Empty audience → no DB call
Set<String> result = repository.findPushDisabledUserIds(List.of());
// result is empty, findByUserIdInAndPushEnabledFalse is never invoked

// Mixed audience → only disabled users returned
Set<String> disabled = repository.findPushDisabledUserIds(List.of("u1", "u2"));
// disabled == {"u1"} (u2 has no settings document → push enabled by default)
```

## Notes

- Uses Mockito's `thenCallRealMethod()` to exercise the default interface method while mocking the delegate query method.
- The "no settings document = push enabled" contract is a behavioral invariant enforced here at the repository layer.
- See [`NotificationSettingsRepository`](https://github.com/flamingo-stack/openframe-oss-lib/blob/main/src/main/java/com/openframe/data/repository/notification/NotificationSettingsRepository.java) for the production interface.
