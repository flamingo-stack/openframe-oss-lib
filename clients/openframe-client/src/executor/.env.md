Utilities for parsing and applying environment variable strings to a `tokio::process::Command`, ensuring only well-formed `KEY=VALUE` pairs are forwarded to child processes.

## Key Components

- **`split_env(var: &str) -> Option<(&str, &str)>`** — Splits a `"KEY=VALUE"` string on the first `=`, returning `(key, value)` or `None` if no `=` is present. Values containing additional `=` characters are preserved intact.

- **`apply_env_vars(cmd: &mut Command, env_vars: &[String])`** — Iterates a slice of env var strings, calling `split_env` on each and setting valid pairs on the command via `cmd.env()`. Malformed entries (missing `=` or empty key) are skipped with a `tracing::warn!` log rather than panicking.

## Usage Example

```rust
use tokio::process::Command;
use crate::env::apply_env_vars;

let mut cmd = Command::new("my-binary");
let vars = vec![
    "DATABASE_URL=postgres://localhost/mydb".to_string(),
    "DEBUG=true".to_string(),
    "MALFORMED_NO_EQUALS".to_string(), // skipped with a warning
    "=EMPTY_KEY".to_string(),          // skipped with a warning
];

apply_env_vars(&mut cmd, &vars);
// cmd now has DATABASE_URL and DEBUG set; malformed entries are warned and dropped
```

## Behavior Notes

- Uses `split_once('=')` so only the **first** `=` is treated as the delimiter; `K=a=b` correctly yields key `K` and value `a=b`.
- Empty keys (e.g., `=VALUE`) are explicitly rejected even though `split_once` would produce a `Some(("", "VALUE"))`.
- Designed as `pub(crate)` — internal to the crate, not part of the public API.
