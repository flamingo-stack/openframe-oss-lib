Utilities for safely reading and sanitizing command output from async streams, enforcing a 10 MiB cap and producing clean UTF-8 strings.

## Key Components

- **`MAX_OUTPUT_SIZE`** — Module-level constant capping output at 10 MiB (`10 * 1024 * 1024` bytes).
- **`read_capped`** — Async function that reads from an optional `AsyncRead` source up to `MAX_OUTPUT_SIZE`. If the cap is reached, it logs a warning and drains the remaining bytes to `/dev/null` to avoid blocking the producer.
- **`clean_string`** — Converts a byte slice to a `String` by removing null bytes (`\x00`) and silently dropping invalid UTF-8 sequences (rather than substituting replacement characters).

## Usage Example

```rust
use tokio::process::Command;

let mut child = Command::new("ls")
    .arg("-la")
    .stdout(std::process::Stdio::piped())
    .spawn()?;

let stdout = child.stdout.take();
let raw_bytes = read_capped(stdout).await;
let output = clean_string(&raw_bytes);

println!("{}", output);
```

```rust
// Standalone string cleaning
let dirty: Vec<u8> = vec![104, 101, 0, 108, 108, 111, 0xFF];
let clean = clean_string(&dirty);
// → "hello"  (null and invalid UTF-8 byte silently dropped)
```

## Notes

- `read_capped` returns an empty `Vec` when passed `None`, making it safe for optional stdio handles.
- `clean_string` trims the slice to a valid UTF-8 boundary before processing if it exceeds `MAX_OUTPUT_SIZE`, preventing split multi-byte characters.
- Invalid UTF-8 sequences are **dropped** (not replaced with `U+FFFD`), but valid `U+FFFD` characters already present in the input are preserved.
