Launches scripts as the active Windows interactive user by acquiring a WTS session token and spawning a child process via `CreateProcessAsUserW`, with stdout/stderr redirected to temporary files.

## Key Components

- **`run_as_interactive`** — Async entry point; builds the command line, creates temp output paths, and offloads the blocking Win32 work to `spawn_blocking`.
- **`run_as_blocking`** — Core synchronous logic: acquires a session token, creates inheritable file handles for stdio, constructs the environment block, spawns the process in suspended state inside a job object, waits up to `timeout_secs`, then reads capped output files.
- **`InteractiveToken`** — RAII wrapper around a duplicated primary `HANDLE`. Calls `WTSGetActiveConsoleSessionId` / `WTSQueryUserToken` then `DuplicateTokenEx` to obtain a primary token usable with `CreateProcessAsUserW`. Falls back to enumerating all WTS sessions if the console session query fails.
- **`build_env_block`** — Merges the user's environment (from `CreateEnvironmentBlock`) with caller-supplied overrides, deduplicating by key (case-insensitive), and serialises to a double-null-terminated UTF-16 block.
- **`build_command_line`** / **`quote`** — Assembles and Windows-escapes the interpreter + script path + arguments following the `CommandLineToArgvW` quoting rules (backslash doubling before closing quotes).
- **`first_active_session_token`** — Enumerates WTS sessions and returns a token for the first `WTSActive` session when the console session is unavailable.

## Usage Example

```rust
let result = run_as_interactive(
    &interpreter,   // &Interpreter { exe, flags, .. }
    &tmp_script,    // &Path to the temp script file
    &ScriptParams {
        args: &[],
        timeout_secs: 60,
        env_vars: &["MY_VAR=value".to_string()],
        ..
    },
)
.await;
```

> **Platform note:** This module is Windows-only. It requires the calling process to hold `SeTcbPrivilege` (or equivalent) so that `WTSQueryUserToken` and `CreateProcessAsUserW` succeed.
