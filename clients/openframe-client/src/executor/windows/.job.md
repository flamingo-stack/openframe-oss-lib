Windows Job Object wrapper that manages process group lifecycle, enabling kill-on-close semantics and whole-process-tree termination on Windows.

## Key Components

### `JobHandle`

A RAII wrapper around a Windows `HANDLE` to a Job Object (`Option<HANDLE>`). Automatically closes the handle via `Drop`.

**Private methods:**

- **`create() -> Option<HANDLE>`** — Creates a new anonymous Job Object and configures `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, so all assigned processes are killed when the last handle is closed. Returns `None` on failure, logging a warning if the limit flag cannot be set.

**Public methods:**

- **`for_pid(pid: u32) -> Self`** — Opens a process by PID (with `PROCESS_TERMINATE | PROCESS_SET_QUOTA`) and assigns it to a new Job Object. Returns an empty `JobHandle(None)` if PID is `0`, job creation fails, or process assignment fails (degraded to single-process kill).

- **`for_handle(process: HANDLE) -> Self`** — Assigns an already-open process handle to a new Job Object. Useful when a `HANDLE` is available directly (e.g., from `CreateProcess`).

- **`terminate(&self)`** — Immediately terminates all processes in the job via `TerminateJobObject` with exit code `1`.

## Usage Example

```rust
// Assign a spawned process (by PID) to a job and terminate the whole tree
let job = JobHandle::for_pid(child_pid);
// ... later, kill all processes in the tree
job.terminate();
// Handle is automatically closed when `job` drops

// Or use an existing HANDLE (e.g., from CreateProcess)
let job = JobHandle::for_handle(process_handle);
job.terminate();
```

> **Platform note:** This module is Windows-only and relies on `windows-rs` bindings. When `JobHandle(None)` is returned, `terminate()` is a no-op and kill behavior degrades to single-process termination.
