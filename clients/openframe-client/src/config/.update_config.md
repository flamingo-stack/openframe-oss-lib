Configuration constants for the OpenFrame update system, defining timeouts, retry policies, concurrency limits, and safety parameters governing binary downloads, NATS messaging, and the last-known-good update ratchet.

## Key Components

| Constant | Value | Purpose |
|---|---|---|
| `MAX_DOWNLOAD_RETRIES` | `3` | Download attempt limit before failure |
| `DOWNLOAD_TIMEOUT_SECS` | `300` | Binary download timeout (5 min) |
| `MIN_BINARY_SIZE_BYTES` | `100 KB` | Sanity check for downloaded binaries |
| `HTTP_CLIENT_TIMEOUT_SECS` | `120` | Timeout for control-plane requests |
| `DOWNLOAD_CLIENT_TIMEOUT_SECS` | `300` | Timeout for binary source requests |
| `CONSUMER_RETRY_ATTEMPTS_PER_CYCLE` | `5` | NATS consumer retries per cycle |
| `INITIAL_RETRY_DELAY_MS` / `MAX_RETRY_DELAY_MS` | `1s` / `30s` | Exponential backoff bounds |
| `CONSUMER_CYCLE_PAUSE_MS` | `30s` | Pause between retry cycles |
| `RECONNECTION_DELAY_MS` | `5s` | Delay before NATS reconnect |
| `EXECUTION_MIN_CONCURRENCY` | `4` | Minimum concurrent executions |
| `BOOT_MARKER_WAIT_SECS` | `90` | New binary boot verification window |
| `CRASH_LOOP_MAX_BOOT_ATTEMPTS` | `3` | Unverified boots before rollback |
| `ALLOW_DOWNGRADE` | `false` | Blocks LKG ratchet downgrades |
| `UPDATER_TRANSCRIPTS_KEPT` | `5` | Update attempt logs retained |
| `TEMP_LEFTOVER_MIN_AGE_SECS` | `3600` | Temp file sweep minimum age |
| `CONSUMER_ACK_WAIT_SECS` | `120` | NATS ACK deadline |
| `CONSUMER_MAX_DELIVER` | `10` | Standard NATS redelivery cap |
| `UNINSTALL_CONSUMER_MAX_DELIVER` | `20` | Extended budget for uninstall ops |
| `RESTART_CONSUMER_MAX_DELIVER` | `20` | Extended budget for restart ops |
| `CLIENT_UPDATE_PENDING_TTL_SECS` | `300` | Client-before-tool ordering flag TTL |
| `PROGRESS_ACK_INTERVAL_SECS` | `60` | In-progress ACK heartbeat interval |

## Usage Example

```rust
use crate::update_config::{
    MAX_DOWNLOAD_RETRIES,
    INITIAL_RETRY_DELAY_MS,
    MAX_RETRY_DELAY_MS,
    BOOT_MARKER_WAIT_SECS,
    ALLOW_DOWNGRADE,
};

// Enforce downgrade protection before applying an update
if target_version < lkg_version && !ALLOW_DOWNGRADE {
    return Err(UpdateError::DowngradeRefused);
}

// Exponential backoff within configured bounds
let delay = (INITIAL_RETRY_DELAY_MS * 2u64.pow(attempt))
    .min(MAX_RETRY_DELAY_MS);

// Wait for the new binary to signal a clean boot
tokio::time::timeout(
    Duration::from_secs(BOOT_MARKER_WAIT_SECS),
    wait_for_boot_marker(),
).await?;
```

> **Note:** `CLIENT_UPDATE_PENDING_TTL_SECS` (300 s) is intentionally larger than `CONSUMER_ACK_WAIT_SECS` (120 s) to ensure the client-before-tool ordering flag survives NATS redelivery gaps during deferred client updates.
