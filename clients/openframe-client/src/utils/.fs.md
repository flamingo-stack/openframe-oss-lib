Provides a single public utility function for safe, atomic file writes that prevent torn reads during concurrent access.

## Key Components

### `atomic_write(path, contents) -> Result<()>`

Writes arbitrary bytes to a file path using a **temp-file + rename** strategy:

1. Creates all parent directories if they don't exist
2. Writes contents to a `NamedTempFile` in the **same directory** as the target (ensures same filesystem, avoiding cross-device rename failures)
3. On Unix, explicitly sets permissions to `0o644` (overriding `NamedTempFile`'s default `0o600`) so unprivileged processes can read the file
4. Calls `persist()` which performs an atomic rename (`rename(2)` on Unix, `MoveFileEx` on Windows), replacing any existing file at the target path

## Usage Example

```rust
use std::path::Path;
use openframe_oss_lib::fs::atomic_write;

fn save_token(token: &[u8]) -> anyhow::Result<()> {
    atomic_write(Path::new("/var/lib/myapp/token.enc"), token)?;
    Ok(())
}
```

## Behavior Notes

| Concern | Behavior |
|---|---|
| Concurrent readers | Never observe a partial write — rename is atomic |
| Pre-existing restrictive permissions (`0o600`) | Overwritten with `0o644` on next write (Unix only) |
| Missing parent directories | Auto-created via `create_dir_all` |
| Cross-platform | Atomic on both Unix and Windows |

## Tests

The included Unix-only test (`atomic_write_sets_644_and_self_heals`) validates two invariants:
- New files are created with `0o644` permissions
- A pre-existing `0o600` file is corrected to `0o644` on the next write, not preserved
