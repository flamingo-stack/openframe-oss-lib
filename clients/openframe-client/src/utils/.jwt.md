Lightweight JWT utility for extracting the `exp` and `iat` claims from a token's payload without performing signature verification.

## Key Components

| Item | Kind | Description |
|---|---|---|
| `token_times_unix` | `pub fn` | Decodes a JWT's `exp` (required) and `iat` (optional) claims from the payload segment as Unix timestamps, returning `None` for malformed tokens or a missing `exp` |
| `JwtTimes` | `pub struct` | `exp: i64`, `iat: Option<i64>`; `ttl_secs()` returns the issuer-granted lifetime (`exp − iat`) when `iat` is present and the lifetime is positive |

## Usage Example

```rust
use openframe::utils::jwt::token_times_unix;

let token = "eyJhbGciOiJIUzI1NiJ9.eyJpYXQiOjE2OTk5OTY0MDAsImV4cCI6MTcwMDAwMDAwMH0.sig";

match token_times_unix(token) {
    Some(times) => match times.ttl_secs() {
        Some(ttl) => println!("Token lives {ttl}s, expires at Unix timestamp {}", times.exp),
        None => println!("Token expires at Unix timestamp {} (no iat)", times.exp),
    },
    None => eprintln!("Malformed token or missing exp claim"),
}
```

## Behaviour Notes

- **No signature verification** — intended for scheduling and expiry pre-checks only; always verify the signature through a proper JWT library before trusting any claims.
- **Lifetime, not wall clock** — `ttl_secs()` is server-relative (`exp − iat`), which is what a refresh timer should use; comparing `exp` with the device clock breaks when that clock is skewed.
- **Strict segment validation** — requires exactly three `.`-separated parts (`header.payload.signature`); tokens with fewer or extra segments return `None`.
- **Tolerant Base64 padding** — trailing `=` padding is stripped before decoding to handle both padded and unpadded URL-safe Base64 variants.
