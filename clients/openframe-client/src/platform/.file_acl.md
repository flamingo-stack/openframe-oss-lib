Provides Windows ACL management for file system paths, exposing two async operations: making paths fully writable and hardening executables to admin-only access. On non-Windows platforms both functions are no-ops.

## Key Components

| Function | Description |
|---|---|
| `ensure_writable(path)` | Clears read-only/system/hidden attributes via `attrib`, takes ownership via `takeown`, then grants full control to Administrators (`S-1-5-32-544`) and SYSTEM (`S-1-5-18`) using `icacls` — recursively. |
| `harden_executable(path)` | Transfers ownership to the Administrators group, removes inherited ACEs, grants full control to SYSTEM and Administrators, and restricts Users (`S-1-5-32-545`) to read+execute only. |

Both functions are **Windows-only** (`#[cfg(target_os = "windows")]`) with silent no-op stubs for Linux/macOS.

## Usage Example

```rust
use std::path::Path;

// Before overwriting a protected directory (e.g., during agent self-update)
let target = Path::new(r"C:\Program Files\my-agent");
ensure_writable(target).await?;

// After writing a new executable, lock it down
let exe = Path::new(r"C:\Program Files\my-agent\agent.exe");
harden_executable(exe).await?;
```

## Notes

- All subprocess failures are **logged as warnings** (`tracing::warn!`) rather than propagated as errors — the function always returns `Ok(())`. Callers should treat subsequent file operations as the real success signal.
- `ensure_writable` applies flags **recursively** (`/S /D` for `attrib`, `/R` for `takeown`, `/T` for `icacls`).
- `harden_executable` uses `/inheritance:r` to strip inherited ACEs before applying explicit grants, preventing overly permissive inherited rules from surviving.
- SID constants used: `S-1-5-18` = SYSTEM, `S-1-5-32-544` = Administrators, `S-1-5-32-545` = Users.
