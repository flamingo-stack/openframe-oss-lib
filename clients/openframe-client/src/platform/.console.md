Provides cross-platform console configuration, enabling ANSI/VT escape code processing and UTF-8 output on Windows while compiling to a no-op on all other platforms.

## Key Components

- **`configure_console()`** — Public function that configures the console environment. On non-Windows targets, this is an empty no-op. On Windows, it:
  - Enables `ENABLE_VIRTUAL_TERMINAL_PROCESSING` via `SetConsoleMode` to support ANSI color/escape sequences
  - Sets the console output code page to UTF-8 (`CP_UTF8 = 65001`) via `SetConsoleOutputCP`
- **`windows` module** — Internal `#[cfg(target_os = "windows")]`-gated module containing the Windows-specific implementation using `winapi`

## Usage Example

Call `configure_console()` once at application startup, before any terminal output:

```rust
fn main() {
    openframe_oss_lib::console::configure_console();

    // ANSI colors and UTF-8 output now work correctly on Windows
    println!("\x1b[32mSuccess!\x1b[0m");
}
```

## Notes

- Requires the `winapi` crate (with `consoleapi`, `processenv`, `winbase`, `wincon` features) on Windows builds
- The `GetConsoleMode` check prevents the mode update if stdout is not a real console (e.g., when output is redirected to a file or pipe)
- Safe to call unconditionally across platforms — the no-op stub on non-Windows targets ensures zero overhead
