One-time Windows startup migration that repairs the `PATH` registry value type from `REG_SZ` back to `REG_EXPAND_SZ`, restoring `%SystemRoot%` variable expansion for system tools.

## Key Components

### `run() -> ()`

The sole public function. Safe to call on every application startup — exits early without modification if:

- The `PATH` value type is already `REG_EXPAND_SZ` (no prior corruption)
- The `PATH` string contains no `%` characters (no variables to expand)

When corruption is detected (`REG_SZ` + `%` variables present), it re-encodes the existing path string as UTF-16 LE and writes it back under `REG_EXPAND_SZ`. Errors are logged as warnings and never panic the caller.

**Registry key targeted:**
```text
HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Session Manager\Environment
```

## Root Cause Context

Previous OpenFrame versions used `set_value()` (winreg crate), which silently writes `REG_SZ` regardless of the original type. This clobbers `REG_EXPAND_SZ`, causing `%SystemRoot%\System32` and similar paths to be treated as literals — making `ping.exe`, `ipconfig.exe`, and other system tools unreachable at runtime.

## Usage Example

Call once at application startup before any subprocess or PATH-dependent logic:

```rust
fn main() {
    // Initialize tracing first so repair logs are captured
    tracing_subscriber::fmt::init();

    // Repair PATH registry type if corrupted by a previous install
    windows_path_migration::run();

    // ... rest of OpenFrame startup
}
```

## Notes

- **Windows-only** — references `winreg` and `HKEY_LOCAL_MACHINE`; guard with `#[cfg(target_os = "windows")]` at the call site if the binary targets multiple platforms
- Requires write access to `HKLM\...\Environment`; runs under the OpenFrame service account which holds the necessary privileges
- Source: [`windows_path_migration.rs`](https://github.com/flamingo-stack/openframe-oss-lib/blob/main/windows_path_migration.rs)
