Async DMG extractor that mounts, copies, and unmounts Apple Disk Image (`.dmg`) files on macOS using `hdiutil` and `cp -R`. On non-macOS targets, all extraction attempts return an error.

## Key Components

- **`DmgExtractor`** — Cloneable unit struct; implement `Default` via `new()`.
- **`extract_all(dmg_bytes, target_dir, source_path)`** — Primary public method. Writes bytes to a temp file, mounts the image, optionally scopes to a sub-path within the mount, copies contents to `target_dir`, then cleans up regardless of copy success.
- **`mount(dmg_path, mount_point)`** *(macOS only)* — Invokes `hdiutil attach -nobrowse -readonly -mountpoint`.
- **`unmount(mount_point)`** *(macOS only)* — Invokes `hdiutil detach -quiet`, then removes the mount directory.
- **`copy_recursive(source, target)`** *(macOS only)* — Shells out to `cp -R` to preserve symlinks and resource forks.

## Usage Example

```rust
use bytes::Bytes;
use std::path::Path;

let extractor = DmgExtractor::new();
let dmg_bytes = Bytes::from(std::fs::read("MyApp.dmg")?);
let target = Path::new("/Applications");

// Copy just the .app bundle inside the DMG
extractor
    .extract_all(dmg_bytes, target, Some("MyApp.app"))
    .await?;

// Copy the entire DMG volume contents
extractor
    .extract_all(dmg_bytes, target, None)
    .await?;
```

## Notes

- **macOS only** — The `#[cfg(target_os = "macos")]` gate means `extract_all` returns `Err` at runtime on Linux/Windows; the internal helpers are not compiled at all.
- Temp files and mount points are UUIDs under `std::env::temp_dir()` to avoid collisions.
- Cleanup (unmount + temp file removal) runs even on copy failure; the original copy error is still returned.
