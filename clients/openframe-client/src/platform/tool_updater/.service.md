Implements the `ServiceToolUpdater` struct, which handles the full update lifecycle (prepare → apply → finalize → rollback) for tools installed as system services, including special handling for macOS `.app` bundles.

## Key Components

- **`ServiceToolUpdater`** — Main struct implementing the `ToolUpdater` trait for service-managed tools.
- **`resolve_executable_path`** — Resolves the actual binary path from the tool's `Installation::Service` metadata, supporting both absolute paths and paths relative to the agent directory.
- **`is_app_bundle_download`** — Helper (macOS-only code path) that detects whether a `DownloadConfiguration` targets a `.app` bundle based on the target file name.
- **`prepare`** — Stops the running service and any managed processes, waits 2 seconds, then creates a binary backup (skipped for `.app` bundles, which are protected and large).
- **`apply`** — On macOS with `.app` bundles: removes the old bundle and extracts the full archive. For standard tools: downloads and overwrites the single binary.
- **`finalize`** — Starts the system service by name and cleans up the backup file.
- **`rollback`** — Restores the binary from backup (or warns if none exists for `.app` bundles) and attempts to restart the service.

## Usage Example

```rust
use crate::updater::service::ServiceToolUpdater;
use crate::updater::{ToolUpdater, ToolUpdaterDeps};

let updater = ServiceToolUpdater::new(deps);

let ctx = updater.prepare(&installed_tool).await?;
let new_installation = updater.apply(&installed_tool, &download_config, &ctx).await?;
updater.finalize(&installed_tool, &ctx).await?;

// On failure:
updater.rollback(&installed_tool, &ctx).await?;
```

> **Note:** The `.app` bundle path is compiled in only on `target_os = "macos"`. On other platforms, only the standard single-binary update path is active. If rollback is triggered with no backup (i.e., after a `.app` bundle update), a warning is emitted and a server reinstall is required.
