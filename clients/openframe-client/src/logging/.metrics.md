A tracing-integrated metrics collection system that captures counter, gauge, and histogram values from `tracing` events and stores them in a thread-safe, shared `MetricsStore`.

## Key Components

| Item | Description |
|---|---|
| `MetricValue` | Enum representing the three supported metric types: `Counter(u64)`, `Gauge(f64)`, and `Histogram(Vec<f64>)` |
| `Metric` | Struct holding a metric's name, value, label map, and UTC timestamp |
| `MetricsStore` | `HashMap`-backed storage with methods to record and retrieve metrics |
| `MetricsLayer` | A `tracing_subscriber::Layer` that intercepts tracing events and writes extracted metrics to the store |
| `MetricVisitor` | Internal `tracing::field::Visit` implementation that parses field names (`counter`, `gauge`, `histogram`) from events |

## Usage Example

```rust
use tracing_subscriber::prelude::*;
use std::collections::HashMap;

// Create the layer and get a handle to the shared store
let (metrics_layer, store) = MetricsLayer::new();

// Register the layer with tracing
tracing_subscriber::registry()
    .with(metrics_layer)
    .init();

// Emit metrics via tracing events — field name determines metric type
tracing::info!(counter = 1u64, request_id = "abc123");
tracing::info!(gauge = 0.75f64);
tracing::info!(histogram = 42.0f64);

// Read back recorded metrics
let store = store.read().await;
for metric in store.get_metrics() {
    println!("{:?}", metric);
}

// Or record directly without tracing
let mut store = MetricsStore::new();
store.record_counter("http_requests", 100, HashMap::new());
store.record_gauge("cpu_usage", 0.63, HashMap::new());
store.record_histogram("response_time_ms", 120.5, HashMap::new());
```

## Notes

- **Histogram accumulation**: unlike counters and gauges (which overwrite), histogram entries are appended to the existing `Vec<f64>` on each call.
- **Field-name convention**: `MetricVisitor` uses the tracing field name as the metric type signal (`counter`, `gauge`, `histogram`); any additional fields are captured as string labels.
- **Blocking write in async context**: `MetricsLayer::on_event` uses `blocking_write()` — avoid high-frequency tracing in latency-sensitive async paths.
