Manages NATS JetStream log streaming for the OpenFrame agent, handling connection lifecycle, log source discovery, and batched log publishing to the server.

## Key Components

### `NatsLogConnection`
Wraps an `async_nats` JetStream context with tenant-aware connection setup. Connects via WebSocket (`wss://`) with custom headers for tenant routing and machine identification. Handles reconnect callbacks and publishes serialized `LogBatchMessage` payloads to the `agents.logs` subject.

### `LogStreamingRunManager`
Orchestrates the full log streaming lifecycle. Resolves server host, tenant domain, and hostname at construction time, then on `start()`:
- Waits for the initial authentication key before connecting
- Creates a `LogSourceRegistry` seeded with the primary OpenFrame log file
- Spawns source discovery and enters the main streaming loop — all in a detached `tokio::spawn`

### `spawn_source_discovery`
Background task that polls every 30 seconds for Meshcentral installation. Once detected, registers a `FileLogSource` for its log file via an `mpsc` channel into the main loop.

### `log_streaming_loop`
Core event loop ticking every 60 seconds. Drains newly discovered sources, reads up to 50 log entries across all registered sources, and publishes batches to NATS. On publish failure, rolls back source offsets for retry. On success, commits offsets and persists file position.

## Usage Example

```rust
let manager = LogStreamingRunManager::new(
    &initial_config_service,
    &agent_config_service,
    &installed_tools_service,
    &directory_manager,
)?;

manager.start().await?;
```

## Constants

| Constant | Value | Purpose |
|---|---|---|
| `BATCH_INTERVAL_SECS` | 60 | Log flush frequency |
| `MAX_LOGS_PER_BATCH` | 50 | Per-publish log cap |
| `RECONNECT_DELAY_SECS` | 5 | Retry backoff on failure |
| `SOURCE_DISCOVERY_INTERVAL_SECS` | 30 | Meshcentral poll interval |
| `INITIAL_KEY_CHECK_INTERVAL_SECS` | 10 | Auth key readiness poll |
