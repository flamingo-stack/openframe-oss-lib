Listener module aggregator for OpenFrame's event-driven messaging system. Re-exports all listener types used to handle incoming tool lifecycle and client update events.

## Key Components

| Export | Description |
|---|---|
| `ExecutionListener` | Core trait/struct for handling execution-phase events |
| `OpenFrameClientUpdateListener` | Handles client update notifications from the OpenFrame platform |
| `ToolAgentUpdateListener` | Processes agent-level update messages for installed tools |
| `ToolInstallationMessageListener` | Responds to tool installation lifecycle events |
| `ToolRestartMessageListener` | Handles tool restart command messages |
| `ToolUninstallMessageListener` | Responds to tool uninstall command messages |

Also declares `client_update_gate` as a submodule (not re-exported directly), likely used internally to gate or throttle client update processing.

## Usage Example

```rust
use listeners::{
    ExecutionListener,
    OpenFrameClientUpdateListener,
    ToolInstallationMessageListener,
    ToolRestartMessageListener,
    ToolUninstallMessageListener,
    ToolAgentUpdateListener,
};

// Register listeners with your message dispatcher
let install_listener = ToolInstallationMessageListener::new(/* ... */);
let restart_listener = ToolRestartMessageListener::new(/* ... */);
let uninstall_listener = ToolUninstallMessageListener::new(/* ... */);
```

## Notes

- All public listener types follow a consistent message-handler pattern suited for async MSP tool orchestration within [OpenFrame](https://openframe.ai).
- The `client_update_gate` submodule is available for internal use but not part of the public API surface.
- See the [source on GitHub](https://github.com/flamingo-stack/openframe-oss-lib/blob/main/src/listeners/mod.rs) for the full module tree.
