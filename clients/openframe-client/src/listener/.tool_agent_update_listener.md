Manages a persistent NATS JetStream push consumer that listens for tool agent update messages, handling reconnection, retry logic, and message dispatch with per-tool sequencing.

## Key Components

### `ToolAgentUpdateListener` (struct)
The primary struct holding references to the NATS connection manager, update service, configuration service, and tool run manager.

| Field | Type | Purpose |
|---|---|---|
| `nats_connection_manager` | `NatsConnectionManager` | Manages NATS client lifecycle and reconnect signals |
| `tool_agent_update_service` | `ToolAgentUpdateService` | Processes parsed update messages |
| `config_service` | `AgentConfigurationService` | Retrieves the local machine ID |
| `tool_run_manager` | `ToolRunManager` | Gates concurrent dispatch per tool via `park_or_dispatch` |

### Key Methods

- **`start()`** — Spawns a background `tokio` task that loops indefinitely, restarting `listen()` after `RECONNECTION_DELAY_MS` on any exit or error.
- **`listen()`** — Creates a JetStream push consumer and drives a `tokio::select!` loop, handling messages and NATS reconnect signals.
- **`handle_message()`** — Deserializes the raw payload into `ToolAgentUpdateMessage`, then calls `park_or_dispatch` keyed on `tool-update:<tool_agent_id>` to serialize updates per tool.
- **`dispatch()`** — Calls `tool_agent_update_service.process_update()` and explicitly acks on success; leaves the message unacked for JetStream redelivery on failure.
- **`create_consumer()`** — Retries consumer creation with exponential backoff within cycles, falling back to fetching an existing durable consumer on name-conflict errors.

### Consumer Configuration (NATS JetStream)

```text
Stream:          TOOL_UPDATE
Filter subject:  machine.all.tool.*.update
Deliver subject: machine.<machine_id>.tool.update.inbox
Durable name:    machine_<machine_id>_tool_update_consumer
Deliver policy:  New
```

## Usage Example

```rust
let listener = ToolAgentUpdateListener::new(
    nats_connection_manager,
    tool_agent_update_service,
    config_service,
    tool_run_manager,
);

// Spawns a self-healing background task
let _handle = listener.start().await?;
```

> Reconnection and retry parameters are governed by constants in [`update_config`](https://github.com/flamingo-stack/openframe-oss-lib/blob/main/src/config/update_config.rs) (e.g. `RECONNECTION_DELAY_MS`, `CONSUMER_MAX_DELIVER`, `MAX_RETRY_DELAY_MS`).
