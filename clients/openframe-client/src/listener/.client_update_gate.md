Provides a gate that holds NATS JetStream messages in a "parked" state during client updates, preventing dispatch until the update completes.

## Key Components

### `park_or_dispatch`

An async function that either immediately dispatches a NATS message or parks it with periodic `Progress` acknowledgements until a pending client update resolves.

**Parameters:**
- `manager: ToolRunManager` — checks whether a client update is currently in progress
- `message: Message` — the NATS JetStream message to dispatch or park
- `label: String` — a human-readable identifier used in log output
- `dispatch: F` — a one-shot async closure invoked with the message once it is safe to proceed

**Behavior:**
- If no update is pending, the dispatch closure is called immediately inline
- If an update is pending, a background task is spawned that sends `AckKind::Progress` to the NATS server every `PROGRESS_ACK_INTERVAL_SECS` seconds, preventing the message from timing out and triggering redelivery
- Once `is_client_update_pending()` returns `false`, the parked message is dispatched
- If a `Progress` ack fails, the park is abandoned and natural NATS redelivery takes over

## Usage Example

```rust
park_or_dispatch(
    tool_run_manager.clone(),
    nats_message,
    "tool_run:abc123".to_string(),
    |msg| async move {
        handle_tool_run(msg).await;
    },
)
.await;
```

## Notes

- The parking loop runs in a detached `tokio::spawn` task, so `park_or_dispatch` returns immediately when parking is required
- Relies on [`PROGRESS_ACK_INTERVAL_SECS`](https://github.com/flamingo-stack/openframe-oss-lib/blob/main/src/config/update_config.rs) for the heartbeat cadence
- Failed acks are treated as non-fatal — NATS redelivery acts as the fallback recovery path
