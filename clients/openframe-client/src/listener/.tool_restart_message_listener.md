Async NATS JetStream push-consumer that listens for tool restart messages on a per-machine subject and drives the `ToolRestartService` to restart managed tools.

## Key Components

### `ToolRestartMessageListener` (struct)
The primary listener type, holding references to the NATS connection manager, restart service, agent configuration, and tool run manager. Implements `Clone` to support `tokio::spawn` ownership transfer.

| Method | Description |
|---|---|
| `new(...)` | Constructs the listener from its four service dependencies |
| `start()` | Spawns a supervised `tokio` task that calls `listen()` in a loop, reconnecting after `RECONNECTION_DELAY_MS` on any exit |
| `listen()` | Inner loop: resolves a NATS client, creates the JetStream push consumer, and drives the `tokio::select!` message pump |
| `handle_message()` | Deserializes a `ToolRestartMessage`, then calls `park_or_dispatch` to serialise concurrent restarts per tool |
| `dispatch()` | Calls `restart_guarded`, maps `RestartOutcome` variants to ACK/no-ACK decisions, and logs results |
| `create_consumer()` | Retry loop with exponential back-off per attempt and a configurable cycle pause; handles the `consumer name already in use` (error 10013) edge case by fetching the existing consumer |
| `build_consumer_configuration()` | Assembles a `push::Config` with a durable name, filter/deliver subjects, ACK wait, and max-deliver bound |
| `build_filter_subject()` | `machine.<id>.tool-restart` |
| `build_deliver_subject()` | `machine.<id>.tool-restart.inbox` |
| `build_durable_name()` | `machine_<id>_tool-restart_consumer` |

## Usage Example

```rust
let listener = ToolRestartMessageListener::new(
    nats_connection_manager,
    tool_restart_service,
    config_service,
    tool_run_manager,
);

// Spawns a self-healing background task; hold the handle to
// observe or cancel it.
let handle = listener.start().await?;
handle.await?;
```

## Retry & Back-off Behaviour

```text
Attempt 1 → wait INITIAL_RETRY_DELAY_MS
Attempt 2 → wait min(delay * 2, MAX_RETRY_DELAY_MS)
...
After CONSUMER_RETRY_ATTEMPTS_PER_CYCLE → pause CONSUMER_CYCLE_PAUSE_MS → next cycle
```

All delay constants are sourced from `update_config` and tunable at build time.
