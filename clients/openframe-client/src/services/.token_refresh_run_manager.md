Manages proactive JWT access token refresh in a background Tokio task, ensuring the shared token stays valid before expiry without requiring a NATS reconnect.

## Key Components

**`TokenRefreshRunManager`** — Cloneable struct holding references to `AgentAuthService` and `AgentConfigurationService`.

- **`new()`** — Constructs the manager with the required service dependencies.
- **`start()`** — Spawns a background Tokio task that loops indefinitely, sleeping until the next scheduled refresh, then calls `reauthenticate()` with a timeout, retrying on failure.

**`next_refresh_delay()`** *(private async fn)* — Computes the sleep duration until the next refresh by reading the current token, decoding its `exp` claim, and subtracting a lead margin.

**Timing constants:**

| Constant | Value | Purpose |
|---|---|---|
| `REFRESH_MARGIN` | 5 min | Refresh this early before `exp` |
| `MIN_LEAD` | 15 s | Minimum lead for short-lived tokens |
| `FALLBACK_INTERVAL` | 30 min | Used when `exp` is undecodable |
| `RETRY_INTERVAL` | 60 s | Delay between failed refresh retries |
| `REAUTH_TIMEOUT` | 30 s | Cap per `reauthenticate()` call |

## Usage Example

```rust
let manager = TokenRefreshRunManager::new(
    auth_service.clone(),
    config_service.clone(),
);

// Spawns a background task; call once at agent startup.
manager.start();
```

The task wakes before token expiry (`exp − REFRESH_MARGIN`), calls `reauthenticate()`, and retries every 60 s on failure. Short-lived tokens (TTL ≤ `REFRESH_MARGIN`) use `MIN_LEAD` to avoid a tight refresh loop.
