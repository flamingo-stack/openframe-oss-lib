Orchestrates safe restart of installed tools, handling both OS-managed services and supervisor-managed processes with proper locking, cancellation safety, and panic recovery.

## Key Components

### `RestartOutcome` (enum)
Represents the result of a restart attempt:
- `Restarted` — tool was found and restarted successfully
- `NotInstalled` — tool not found in the registry
- `Busy` — tool lock is held by another operation

### `UpdatingGuard` (struct)
RAII guard that clears the updating flag and releases the tool lock on drop, surviving both task cancellation and panics. Ensures the lock is never orphaned regardless of how the restart operation exits.

### `ToolRestartService` (struct)
Primary service struct with three public/internal methods:

| Method | Visibility | Description |
|---|---|---|
| `new(...)` | `pub` | Constructor injecting dependencies |
| `restart_guarded(tool_agent_id)` | `pub` | Entry point: acquires tool lock, sets updating flag, wraps execution in panic recovery |
| `restart_by_tool_agent_id(...)` | private | Resolves tool from registry, delegates to `restart_tool` |
| `restart_tool(tool)` | private | Stops the tool then restarts by install type (service vs. supervised process) |

## Usage Example

```rust
let service = ToolRestartService::new(
    installed_tools_service,
    tool_kill_service,
    tool_run_manager,
);

match service.restart_guarded("my-agent-id").await? {
    RestartOutcome::Restarted    => info!("Tool restarted successfully"),
    RestartOutcome::NotInstalled => warn!("Tool not found in registry"),
    RestartOutcome::Busy         => warn!("Tool is locked by another operation"),
}
```

**Service vs. supervised process behaviour:**
- `Installation::Service` — explicitly calls `system_service::start_service`, with a retry and a running-check to tolerate OS supervisor races.
- All other install types — delegates to `ToolRunManager::run_new_tool`, which re-supervises the process once the updating flag clears.
