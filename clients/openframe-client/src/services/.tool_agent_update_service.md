Orchestrates the full lifecycle of tool agent updates, handling version upgrades, asset updates, installation type migrations, and self-healing repair for broken or interrupted installs.

## Key Components

### `ToolAgentUpdateService`
The primary service struct, composed of injected dependencies:

| Field | Role |
|---|---|
| `github_download_service` | Downloads tool binaries from GitHub releases |
| `tool_agent_file_client` | File-level client for tool agent artifacts |
| `installed_tools_service` | Reads/writes tool registry records |
| `tool_kill_service` | Stops running tool processes before updates |
| `tool_run_manager` | Manages update flags and post-update relaunch |
| `directory_manager` | Resolves paths and checks binary presence |
| `config_service` | Reads agent configuration |
| `installed_agent_publisher` | Publishes post-update status messages |
| `command_params_resolver` | Resolves runtime command parameters |

### Key Methods

- **`new()`** — Constructs the service and ensures required directories exist at startup.
- **`process_update()`** — Entry point for handling a `ToolAgentUpdateMessage`. Detects repair needs (interrupted installs, missing binaries), computes which tool/assets need updating, coordinates stop/update/relaunch, and marks records as `Installed` on success.
- **`do_updates()`** — Sequences tool update before asset updates; stops the tool once when only assets need updating.
- **`do_tool_update()`** — Resolves the OS-specific download config, detects if an installation type migration is needed, and delegates to either `run_migration` or `run_update`.

## Usage Example

```rust
let svc = ToolAgentUpdateService::new(
    github_download_service,
    tool_agent_file_client,
    installed_tools_service,
    tool_kill_service,
    tool_run_manager,
    directory_manager,
    config_service,
    installed_agent_publisher,
    command_params_resolver,
);

let message = ToolAgentUpdateMessage {
    tool_agent_id: "my-tool".to_string(),
    version: "1.2.3".to_string(),
    download_configurations: vec![/* OS-specific configs */],
    assets: None,
};

svc.process_update(message).await?;
```

> **Self-healing behavior:** If a tool record is stuck in `Installing` state or its binary is missing on disk, `process_update` automatically forces a repair pass before applying the version update.
