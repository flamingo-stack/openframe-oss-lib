Manages the lifecycle of a NATS WebSocket connection for the OpenFrame agent, including initial connection setup, TLS configuration, automatic reconnection, and token-based reauthentication.

## Key Components

| Item | Description |
|------|-------------|
| `NatsConnectionManager` | Core struct holding the NATS client, reconnect broadcast channel, and injected service dependencies |
| `connect()` | Establishes the NATS connection with auth callbacks, reconnect delays, ping intervals, and optional dev TLS config |
| `get_client()` | Returns the active `Arc<Client>` or errors if `connect()` has not been called |
| `subscribe_reconnect()` | Returns a `broadcast::Receiver<()>` that fires whenever the client re-establishes a dropped connection |
| `perform_reauthentication_and_build_url()` | Private async method called by the NATS auth URL callback; refreshes the access token within a 10-second timeout and rebuilds the connection URL |
| `build_nats_connection_url()` | Constructs the WebSocket URL with a Bearer token as a query parameter (`/ws/nats?authorization=<token>`) |

## Usage Example

```rust
let manager = NatsConnectionManager::new(
    "wss://nats.example.com".to_string(),
    config_service,
    initial_configuration_service,
    auth_service,
    tls_config_provider,
);

// Subscribe to reconnect events before connecting
let mut reconnect_rx = manager.subscribe_reconnect();

// Establish connection
manager.connect().await?;

// Retrieve client for publishing/subscribing
let client = manager.get_client().await?;
client.publish("agent.heartbeat", "ping".into()).await?;

// React to reconnect events (e.g., re-subscribe to subjects)
tokio::spawn(async move {
    while reconnect_rx.recv().await.is_ok() {
        // Re-register subscriptions after reconnect
    }
});
```

## Notes

- Credentials use a static `machine` username with an empty password; actual authorization is handled via the JWT token embedded in the connection URL.
- TLS client configuration is only applied when `InitialConfigurationService::is_local_mode()` returns `true` (development environments).
- The `reconnect_tx` broadcast only fires on *subsequent* reconnections (not the initial connect) using an `AtomicBool` guard.
