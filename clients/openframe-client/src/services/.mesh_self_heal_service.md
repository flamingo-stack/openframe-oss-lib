Monitors the MeshCentral agent's health by continuously scanning its log file for connection failure/success markers and healing (refreshing the `.msh`, then restarting the agent) when it becomes stuck, silent, or loses its ServerID.

## Key Components

| Item | Description |
|------|-------------|
| `MeshSelfHealService` | Main service struct holding references to directory management, tool lifecycle, config, and an HTTP client |
| `run()` | Spawns the background watcher loop as a detached Tokio task |
| `watch()` | Core polling loop — reads new log lines every 30s, tracks health state, and triggers heal actions |
| `heal()` | Single heal path used by every unhealthy branch (missing ServerID, stuck, silent, disconnected): refreshes the `.msh`, then restarts the agent so it re-imports it |
| `is_disconnected()` | Positive-health check — treats "no healthy marker within `DISCONNECTED_DURATION`" as unhealthy even while the log stays busy, using the watcher's own uptime as the grace window before the first marker |
| `cooldown_for()` | Exponential, capped backoff applied to heals that keep failing to restore a server session |
| `restart_agent()` | Attempts a guarded restart via `ToolRestartService`, falling back to a process kill if the agent is unregistered |
| `try_refresh_msh()` | Fetches a fresh `.msh` config from `/generate-msh` and atomically rewrites the file if `MeshID` or `ServerID` changed |
| `current_msh_missing_serverid()` | Returns `true` when the on-disk `.msh` lacks a `ServerID` (agent cannot authenticate) |

### Timing Constants

| Constant | Value | Purpose |
|----------|-------|---------|
| `POLL_INTERVAL` | 30s | Log scan frequency |
| `STUCK_DURATION` | 10m | Max time a failure marker may persist without a healthy connect |
| `SILENCE_DURATION` | 90m | Max total log silence before assuming the agent is wedged or dead |
| `DISCONNECTED_DURATION` | 3h | Max time without a healthy marker — the agent reconnects hourly, and missing one beat is normal, so two are allowed before assuming it holds no session |
| `ACTION_COOLDOWN` | 60m | Base gap between heal attempts, doubled per consecutive failed heal up to 8x |

## Usage Example

```rust
let heal = MeshSelfHealService::new(
    directory_manager,
    installed_tools,
    tool_kill,
    tool_restart,
    initial_config,
    agent_config,
    tool_run_manager,
    Arc::clone(&deactivation),
);

// Spawns background watcher; returns immediately.
heal.run().await?;
```

Health is asserted from the *presence* of a recent healthy marker, not merely the absence of a failing one: any log line refreshes the silence timer, so an agent that keeps writing while never connecting would otherwise look healthy forever. A heal deliberately does not clear `last_healthy` — the restart has to earn its success by producing a healthy marker, and consecutive heals that don't escalate a warning and back off. After `MAX_DISCONNECT_HEALS` such heals the disconnect branch switches itself off (the `stuck` and ServerID branches stay live), so a renamed healthy marker in a future agent build degrades to a logged error rather than a fleet-wide restart loop.

The watcher exits only on an unexpected panic; the `run()` caller logs an error if that occurs. The service skips all heal logic while `DeactivationService::is_suspended()` is true (tenant offboarded) and resets timers after a detected host suspend to avoid false-positive restarts.
