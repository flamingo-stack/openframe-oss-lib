Handles background fetching and persistence of the initial registration key for legacy agent upgrades where the key is absent from local configuration.

## Key Components

- **`InitialKeyService`** — Main service struct holding an HTTP client, base URL, and references to `InitialConfigurationService` and `AgentConfigurationService`
- **`ensure_initial_key`** — Public async entry point; no-ops if the key already exists, otherwise spawns a background task that retries indefinitely until the key is fetched and saved
- **`fetch_registration_secret`** — Makes an authenticated `GET` request to `/clients/agent/registration-secret/active`, deserializing the JSON response into a key string
- **`is_key_missing`** — Delegates to `InitialConfigurationService` to check whether the key needs to be populated
- **`RegistrationSecretResponse`** — Private deserialization target for the API response `{ "key": "..." }`
- **`RETRY_INTERVAL_SECS`** — Constant (60s) controlling the delay between failed fetch attempts

## Usage Example

```rust
use std::sync::Arc;
use reqwest::Client;

let service = Arc::new(InitialKeyService::new(
    Client::new(),
    "https://api.example.com".to_string(),
    initial_config_service,
    agent_config_service,
));

// Call at agent startup; silently returns if key already present,
// otherwise spawns a background retry loop.
service.ensure_initial_key().await;
```

## Notes

- The retry loop runs in a detached `tokio::spawn` task and exits only on success, making the caller non-blocking
- Errors during save (e.g., disk/config write failures) are logged but cause the loop to exit rather than retry — only HTTP fetch failures trigger the 60-second backoff
