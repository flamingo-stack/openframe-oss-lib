Defines the data structures for tool installation messages exchanged between the OpenFrame agent and the tool management system, including asset metadata and OS-specific filename resolution.

## Key Components

### Structs

- **`ToolInstallationMessage`** — Top-level message payload describing a tool to install or reinstall, including versioning, command arguments, optional download configurations, and associated assets. Serializes to/from camelCase JSON.
  - `effective_version()` — Returns the version string, applying any local override from `tool_version_overrides` if present.

- **`Asset`** — Describes a binary or file asset associated with a tool, with source, path, executable flag, and optional per-asset download configurations.
  - `original_version()` — Returns the asset's version or an empty string if unset.
  - `effective_version()` — Returns the version with any override applied.

- **`LocalFilenameConfig`** — Maps a filename to a target OS string (`"windows"`, `"macos"`, `"linux"`).
  - `matches_current_os()` — Case-insensitively checks whether the config applies to the current compile-target OS using `cfg!` macros.

### Enums

- **`AssetSource`** — Enumerates valid asset download sources: `Artifactory`, `ToolApi`, `Github`.

## Usage Example

```rust
use crate::tool_installation_message::{ToolInstallationMessage, Asset, AssetSource, LocalFilenameConfig};

// Deserialize an incoming installation message (e.g., from JSON over the wire)
let msg: ToolInstallationMessage = serde_json::from_str(&raw_json)?;

// Resolve effective version (may be overridden locally)
println!("Installing {} at version {}", msg.tool_id, msg.effective_version());

// Filter assets for the current OS
if let Some(assets) = &msg.assets {
    for asset in assets {
        let local_name = asset
            .local_filename_configuration
            .iter()
            .find(|c| c.matches_current_os())
            .map(|c| c.filename.as_str())
            .unwrap_or("unknown");

        println!("Asset {} -> local file: {}", asset.id, local_name);
    }
}
```

## Notes

- Optional fields (`download_configurations`, `installation_command_args`, `assets`, etc.) are omitted from serialization when `None`, keeping message payloads compact.
- Version overrides are applied at runtime via `tool_version_overrides::lookup`, allowing pinned versions without modifying incoming messages.
