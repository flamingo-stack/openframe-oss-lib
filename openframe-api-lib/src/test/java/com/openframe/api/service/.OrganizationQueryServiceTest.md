Unit tests for `OrganizationQueryService` that verify service-level contract behavior including total count reporting, pagination, cursor encoding, and filter forwarding to the repository layer. The repository is fully mocked so tests remain focused on service logic.

## Key Components

| Test | What It Verifies |
|---|---|
| `filteredCountIsTotalNotPageSize` | `filteredCount` reflects the full repository count (137), not the returned page size |
| `hasNextPageWhenFull` | `hasNextPage` is `true` when the service fetches `limit + 1` records and trims the last |
| `compoundCursorForLastActivitySort` | `updatedAt`-based sorts produce `<millis>_<id>` compound cursors via `CursorCodec` |
| `lastActivityRangeIsForwardedToRepository` | `lastActivityFrom`/`lastActivityTo` on `OrganizationFilterOptions` are not silently dropped before reaching `buildOrganizationQuery` |
| `plainCursorForLegacyIdSort` | `_id` sorts produce a plain ObjectId cursor (no compound encoding) |

## Usage Example

```java
// Run a single test from CLI
./mvnw test -pl api -Dtest=OrganizationQueryServiceTest#compoundCursorForLastActivitySort

// Run all tests in the class
./mvnw test -pl api -Dtest=OrganizationQueryServiceTest
```

## Notes

- **Pagination strategy:** the service always requests `limit + 1` items from the repository; if all extra items are returned, `hasNextPage` is set to `true` and the list is trimmed before returning.
- **Regression guard:** `lastActivityRangeIsForwardedToRepository` uses `ArgumentCaptor` to catch a past bug where `lastActivityFrom`/`lastActivityTo` were silently dropped in the service builder — it validates at the `buildOrganizationQuery` call site, making it robust to downstream `Query` shape changes.
- **Cursor encoding:** `CursorCodec.decode` is used in assertions to keep tests readable regardless of the Base64 encoding layer.
