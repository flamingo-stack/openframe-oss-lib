Unified response DTO returned by fire-and-forget RMM dispatch mutations (`runCommand`, `cancelExecution`, `runScript`) over core NATS, carrying the server-minted `executionId` used to correlate asynchronous agent results.

## Key Components

| Member | Type | Description |
|---|---|---|
| `executionId` | `String` | Server-generated identifier linking the dispatch request to the agent's async result |

Lombok `@Data` generates getters, setters, `equals`, `hashCode`, and `toString`. `@Builder` provides a fluent construction API.

## Usage Example

```java
// Building a response after dispatching a NATS command
DispatchResponse response = DispatchResponse.builder()
    .executionId("exec-7f3a1c9b-42d0-4e8f-b6d2-1a2b3c4d5e6f")
    .build();

// Accessing the executionId for dashboard correlation
String id = response.getExecutionId();
```

## Notes

- Intentionally minimal — all three dispatch mutations (`runCommand`, `cancelExecution`, `runScript`) share this single DTO to avoid duplicate one-field classes.
- The `executionId` is **server-minted**; clients treat it as an opaque correlation token.
- Pairs with the agent's async result stream where the same `executionId` surfaces in the completion payload.
