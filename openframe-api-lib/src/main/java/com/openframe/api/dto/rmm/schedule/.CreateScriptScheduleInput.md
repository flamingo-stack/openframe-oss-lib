DTO for creating a new script schedule in the OpenFrame RMM (Remote Monitoring & Management) module. Tenant attribution is derived from the authenticated principal at the resolver layer, not from client input.

## Key Components

| Field | Type | Constraints | Description |
|---|---|---|---|
| `name` | `String` | `@NotBlank` | Human-readable schedule name |
| `description` | `String` | — | Optional description |
| `supportedPlatforms` | `List<ScriptPlatform>` | — | Target OS/platform filters |
| `scriptIds` | `List<String>` | — | IDs of scripts to execute |
| `trigger` | `ScriptScheduleTrigger` | `@NotNull` | Trigger type/configuration |
| `startAt` | `Instant` | — | First run time as UTC instant; schedule is skipped by the runner until set |
| `repeat` | `Long` | `@Min(1800)` | Repeat interval in seconds (minimum 30 minutes) |

## Usage Example

```java
CreateScriptScheduleInput input = new CreateScriptScheduleInput();
input.setName("Nightly Patch Check");
input.setDescription("Runs patch audit scripts on all Windows servers");
input.setSupportedPlatforms(List.of(ScriptPlatform.WINDOWS));
input.setScriptIds(List.of("script-abc123", "script-def456"));
input.setTrigger(ScriptScheduleTrigger.RECURRING);
input.setStartAt(Instant.parse("2025-01-01T02:00:00Z"));
input.setRepeat(86400L); // 24 hours
```

## Notes

- **Tenant isolation** — the tenant ID is never accepted from the client; it is injected server-side from the authenticated principal, preventing cross-tenant schedule creation.
- **`startAt` semantics** — a `null` value means the schedule will not fire until a start time is explicitly set. The dashboard is responsible for converting local Date/Time selections to UTC before submission.
- **`repeat` minimum** — enforced at 1800 seconds (30 minutes) via `@Min` to prevent runaway scheduling.
