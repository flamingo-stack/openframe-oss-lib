Maps `ScriptExecution` document entities to `ScriptExecutionResponse` DTOs with no business logic or GraphQL concerns.

## Key Components

| Component | Description |
|---|---|
| `ScriptExecutionMapper` | Spring `@Component` responsible solely for entity-to-DTO field mapping |
| `toResponse(ScriptExecution)` | Converts a `ScriptExecution` document into a `ScriptExecutionResponse` DTO using the builder pattern |

## Mapped Fields

All fields are mapped 1:1 from entity to DTO:

| Field | Description |
|---|---|
| `id`, `executionId`, `scriptId`, `scheduleId`, `machineId` | Identity and relationship references |
| `privilegeLevel`, `initiatedBy`, `status` | Execution context |
| `dispatchedAt`, `statusChangedAt`, `finishedAt` | Lifecycle timestamps |
| `exitCode`, `executionTimeMs`, `timedOut` | Execution result metadata |
| `stdout`, `stdoutTruncated`, `stderr`, `stderrTruncated`, `error` | Output and error capture |

## Usage Example

```java
@Service
public class ScriptExecutionService {

    private final ScriptExecutionMapper mapper;

    public ScriptExecutionService(ScriptExecutionMapper mapper) {
        this.mapper = mapper;
    }

    public ScriptExecutionResponse getExecution(ScriptExecution entity) {
        return mapper.toResponse(entity);
    }
}
```

## Notes

- **No business logic** — pure structural mapping only; connection/pagination envelopes are assembled upstream in `GraphQLExecutionMapper`.
- **Spring-managed** — injectable as a standard `@Component` wherever DTO conversion is needed.
