Manages persistence and retrieval of batch command execution records, serving as the command counterpart to `ScriptExecutionService`. Tenant scoping is handled internally via `TenantIdProvider`.

## Key Components

| Member | Description |
|---|---|
| `createBatch(...)` | Bulk-persists one `RUNNING` execution row per target machine under a shared `executionId`. Unique constraint: `(tenantId, executionId, machineId)`. |
| `getBatchResults(...)` | Retrieves current execution rows for a batch dispatch, scoped to the resolved tenant. Rows may still be `RUNNING` if the agent has not yet reported. |
| `buildRunningRow(...)` | Private builder that constructs a `CommandExecution` document with `RUNNING` status, stamping both `dispatchedAt` and `statusChangedAt` to the same `Instant`. |

## Usage Example

```java
// Dispatch a batch command to multiple machines
List<CommandExecution> executions = commandExecutionService.createBatch(
    "exec-abc-123",
    "Get-Service | Where-Object {$_.Status -eq 'Running'}",
    ScriptShell.POWERSHELL,
    List.of("machine-1", "machine-2", "machine-3"),
    PrivilegeLevel.ADMIN,
    60,
    "user@example.com"
);

// Poll results after agent callbacks
List<CommandExecution> results = commandExecutionService.getBatchResults(
    "exec-abc-123",
    List.of("machine-1", "machine-2", "machine-3")
);

results.forEach(r ->
    log.info("Machine {} → {}", r.getMachineId(), r.getStatus())
);
```

## Notes

- Tenant resolution is implicit — callers do not pass a `tenantId` directly.
- `getBatchResults` silently omits machines with no matching row (via `Optional::stream` flatMap), so result count may be less than `machineIds.size()` if rows were not yet created or belong to a different tenant.
