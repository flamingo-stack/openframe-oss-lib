Manages the assignment of devices (machines) to script schedules within the RMM (Remote Monitoring & Management) module, providing CRUD-style set reconciliation for machine-to-schedule relationships scoped by tenant.

## Key Components

| Member | Description |
|---|---|
| `setDevices()` | Reconciles the full set of assigned machines for a schedule — adds new entries and removes stale ones in a single transaction |
| `getMachineIds()` | Returns the list of machine IDs assigned to a single schedule |
| `getMachineIdsByScheduleIds()` | Batch lookup returning a map of `scheduleId → List<machineId>` for multiple schedules |
| `requireVisibleSchedule()` | Guard that throws `NotFoundException` if the schedule is missing or has `DELETED` status |

## Usage Example

```java
// Assign a specific set of devices to a schedule (full replace semantics)
scriptScheduleDeviceService.setDevices(
    "sched-abc123",
    List.of("machine-1", "machine-2", "machine-3"),
    "user-xyz"
);

// Fetch machines for a single schedule
List<String> machineIds = scriptScheduleDeviceService.getMachineIds("sched-abc123");

// Batch fetch for multiple schedules (e.g. when rendering a list view)
Map<String, List<String>> bySchedule = scriptScheduleDeviceService
    .getMachineIdsByScheduleIds(List.of("sched-abc123", "sched-def456"));
```

## Notes

- `setDevices` uses **set-difference reconciliation**: only the delta (additions/removals) is written, avoiding full table replacement.
- All operations are **tenant-scoped** via `TenantIdProvider` — cross-tenant leakage is not possible.
- Schedules with `ScriptStatus.DELETED` are treated as non-existent; callers receive a `NotFoundException`.
