Service layer class responsible for retrieving and filtering `ToolConnection` records, automatically excluding connections with a `DISCONNECTED` status from all query results.

## Key Components

| Method | Description |
|---|---|
| `findById(String id)` | Looks up a single `ToolConnection` by ID; returns empty if not found or disconnected |
| `getToolConnectionsForMachines(List<String> machineIds)` | Batch-loads connections for multiple machines; returns a parallel list preserving input order (designed for DataLoader use) |
| `getToolConnectionsForMachine(String machineId)` | Returns all active connections for a single machine |
| `excludeDisconnected(List<ToolConnection>)` | Private helper that filters out any connection with `ConnectionStatus.DISCONNECTED` |
| `isNotDisconnected(ToolConnection)` | Predicate used by both `findById` and `excludeDisconnected` |

## Usage Example

```java
// Inject the service
@Autowired
private ToolConnectionService toolConnectionService;

// Look up a single connection (empty if disconnected)
Optional<ToolConnection> conn = toolConnectionService.findById("conn-abc123");

// Fetch all active connections for one machine
List<ToolConnection> connections = toolConnectionService.getToolConnectionsForMachine("machine-001");

// Batch fetch for a GraphQL DataLoader (preserves machineIds order)
List<String> machineIds = List.of("machine-001", "machine-002", "machine-003");
List<List<ToolConnection>> batchResults = toolConnectionService.getToolConnectionsForMachines(machineIds);
// batchResults.get(0) → connections for "machine-001", etc.
```

## Notes

- All methods operate under `@Transactional(readOnly = true)` — no write operations are performed.
- `getToolConnectionsForMachines` preserves the input list order, making it safe to use as a [Spring DataLoader](https://github.com/graphql-java/java-dataloader) batch function where index alignment between keys and results is required.
- Connections in `DISCONNECTED` state are silently excluded at the service layer rather than the repository layer, keeping query logic clean.
