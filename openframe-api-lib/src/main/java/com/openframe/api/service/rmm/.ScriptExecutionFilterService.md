Provides faceted filter options for the Execution History tab, returning distinct initiator, status, and machine options with live counts for a given script, scoped to the current tenant.

## Key Components

- **`getExecutionFilters(scriptId, input, search)`** — Main entry point. Queries three facets (initiators, statuses, machines) and a filtered total count from the repository, then maps raw ID/count maps into labeled filter options via `ScriptFilterOptionMapper`.
- **`toQueryFilter(input)`** — Private helper that converts a `ScriptExecutionFilterInput` DTO into a `ScriptExecutionQueryFilter` for repository queries. Returns `null` if input is absent (no active filters).
- **`ScriptFilterOptionMapper`** — Delegated label resolution: `userLabeled` resolves initiator IDs to display names, `machineLabeled` resolves machine IDs, and `selfLabeled` passes statuses through as-is.
- **`TenantIdProvider`** — Ensures all repository calls are tenant-scoped.

## Usage Example

```java
@Autowired
ScriptExecutionFilterService executionFilterService;

// Build active filter state from the UI
ScriptExecutionFilterInput input = ScriptExecutionFilterInput.builder()
        .statuses(List.of("SUCCESS", "FAILED"))
        .initiatorIds(List.of("user-123"))
        .machineIds(List.of())
        .build();

// Fetch faceted filters for a specific script
ScriptExecutionFilters filters = executionFilterService.getExecutionFilters(
        "script-abc",
        input,
        "deploy"   // optional search string
);

// Use results to populate the Execution History filter panel
int totalMatching = filters.getFilteredCount();
List<FilterOption> initiatorOptions = filters.getInitiators();
```

> **Note:** The initiator facet intentionally excludes the initiator field from its own filter constraints, allowing the UI to show all available initiators while other filters (status, machine) remain active — a standard faceted-search exclusion pattern.
