Manages CRUD operations and lifecycle transitions for RMM script schedules within a tenant-scoped context, enforcing name uniqueness, soft-delete semantics, and half-hour grid timing constraints.

## Key Components

| Member | Description |
|---|---|
| `SLOT_SECONDS` | Constant (`1800L`) defining the half-hour execution grid |
| `NAME_UNIQUE_STATUSES` | Statuses (`ACTIVE`, `ARCHIVED`) that participate in name uniqueness checks |
| `create()` | Creates a new schedule; throws `ConflictException` on duplicate name |
| `get()` | Retrieves a single schedule by ID; throws `NotFoundException` for missing/deleted |
| `findById()` | Non-throwing optional lookup; returns empty for missing or soft-deleted schedules |
| `getSchedulesByIds()` | Batch lookup by a collection of IDs |
| `list()` | Cursor-paginated, filtered, and sorted listing using "fetch limit + 1" pagination |
| `update()` | Full replacement (PUT semantics) with name conflict and timing validation |
| `delete()` | Soft-deletes by transitioning status to `DELETED`; idempotent |
| `archive()` / `unarchive()` | Transitions schedule between `ARCHIVED` and `ACTIVE`; both idempotent |
| `validateTiming()` | Enforces grid alignment for `startAt` and `repeatSeconds` |

## Usage Example

```java
// Create a new schedule
CreateScriptScheduleInput input = CreateScriptScheduleInput.builder()
    .name("Nightly Cleanup")
    .trigger(ScriptScheduleTrigger.DATE_TIME)
    .startAt(Instant.parse("2025-01-01T00:00:00Z"))
    .repeat(3600L)
    .build();

ScriptScheduleResponse created = scriptScheduleService.create(input, "user-123");

// Paginated listing with filter
CursorPaginationCriteria pagination = CursorPaginationCriteria.of(20, null);
CountedGenericQueryResult<ScriptScheduleResponse> result =
    scriptScheduleService.list(filter, "cleanup", sort, pagination);

// Soft-delete
String deletedId = scriptScheduleService.delete(created.getId());

// Archive / restore
scriptScheduleService.archive(created.getId());
scriptScheduleService.unarchive(created.getId());
```

## Notes

- Tenant isolation is resolved automatically via `TenantIdProvider`; callers do not pass `tenantId`.
- `ScriptStatus.DELETED` is treated as non-existent in `get()` and `update()`, but `delete()` itself is idempotent against already-deleted records.
- Schedules with a `DATE_TIME` trigger have `nextRunAt` set to `startAt`; event-driven triggers (`DEVICE_ONLINE`) set `nextRunAt` to `null`.
