Configuration properties class for Firebase Cloud Messaging (FCM) push notifications, binding `openframe.push.fcm.*` properties and validating them at application startup.

## Key Components

| Member | Default | Description |
|---|---|---|
| `projectId` | *(required)* | GCP project ID; must be set explicitly — Application Default Credentials carry no project |
| `maxTitleBytes` | `200` | Byte budget for the notification title |
| `maxBodyBytes` | `1200` | Byte budget for the notification body |
| `maxContextBytes` | `2000` | Byte budget for the context/data payload |
| `connectTimeout` | `5s` | HTTP connection timeout to FCM |
| `readTimeout` | `10s` | HTTP read timeout from FCM |
| `validate()` | — | Enforces non-blank `projectId`, non-negative budgets, and ensures the combined payload fits FCM's hard limit |

`afterPropertiesSet()` calls `validate()` immediately after Spring binds properties, so misconfiguration fails fast at startup rather than at the first push attempt.

## Usage Example

```yaml
openframe:
  push:
    fcm:
      project-id: my-gcp-project
      max-title-bytes: 150
      max-body-bytes: 1000
      max-context-bytes: 1800
      connect-timeout: 5s
      read-timeout: 10s
```

```java
@Configuration
@EnableConfigurationProperties(FcmProperties.class)
public class FcmConfig {

    @Bean
    public FcmPushSender fcmPushSender(FcmProperties props) {
        return new FcmPushSender(props);
    }
}
```

> **Startup guard:** if `project-id` is blank or the sum of byte budgets exceeds FCM's payload limit (accounting for envelope overhead defined in `FcmPushSender.ENVELOPE_HEADROOM_BYTES`), the application will refuse to start with a descriptive `IllegalStateException`.
