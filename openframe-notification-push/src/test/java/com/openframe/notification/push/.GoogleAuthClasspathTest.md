Validates that the Google Auth library is not split across incompatible versions on the classpath, preventing a subtle FCM authentication failure caused by `NoClassDefFoundError` during token refresh.

## Key Components

- **`google_auth_halves_are_not_split()`** — Asserts that `com.google.auth.CredentialTypeForMetrics` is resolvable and that `com.google.auth.Credentials` and `GoogleCredentials` originate from the same JAR version.
- **`jarOf(Class<?>)`** — Extracts the version segment from a class's JAR path using the `google-auth-library-*` path pattern, enabling version equality comparison.

## Usage Example

```java
// This test runs automatically as part of the test suite.
// No setup required — it inspects the live classpath at test time.

// If the test fails with something like:
//   expected: "0.26.0"
//    but was: "1.19.0"
// it means two different versions of google-auth-library are present,
// e.g., google-auth-library-credentials and google-auth-library-oauth2-http
// are resolving from different dependency trees.

// Fix by enforcing a single version in your build file:
// (Maven)
// <dependencyManagement>
//   <dependency>
//     <groupId>com.google.auth</groupId>
//     <artifactId>google-auth-library-bom</artifactId>
//     <version>1.19.0</version>
//     <type>pom</type>
//     <scope>import</scope>
//   </dependency>
// </dependencyManagement>
```

> **Why this matters:** A split Google Auth classpath silently succeeds in unit tests using mocks but throws `NoClassDefFoundError` at runtime on the first FCM token refresh — a failure mode that only appears in production or integration environments.
