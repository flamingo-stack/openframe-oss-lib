Resolves effective frontend feature flags by merging per-tenant database overrides on top of YAML-configured defaults, with a Caffeine cache to keep repeated lookups cheap.

## Key Components

| Member | Type | Description |
|---|---|---|
| `CACHE_TTL` | `Duration` (5 min) | TTL for the per-tenant overrides cache |
| `overridesCache` | `Cache<String, Map<String, Boolean>>` | Caffeine cache keyed by tenant ID |
| `getEffectiveFlags()` | `public Map<String, Boolean>` | Returns the merged flag map (defaults + DB overrides) |
| `loadOverrides()` | `private Map<String, Boolean>` | Fetches tenant overrides from the repository, using the cache |

**Merge precedence:** DB override value → YAML default value. Any override-only keys are appended after the YAML defaults in insertion order.

**Failure behavior:** If the repository call throws, the error is logged at `WARN` level and an empty map is returned, so defaults remain in effect.

## Usage Example

```java
@Component
@RequiredArgsConstructor
public class FeatureFlagResolver {

    private final FeFeatureFlagService feFeatureFlagService;

    // Called from a GraphQL query handler
    public Map<String, Boolean> frontendFlags() {
        // Returns yml defaults overridden by any per-tenant DB values.
        // Result is cached per tenant for 5 minutes.
        return feFeatureFlagService.getEffectiveFlags();
    }
}
```

## Notes

- Requires a `TenantIdProvider` bean to scope the cache per tenant.
- The underlying `FeFeatureFlagsRepository` is expected to return at most one document via `findFirstBy()`.
- Cache entries expire **5 minutes** after write; flag changes in the DB are reflected within that window without a restart.
